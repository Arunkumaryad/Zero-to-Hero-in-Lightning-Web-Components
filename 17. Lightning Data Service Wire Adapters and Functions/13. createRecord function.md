# `createRecord()` Function in Lightning Web Components

## 1. Overview

This folder demonstrates how to create a Salesforce record from a
Lightning Web Component (LWC) using the `createRecord()` function from
`lightning/uiRecordApi`.

The example creates a **Contact** record. The user enters First Name,
Last Name, Title, Phone, and Email, then clicks **Create Contact**. The
component sends the values to Salesforce, displays a success or error
toast, and clears the form after a successful save.

## 2. Definition From the Screenshot

> **createRecord** --- CreateRecord is used to create a record.

### Syntax shown in the screenshot

``` javascript
import { createRecord } from 'lightning/uiRecordApi';

createRecord(recordInput: Record): Promise<Record>
```

### `recordInput` definition shown in the screenshot

> **recordInput** --- A Record Input object is used to create the
> record. This object takes the object API name and fields details as
> input.

In simple terms, `recordInput` tells Salesforce which object to create
and which field values to save. `createRecord()` returns a Promise that
resolves with the created record or rejects if creation fails.

## 3. What Is `createRecord()`?

`createRecord()` is a function from `lightning/uiRecordApi` that creates
a Salesforce record using the UI API and Lightning Data Service. It can
create supported records from an LWC without a custom Apex method for a
straightforward create operation.

**Benefits** - Creates records directly from an LWC. - Uses Salesforce
UI API and Lightning Data Service. - Respects the current user's object
permissions and field-level security. - Returns the newly created
record, including its ID. - Supports Promise-based success and error
handling.

## 4. `recordInput` Structure

A record input object contains two important properties:

  Property    Meaning
  ----------- -------------------------------------------------------
  `apiName`   API name of the Salesforce object, such as `Contact`.
  `fields`    Object containing field API names and values to save.

Example:

``` javascript
const recordInput = {
    apiName: 'Contact',
    fields: {
        FirstName: 'Anuj',
        LastName: 'Kumar',
        Title: 'Developer',
        Phone: '9876543210',
        Email: 'anuj@example.com'
    }
};
```

Prefer importing the object from `@salesforce/schema` rather than
hard-coding the object API name.

### B. JavaScript --- `createRecordDemo.js`

``` javascript
import { LightningElement } from 'lwc';
import { createRecord } from 'lightning/uiRecordApi';
import CONTACT_OBJECT from '@salesforce/schema/Contact';
import { ShowToastEvent } from 'lightning/platformShowToastEvent';

export default class CreateRecordDemo extends LightningElement {
    formFields = {};

    changeHandler(event) {
        const { name, value } = event.target;

        this.formFields = {
            ...this.formFields,
            [name]: value
        };
    }

    handleSubmit(event) {
        event.preventDefault();

        const inputs = [
            ...this.template.querySelectorAll('lightning-input')
        ];

        const allValid = inputs.reduce((validSoFar, input) => {
            input.reportValidity();
            return validSoFar && input.checkValidity();
        }, true);

        if (allValid) {
            this.createContact();
        }
    }

    createContact() {
        const recordInput = {
            apiName: CONTACT_OBJECT.objectApiName,
            fields: { ...this.formFields }
        };

        createRecord(recordInput)
            .then((result) => {
                this.showToast(
                    'Success',
                    `Contact created with Id: ${result.id}`,
                    'success'
                );

                this.template.querySelector('form.createForm').reset();
                this.formFields = {};
            })
            .catch((error) => {
                this.showToast(
                    'Error creating Contact',
                    this.getErrorMessage(error),
                    'error'
                );
            });
    }

    getErrorMessage(error) {
        if (error?.body?.output?.errors?.length) {
            return error.body.output.errors
                .map((item) => item.message)
                .join(', ');
        }

        if (error?.body?.output?.fieldErrors) {
            return Object.values(error.body.output.fieldErrors)
                .flat()
                .map((item) => item.message)
                .join(', ');
        }

        if (Array.isArray(error?.body)) {
            return error.body.map((item) => item.message).join(', ');
        }

        return error?.body?.message ||
            error?.message ||
            'An unknown error occurred.';
    }

    showToast(title, message, variant) {
        const event = new ShowToastEvent({
            title,
            message,
            variant: variant || 'success'
        });

        this.dispatchEvent(event);
    }
}
```

## 7. Code Explanation Step by Step

### Step 1: Import modules

``` javascript
import { LightningElement } from 'lwc';
import { createRecord } from 'lightning/uiRecordApi';
import CONTACT_OBJECT from '@salesforce/schema/Contact';
import { ShowToastEvent } from 'lightning/platformShowToastEvent';
```

-   `LightningElement` is the base class for an LWC.
-   `createRecord` creates a record through the UI API.
-   `CONTACT_OBJECT` is the schema reference for the Contact object.
-   `ShowToastEvent` displays a toast notification.

### Step 2: Store input values

``` javascript
formFields = {};
```

This object stores the values entered by the user. For example:

``` javascript
{
    FirstName: 'Anuj',
    LastName: 'Kumar',
    Title: 'Developer',
    Phone: '9876543210',
    Email: 'anuj@example.com'
}
```

### Step 3: Handle changes in all inputs

``` javascript
changeHandler(event) {
    const { name, value } = event.target;

    this.formFields = {
        ...this.formFields,
        [name]: value
    };
}
```

-   `event.target` identifies the input that changed.
-   `name` contains its field API name, such as `FirstName`.
-   `value` contains the user's entry.
-   `[name]` is a computed property name that stores the value under the
    correct key.
-   The spread operator preserves values entered in the other inputs.

### Step 4: Build `recordInput`

``` javascript
const recordInput = {
    apiName: CONTACT_OBJECT.objectApiName,
    fields: { ...this.formFields }
};
```

-   `apiName` identifies the Salesforce object.
-   `fields` contains the field API names and their values.

### Step 5: Call `createRecord()`

``` javascript
createRecord(recordInput)
    .then((result) => {
        // Record created successfully.
    })
    .catch((error) => {
        // Record creation failed.
    });
```

`createRecord()` returns a Promise: - `.then()` runs when Salesforce
creates the record successfully. - `.catch()` runs if the operation
fails. - `result.id` contains the new record's ID.

### Step 6: Show a toast

``` javascript
const event = new ShowToastEvent({
    title: 'Success',
    message: `Contact created with Id: ${result.id}`,
    variant: 'success'
});

this.dispatchEvent(event);
```

A toast is a temporary notification. Common variants are `success`,
`error`, `warning`, and `info`.

### Step 7: Reset the form

``` javascript
this.template.querySelector('form.createForm').reset();
this.formFields = {};
```

The first statement clears the UI inputs. The second clears the
JavaScript object so old values are not reused.

## 9. Important Concepts

### Lightning Data Service (LDS)

Lightning Data Service provides access to Salesforce records through
supported UI API operations. It handles much of the record interaction
and respects the user's access.

### UI API

The User Interface API provides Salesforce data and metadata in a format
designed for building user interfaces. LWC functions such as
`createRecord`, `updateRecord`, and `deleteRecord`, and wire adapters
such as `getRecord`, use UI API.

### Schema Import

``` javascript
import CONTACT_OBJECT from '@salesforce/schema/Contact';
```

Schema imports reference Salesforce objects and fields. They are
preferable to hard-coded API names because they provide compile-time
checking and help Salesforce track dependencies.

### Promise

A Promise represents the eventual success or failure of an asynchronous
operation. `createRecord()` returns a Promise, so use `.then()` /
`.catch()` or `async` / `await` to handle its result.

### Object Permissions and Field-Level Security

UI API operations respect the current user's access. The user needs the
required object permissions and access to the fields being submitted.
Required fields, validation rules, duplicate rules, and other Salesforce
rules can also cause the create operation to fail.

## 11. Interview Questions and Answers

### Q1. What is `createRecord()` in LWC?

It is a function from `lightning/uiRecordApi` used to create a
Salesforce record from an LWC using UI API.

### Q2. From which module is `createRecord()` imported?

``` javascript
import { createRecord } from 'lightning/uiRecordApi';
```

### Q3. What is the syntax of `createRecord()`?

``` javascript
createRecord(recordInput);
```

It accepts a record input object and returns a Promise.

### Q4. What is `recordInput`?

An object containing the Salesforce object API name and the field values
to save.

### Q5. What are the two main properties of `recordInput`?

-   `apiName` --- the API name of the object to create.
-   `fields` --- an object containing field API names and values.

### Q6. What does `createRecord()` return?

A Promise. It resolves with the created record, including its ID, or
rejects with an error.

### Q7. Why use `.then()` and `.catch()`?

`.then()` handles successful completion, while `.catch()` handles
errors.

### Q8. What is Lightning Data Service?

A Salesforce service that lets Lightning components work with records
through supported data operations while respecting Salesforce security
and sharing behavior.

### Q9. Do we need Apex to create a standard Salesforce record?

Not for a straightforward create operation supported by UI API.
`createRecord()` can perform it from the client.

### Q10. When should we use Apex instead?

Use Apex when the operation needs complex server-side business logic,
multiple coordinated DML operations, unsupported UI API functionality,
or other server-side processing.

### Q11. What is the purpose of `@salesforce/schema`?

It provides references to Salesforce objects and fields. Schema imports
improve maintainability and provide compile-time checking.

### Q12. Why use `CONTACT_OBJECT.objectApiName`?

It obtains the Contact object's API name from the schema reference
instead of hard-coding `'Contact'`.

### Q13. What is `ShowToastEvent`?

A platform event used to display a toast notification to the user.

### Q14. What are common toast variants?

`success`, `error`, `warning`, and `info`.

### Q15. How do you get the ID of the newly created record?

Read `result.id` from the result passed to the `.then()` callback.

### Q16. Difference between `createRecord()` and `updateRecord()`?

`createRecord()` creates a new record. `updateRecord()` updates an
existing record and requires its ID.

### Q17. Difference between `createRecord()` and Apex `insert`?

`createRecord()` uses UI API and is designed for client-side record
creation under UI API access rules. Apex `insert` is server-side DML and
is suitable for custom server-side logic and more complex transactions.

### Q18. Does `createRecord()` bypass validation rules?

No. Applicable Salesforce validation and platform rules still apply. If
a rule blocks the save, the Promise rejects.

### Q19. How can you validate inputs before creating a record?

Use input attributes such as `required` and methods such as
`checkValidity()` and `reportValidity()` before calling
`createRecord()`.

### Q20. What is the purpose of `event.target.name`?

It identifies the input that generated the change event. Here, the input
name matches the Salesforce field API name, so one handler can store
values for multiple fields.

### Q21. Why clear form data after successful creation?

To prevent previously entered values from being accidentally reused in
another create operation.

### Q22. What permissions are required to create a Contact?

The user needs Create access on Contact and access to the fields being
populated. Required fields and Salesforce validation rules must also be
satisfied.
