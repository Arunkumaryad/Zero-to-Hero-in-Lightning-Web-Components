# `@wire` Service in LWC — Fetch User Details

## 1. Overview

This folder demonstrates the LWC wire service and how to fetch a Salesforce User record's Name and Email using the `getRecord` wire adapter. The screenshots show two patterns: a **wired function** and a **wired property**. Both use Salesforce UI API through `lightning/uiRecordApi`.

## 2. Definitions from the Screenshots

The following preserves the meaning of the supplied slide text, with formatting adjusted for readability.

### What is `@wire` Service?

1. Wire service is built on Lightning Data Service.
2. LWC components use `@wire` in their JavaScript class to read data from one of the wire adapters in the `lightning/ui*Api` namespace.
3. `@wire` is a reactive service.
4. The wire adapter defines the data shape that the wire service provisions in an immutable stream.

### Wire syntax shown in the screenshot

```javascript
import { adapterId } from 'adapterModule';

@wire(adapterId, adapterConfig)
propertyOrFunction;
```

### Import a Salesforce standard object

**Syntax shown:**

```javascript
import objectName from '@salesforce/schema/object';
```

**Example shown:**

```javascript
import ACCOUNT_OBJECT from '@salesforce/schema/Account';
```

### Import a Salesforce custom object

The screenshot shows this example:

```javascript
import PROPERTY_OBJECT from '@salesforce/schema/Property__c';
```

For a custom object, use its actual API name, including the `__c` suffix.

## 3. What Is the Wire Service?

The wire service provisions data to an LWC reactively. It can use a supported UI API wire adapter or an Apex method. In this example, `getRecord` from `lightning/uiRecordApi` reads a User record.

- **Reactive:** when a reactive wire parameter changes, the service provisions data again.
- **Immutable:** treat provisioned data as read-only. Make a copy if you need to transform it.
- **Asynchronous:** data may not be available during the first render.
- **Error handling:** the result can contain `data` or `error`.
- **Caching:** LDS/UI API can use client-side caching where applicable.

## 4. Example: Fetch User Details Using a Wired Function

### JavaScript — `wireDemoUsers.js`

```javascript
import { LightningElement, wire } from 'lwc';
import Id from '@salesforce/user/Id';
import { getRecord } from 'lightning/uiRecordApi';
import NAME_FIELD from '@salesforce/schema/User.Name';
import EMAIL_FIELD from '@salesforce/schema/User.Email';

const FIELDS = [NAME_FIELD, EMAIL_FIELD];

export default class WireDemoUsers extends LightningElement {
    userId = Id;
    userDetails;

    @wire(getRecord, { recordId: '$userId', fields: FIELDS })
    userDetailHandler({ data, error }) {
        if (data) {
            this.userDetails = data.fields;
        } else if (error) {
            this.userDetails = undefined;
            console.error('Unable to fetch user details:', error);
        }
    }
}
```

### HTML — `wireDemoUsers.html`

```html
<template>
    <lightning-card title="User Detail Using Wire Function">
        <div class="slds-var-p-around_medium">
            <template lwc:if={userDetails}>
                <div>Email: {userDetails.Email.value}</div>
                <div>Name: {userDetails.Name.value}</div>
            </template>
        </div>
    </lightning-card>
</template>
```

### How it works

1. `@salesforce/user/Id` imports the current logged-in user's ID.
2. `NAME_FIELD` and `EMAIL_FIELD` import field references from the User object.
3. `FIELDS` identifies which fields `getRecord` should retrieve.
4. `@wire(getRecord, ...)` requests the current user's record.
5. The wired function receives an object containing `data` or `error`.
6. When data is available, the component stores the returned fields and displays Name and Email.

> **Important:** This fetches the currently logged-in user's details, not an arbitrary user's details. Access remains subject to Salesforce permissions and UI API support.

## 5. Example: Fetch User Details Using a Wired Property

### JavaScript — `wireDemoUsers.js`

```javascript
import { LightningElement, wire } from 'lwc';
import Id from '@salesforce/user/Id';
import { getRecord } from 'lightning/uiRecordApi';
import NAME_FIELD from '@salesforce/schema/User.Name';
import EMAIL_FIELD from '@salesforce/schema/User.Email';

const FIELDS = [NAME_FIELD, EMAIL_FIELD];

export default class WireDemoUsers extends LightningElement {
    userId = Id;

    @wire(getRecord, { recordId: '$userId', fields: FIELDS })
    userDetailProperty;
}
```

### HTML — `wireDemoUsers.html`

```html
<template>
    <lightning-card title="User Detail Using Wire Property">
        <div class="slds-var-p-around_medium">
            <template lwc:if={userDetailProperty.data}>
                <div>Email: {userDetailProperty.data.fields.Email.value}</div>
                <div>Name: {userDetailProperty.data.fields.Name.value}</div>
            </template>

            <template lwc:if={userDetailProperty.error}>
                <p class="slds-text-color_error">Unable to load user details.</p>
            </template>
        </div>
    </lightning-card>
</template>
```

### How it works

1. The wire service provisions its result to `userDetailProperty`.
2. The result contains `data` on success or `error` on failure.
3. The template reads field values from `userDetailProperty.data.fields`.
4. Conditional rendering prevents field access before data is available.

## 6. Wired Function vs. Wired Property

| Wired function | Wired property |
|---|---|
| Receives the result in a JavaScript function. | Receives the result on a property. |
| Useful when data must be processed or coordinated in JavaScript. | Convenient when the template can use the response directly. |
| Handle `data` and `error` in the function. | Read `.data` and `.error` in the template or getters. |
| Example: `userDetailHandler({ data, error })` | Example: `userDetailProperty` |

Both patterns are reactive. Choose the pattern that makes the component easier to maintain.

## 8. Setup and Run

1. Open your Salesforce DX project in VS Code.
2. Create an LWC named `wireDemoUsers` using Salesforce CLI or **SFDX: Create Lightning Web Component**.
3. Add the JavaScript and HTML from either example. To compare both patterns, create separate components or switch the code between examples.
4. Expose the component on a Lightning App Page with this metadata:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<LightningComponentBundle xmlns="http://soap.sforce.com/2006/04/metadata">
    <apiVersion>67.0</apiVersion>
    <isExposed>true</isExposed>
    <targets>
        <target>lightning__AppPage</target>
    </targets>
</LightningComponentBundle>
```

5. Use an API version supported by your Salesforce project and org; change `67.0` if needed.
6. Deploy the component.
7. Open **Lightning App Builder**, add the component to a Lightning App Page, save, and activate it.
8. Open the page and verify that Name and Email appear.

## 9. Common Mistakes and Troubleshooting

- **Wrong field API name:** confirm the field exists and use the correct schema import.
- **Reading data too early:** wire results are asynchronous; use conditional rendering.
- **Ignoring errors:** inspect `error` and show a helpful message.
- **Mutating wired data:** treat the provisioned object as immutable; copy it before changing it.
- **Hard-coding a user ID:** use `@salesforce/user/Id` when the current user is intended.
- **Incorrect property path:** wired properties expose `.data` and `.error`; field values are under `.data.fields`.
- **Insufficient access:** verify the running user's access to the data and fields.
- **Fetching another user's ID:** retrieving another user's details may be subject to permissions and UI API restrictions.

## 10. Interview Questions and Short Answers

### Q1. What is the `@wire` service in LWC?
A reactive mechanism that provisions data from a supported wire adapter or Apex method to a component.

### Q2. What does it mean that wire data is immutable?
Do not mutate the provisioned object directly. Make a copy if local changes are required.

### Q3. Wired property vs. wired function?
A wired property receives the result directly. A wired function receives the result in JavaScript, where it can be processed.

### Q4. What is `getRecord`?
A UI API wire adapter that retrieves a Salesforce record's data for requested fields.

### Q5. What is `@salesforce/user/Id`?
A Salesforce module that provides the current logged-in user's ID.

### Q6. Why import fields from `@salesforce/schema`?
Schema imports provide explicit references to objects and fields and help Salesforce validate those references.

### Q7. What does `$userId` mean in the wire configuration?
The `$` prefix makes `userId` reactive. When it changes, the wire service can provision data again.

### Q8. How do you handle wire errors?
For a wired function, inspect its `error` argument. For a wired property, inspect `.error` and show an appropriate message.

### Q9. Can a wire function run more than once?
Yes. The service can provision values multiple times, for example when reactive parameters change or data is refreshed.

### Q10. When would you use an imperative call instead of `@wire`?
When you need to control exactly when an operation runs, especially for actions such as creating, updating, or deleting records.

### Q11. Is the wire service only for UI API?
No. It supports UI API wire adapters and supported Apex methods.

### Q12. What is the difference between `data` and `error`?
`data` contains the successful result; `error` describes a failed request.

## 11. Quick Revision Notes

- `@wire` is reactive and provisions an immutable stream of data.
