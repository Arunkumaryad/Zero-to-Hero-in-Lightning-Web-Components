# getRecord Wire Adapter in Lightning Web Components (LWC)

## 1. Overview

This folder demonstrates the Salesforce `getRecord` wire adapter in Lightning Web Components (LWC). It retrieves a Salesforce record through Lightning Data Service (LDS).

The example follows the screenshots and uses the standard **Account** object to display:
- Account Name
- Account Owner Name
- Annual Revenue

The component is intended for an Account **Lightning Record Page**. Salesforce supplies the current record ID through the public `recordId` property.

## 2. Definition From the Screenshot

> **getRecord**  
> Use this wire adapter to get the record’s data.

### Parameters shown in the screenshot

- **`recordId`** — The ID of the record to retrieve. It is a record ID, not a record type ID.
- **`fields`** — A field name or an array of field names to return.
- **`layoutTypes`** — Specifies the layout type. Supported values are `Compact` and `Full` (the default is `Full`).
- **`modes`** — Used with `layoutTypes`. Supported values are `Create`, `Edit`, and `View` (the default is `View`).
- **`optionalFields`** — A field name or array of field names. If the user can access an optional field, it is included in the response. If the user cannot access it, the request can still succeed without that field.

> **Correction to the slide:** The slide describes `recordId` as the ID of the record type. The correct definition is **the ID of the record being retrieved**. A record ID and a record type ID are different Salesforce IDs.

## 3. Syntax From the Screenshot

`getRecord` supports two common configuration patterns.

### Pattern 1 — Request specific fields

```javascript
import { LightningElement, wire } from 'lwc';
import { getRecord } from 'lightning/uiRecordApi';

@wire(getRecord, {
    recordId: '001XXXXXXXXXXXXXXX',
    fields: ['Account.Name', 'Account.AnnualRevenue'],
    optionalFields: ['Account.Phone']
})
record;
```

### Pattern 2 — Request fields from a layout

```javascript
import { LightningElement, wire } from 'lwc';
import { getRecord } from 'lightning/uiRecordApi';

@wire(getRecord, {
    recordId: '001XXXXXXXXXXXXXXX',
    layoutTypes: ['Full'],
    modes: ['View'],
    optionalFields: ['Account.Phone']
})
record;
```

The ID above is a placeholder. On a real Lightning Record Page, use the reactive `'$recordId'` property.

## 4. What Is `getRecord`?

`getRecord` is a wire adapter exported by `lightning/uiRecordApi`. It retrieves a Salesforce record and requested field data through Lightning Data Service and the User Interface API.

Use it when an LWC needs to display record details without writing an Apex method just to query the record.

Common use cases:
- Display details on a record page.
- Retrieve a known set of fields.
- Read raw field values or formatted display values.
- Build a custom record-detail component.
- Use LDS and platform record/field access behavior.

`getRecord` retrieves data. It does not create, update, or delete records.

## 5. Complete Example Based on the Screenshots

### Expected output

The component displays the current Account's Name, Owner, and Annual Revenue. The values below are illustrative; actual values come from the Account record in your org.


### JavaScript — `getRecordDemo.js`

This example uses the screenshot's `Full` layout and `View` mode. It uses Salesforce's `getFieldValue` and `getFieldDisplayValue` helpers to read field data.

```javascript
import { LightningElement, wire, api } from 'lwc';
import {
    getRecord,
    getFieldValue,
    getFieldDisplayValue
} from 'lightning/uiRecordApi';

import NAME_FIELD from '@salesforce/schema/Account.Name';
import OWNER_NAME_FIELD from '@salesforce/schema/Account.Owner.Name';
import ANNUAL_REVENUE_FIELD from '@salesforce/schema/Account.AnnualRevenue';

export default class GetRecordDemo extends LightningElement {
    // Salesforce supplies this automatically on a record page.
    @api recordId;

    name;
    ownerName;
    annualRevenue;
    error;

    @wire(getRecord, {
        recordId: '$recordId',
        layoutTypes: ['Full'],
        modes: ['View']
    })
    accountHandler({ data, error }) {
        if (data) {
            this.name = getFieldValue(data, NAME_FIELD);
            this.ownerName = getFieldValue(data, OWNER_NAME_FIELD);

            // Use the formatted value for display when available.
            this.annualRevenue =
                getFieldDisplayValue(data, ANNUAL_REVENUE_FIELD) ??
                getFieldValue(data, ANNUAL_REVENUE_FIELD);

            this.error = undefined;
        } else if (error) {
            this.error = error;
            this.name = undefined;
            this.ownerName = undefined;
            this.annualRevenue = undefined;
        }
    }
}
```

## 6. Explanation of the JavaScript

### A. Import modules

- `LightningElement` is the base class for an LWC.
- `wire` connects the component to a wire adapter.
- `api` exposes a public property to the Lightning page or parent component.
- `getRecord` retrieves the record.
- `getFieldValue` reads a field's raw value.
- `getFieldDisplayValue` reads its formatted display value, when available.

### B. Import Account fields

```javascript
import NAME_FIELD from '@salesforce/schema/Account.Name';
import OWNER_NAME_FIELD from '@salesforce/schema/Account.Owner.Name';
import ANNUAL_REVENUE_FIELD from '@salesforce/schema/Account.AnnualRevenue';
```

Schema imports provide references to Salesforce objects and fields. They help validate dependencies and support safe field renaming.

### C. Receive the current record ID

```javascript
@api recordId;
```

When the component is placed on a Lightning Record Page, Salesforce automatically supplies the current record's ID through this property.

### D. Call the wire adapter

```javascript
@wire(getRecord, {
    recordId: '$recordId',
    layoutTypes: ['Full'],
    modes: ['View']
})
accountHandler({ data, error }) {
    // Handle the response.
}
```

- `recordId` identifies the record to retrieve.
- `'$recordId'` makes the configuration reactive.
- `layoutTypes: ['Full']` requests fields from the Full page layout.
- `modes: ['View']` requests the View-mode layout.
- The wire handler receives `data` or `error`.

### E. Read field values

`getFieldValue(data, FIELD_REFERENCE)` returns the raw value. `getFieldDisplayValue(data, FIELD_REFERENCE)` returns a formatted value when Salesforce provides one. The latter is useful for currency, dates, and percentages.

## 7. `fields` vs. `layoutTypes`

| Configuration | Meaning | When to use |
|---|---|---|
| `fields` | Requests an explicit list of fields. | When the component needs a known, limited set of fields. |
| `layoutTypes` | Requests fields included in a specified layout. | When the component should follow the user's page layout. |
| `optionalFields` | Adds fields when the user has access; inaccessible optional fields do not cause the request to fail. | When extra fields are useful but not essential. |

### Example using explicit fields

```javascript
const FIELDS = [
    NAME_FIELD,
    OWNER_NAME_FIELD,
    ANNUAL_REVENUE_FIELD
];

@wire(getRecord, {
    recordId: '$recordId',
    fields: FIELDS
})
accountHandler({ data, error }) {
    // Handle data or error.
}
```

**Recommendation:** Prefer `fields` when you know exactly which fields the component needs. Layout-based requests can return more data than necessary and can vary with page-layout configuration.

## 8. `getFieldValue` vs. `getFieldDisplayValue`

| Function | Purpose |
|---|---|
| `getFieldValue(record, field)` | Returns the raw field value. |
| `getFieldDisplayValue(record, field)` | Returns the formatted display value, if available. |

For example, a currency field's raw value may be numeric, while its display value may include currency formatting.

## 9. Deployment and Testing Steps

1. Open your Salesforce DX project in VS Code.
2. Go to `force-app/main/default/lwc`.
3. Create an LWC named `getRecordDemo`.
4. Add `getRecordDemo.html`, `getRecordDemo.js`, and `getRecordDemo.js-meta.xml`.
5. Copy the corresponding code from this README into each file.
6. Save all files.
7. Right-click the component folder and select **SFDX: Deploy This Source to Org**.
8. In Salesforce, open an Account record.
9. Click **Setup → Edit Page** or open the Account Record Page in Lightning App Builder.
10. Find `getRecordDemo` under Custom Components.
11. Drag it onto the page, save, and activate the page if required.
12. Open an Account record and verify that Name, Owner, and Annual Revenue appear.

## 10. Troubleshooting

| Problem | What to check |
|---|---|
| No record data appears | Confirm the component is on a record page and `recordId` is populated. |
| Wire adapter returns an error | Check the record ID, object access, field-level security, and browser console. |
| A field is undefined | Confirm the field was requested and the user can access it. |
| Owner name is missing | Check access to the Owner relationship and the requested relationship field. |
| Currency value is not formatted | Use `getFieldDisplayValue`, with `getFieldValue` as a fallback. |
| Component does not appear in App Builder | Check `isExposed` and the `lightning__RecordPage` target in XML. |
| Invalid field error | Verify the field API name and schema import. |

### Required and optional fields

- Fields in `fields` are required for the request. If the user cannot access a required field, the request can fail.
- Fields in `optionalFields` are included when accessible. Lack of access to an optional field does not cause the whole request to fail.

## 11. Interview Questions and Answers

### Q1. What is `getRecord` in LWC?
A wire adapter from `lightning/uiRecordApi` that retrieves a Salesforce record's data through Lightning Data Service.

### Q2. From which module do we import `getRecord`?
```javascript
import { getRecord } from 'lightning/uiRecordApi';
```

### Q3. What are the main configuration properties?
`recordId` and either `fields` or `layoutTypes`. `optionalFields` can also be supplied.

### Q4. What is `recordId`?
The ID of the Salesforce record to retrieve. It is not the record type ID.

### Q5. How does an LWC get the current record ID on a record page?
Declare `@api recordId;`. Salesforce supplies the current record's ID.

### Q6. What is the difference between `fields` and `layoutTypes`?
`fields` requests a specific list of fields. `layoutTypes` requests fields included in a Compact or Full layout for the selected mode.

### Q7. What are the supported layout types?
`Compact` and `Full`.

### Q8. What are the supported modes?
`Create`, `Edit`, and `View`.

### Q9. What is `optionalFields`?
A list of additional fields returned when the current user has access. An inaccessible optional field does not make the request fail.

### Q10. What does `$` mean in `recordId: '$recordId'`?
It makes the wire configuration reactive. When the property changes, the wire service provisions data for the new record ID.

### Q11. Difference between `getFieldValue` and `getFieldDisplayValue`?
`getFieldValue` returns the raw value. `getFieldDisplayValue` returns the formatted display value when available.

### Q12. Does `getRecord` use Apex?
No. It uses Lightning Data Service and UI API. Apex is not required just to retrieve supported record data.

### Q13. Does `getRecord` create or update records?
No. It retrieves data. Use `createRecord`, `updateRecord`, or record form components to make changes.

### Q14. Does Lightning Data Service respect sharing and field-level security?
Yes. UI API and LDS enforce the platform's record access and field-level security behavior for the current user.

### Q15. What happens if a required field is inaccessible?
If a field in `fields` is inaccessible, the request can fail. Use `optionalFields` for extra fields that should not cause the whole request to fail when inaccessible.

### Q16. Can we retrieve parent relationship fields?
Yes, supported relationship fields can be requested using relationship field references, for example `Account.Owner.Name` in the schema import for an Account's owner name.

### Q17. Difference between a record ID and a record type ID?
A record ID identifies an individual record. A record type ID identifies a record type that can control business processes, page layouts, and picklist availability.

### Q18. When should we prefer `fields` over `layoutTypes`?
Prefer `fields` when the component needs a known set of fields. It makes the request explicit and avoids retrieving unnecessary layout fields.
