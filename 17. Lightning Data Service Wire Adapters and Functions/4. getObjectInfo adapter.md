# `getObjectInfo` Wire Adapter in Lightning Web Components (LWC)

## 1. Overview

This folder demonstrates the Salesforce **`getObjectInfo` wire adapter**. It retrieves metadata about a Salesforce object, such as its API name, fields, child relationships, record types, and theme information.

The screenshots use the **Account** object and display its default record type ID and API name.

## 2. Definition From the Screenshot

> **getObjectInfo**
>
> Use this wire adapter to get metadata about a specific object. The response includes metadata describing the object’s fields, child relationships, record type, and theme.

This preserves the definition shown in the supplied screenshot, with Markdown formatting added.

## 3. Syntax From the Screenshot

```javascript
import { LightningElement, wire } from 'lwc';
import { getObjectInfo } from 'lightning/uiObjectInfoApi';
import ACCOUNT_OBJECT from '@salesforce/schema/Account';

export default class Example extends LightningElement {
    @wire(getObjectInfo, { objectApiName: ACCOUNT_OBJECT })
    propertyOrFunction;
}
```

## 4. What Is Object Metadata?

**Object metadata** describes the structure and configuration of a Salesforce object, rather than the values stored in an individual record.

For example, Account object metadata can tell you the object's API name (`Account`), available fields and their properties, record types, the default record type ID for the current context, child relationship information, and theme/display information.

`getObjectInfo` retrieves metadata; it does **not** retrieve a particular Account record's field values. Use `getRecord` when you need the values of a specific record.

## 5. Example From the Screenshots

### JavaScript — `getObjectInfoDemo.js`

```javascript
import { LightningElement, wire } from 'lwc';
import { getObjectInfo } from 'lightning/uiObjectInfoApi';
import ACCOUNT_OBJECT from '@salesforce/schema/Account';

export default class GetObjectInfoDemo extends LightningElement {
    defaultRecordTypeId;
    apiName;
    objectInfo;
    error;

    @wire(getObjectInfo, { objectApiName: ACCOUNT_OBJECT })
    objectInfoHandler({ data, error }) {
        if (data) {
            this.objectInfo = data;
            this.defaultRecordTypeId = data.defaultRecordTypeId;
            this.apiName = data.apiName;
            this.error = undefined;
            console.log('Object metadata:', data);
        } else if (error) {
            this.objectInfo = undefined;
            this.defaultRecordTypeId = undefined;
            this.apiName = undefined;
            this.error = error;
            console.error('Error retrieving object metadata:', error);
        }
    }
}
```

### HTML — `getObjectInfoDemo.html`

```html
<template>
    <lightning-card title="getObjectInfo Adapter">

                <div>Object API Name: {apiName}</div>

            <template lwc:if={error}>
```

## 6. Step-by-Step Explanation

1. **Import `LightningElement` and `wire`:** define the LWC and connect it to a wire adapter.
2. **Import `getObjectInfo`:** the adapter comes from `lightning/uiObjectInfoApi`.
3. **Import the object reference:** `ACCOUNT_OBJECT` comes from `@salesforce/schema/Account`. Schema imports are preferable to hard-coded object-name strings.
4. **Configure the adapter:** `objectApiName: ACCOUNT_OBJECT` tells the adapter which object's metadata to retrieve.
5. **Receive the response:** the wired function receives `data` when successful or `error` when unsuccessful.
6. **Read metadata:** `data.apiName` contains the object's API name; `data.defaultRecordTypeId` contains the default record type ID for the current context.
7. **Display the result:** template bindings render values when `objectInfo` is available.
8. **Handle errors:** the component displays a simple message if metadata cannot be retrieved.

## 7. Important Properties in the Response

| Property | Meaning |
|---|---|
| `apiName` | API name of the object, such as `Account`. |
| `defaultRecordTypeId` | ID of the default record type in the current user's context. |
| `fields` | Metadata for the object's fields. |
| `childRelationships` | Metadata describing child relationships to this object. |
| `recordTypeInfos` | Metadata for the object's record types. |
| `themeInfo` | Theme/display metadata for the object. |

The exact response depends on the object and the metadata available to the current user.

## 8. `getObjectInfo` vs. `getRecord`

| `getObjectInfo` | `getRecord` |
|---|---|
| Retrieves object metadata. | Retrieves values for a particular record. |
| Requires an object API name. | Requires a record ID and requested fields. |
| Useful for field definitions and record type information. | Useful for displaying record data. |
| Imported from `lightning/uiObjectInfoApi`. | Imported from `lightning/uiRecordApi`. |

## 9. How to Deploy and Test

1. Open your Salesforce DX project in VS Code.
2. Create an LWC named `getObjectInfoDemo`.
3. Add the HTML, JavaScript, and metadata XML shown above.
4. Deploy the component to your Salesforce org.
5. Open **Lightning App Builder** and create or edit a Lightning App Page.
6. Drag `getObjectInfoDemo` onto the page.
7. Save and activate the page.
8. Open the page. For the Account example, you should see the object API name and default record type ID.

## 10. Common Mistakes and Troubleshooting

- **Wrong module:** import `getObjectInfo` from `lightning/uiObjectInfoApi`, not `lightning/uiRecordApi`.
- **Wrong object reference:** use `@salesforce/schema/Account` for Account metadata.
- **Expecting record field values:** `getObjectInfo` returns metadata, not data from an Account record.
- **Ignoring errors:** handle the `error` result so problems are visible.
- **Unsupported API version:** set `apiVersion` to one supported by your project and org.
- **Assuming all users see identical metadata:** object and field access can affect what is available.
- **Hard-coding record type IDs:** use the metadata response when the correct record type must be determined dynamically.

## 11. Interview Questions and Short Answers

### Q1. What is `getObjectInfo`?
A UI API wire adapter that retrieves metadata for a Salesforce object.

### Q2. Which module contains `getObjectInfo`?
`lightning/uiObjectInfoApi`.

### Q3. What is the purpose of `@salesforce/schema/Account`?
It imports a schema reference to the Account object.

### Q4. What is the difference between object metadata and record data?
Metadata describes an object's structure and configuration. Record data contains values stored on a particular record.

### Q5. What is `defaultRecordTypeId`?
It is the ID of the default record type for the current context and can help configure record-type-dependent UI behavior.

### Q6. Does `getObjectInfo` return field metadata?
Yes. The response includes a `fields` property containing field metadata available through the UI API.

### Q7. Does `getObjectInfo` retrieve Account records?
No. Use `getRecord` for a specific record's field values.

### Q8. How do you handle errors from a wire adapter?
Use a wired function with `{ data, error }`, or inspect `.data` and `.error` on a wired property.

### Q9. Why use a schema import instead of writing `'Account'`?
Schema imports provide references that Salesforce tooling can validate and track.

### Q10. Can `getObjectInfo` be used with a custom object?
Yes, when the object is supported and accessible. For example, import `PROPERTY_OBJECT` from `@salesforce/schema/Property__c`.

### Q11. What is `recordTypeInfos`?
It contains metadata about the object's record types, including information such as availability and default status.

### Q12. What is the difference between `getObjectInfo` and `getPicklistValues`?
`getObjectInfo` retrieves object-level metadata. `getPicklistValues` retrieves picklist values for a particular field and record type.

## 12. Quick Revision Notes

- `getObjectInfo` retrieves object metadata.
- Import it from `lightning/uiObjectInfoApi`.
- Pass an object reference using `objectApiName`.
- The response includes `apiName`, `defaultRecordTypeId`, `fields`, `childRelationships`, `recordTypeInfos`, and `themeInfo`.
- Use `getRecord` to retrieve a particular record's values.
- Handle both `data` and `error`.
- Use schema imports and avoid hard-coded record type IDs when possible.
