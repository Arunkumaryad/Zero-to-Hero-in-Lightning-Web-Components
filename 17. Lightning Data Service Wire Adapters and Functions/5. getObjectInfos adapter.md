# `getObjectInfos` Wire Adapter in Lightning Web Components (LWC)

## 1. Overview

This folder demonstrates the Salesforce **`getObjectInfos` wire adapter**. It retrieves metadata for **multiple Salesforce objects in one request**. The screenshot example uses the standard **Account** and **Opportunity** objects and displays each object's API name and default record type ID.

## 2. Definition From the Screenshot

> **getObjectInfos**
>
> Use this wire adapter to get metadata for multiple objects. The response includes metadata describing the fields, child relationships, record type, and theme for each object.

This preserves the definition shown in your screenshot, with Markdown formatting added.

## 3. Syntax From the Screenshot

```javascript
import { LightningElement, wire } from 'lwc';
import { getObjectInfos } from 'lightning/uiObjectInfoApi';
import ACCOUNT_OBJECT from '@salesforce/schema/Account';
import OPPORTUNITY_OBJECT from '@salesforce/schema/Opportunity';

export default class GetObjectInfosExample extends LightningElement {
    @wire(getObjectInfos, {
        objectApiNames: [ACCOUNT_OBJECT, OPPORTUNITY_OBJECT]
    })
    propertyOrFunction;
}
```

1. Import `wire`.
2. Import the adapter.
3. Import each object reference needed by the adapter.
4. Call the adapter using `@wire`.

## 4. What Is `getObjectInfos`?

`getObjectInfos` is a wire adapter from `lightning/uiObjectInfoApi`. It retrieves object metadata for multiple objects, rather than only one object.

Use it when a component needs metadata for more than one object, for example:

- Account and Opportunity object metadata.
- Field definitions for several objects.
- Record type information for multiple objects.
- Metadata needed to build a UI that works with more than one object.

It returns metadata, not the field values of individual records. Use `getRecord` to retrieve field values for a specific record.

## 5. Example From the Screenshots

### JavaScript — `getObjectInfosDemo.js`

```javascript
import { LightningElement, wire } from 'lwc';
import { getObjectInfos } from 'lightning/uiObjectInfoApi';
import ACCOUNT_OBJECT from '@salesforce/schema/Account';
import OPPORTUNITY_OBJECT from '@salesforce/schema/Opportunity';

export default class GetObjectInfosDemo extends LightningElement {
    objectInfos;
    error;

    @wire(getObjectInfos, {
        objectApiNames: [ACCOUNT_OBJECT, OPPORTUNITY_OBJECT]
    })
    objectInfoHandler({ data, error }) {
        if (data) {
            this.objectInfos = data;
            this.error = undefined;
            console.log('Object metadata:', data);
        } else if (error) {
            this.objectInfos = undefined;
            this.error = error;
            console.error('Error retrieving object metadata:', error);
        }
    }
}
```

### HTML — `getObjectInfosDemo.html`

```html
<template>
    <lightning-card title="getObjectInfos Adapter">
        <div class="slds-var-p-around_medium">
            <template lwc:if={objectInfos}>
                <template for:each={objectInfos.results} for:item="obj">
                    <div key={obj.result.apiName} class="slds-var-m-bottom_small">
                        <div>Object API Name: {obj.result.apiName}</div>
                        <div>
                            Default Record Type ID:
                            {obj.result.defaultRecordTypeId}
                        </div>
                    </div>
                </template>
            </template>

            <template lwc:if={error}>
                <p class="slds-text-color_error">
                    Unable to retrieve object metadata.
                </p>
            </template>
        </div>
    </lightning-card>
</template>
```

Use an API version supported by your Salesforce project and org. Change `67.0` if your project uses a different supported version.

## 6. Understanding the Response

The adapter returns an object with a `results` array. Each entry corresponds to an object requested in `objectApiNames`. An entry can contain a `result` with metadata for that object or an error for that individual object.

In the template:

- `objectInfos.results` loops through the response entries.
- `obj.result.apiName` displays the object's API name.
- `obj.result.defaultRecordTypeId` displays the default record type ID.
- `key={obj.result.apiName}` gives each rendered item a stable key.

**Important:** a multi-object response can include an error for one object even if another object's metadata is available. For production code, check each result for `result` or `error` before reading nested properties. The simple template above matches the screenshot's example when both objects succeed.

## 7. Important Metadata Properties

| Property | Meaning |
|---|---|
| `apiName` | API name of the object, such as `Account` or `Opportunity`. |
| `defaultRecordTypeId` | Default record type ID for the current user's context. |
| `fields` | Metadata describing the object's fields. |
| `childRelationships` | Metadata describing child relationships to the object. |
| `recordTypeInfos` | Metadata for the object's record types. |
| `themeInfo` | Theme/display metadata for the object. |

The available metadata depends on the object and the current user's access.

## 8. `getObjectInfo` vs. `getObjectInfos`

| `getObjectInfo` | `getObjectInfos` |
|---|---|
| Retrieves metadata for one object. | Retrieves metadata for multiple objects. |
| Uses the `objectApiName` configuration property. | Uses the `objectApiNames` array. |
| Example: Account. | Example: Account and Opportunity. |
| Imported from `lightning/uiObjectInfoApi`. | Imported from `lightning/uiObjectInfoApi`. |

## 9. `getObjectInfos` vs. `getRecord`

| `getObjectInfos` | `getRecord` |
|---|---|
| Retrieves metadata for multiple objects. | Retrieves field values for a particular record. |
| Uses object API name references. | Uses a record ID and requested fields. |
| Useful for object fields and record type metadata. | Useful for showing record data such as Account Name or Phone. |

## 11. Common Mistakes and Troubleshooting

- **Wrong adapter name:** use `getObjectInfos` (plural) for multiple objects.
- **Wrong module:** import it from `lightning/uiObjectInfoApi`.
- **Wrong configuration property:** use `objectApiNames` with an array, not `objectApiName`.
- **Expecting record values:** this adapter returns metadata, not individual Account or Opportunity field values.
- **Assuming every result succeeded:** inspect each response entry for `result` or `error`.
- **Unsupported API version:** set `apiVersion` to a version supported by your project and org.
- **Hard-coding record type IDs:** use metadata returned by the adapter when you need a record type dynamically.

## 12. Interview Questions and Short Answers

### Q1. What is `getObjectInfos`?
A UI API wire adapter that retrieves metadata for multiple Salesforce objects.

### Q2. Which module contains `getObjectInfos`?
`lightning/uiObjectInfoApi`.

### Q3. What is the difference between `getObjectInfo` and `getObjectInfos`?
`getObjectInfo` retrieves metadata for one object using `objectApiName`; `getObjectInfos` retrieves metadata for multiple objects using `objectApiNames`.

### Q4. What is `objectApiNames`?
An array of object references identifying which objects' metadata should be retrieved.

### Q5. Does `getObjectInfos` retrieve record data?
No. It retrieves object metadata. Use `getRecord` for a particular record's field values.

### Q6. What does `defaultRecordTypeId` represent?
The default record type ID for the current context.

### Q7. What does the `results` array contain?
An entry for each requested object, containing metadata when successful or an error for an object that could not be retrieved.

### Q8. Why use schema imports?
Schema imports provide references that Salesforce tooling can validate and track. They also reduce mistakes caused by hard-coded API names.

### Q9. Can it be used for custom objects?
Yes, if the objects are supported and accessible. For example, import `PROPERTY_OBJECT` from `@salesforce/schema/Property__c` and include it in the array.

### Q10. What is the difference between metadata and record data?
Metadata describes an object's structure and configuration. Record data contains values stored in a particular Salesforce record.

### Q11. What is `recordTypeInfos`?
Metadata about an object's record types, including details such as availability and default status.

### Q12. How should errors be handled?
Check the top-level wire error and, for multi-object results, inspect each entry to see whether it has a `result` or an `error`.

## 13. Quick Revision Notes

- `getObjectInfos` retrieves metadata for multiple objects.
- Import it from `lightning/uiObjectInfoApi`.
- Configure it with `objectApiNames: [OBJECT_ONE, OBJECT_TWO]`.
- The response contains a `results` array.
- Successful entries expose object metadata through `result`.
- Metadata includes `apiName`, `defaultRecordTypeId`, `fields`, `childRelationships`, `recordTypeInfos`, and `themeInfo`.
- Use `getObjectInfo` for one object and `getRecord` for an individual record's values.
- Handle errors at both the wire level and per-object result level.
