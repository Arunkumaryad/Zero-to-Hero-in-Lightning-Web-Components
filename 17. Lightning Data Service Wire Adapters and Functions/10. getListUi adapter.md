# `getListUi` Wire Adapter (Beta) in Lightning Web Components

## 1. Overview

This folder demonstrates the Salesforce `getListUi` wire adapter in a Lightning Web Component (LWC).

`getListUi` is designed to retrieve records and list-view metadata for a specified Salesforce list view. The example in the screenshots uses the **All Contacts** list view and displays each Contact's Name, Email, and Title. It also demonstrates page navigation using `pageToken`, `nextPageToken`, and `previousPageToken`.

> **Important:** The supplied training slide explicitly says that `lightning/uiListApi` is for evaluation purposes only and not for production use. Treat this as a learning example. Before using it in any application, check the current Salesforce documentation and API support status for your org and release.

## 2. Definition From the Screenshot

> **getListUi** — Use this wire adapter to get the records and metadata for a list view.

The screenshot also states:

> `lightning/uiListApi` is for evaluation purposes only, not for production use.

Parameter descriptions shown in the screenshot:

- **objectApiName** — The API name of a supported object.
- **listViewApiName** — The API name of a list view, such as `AllAccounts`, `AllContacts`, etc.
- **sortBy, pageSize, pageToken** — Additional configuration options used to control sorting and paging.

## 3. What Is a Salesforce List View?

A Salesforce list view is a saved view of an object's records. It can filter records based on criteria and display selected columns.

Examples include **All Contacts**, **Recently Viewed Contacts**, **My Accounts**, and **All Opportunities**. A list view lets users see a subset of records without opening each record individually.

## 4. Important Parameters

| Parameter | Meaning |
|---|---|
| `objectApiName` | API name/reference of the object, such as `Contact` or `Account`. |
| `listViewApiName` | API name of the saved list view, such as `AllContacts`. |
| `pageSize` | Maximum number of records requested in one page. |
| `sortBy` | Field or fields used for sorting, where supported. |
| `pageToken` | Token identifying the page to retrieve. Use a token returned by the response for navigation. |
| `nextPageToken` | Token for retrieving the next page, if one exists. |
| `previousPageToken` | Token for retrieving the previous page, if available. |

**Note:** A list view's API name is not necessarily the same as its displayed label. Confirm the correct API name in Salesforce.

## 5. How the Example Works

1. Import `getListUi` from `lightning/uiListApi`.
2. Import the Contact object reference and Contact Title field reference.
3. Configure the adapter for the `AllContacts` list view.
4. Request 10 records per page.
5. Store the returned records and page tokens.
6. Display Name, Email, and Title in an HTML table.
7. When the user selects **Next** or **Previous**, update `pageToken`.
8. The reactive wire configuration requests the page associated with the new token.

## 6. Complete Example Based on the Screenshots

### JavaScript — `getListUiDemoLWC.js`

This is a cleaned-up version of the screenshot code. It retains the same core approach and adds basic error and button-state handling.

```javascript
import { LightningElement, wire } from 'lwc';
import { getListUi } from 'lightning/uiListApi';

import CONTACT_OBJECT from '@salesforce/schema/Contact';
import TITLE_FIELD from '@salesforce/schema/Contact.Title';

export default class GetListUiDemoLWC extends LightningElement {
    contacts = [];
    pageToken = null;
    nextPageToken = null;
    previousPageToken = null;
    error;

    @wire(getListUi, {
        objectApiName: CONTACT_OBJECT,
        listViewApiName: 'AllContacts',
        pageSize: 10,
        sortBy: TITLE_FIELD,
        pageToken: '$pageToken'
    })
    listViewHandler({ data, error }) {
        if (data) {
            console.log('getListUi data:', data);

            this.contacts = data.records.records;
            this.nextPageToken = data.records.nextPageToken;
            this.previousPageToken = data.records.previousPageToken;
            this.error = undefined;
        } else if (error) {
            console.error('getListUi error:', error);

            this.contacts = [];
            this.nextPageToken = null;
            this.previousPageToken = null;
            this.error = error;
        }
    }

    handlePreviousPage() {
        if (this.previousPageToken) {
            this.pageToken = this.previousPageToken;
        }
    }

    handleNextPage() {
        if (this.nextPageToken) {
            this.pageToken = this.nextPageToken;
        }
    }

    get isPreviousDisabled() {
        return !this.previousPageToken;
    }

    get isNextDisabled() {
        return !this.nextPageToken;
    }
}
```

### HTML — `getListUiDemoLWC.html`

This template displays the same three columns shown in the screenshot.

```html
<template>
    <lightning-card title="getListUi Demo">
        <div class="slds-p-around_medium">
            <template lwc:if={error}>
                <div class="slds-text-color_error" role="alert">
                    Unable to load the Contact list. Check the browser console and Salesforce permissions.
                </div>
            </template>

            <template lwc:else>
                <div class="slds-scrollable_x">
                    <table class="slds-table slds-table_cell-buffer slds-table_bordered">
                        <thead>
                            <tr>
                                <th scope="col">Name</th>
                                <th scope="col">Email</th>
                                <th scope="col">Title</th>
                            </tr>
                        </thead>
                        <tbody>
                            <template for:each={contacts} for:item="contact">
                                <tr key={contact.id}>
                                    <td>{contact.fields.Name.value}</td>
                                    <td>{contact.fields.Email.value}</td>
                                    <td>{contact.fields.Title.value}</td>
                                </tr>
                            </template>
                        </tbody>
                    </table>
                </div>

                <template lwc:if={contacts.length}>
                    <div class="slds-grid slds-gutters slds-m-top_large">
                        <div class="slds-col">
                            <lightning-button
                                label="Previous"
                                onclick={handlePreviousPage}
                                disabled={isPreviousDisabled}>
                            </lightning-button>
                        </div>
                        <div class="slds-col">
                            <lightning-button
                                label="Next"
                                onclick={handleNextPage}
                                disabled={isNextDisabled}>
                            </lightning-button>
                        </div>
                    </div>
                </template>
            </template>
        </div>
    </lightning-card>
</template>
```

## 7. Explanation of the JavaScript

### A. Import the required modules

```javascript
import { LightningElement, wire } from 'lwc';
import { getListUi } from 'lightning/uiListApi';
```

- `LightningElement` is the base class for an LWC.
- `wire` connects the component to a Salesforce data source.
- `getListUi` is the list-view wire adapter shown in the training material.

### B. Import the object and field references

```javascript
import CONTACT_OBJECT from '@salesforce/schema/Contact';
import TITLE_FIELD from '@salesforce/schema/Contact.Title';
```

These schema imports identify the Contact object and Title field. Schema imports are preferable to manually typed API-name strings because Salesforce can validate and track dependencies.

### C. Declare state properties

```javascript
contacts = [];
pageToken = null;
nextPageToken = null;
previousPageToken = null;
```

- `contacts` stores the records displayed in the table.
- `pageToken` identifies the page requested by the wire adapter.
- `nextPageToken` and `previousPageToken` are returned by the response and are used for navigation.

### D. Configure the wire adapter

```javascript
@wire(getListUi, {
    objectApiName: CONTACT_OBJECT,
    listViewApiName: 'AllContacts',
    pageSize: 10,
    sortBy: TITLE_FIELD,
    pageToken: '$pageToken'
})
listViewHandler({ data, error }) {
    // Process the response.
}
```

- `objectApiName` specifies the object.
- `listViewApiName` specifies the list view.
- `pageSize` requests 10 records per page.
- `sortBy` specifies the sort field in this example.
- `'$pageToken'` makes the configuration reactive. When `pageToken` changes, the wire service provisions data for the new page.

The adapter's exact supported configuration and response shape can vary with API status and release. Verify the current reference before relying on this example.

### E. Read records and page tokens

```javascript
this.contacts = data.records.records;
this.nextPageToken = data.records.nextPageToken;
this.previousPageToken = data.records.previousPageToken;
```

The example reads the record collection and navigation tokens from the response.

### F. Navigate between pages

```javascript
handleNextPage() {
    if (this.nextPageToken) {
        this.pageToken = this.nextPageToken;
    }
}

handlePreviousPage() {
    if (this.previousPageToken) {
        this.pageToken = this.previousPageToken;
    }
}
```

The handlers update `pageToken`. Because the wire configuration references `'$pageToken'`, changing it causes the adapter to request the corresponding page.

## 8. Understanding the HTML Table

```html
<template for:each={contacts} for:item="contact">
    <tr key={contact.id}>
        <td>{contact.fields.Name.value}</td>
        <td>{contact.fields.Email.value}</td>
        <td>{contact.fields.Title.value}</td>
    </tr>
</template>
```

- `for:each` loops through the Contact records.
- `for:item="contact"` gives each row's record the local name `contact`.
- `key={contact.id}` provides a stable unique key for LWC rendering.
- `contact.fields.Name.value` reads the Contact Name.
- `contact.fields.Email.value` reads the Email.
- `contact.fields.Title.value` reads the Title.

## 10. Permissions and Troubleshooting

| Problem | What to check |
|---|---|
| No records appear | Confirm the list view exists, its API name is correct, and the user can access it. |
| Adapter returns an error | Check the browser console, API support status, and Salesforce release documentation. |
| Next button does not work | Confirm that `nextPageToken` is returned and is not `null`. |
| Previous button does not work | Confirm that `previousPageToken` is returned and is not `null`. |
| A column is blank | Confirm the field is included in the response and the user has field-level access. |
| Component does not appear in App Builder | Check `isExposed` and the `lightning__AppPage` target. |
| Sorting does not behave as expected | Verify the supported `sortBy` format and whether the selected field can be sorted. |
| `AllContacts` is not found | Check the list view's actual API name; its label and API name can differ. |

## 11. Production Considerations

The screenshot explicitly warns that `lightning/uiListApi` is for evaluation purposes only and not for production use. Treat this as a learning example, not a production recommendation.

1. Check current Salesforce documentation for the adapter's release status.

## 12. Interview Questions and Answers

### Q1. What is `getListUi`?
It is a list-view wire adapter shown in the training material for retrieving records and metadata for a specified Salesforce list view.

### Q2. From which module is `getListUi` imported?
```javascript
import { getListUi } from 'lightning/uiListApi';
```

### Q3. What is a Salesforce List View?
A list view is a saved view of an object's records, generally defined by filters and displayed columns.

### Q4. What is `objectApiName`?
It is the API name/reference of the Salesforce object whose records are requested, such as Contact or Account.

### Q5. What is `listViewApiName`?
It is the API name of the list view to retrieve, for example `AllContacts`. The API name may differ from the displayed label.

### Q6. What is `pageSize`?
It specifies how many records are requested for a page.

### Q7. What is `pageToken`?
It is a token used to identify the page to retrieve. A next or previous token from a response can be used for navigation.

### Q8. What are `nextPageToken` and `previousPageToken`?
They are response tokens used to request the next and previous pages when those pages are available.

### Q9. Why is `'$pageToken'` used instead of `pageToken`?
The `$` prefix makes the wire configuration reactive. When the component property changes, the wire service provisions data again using the new value.

### Q10. What is the purpose of `@wire`?
The wire service provisions data reactively from a wire adapter or Apex method. It can be used with a property or a function.

### Q11. What is the difference between a wire property and a wire function?
A wire property receives the provisioned value directly. A wire function lets the component process the `{ data, error }` response before assigning values to component properties.

### Q12. What is the purpose of `sortBy`?
It specifies the field used to sort list data, subject to the adapter's supported configuration.

### Q13. Why is `for:each` used in the HTML?
It iterates over the returned records and creates a table row for each Contact.

### Q14. Why is a `key` required in an LWC list?
A stable unique key helps LWC identify list items efficiently when rendering and updating the DOM.

### Q15. What is the difference between a list view and a SOQL query?
A list view is a saved Salesforce user-facing view with filters and columns. SOQL is a query language used by developers to retrieve records according to a query.

### Q16. Is `getListUi` recommended for production according to the supplied screenshot?
No. The screenshot explicitly says the `lightning/uiListApi` module is for evaluation purposes only and not for production use. Always verify the current official release status.

### Q17. What alternatives can be considered for production list data?
Depending on the use case, consider the GraphQL wire adapter or Apex. Evaluate filtering, sorting, pagination, security, and supported Salesforce features before choosing.

### Q18. Why should field-level security be considered?
The component should only expose data the running user is authorized to access. Object permissions, field-level security, and record sharing must be respected.
