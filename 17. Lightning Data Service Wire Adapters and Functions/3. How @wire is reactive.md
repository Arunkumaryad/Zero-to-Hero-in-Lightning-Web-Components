# How `@wire` Is Reactive in Lightning Web Components (LWC)

## 1. Overview

This folder explains how the LWC `@wire` service reacts to data and parameter changes. The screenshots show fetching the logged-in Salesforce user's Name and Email with `getRecord`, using both a wired function and a wired property.

## 2. Definitions From the Screenshots

The following wording preserves the definitions shown in the supplied slides, with formatting adjusted for readability.

### What is `@wire` Service?

1. Wire service is built on Lightning Data Service.
2. LWC component use `@wire` in their JavaScript class to read data from one of the wire adapters in the `lightning/ui*Api` namespace.
3. `@wire` is a reactive service.
4. The wire adapter defines the data shape that the wire service provisions in an immutable stream.

### Wire syntax shown in the screenshot

```javascript
import { adapterId } from 'adapterModule';

@wire(adapterId, adapterConfig)
propertyOrFunction;
```

### Main idea

A wire adapter provisions data to a component. When a reactive configuration value changes, the wire service can provision a new result. Treat provisioned data as immutable.

## 3. What Does “Reactive” Mean?

In LWC, **reactive** means that a value is tracked by the framework and changes can cause the component to update. In a wire configuration, a property prefixed with `$` is a reactive reference.

```javascript
@wire(getRecord, { recordId: '$userId', fields: FIELDS })
userDetailProperty;
```

Here, `'$userId'` tells the wire service to use the component's `userId` property as a reactive configuration value. If `userId` changes to another valid record ID, the wire service can provision data for the new record.

The `$` prefix is special in wire configuration. It is not JavaScript string interpolation.

## 4. Example From the Screenshots: Fetch the Current User

The screenshots show two approaches:

- **Wired function:** process `data` and `error` in JavaScript.
- **Wired property:** read the result through `.data` or `.error`.

### JavaScript — `wireDemoUsers.js`

```javascript
import { LightningElement, wire } from 'lwc';
import Id from '@salesforce/user/Id';
import { getRecord } from 'lightning/uiRecordApi';
import NAME_FIELD from '@salesforce/schema/User.Name';
import EMAIL_FIELD from '@salesforce/schema/User.Email';

const FIELDS = [NAME_FIELD, EMAIL_FIELD];

export default class WireDemoUsers extends LightningElement {
    userId = Id;
    userDetails;

    // Wired function: process the response in JavaScript.
    @wire(getRecord, { recordId: '$userId', fields: FIELDS })
    userDetailHandler({ data, error }) {
        if (data) {
            this.userDetails = data.fields;
            console.log('User details:', this.userDetails);
        } else if (error) {
            this.userDetails = undefined;
            console.error('Unable to fetch user details:', error);
        }
    }

    // Wired property: access the response directly in the template.
    @wire(getRecord, { recordId: '$userId', fields: FIELDS })
    userDetailProperty;
}
```

> **Note:** Both patterns are included in one class to match the screenshots. In a production component, one wire may be enough if both views can share the same result. Separate wires are useful for learning or when results need different handling.

### HTML — `wireDemoUsers.html`

```html
<template>
    <lightning-card title="User Detail Using Wire Function">
        <div class="slds-var-p-around_medium">
            <template lwc:if={userDetails}>
                <div>Email: {userDetails.Email.value}</div>
                <div>Name: {userDetails.Name.value}</div>
            </template>
        </div>
    </lightning-card>

    <br />

    <lightning-card title="User Detail Using Wire Property">
        <div class="slds-var-p-around_medium">
            <template lwc:if={userDetailProperty.data}>
                <div>Email: {userDetailProperty.data.fields.Email.value}</div>
                <div>Name: {userDetailProperty.data.fields.Name.value}</div>
            </template>

            <template lwc:if={userDetailProperty.error}>
                <p class="slds-text-color_error">Unable to load user details.</p>
            </template>
        </div>
    </lightning-card>
</template>
```

## 5. Step-by-Step Explanation

1. **Import LWC features:** `LightningElement` is the base class, and `wire` connects the component to a supported data source.
2. **Get the current user's ID:** `@salesforce/user/Id` provides the logged-in user's ID.
3. **Import field references:** `@salesforce/schema/User.Name` and `@salesforce/schema/User.Email` identify the fields to retrieve.
4. **Create the fields array:** `FIELDS` specifies the fields required by `getRecord`.
5. **Configure the wire adapter:** `recordId: '$userId'` is reactive; the service uses the current value of `userId`.
6. **Handle the function result:** the wired function receives an object containing `data` or `error`.
7. **Render only when data exists:** `lwc:if` prevents the template from trying to display values before data arrives.
8. **Observe reactive updates:** if `userId` changes, the wire service can provision data for the new ID and the UI updates when the component state changes.

## 6. Wired Function vs. Wired Property

| Wired function | Wired property |
|---|---|
| Receives the result in JavaScript. | Receives the result on a property. |
| Useful when data must be transformed or coordinated. | Useful when the template can consume the result directly. |
| Handle `data` and `error` arguments. | Read `.data` and `.error`. |
| Example: `userDetailHandler({ data, error })` | Example: `userDetailProperty.data` |

Both patterns are reactive. A wired function is not a one-time callback; the wire service may invoke it multiple times.

## 7. Important Concepts

### Reactive parameter (`$userId`)

The `$` prefix makes the property a reactive wire configuration value. A change to that property can cause the wire adapter to provision a new result.

### Immutable data

Treat data provided by the wire service as read-only. If you need to modify it for local UI purposes, create a copy rather than mutating the original object.

### `data` and `error`

- `data` contains the successful result.
- `error` contains error information if the request fails.
- A robust component should account for loading, success, and error states.

### Lightning Data Service (LDS)

LDS is Salesforce's client-side data layer. UI API wire adapters such as `getRecord` use LDS capabilities, including shared data and caching where applicable. Salesforce permissions continue to apply.

### `getRecord`

`getRecord` is imported from `lightning/uiRecordApi`. It retrieves a record using its ID and requested fields.

3. Add the JavaScript, HTML, and metadata shown above.
4. Deploy the component to your Salesforce org.

## 9. Common Mistakes

- **Missing `$` in the reactive parameter:** `recordId: 'userId'` is a literal string, not a reference. Use `recordId: '$userId'`.
- **Assuming data is immediately available:** the wire service is asynchronous. Use conditional rendering.
- **Not handling errors:** inspect `error` and provide a user-friendly message.
- **Changing provisioned data directly:** treat wired data as immutable.
- **Using a hard-coded user ID:** use `@salesforce/user/Id` when the current user is intended.
- **Incorrect field path:** wired property values are accessed under `.data.fields`; each field value is commonly accessed with `.value`.
- **Ignoring permissions:** record and field access are controlled by Salesforce security and UI API support.

## 10. Interview Questions and Short Answers

### Q1. What does reactive mean in LWC?
A value is reactive when changes to it can cause the framework to update the component or re-evaluate a reactive wire configuration.

### Q2. Why is `$` used in `@wire` configuration?
It marks a component property as a reactive reference. For example, `recordId: '$userId'` uses the current value of `userId`.

### Q3. Wired function vs. wired property?
A wired function receives the result in JavaScript for processing; a wired property exposes the result as a property with `.data` and `.error`.

### Q4. Can a wired function execute more than once?
Yes. The service can provision values multiple times, including when reactive parameters change.

### Q5. Is wire data mutable?
Treat it as immutable. Copy it before making local changes.

### Q6. What is `getRecord`?
A UI API wire adapter that retrieves a Salesforce record's requested fields.

### Q7. How do you get the current user's ID?
Import `Id` from `@salesforce/user/Id`.

### Q8. Why use schema imports?
They provide explicit object and field references that Salesforce tooling can validate and track.

### Q9. How do you handle wire errors?
A wired function receives an `error` value; a wired property's `.error` is populated. Handle it and show a useful message.

### Q10. Is `@wire` only used with UI API?
No. It supports UI API wire adapters and supported Apex methods.

### Q11. Does changing any JavaScript variable always rerun a wire?
No. Use the property as a reactive configuration reference (with `$` in the wire config), and ensure its value changes.

### Q12. When might you use an imperative call instead?
When you need to control when the call runs, such as after a button click, or when performing an operation not suited to a wire adapter.

## 11. Quick Revision

- `@wire` provisions data reactively.
- Wire data should be treated as immutable.
- `getRecord` is from `lightning/uiRecordApi`.
- `@salesforce/user/Id` provides the current user's ID.
- `$userId` is a reactive wire configuration reference.
- Wired functions process `{ data, error }`.
- Wired properties expose `.data` and `.error`.
- Use conditional rendering and error handling.
- LDS/UI API respects Salesforce security and permissions.
