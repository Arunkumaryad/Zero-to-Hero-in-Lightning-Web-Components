# getPicklistValuesByRecordType Wire Adapter in LWC

## 1. Overview

This folder demonstrates the Salesforce `getPicklistValuesByRecordType` wire adapter in Lightning Web Components (LWC). It retrieves picklist values for every picklist field on a specified object and record type.

The example uses the standard **Account** object and displays two picklists:
- **Rating**
- **Industry**

Both dropdowns use `lightning-combobox`. When a user selects a value, the component displays that selection below the dropdown.

## 2. Definition From the Screenshot

> **getPicklistValuesByRecordType**  
> Use this wire adapter to get the values for every picklist of a specified record type.

### Configuration properties from the slide

- **`recordTypeId`** — The ID of the record type. Use the Object Info `defaultRecordTypeId` property, which is returned from `getObjectInfo`.
- **`objectApiName`** — The API name of the object.

## 3. Syntax From the Screenshot

```javascript
import { LightningElement, wire } from 'lwc';
import { getPicklistValuesByRecordType } from 'lightning/uiObjectInfoApi';
import ACCOUNT_OBJECT from '@salesforce/schema/Account';

export default class Example extends LightningElement {

        objectApiName: ACCOUNT_OBJECT,

    })
    propertyOrFunction;

```

**Best practice:** Do not hard-code record type IDs in a real component. Retrieve the ID dynamically with `getObjectInfo`, as shown below.

## 4. What Is `getPicklistValuesByRecordType`?

`getPicklistValuesByRecordType` is a Lightning Data Service (LDS) wire adapter exported by `lightning/uiObjectInfoApi`. It retrieves picklist metadata for all picklist fields on an object for a particular record type.

Use it when a component needs values for multiple picklist fields on the same object and record type. For example, the Account object has the `Rating`, `Industry`, and `Type` picklist fields.

The adapter returns metadata. It does **not** create or update Salesforce records.

## 5. Complete Example Based on the Screenshots

The screenshot gets Account object information with `getObjectInfo`, reads the default record type ID, and then retrieves Rating and Industry picklist options.

### Important correction

The screenshot appears to use a nested reactive expression such as:

```javascript
recordTypeId: '$objectInfo.data.defaultRecordTypeId'
```

For a clear and reliable implementation, assign `data.defaultRecordTypeId` to a component property in the `getObjectInfo` handler, then use `recordTypeId: '$recordTypeId'` in the picklist wire configuration. This is the pattern used in the complete example.

### JavaScript — `getPicklistValuesByRecordTypeDemo.js`

```javascript
import { LightningElement, wire } from 'lwc';
import {
    getPicklistValuesByRecordType,
    getObjectInfo
} from 'lightning/uiObjectInfoApi';

import ACCOUNT_OBJECT from '@salesforce/schema/Account';

export default class GetPicklistValuesByRecordTypeDemo extends LightningElement {
    recordTypeId;

    ratingOptions = [];
    industryOptions = [];

    selectedRating = '';
    selectedIndustry = '';

    error;

    // Get Account object information and its default record type ID.
    @wire(getObjectInfo, { objectApiName: ACCOUNT_OBJECT })
    objectInfoHandler({ data, error }) {
        if (data) {
            this.recordTypeId = data.defaultRecordTypeId;
            this.error = undefined;
        } else if (error) {
            this.error = error;
            this.recordTypeId = undefined;
        }
    }

    // Get picklist metadata for all Account picklist fields.
    @wire(getPicklistValuesByRecordType, {
        objectApiName: ACCOUNT_OBJECT,
        recordTypeId: '$recordTypeId'
    })
    picklistHandler({ data, error }) {
        if (data) {
            this.ratingOptions = this.picklistGenerator(
                data.picklistFieldValues.Rating
            );

            this.industryOptions = this.picklistGenerator(
                data.picklistFieldValues.Industry
            );

            this.error = undefined;
        } else if (error) {
            this.error = error;
            this.ratingOptions = [];
            this.industryOptions = [];
        }
    }

    // Convert Salesforce values into the format lightning-combobox expects.
    picklistGenerator(picklistData) {
        return picklistData.values.map((item) => ({
            label: item.label,
            value: item.value
        }));
    }

    // Handle changes from both comboboxes.
    handleChange(event) {
        const { name, value } = event.target;

        if (name === 'rating') {
            this.selectedRating = value;
        }

        if (name === 'industry') {
            this.selectedIndustry = value;
        }
    }
}
```

## 6. How the JavaScript Works

### A. Import modules and schema

- `LightningElement` is the base class for an LWC.
- `wire` connects the component to a wire adapter.
- `getObjectInfo` retrieves object metadata.
- `getPicklistValuesByRecordType` retrieves picklist metadata for the specified object and record type.
- `ACCOUNT_OBJECT` is the schema reference for Account.

### B. Get the record type ID

```javascript
@wire(getObjectInfo, { objectApiName: ACCOUNT_OBJECT })
objectInfoHandler({ data, error }) {
    if (data) {
        this.recordTypeId = data.defaultRecordTypeId;
    }
}
```

`getObjectInfo` returns object metadata, including `defaultRecordTypeId`. We store that ID in `recordTypeId` so the next wire adapter can use it.

### C. Retrieve picklist values

```javascript
@wire(getPicklistValuesByRecordType, {
    objectApiName: ACCOUNT_OBJECT,
    recordTypeId: '$recordTypeId'
})
picklistHandler({ data, error }) {
    if (data) {
        this.ratingOptions =
            this.picklistGenerator(data.picklistFieldValues.Rating);
        this.industryOptions =
            this.picklistGenerator(data.picklistFieldValues.Industry);
    }
}
```

The `$` makes `recordTypeId` reactive. When its value becomes available or changes, the wire service provisions data using the updated configuration.

The response contains `data.picklistFieldValues`. Each field entry has a `values` array.

### D. Convert values for the combobox

```javascript
picklistGenerator(picklistData) {
    return picklistData.values.map((item) => ({
        label: item.label,
        value: item.value
    }));
}
```

The combobox expects an array of `{ label, value }` objects. The `map()` method prepares the Salesforce response in that format.

### E. Handle selection

`event.target.name` identifies which combobox changed, and `event.target.value` contains the selected value. The handler updates `selectedRating` or `selectedIndustry`, and the template displays the updated property.

## 7. Understanding the HTML

| Attribute | Purpose |
|---|---|
| `name` | Identifies the combobox in JavaScript. |
| `label` | Displays the field label. |
| `value` | Holds the currently selected value. |
| `placeholder` | Displays guidance before selection. |
| `options` | Supplies the picklist options. |
| `onchange` | Calls the JavaScript handler when selection changes. |

Example:

```html
<lightning-combobox
    name="rating"
    label="Rating"
    value={selectedRating}
    placeholder="Select Rating"
    options={ratingOptions}
    onchange={handleChange}>
</lightning-combobox>
```

The adapter returns picklist metadata grouped by field API name. A simplified illustration of the relevant response shape is:

This is an illustrative response. Actual values depend on the org's picklist setup and record type.

## 9. `getPicklistValues` vs. `getPicklistValuesByRecordType`

| Feature | `getPicklistValues` | `getPicklistValuesByRecordType` |
|---|---|---|
| Purpose | Gets values for one specified picklist field. | Gets values for all picklist fields for a record type. |
| Configuration | `recordTypeId`, `fieldApiName` | `objectApiName`, `recordTypeId` |
| Best use | When you know the specific field needed. | When you need multiple picklist fields on the object. |

## 10. `getObjectInfo` and `defaultRecordTypeId`

`getObjectInfo` is another wire adapter from `lightning/uiObjectInfoApi`. It retrieves object metadata, including:

- Object API name and label.
- Field metadata.
- Record type information.
- The current user's default record type ID.

The default record type is suitable for many new-record scenarios. When editing an existing record, use that record's actual `RecordTypeId` if the picklist choices must match its record type.

## 12. Troubleshooting

| Problem | What to check |
|---|---|
| Dropdowns are empty | Check that `recordTypeId` is populated and the response contains the expected field API names. |
| Wire adapter returns an error | Check object access, field permissions, record type configuration, and browser console. |
| Wrong options appear | Confirm that the component uses the intended record type ID. |
| `recordTypeId` is undefined | Check that `getObjectInfo` returns data and assigns `data.defaultRecordTypeId`. |
| Combobox shows no options | Ensure every option has `label` and `value`, and `options` is correctly bound. |
| A field is missing from the response | Confirm it is a picklist field on the requested object and check its API name. |
| Custom object is used | Import its schema, e.g. `@salesforce/schema/Property__c`, and use the correct API name. |

### Dependent picklists

The response can include `controllerValues` and `validFor` metadata for dependent picklists. A component must use that metadata to filter dependent options based on the controlling field's selected value. This example demonstrates ordinary picklists and does not implement dependency filtering.

## 13. Interview Questions and Answers

### Q1. What is `getPicklistValuesByRecordType`?
A wire adapter that retrieves picklist values for all picklist fields on an object for a specified record type.

### Q2. From which module do we import it?
`lightning/uiObjectInfoApi`.

### Q3. What configuration properties does it require?
`objectApiName` and `recordTypeId`.

### Q4. Why is `recordTypeId` important?
Picklist values can differ by record type. The ID tells Salesforce which record-type-specific values to return.

### Q5. How do you get the default record type ID?
Use `getObjectInfo` and read `data.defaultRecordTypeId`.

### Q6. What is the difference between `getPicklistValues` and `getPicklistValuesByRecordType`?
The first retrieves values for one specified field. The second retrieves values for all picklist fields for the specified object and record type.

### Q7. Where are picklist values available in the response?
Under `data.picklistFieldValues`, for example `data.picklistFieldValues.Rating.values`.

### Q8. Why do we use `map()`?
To convert Salesforce picklist values into the `{ label, value }` format required by `lightning-combobox`.

### Q9. What does `$recordTypeId` mean in the wire configuration?
The `$` marks the property as reactive. When the property changes, the wire service provisions data again.

### Q10. Does this adapter create or update records?
No. It retrieves metadata only. Use a record form, LDS function, or suitable Apex operation to save records.

### Q11. Can we use this adapter with custom objects?
Yes, for objects supported by UI API and accessible to the user. Import the custom object schema reference and pass it as `objectApiName`.

### Q12. What is `defaultRecordTypeId`?
The default record type ID for the current user on the specified object, returned by `getObjectInfo`.

### Q13. What is a dependent picklist?
A picklist whose available values depend on the selected value of another controlling field.

### Q14. What is the role of `lightning-combobox`?
It displays a single-select dropdown. Its `options` property receives `{ label, value }` objects, and its change event provides the selected value.

### Q15. Why avoid hard-coded record type IDs?
IDs can differ between orgs and environments. Retrieving them dynamically makes components more portable and maintainable.
