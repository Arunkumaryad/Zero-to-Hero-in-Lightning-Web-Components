# getNavItems Wire Adapter (Beta) in Lightning Web Components

## 1. Overview

This folder demonstrates the Salesforce `getNavItems` wire adapter in a Lightning Web Component (LWC).

`getNavItems` retrieves navigation items that are available in the Salesforce navigation menu. The screenshot example requests the navigation item named `standard-Account` and displays its `developerName`, `objectApiName`, and `pageReference.type`.

> **Beta / evaluation-only warning:** The supplied slide says that `lightning/uiAppsApi` is for evaluation purposes only and not for production use. Salesforce's current documentation also labels `getNavItems` and the UI Apps API as Beta. Do not use this example in production unless Salesforce changes the support status and your organization approves its use.

## 2. Definition From the Screenshot

## 3. What Is a Salesforce Navigation Menu?

A Salesforce navigation menu contains tabs or items that let users open different areas of Salesforce, such as Accounts, Contacts, Opportunities, and other available pages. The available items can depend on the Salesforce app, its navigation configuration, the user's permissions, and the display form factor.

Example Account navigation item:
- Developer name: `standard-Account`
- Object API name: `Account`
- Page reference type: `standard__objectPage`

## 4. Important Parameters and Properties

| Parameter / property | Meaning |
|---|---|
| `navItemNames` | Array of TabDefinition `name` values to include in the response. If omitted, all navigation items for the requested form factor can be returned. |
| `pageSize` | Maximum number of navigation items returned on one page. Current documentation gives a default of 25; the screenshot requests 30. |
| `formFactor` | Optional display size: `Large` (desktop, default), `Medium` (tablet), or `Small` (phone). |
| `page` | Optional zero-based page offset. Default is `0`. |
| `developerName` | Unique developer name identifying a navigation item, for example `standard-Account`. |
| `objectApiName` | API name of the associated object, when the item represents an object page. |
| `pageReference` | Page Reference describing the destination. |
| `pageReference.type` | Type of destination, for example `standard__objectPage`. |

**Important:** `navItemNames` expects navigation item names (TabDefinition names), not object API names. The screenshot passes `standard-Account`, not simply `Account`.

## 5. How the Example Works

1. Import `LightningElement` and `wire` from `lwc`.
2. Import `getNavItems` from `lightning/uiAppsApi`.
3. Configure `navItemNames: ['standard-Account']`.
4. Set `pageSize` to `30`.
5. Use a wire function to receive `{ data, error }`.
6. If data is returned, read the first item from `data.navItems[0]`.
7. Store that item in `this.result`.
8. Display its developer name, object API name, and page reference type in the HTML.

## 6. Complete Example Based on the Screenshots

### JavaScript — `getNavItemDemo.js`

This cleaned-up version retains the screenshot's implementation and adds an error property.

```javascript
import { LightningElement, wire } from 'lwc';
import { getNavItems } from 'lightning/uiAppsApi';

export default class GetNavItemDemo extends LightningElement {
    result;
    error;

    @wire(getNavItems, {
        navItemNames: ['standard-Account'],
        pageSize: 30
    })
    navItemHandler({ data, error }) {
        if (data) {
            console.log('Nav Item Data:', data);
            this.result = data.navItems[0];
            this.error = undefined;
        } else if (error) {
            console.error('Navigation item error:', error);
            this.result = undefined;
            this.error = error;
        }
    }
}
```

### HTML — `getNavItemDemo.html`

```html
<template>
    <lightning-card title="NavItems Demo">
        <div class="slds-p-around_medium">
            <template lwc:if={result}>
                <div>developerName - {result.developerName}</div>
                <div>objectApiName - {result.objectApiName}</div>
                <div>pageReference - {result.pageReference.type}</div>
            </template>

            <template lwc:if={error}>
                <div class="slds-text-color_error" role="alert">
                    Unable to retrieve navigation items. Check the browser console.
                </div>
            </template>
        </div>
    </lightning-card>
</template>
```

### Metadata — `getNavItemDemo.js-meta.xml`


Use an API version supported by your Salesforce project and org. The screenshot uses `67.0`; update it if your project uses another supported version.

## 7. JavaScript Explanation

### Import statements

```javascript
import { LightningElement, wire } from 'lwc';
import { getNavItems } from 'lightning/uiAppsApi';
```

- `LightningElement` is the base class for an LWC.
- `wire` connects the component to a Salesforce data source.
- `getNavItems` retrieves navigation menu items.
- `lightning/uiAppsApi` is the module from which the adapter is imported.

### Component properties

```javascript
result;
error;
```

`result` stores the navigation item to display. `error` stores an error returned by the wire service.

### Wire configuration

```javascript
@wire(getNavItems, {
    navItemNames: ['standard-Account'],
    pageSize: 30
})
navItemHandler({ data, error }) {
    // Process the response.
}
```

- `navItemNames` filters the response to the requested navigation item name.
- `pageSize` requests up to 30 navigation items on one page.
- `@wire` provisions data reactively.
- `navItemHandler` receives the `{ data, error }` response.

The screenshot uses a static array. A component property can also be used with the `$` reactive prefix if it contains the expected navigation item names.

### Reading the response

```javascript
if (data) {
    this.result = data.navItems[0];
}
```

The response contains a `navItems` array. `[0]` selects its first element. If multiple items are requested, iterate over the array instead of displaying only the first item.

### Error handling

```javascript
if (error) {
    console.error(error);
}
```

The error branch runs when the adapter cannot provide data. Logging the error helps with debugging; a user-friendly message can also be displayed in the template.

## 8. HTML Explanation

```html
<template lwc:if={result}>
    <div>developerName - {result.developerName}</div>
    <div>objectApiName - {result.objectApiName}</div>
    <div>pageReference - {result.pageReference.type}</div>
</template>
```

- `lwc:if={result}` displays the section when a result exists.
- `{result.developerName}` displays the unique navigation item developer name.
- `{result.objectApiName}` displays the related object API name, when available.
- `{result.pageReference.type}` displays the destination page type.

Expected example output from the screenshot:

```text

objectApiName - Account

```

Actual values depend on the item returned by Salesforce and the current app configuration.

## 10. Troubleshooting

| Problem | What to check |
|---|---|
| `data.navItems` is empty | Confirm `standard-Account` is a valid navigation item name for the current app and user. |
| `result` is undefined | Check whether data was returned and whether the array contains an item. |
| `objectApiName` is blank | Not every navigation item represents an object page; inspect the returned item. |
| `pageReference.type` is blank | Check that `pageReference` exists before reading its `type`. |
| Adapter returns an error | Check Beta API availability, org/release support, browser console details, and Salesforce documentation. |
| Component does not appear in App Builder | Confirm `isExposed` is `true` and the `lightning__AppPage` target is present. |
| Different users see different results | Navigation items can depend on user app access, permissions, and the configured navigation menu. |

## 11. Production Considerations

The supplied slide says the API is for evaluation purposes only and not for production use. Salesforce's current developer documentation labels `getNavItems` and `lightning/uiAppsApi` as Beta.

Before considering this API for a real project:

1. Review the current Salesforce Beta Services terms and product documentation.
2. Confirm whether Salesforce has changed the API's release status.
3. Confirm that your organization permits use of the Beta feature.
4. Plan for possible changes to behavior, response shape, or availability.
5. Do not assume a Beta API has production support or a stable contract.

If the requirement is to navigate users to a page, investigate the supported `lightning/navigation` module and `NavigationMixin`. `NavigationMixin` performs navigation; it is not a direct replacement for retrieving the full navigation menu.

## 12. Interview Questions and Answers

### Q1. What is `getNavItems`?
A Lightning Web Components wire adapter used to retrieve items in the Salesforce navigation menu.

### Q2. From which module is `getNavItems` imported?
```javascript
import { getNavItems } from 'lightning/uiAppsApi';
```

### Q3. What is the purpose of `lightning/uiAppsApi`?
It is the UI Apps API module. Salesforce currently documents it as Beta and identifies `getNavItems` as its wire adapter.

### Q4. What does `navItemNames` represent?
A list of TabDefinition `name` values used to filter returned navigation items, for example `standard-Account`.

### Q5. Is `standard-Account` an object API name?
No. It is a navigation item developer name. The related object's API name is `Account`.

### Q6. What is the purpose of `pageSize`?
It controls the maximum number of navigation items returned on a page. The screenshot requests 30; Salesforce's current reference documents a default of 25.

### Q7. What is `formFactor`?
It specifies the display size: `Large`, `Medium`, or `Small`. `Large` is the default.

### Q8. What does `page` do?
It specifies the zero-based page offset from which navigation items are returned. The default is `0`.

### Q9. What is `developerName`?
The unique developer name identifying a navigation item, such as `standard-Account`.

### Q10. What is `objectApiName`?
The Salesforce object API name associated with a navigation item, when it represents an object page.

### Q11. What is a Page Reference?
A JavaScript object that describes a page type, its attributes, and its state. Salesforce recommends Page References instead of hard-coded URL formats for navigation.

### Q12. What does `pageReference.type` represent?
It identifies the destination page type. For example, `standard__objectPage` represents a standard object page.

### Q13. Why is `data.navItems[0]` used?
`navItems` is an array. `[0]` selects the first item. If multiple items are requested, iterate over the array.

### Q14. What is the purpose of `@wire`?
The wire service provisions data reactively from a wire adapter or Apex method. It can be used with a property or a function.

### Q15. What is the difference between a wire property and a wire function?
A wire property receives the response on its `data` and `error` properties. A wire function receives an object containing `data` and `error`, allowing the component to process the response.

### Q16. Is `getNavItems` production-ready?
The screenshot and current Salesforce reference identify it as Beta / evaluation-only. Do not assume it is production-ready; verify the latest release status and applicable terms.

### Q17. What is the difference between `getNavItems` and `NavigationMixin`?
`getNavItems` retrieves navigation menu item data. `NavigationMixin` navigates to a page or generates a URL using a Page Reference.

### Q18. Why can navigation items differ between users?
Available items can depend on the user's app access, permissions, and the app's navigation configuration.
