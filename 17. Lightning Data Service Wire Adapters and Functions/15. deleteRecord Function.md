# `deleteRecord()` Function in Salesforce Lightning Web Components (LWC)

## 1. Overview

This folder demonstrates how to delete an existing Salesforce record from a Lightning Web Component (LWC) using the `deleteRecord()` function from `lightning/uiRecordApi`.

The example shown in the screenshots contains:
- A text input where the user enters a Salesforce Record ID.
- A **Delete Record** button.
- A JavaScript handler that calls `deleteRecord()` with the entered ID.
- Success and error toast messages using `ShowToastEvent`.
- A Lightning App Page target in the component metadata.

The example uses a Contact record ID in the UI. You can use the same approach for other supported Salesforce records by providing the ID of the record you intend to delete and ensuring the user has the required permissions.

> **Important:** Deleting a record is a destructive operation. In a real application, consider adding a confirmation step, validating the record ID, and ensuring that the user understands which record will be deleted.

## 2. Definition From the Screenshot

> **deleteRecord** — Use this function to delete a record.

### Syntax shown in the screenshot

```javascript
import { deleteRecord } from 'lightning/uiRecordApi';

deleteRecord(recordId: string): Promise<void>
```

### Parameter definition shown in the screenshot

> **recordId — (Required)** The ID of the record to delete.

In simple terms:
- `recordId` is the Salesforce ID of the record that you want to delete.
- The function returns a Promise.
- The Promise resolves when the record is successfully deleted.
- If Salesforce cannot delete the record, the Promise rejects with an error.

## 3. What Is `deleteRecord()`?

`deleteRecord()` is a function imported from `lightning/uiRecordApi`. It deletes an existing Salesforce record through the Lightning UI API.

It is useful when an LWC needs to delete a record without writing a custom Apex delete method for a straightforward deletion operation.

### Key points

- It deletes an existing record using its Salesforce record ID.
- It is imported from `lightning/uiRecordApi`.
- It returns a Promise with no data value on successful completion (`Promise<void>`).
- It supports asynchronous success and error handling using `.then()` and `.catch()`.
- It follows Salesforce access controls and applicable platform rules.

### B. JavaScript — `deleteRecordDemo.js`

This is the JavaScript logic shown in the screenshot: read the ID from the input, call `deleteRecord()`, and show a success or error toast.

```javascript
import { LightningElement } from 'lwc';
import { deleteRecord } from 'lightning/uiRecordApi';
import { ShowToastEvent } from 'lightning/platformShowToastEvent';

export default class DeleteRecordDemo extends LightningElement {
    recordId;

    changeHandler(event) {
        this.recordId = event.target.value;
    }

    deleteHandler() {
        deleteRecord(this.recordId)
            .then(() => {
                this.showToast(
                    'Success',
                    'Record deleted successfully',
                    'success'
                );
            })
            .catch((error) => {
                console.error('Error deleting record: ', error);
                this.showToast(
                    'Error',
                    'Error deleting record',
                    'error'
                );
            });
    }

    showToast(title, message, variant) {
        const event = new ShowToastEvent({
            title,
            message,
            variant
        });

        this.dispatchEvent(event);
    }
}
```

## 6. Code Explanation Step by Step

### Step 1: Import the required modules

```javascript
import { LightningElement } from 'lwc';
import { deleteRecord } from 'lightning/uiRecordApi';
import { ShowToastEvent } from 'lightning/platformShowToastEvent';
```

- `LightningElement` is the base class for an LWC.
- `deleteRecord` is the UI API function used to delete a record.
- `ShowToastEvent` displays a toast notification to the user.

### Step 2: Declare a property to store the Record ID

```javascript
recordId;
```

This property stores the Salesforce ID entered by the user.

### Step 3: Capture the input value

```javascript
changeHandler(event) {
    this.recordId = event.target.value;
}
```

When the user types or changes the Record ID, the `change` event invokes `changeHandler()`. The entered value is stored in `this.recordId`.

### Step 4: Call `deleteRecord()`

```javascript
deleteHandler() {
    deleteRecord(this.recordId)
        .then(() => {
            // Handle successful deletion.
        })
        .catch((error) => {
            // Handle deletion failure.
        });
}
```

The button invokes `deleteHandler()`. The method passes the entered record ID to `deleteRecord()`.

### Step 5: Handle successful deletion

```javascript
.then(() => {
    this.showToast(
        'Success',
        'Record deleted successfully',
        'success'
    );
})
```

The `.then()` callback runs when Salesforce successfully deletes the record. It displays a success toast.

### Step 6: Handle errors

```javascript
.catch((error) => {
    console.error('Error deleting record: ', error);
    this.showToast('Error', 'Error deleting record', 'error');
});
```

The `.catch()` callback runs if the deletion fails. The error is logged to the browser console and an error toast is displayed.

### Step 7: Display the toast message

```javascript
showToast(title, message, variant) {
    const event = new ShowToastEvent({
        title,
        message,
        variant
    });

    this.dispatchEvent(event);
}
```

`ShowToastEvent` displays a notification. The `variant` controls its appearance, such as `success`, `error`, `warning`, or `info`.

## 7. Improved Version for a Real Project

The following optional improvement adds basic input validation and asks the user to confirm before deleting. It keeps the same `deleteRecord()` function.

### Improved HTML

```html
<template>
    <lightning-card title="Delete Record Demo">
        <div class="slds-p-around_medium">
            <lightning-input
                label="Record Id"
                name="recordId"
                value={recordId}
                onchange={changeHandler}
                placeholder="Enter a Salesforce Record ID">
            </lightning-input>

            <div class="slds-m-top_medium">
                <lightning-button
                    label="Delete Record"
                    variant="destructive"
                    onclick={deleteHandler}
                    disabled={isDeleteDisabled}>
                </lightning-button>
            </div>
        </div>
    </lightning-card>
</template>
```

### Improved JavaScript

```javascript
import { LightningElement } from 'lwc';
import { deleteRecord } from 'lightning/uiRecordApi';
import { ShowToastEvent } from 'lightning/platformShowToastEvent';

export default class DeleteRecordDemo extends LightningElement {
    recordId = '';
    isDeleting = false;

    get isDeleteDisabled() {
        return !this.recordId.trim() || this.isDeleting;
    }

    changeHandler(event) {
        this.recordId = event.target.value.trim();
    }

    async deleteHandler() {
        if (!this.recordId) {
            this.showToast('Warning', 'Please enter a Record ID.', 'warning');
            return;
        }

        const confirmed = window.confirm(
            'Are you sure you want to delete this record? This action may be difficult to reverse.'
        );

        if (!confirmed) {
            return;
        }

        this.isDeleting = true;

        try {
            await deleteRecord(this.recordId);

            this.showToast(
                'Success',
                'Record deleted successfully.',
                'success'
            );

            this.recordId = '';
        } catch (error) {
            const message =
                error?.body?.message || 'An error occurred while deleting the record.';

            this.showToast('Error', message, 'error');
            console.error('Error deleting record:', error);
        } finally {
            this.isDeleting = false;
        }
    }

    showToast(title, message, variant) {
        this.dispatchEvent(
            new ShowToastEvent({
                title,
                message,
                variant
            })
        );
    }
}
```

**Note:** This is an optional learning improvement, not the exact JavaScript from the screenshot. `window.confirm()` is a simple browser confirmation; for a polished Salesforce UI, use a Lightning modal such as `LightningConfirm`. Also, client-side input validation does not replace Salesforce permissions or server-side checks.

## 10. Important Concepts

### UI API
The User Interface API provides Salesforce data and metadata for user-interface development. `deleteRecord()` is one of the functions available through `lightning/uiRecordApi`.

### Lightning Data Service (LDS)
Lightning Data Service provides record data access for Lightning components. UI API functions integrate with the Salesforce data and security model.

### Promise
A Promise represents the eventual success or failure of an asynchronous operation. `deleteRecord()` returns a Promise.

### `.then()`
Runs when the Promise resolves successfully.

### `.catch()`
Runs when the Promise rejects. Use it to handle and display errors.

### `ShowToastEvent`
A platform event used to show a toast notification to the user.

### Record ID
A Salesforce record ID uniquely identifies a record. Salesforce IDs are commonly 15 or 18 characters long. Always use the actual ID of the record you intend to delete.

### Object Permissions and Record Access
The current user must have the required permissions and access to delete the target record. Sharing, object permissions, and other Salesforce rules can affect whether deletion succeeds.

### Related Records and Delete Restrictions
A deletion can be blocked by relationships, restrictions, automation, or other platform rules. Review the returned error rather than assuming every record can be deleted.

## 11. Troubleshooting

| Problem | What to check |
|---|---|
| Nothing happens after clicking Delete | Confirm `onclick={deleteHandler}` is correctly connected and the component is deployed. |
| Record ID is undefined | Confirm `onchange={changeHandler}` is connected and the input value is being stored. |
| Invalid ID error | Copy the actual Salesforce record ID and ensure it belongs to the intended org. |
| Insufficient access error | Check the user's object-level Delete permission and access to the record. |
| Record cannot be deleted | Check relationship restrictions, validation/automation behavior, and the error returned by Salesforce. |
| Success toast does not appear | Confirm `ShowToastEvent` is imported and dispatched correctly. |
| Error toast appears | Inspect `error.body.message` or the error object in the browser console. |
| Record still appears on a page | Refresh the page or the relevant record/list data after deletion. |

## 12. Interview Questions and Answers

### Q1. What is `deleteRecord()` in LWC?
It is a function from `lightning/uiRecordApi` used to delete an existing Salesforce record.

### Q2. From which module do we import `deleteRecord()`?
```javascript
import { deleteRecord } from 'lightning/uiRecordApi';
```

### Q3. What is the syntax of `deleteRecord()`?
```javascript
deleteRecord(recordId);
```

### Q4. What parameter does `deleteRecord()` accept?
It accepts one required parameter: `recordId`, the ID of the record to delete.

### Q5. What does `deleteRecord()` return?
It returns a Promise with the type `Promise<void>`. It resolves when deletion succeeds and rejects when deletion fails.

### Q6. Does `deleteRecord()` require a `recordInput` object?
No. It accepts the record ID directly as a string.

### Q7. What is the difference between `deleteRecord()` and `updateRecord()`?
`deleteRecord()` removes an existing record. `updateRecord()` changes field values on an existing record.

### Q8. What is the difference between `deleteRecord()` and `delete` DML in Apex?
`deleteRecord()` performs a client-side UI API deletion and respects UI API access rules. Apex `delete` is server-side DML and is useful when deletion is part of more complex server-side logic.

### Q9. Why do we use `.then()` with `deleteRecord()`?
To execute code after the deletion Promise resolves successfully.

### Q10. Why do we use `.catch()`?
To handle errors when the deletion Promise rejects.

### Q11. What is `ShowToastEvent`?
It is used to display a toast notification in the Salesforce UI.

### Q12. From which module is `ShowToastEvent` imported?
```javascript
import { ShowToastEvent } from 'lightning/platformShowToastEvent';
```

### Q13. What are the common toast variants?
`success`, `error`, `warning`, and `info`.

### Q14. What permissions are required to delete a record?
The user needs the appropriate Delete object permission and access to the target record, subject to Salesforce security and platform rules.

### Q15. Can `deleteRecord()` delete any Salesforce record?
It can delete supported records when the user has the required access and Salesforce rules allow the deletion. Some records may be restricted by relationships or platform behavior.

### Q16. How can you get a record ID in LWC?
It can be passed to a record-page component through the public `@api recordId` property, obtained from a selected row, or supplied through another trusted UI flow. In this screenshot example, the user enters it manually.

### Q17. Why should we confirm before deleting a record?
Deletion is destructive. Confirmation helps prevent accidental deletion of the wrong record.

### Q18. Does `deleteRecord()` bypass Salesforce security?
No. It follows the applicable UI API and Salesforce access controls.

### Q19. What happens if the record ID is invalid?
The Promise rejects and the error handler can display the returned error.

### Q20. Can we use `async/await` instead of `.then()` and `.catch()`?
Yes. `async/await` can be used with `try/catch` to handle the Promise.

### Q21. What is the difference between `Promise<void>` and `Promise<Record>`?
`Promise<void>` indicates that the operation does not resolve with a record value. `Promise<Record>` resolves with a record value. `deleteRecord()` returns `Promise<void>`.

### Q22. How would you refresh related UI after deletion?
Use the appropriate refresh mechanism for the data source, such as `refreshApex()` for wired Apex data, or refresh the relevant view where appropriate. Choose the method based on how the component obtained its data.
