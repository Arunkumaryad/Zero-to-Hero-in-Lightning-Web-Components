# `getPicklistValues` Wire Adapter in Lightning Web Components (LWC)

## 1. Overview

This folder demonstrates Salesforce's **`getPicklistValues` wire adapter**. It retrieves the available picklist options for a specified field, based on a record type. The example uses the standard **Account Industry** and **Account Type** picklist fields and displays the selected option in a `lightning-combobox`.

> **Important naming note:** The folder requested is named `getPicklistValuesByRecordType adapter`, but the screenshots' JavaScript uses `getPicklistValues` twice—once for `Account.Industry` and once for `Account.Type`. This README documents the code actually shown. `getPicklistValuesByRecordType` is a different adapter that retrieves picklist metadata for all picklist fields for a given record type.

## 2. Definition From the Screenshot

> **getPicklistValues**
>
> Use this wire adapter to get the picklist values for a specified field.

### Configuration parameters shown in the slide

- **`recordTypeId`** — The ID of the record type. Use the `defaultRecordTypeId` property returned from `getObjectInfo`.
- **`fieldApiName`** — The API name of the picklist field.

## 3. Syntax From the Screenshot

```javascript
import { LightningElement, wire } from 'lwc';
import { getPicklistValues } from 'lightning/uiObjectInfoApi';
import INDUSTRY_FIELD from '@salesforce/schema/Account.Industry';

export default class Example extends LightningElement {
    @wire(getPicklistValues, {
        recordTypeId: '012000000000000AAA',
        fieldApiName: INDUSTRY_FIELD
    })
    propertyOrFunction;
}
```

**Best practice:** avoid hard-coding a record type ID. Retrieve the default record type ID dynamically using `getObjectInfo`, as shown in the complete example below.

## 4. What Is `getPicklistValues`?

`getPicklistValues` is a Lightning Data Service (UI API) wire adapter available from `lightning/uiObjectInfoApi`. It retrieves the available values for one picklist field for a specified record type.

Use it when you need to populate a dropdown based on Salesforce picklist metadata, such as Account Industry, Account Type, Contact Salutation, or a custom object's picklist field. The adapter supplies labels and stored values; it does not create or update a record by itself.

## 5. Complete Example Based on the Screenshots

The screenshot code gets the default Account record type ID with `getObjectInfo`, then uses it to load Industry and Type options. The code below follows that design and includes loading/error handling.

### JavaScript — `getPicklistValuesDemo.js`

```javascript
import { LightningElement, wire } from 'lwc';
import { getObjectInfo, getPicklistValues } from 'lightning/uiObjectInfoApi';
import ACCOUNT_OBJECT from '@salesforce/schema/Account';
import INDUSTRY_FIELD from '@salesforce/schema/Account.Industry';
import TYPE_FIELD from '@salesforce/schema/Account.Type';

export default class GetPicklistValuesDemo extends LightningElement {
    recordTypeId;
    selectedIndustry = '';
    selectedType = '';
    industryOptions = [];
    typeOptions = [];
    error;

    @wire(getObjectInfo, { objectApiName: ACCOUNT_OBJECT })
    objectInfoHandler({ data, error }) {
        if (data) {
            this.recordTypeId = data.defaultRecordTypeId;
            this.error = undefined;
        } else if (error) {
            this.error = error;
            this.recordTypeId = undefined;
        }
    }

    @wire(getPicklistValues, {
        recordTypeId: '$recordTypeId',
        fieldApiName: INDUSTRY_FIELD
    })
    industryPicklistHandler({ data, error }) {
        if (data) {
            this.industryOptions = data.values.map((item) => ({
                label: item.label,
                value: item.value
            }));
            this.error = undefined;
        } else if (error) {
            this.error = error;
            this.industryOptions = [];
        }
    }

    @wire(getPicklistValues, {
        recordTypeId: '$recordTypeId',
        fieldApiName: TYPE_FIELD
    })
    typePicklistHandler({ data, error }) {
        if (data) {
            this.typeOptions = data.values.map((item) => ({
                label: item.label,
                value: item.value
            }));
            this.error = undefined;
        } else if (error) {
            this.error = error;
            this.typeOptions = [];
        }
    }

    handleChange(event) {
        this.selectedIndustry = event.detail.value;
    }

    handleTypeChange(event) {
        this.selectedType = event.detail.value;
    }
}
```

## 6. How the Code Works

1. **Import the object and fields.** `ACCOUNT_OBJECT`, `INDUSTRY_FIELD`, and `TYPE_FIELD` are schema references.
2. **Get object metadata.** `getObjectInfo` retrieves Account metadata, including `defaultRecordTypeId`.
3. **Load Industry options.** `getPicklistValues` uses the reactive `recordTypeId` and `INDUSTRY_FIELD`.
4. **Load Type options.** A second wire adapter uses the same record type ID and `TYPE_FIELD`.
5. **Format the options.** Each option is mapped to `{ label, value }`, which `lightning-combobox` expects.
6. **Handle selection.** `event.detail.value` contains the selected option's stored value.
7. **Render the selected value.** The template displays the selection below each combobox.

## 7. Important Concepts

### `recordTypeId`

Picklist values can vary by record type because administrators can make certain values available or unavailable for each record type. Use the record type ID relevant to the record being created or edited. For a new record, `getObjectInfo`'s `defaultRecordTypeId` is a common starting point; for an existing record, use that record's actual record type when appropriate.

### `fieldApiName`

This is the API name of the picklist field. A schema import such as `@salesforce/schema/Account.Industry` is preferred to a hard-coded string because Salesforce tooling can validate the reference.

### `data.values`

The response's `values` array contains entries with `label` and `value` properties. The label is displayed to the user; the value is the stored picklist value.

### `lightning-combobox`

This base component renders a single-select dropdown. Its `options` property expects an array of objects with `label` and `value`, and `onchange` receives the selected value in `event.detail.value`.

## 8. `getPicklistValues` vs. `getPicklistValuesByRecordType`

| `getPicklistValues` | `getPicklistValuesByRecordType` |
|---|---|
| Retrieves values for one specified field. | Retrieves picklist values for all picklist fields available for a specified record type. |
| Configuration includes `recordTypeId` and `fieldApiName`. | Configuration includes `objectApiName` and `recordTypeId`. |
| Useful when you know which picklist field you need. | Useful when you need metadata for multiple picklist fields on an object. |
| Used in the screenshots. | Not used in the screenshot code. |

If you keep the folder name `getPicklistValuesByRecordType adapter`, explain in the repository that the included example demonstrates `getPicklistValues`; alternatively, rename the folder to `getPicklistValues adapter` for clarity.

3. Add the HTML, JavaScript, and XML files shown above.
4. Deploy the component to your Salesforce org.

## 10. Troubleshooting

- **No picklist options:** confirm the record type ID and field API name.
- **Wrong values for a record type:** check the values assigned to that record type in Setup.
- **Hard-coded record type ID:** retrieve it using `getObjectInfo`.
- **Schema import error:** verify API names, including `__c` for custom fields.
- **Combobox does not update:** ensure `value`, `options`, and `onchange` are bound correctly.
- **Field not accessible:** check object permissions, field-level security, and user access.
- **Dependent picklist:** use returned `controllerValues` and `validFor` information to filter choices based on the controlling field. The screenshot example does not implement dependency filtering.

## 11. Interview Questions and Short Answers

### Q1. What is `getPicklistValues`?
A wire adapter that retrieves available values for a specified picklist field and record type.

### Q2. Which module exports it?
`lightning/uiObjectInfoApi`.

### Q3. Which parameters does it require?
`recordTypeId` and `fieldApiName`.

### Q4. Why is `recordTypeId` important?
Available picklist values can differ between record types.

### Q5. How can you get the default record type ID dynamically?
Use `getObjectInfo` and read `data.defaultRecordTypeId`.

### Q6. What is the difference between label and value?
`label` is user-facing text; `value` is the stored picklist value.

### Q7. Why use `'$recordTypeId'` in wire configuration?
The `$` makes the property reactive. When `recordTypeId` changes, the wire service provisions data again.

### Q8. What does `lightning-combobox` expect in `options`?
An array such as `[{ label: 'Display Text', value: 'stored_value' }]`.

### Q9. Does this adapter save the selected value to Salesforce?
No. It supplies picklist metadata. Saving requires a record form or another data operation.

### Q10. What is the difference between `getPicklistValues` and `getPicklistValuesByRecordType`?
The first returns values for one field; the second returns picklist metadata for all picklist fields on an object for a record type.

### Q11. Can this adapter be used with custom picklist fields?
Yes, if the object and field are supported and accessible. Import the field using its schema reference, such as `@salesforce/schema/Property__c.Status__c`.

### Q12. How do you handle errors from a wire adapter?
Use the wire function's `{ data, error }` parameters, clear stale values when needed, and display a useful message.
