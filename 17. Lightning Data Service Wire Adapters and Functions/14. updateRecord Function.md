# `updateRecord()` Function in Salesforce LWC

## 1. Overview

This folder demonstrates how to update existing Salesforce records from a Lightning Web Component (LWC) using `updateRecord()` from `lightning/uiRecordApi`.

The screenshot example displays Contact records in a `lightning-datatable`. Users can edit selected fields inline and save their changes. The component reads the draft values, calls `updateRecord()` for each changed row, and handles success or failure.

> **Production note:** The screenshot imports `getListUi` from `lightning/uiListApi`. This adapter is beta/evaluation-only and is not intended for production use. It is included here to explain the original demo. For production list retrieval, choose a currently supported approach such as GraphQL or Apex, depending on the use case. The main topic documented here is `updateRecord()`.

## 2. Definition From the Screenshot

> **updateRecord** — Use this wire adapter to update a record. Provide the recordId of the record to update in `recordInput`.

### Syntax shown in the screenshot

```javascript
import { updateRecord } from 'lightning/uiRecordApi';

updateRecord(
    recordInput: Record,
    clientOptions?: Object
): Promise<Record>
```

### Parameter definitions shown in the screenshot

> **recordInput** — A Record Input object is used to update the object.

> **clientOptions (optional)** — To check for conflicts before you update a record.

In simple terms:
- `recordInput` identifies the record and contains the new field values.
- `clientOptions` is optional. It can be used for conflict checking, such as with `ifUnmodifiedSince`.
- `updateRecord()` returns a Promise. It resolves when the update succeeds and rejects if it fails.

## 3. What Is `updateRecord()`?

`updateRecord()` is a function from `lightning/uiRecordApi` that updates an existing Salesforce record through UI API and Lightning Data Service. It is useful for straightforward record updates from an LWC without writing a custom Apex update method.

**Benefits**
- Updates Salesforce records directly from an LWC.
- Uses UI API and Lightning Data Service.
- Respects the current user's object permissions and field-level security.
- Returns a Promise for success and error handling.
- Supports optional conflict checking through `clientOptions`.

## 4. `recordInput` Structure

For an update, `recordInput` contains a `fields` object. This object must include the record's `Id` and the fields to update.

```javascript
const recordInput = {
    fields: {
        Id: '003XXXXXXXXXXXXXXX',
        Title: 'Senior Developer',
        Phone: '9876543210',
        Email: 'anuj@example.com'
    }
};
```

**Important:** Unlike `createRecord()`, `updateRecord()` does not require an `apiName` property. Include the record ID in `recordInput.fields.Id`.

### A. HTML — `updateRecordDemo.html`

```html
</template>
```

### B. JavaScript — `updateRecordDemo.js`

This follows the screenshot's approach: retrieve the Contact list view using `getListUi`, map the records into datatable rows, and update edited rows using `updateRecord()`.

```javascript
import { LightningElement, wire } from 'lwc';
import { getListUi } from 'lightning/uiListApi';
import { updateRecord } from 'lightning/uiRecordApi';
import CONTACT_OBJECT from '@salesforce/schema/Contact';

const COLS = [
    { label: 'Id', fieldName: 'Id' },
    { label: 'Name', fieldName: 'Name' },
    { label: 'Title', fieldName: 'Title', editable: true },
    { label: 'Phone', fieldName: 'Phone', editable: true },
    { label: 'Email', fieldName: 'Email', type: 'email', editable: true }
];

export default class UpdateRecordDemo extends LightningElement {
    contacts = [];
    columns = COLS;
    draftValues = [];

    @wire(getListUi, {
        objectApiName: CONTACT_OBJECT,
        listViewApiName: 'AllContacts'
    })
    listViewHandler({ data, error }) {
        if (data) {
            this.contacts = data.records.records.map((item) => ({
                Id: this.getValue(item, 'Id'),
                Name: this.getValue(item, 'Name'),
                Title: this.getValue(item, 'Title'),
                Phone: this.getValue(item, 'Phone'),
                Email: this.getValue(item, 'Email')
            }));
        } else if (error) {
            console.error('Error loading Contacts:', error);
        }
    }

    getValue(record, fieldName) {
        return record.fields[fieldName]?.value;
    }

    handleSave(event) {
        const recordInputs = event.detail.draftValues.map((draft) => {
            const fields = { ...draft };
            return { fields };
        });

        const promises = recordInputs.map((recordInput) =>
            updateRecord(recordInput)
        );

        Promise.all(promises)
            .then(() => {
                console.log('Contact records updated successfully.');
                this.draftValues = [];
            })
            .catch((error) => {
                console.error('Error updating the records:', error);
            });
    }
}
```

**Important details**
- `key-field="Id"` identifies each row. The property name is case-sensitive and must match `Id` in the row objects.
- `editable: true` enables inline editing for the specified columns.
- `event.detail.draftValues` contains only changed fields plus the row ID.
- Each draft is passed to `updateRecord()` as `{ fields: draft }`.
- `Promise.all()` waits for all update Promises. If one rejects, the `Promise.all()` chain rejects.

## 7. Code Explanation Step by Step

### Step 1: Import modules

```javascript
import { LightningElement, wire } from 'lwc';
import { getListUi } from 'lightning/uiListApi';
import { updateRecord } from 'lightning/uiRecordApi';
import CONTACT_OBJECT from '@salesforce/schema/Contact';
```

- `LightningElement` is the base class for an LWC.
- `wire` provisions data reactively.
- `getListUi` retrieves list-view data in the screenshot's demo; it is beta/evaluation-only.
- `updateRecord` updates an existing record.
- `CONTACT_OBJECT` is the schema reference for Contact.

### Step 2: Define columns

```javascript
const COLS = [
    { label: 'Id', fieldName: 'Id' },
    { label: 'Name', fieldName: 'Name' },
    { label: 'Title', fieldName: 'Title', editable: true },
    { label: 'Phone', fieldName: 'Phone', editable: true },
    { label: 'Email', fieldName: 'Email', type: 'email', editable: true }
];
```

`label` is the column heading, `fieldName` maps to a property in the row object, `editable: true` enables editing, and `type: 'email'` displays an email field appropriately.

### Step 3: Store records and drafts

```javascript
contacts = [];
columns = COLS;
draftValues = [];
```

- `contacts` contains table rows.
- `columns` contains the table configuration.
- `draftValues` contains unsaved inline edits.

### Step 4: Retrieve and map records

The `@wire` handler receives either `data` or `error`. The example maps the UI API record structure into simple objects for the datatable. The `AllContacts` list view must exist and be accessible to the user.

### Step 5: Read a field value

```javascript
getValue(record, fieldName) {
    return record.fields[fieldName]?.value;
}
```

This helper extracts the field value from the UI API record response. Optional chaining avoids an error if a field is absent.

### Step 6: Capture inline edits

When a user edits cells and clicks Save, the datatable fires `onsave`. The changed values are available in:

```javascript
event.detail.draftValues
```

Each draft includes the row key (`Id`) and only the fields that changed.

### Step 7: Prepare the update input

```javascript
const recordInputs = event.detail.draftValues.map((draft) => {
    const fields = { ...draft };
    return { fields };
});
```

This produces an input like:

```javascript
{
    fields: {
        Id: '003XXXXXXXXXXXXXXX',
        Phone: '9876543210'
    }
}
```

### Step 8: Update records

```javascript
const promises = recordInputs.map((recordInput) =>
    updateRecord(recordInput)
);
```

Each call returns a Promise for one record update.

### Step 9: Wait for completion

```javascript
Promise.all(promises)
    .then(() => {
        this.draftValues = [];
    })
    .catch((error) => {
        console.error(error);
    });
```

The success handler runs when all supplied Promises resolve. The error handler runs if at least one rejects.

> **Transaction note:** Multiple `updateRecord()` calls are separate UI API operations. `Promise.all()` coordinates their JavaScript Promises; it does not make them one atomic Salesforce transaction. Some records may save even if another update fails.

## 8. `clientOptions` and Conflict Detection

The second parameter is optional. One supported use is optimistic concurrency checking with `ifUnmodifiedSince`.

```javascript
updateRecord(
    {
        fields: {
            Id: recordId,
            Phone: '9876543210'
        }
    },
    {
        ifUnmodifiedSince: lastModifiedDate
    }
);
```

`lastModifiedDate` must be the record's `LastModifiedDate` value captured when the record was read. Do not substitute the current time. If the record has changed since that timestamp, the update can fail rather than overwrite the newer change.

## 10. Important Concepts

### Lightning Data Service (LDS)
A Salesforce service that provides record access through supported UI API operations and respects the user's access.

### UI API
The User Interface API provides Salesforce data and metadata for user-interface development. Functions such as `createRecord`, `updateRecord`, and `deleteRecord`, and wire adapters such as `getRecord`, use UI API.

### `lightning-datatable`
A base component for displaying records in rows and columns. It supports features such as sorting, row selection, and inline editing when configured.

### Inline Editing
Allows users to edit supported cells directly in the table. Set `editable: true` in the column definition.

### Draft Values
`event.detail.draftValues` is an array of changed field values for edited rows. It is not necessarily a complete copy of each row.

### Promise and `Promise.all()`
A Promise represents the eventual success or failure of an asynchronous operation. `Promise.all()` waits for all supplied Promises and rejects if any one rejects.

### Optimistic Concurrency
A check that helps prevent overwriting a record that another user changed after it was read. `ifUnmodifiedSince` uses the record's `LastModifiedDate`.

### Permissions and Validation
The user needs Edit access to the object and access to the fields being changed. Validation rules and other Salesforce business rules still apply.

## 11. Troubleshooting

| Problem | What to check |
|---|---|
| Records are not displayed | Confirm the list view exists, is accessible, and the adapter returns data. |
| Inline editing is unavailable | Confirm the column has `editable: true` and the user can edit the field. |
| Save does not update a record | Confirm the draft contains `Id` and correct field API names. |
| `updateRecord()` rejects | Inspect the error. Check permissions, validation rules, required fields, and field-level security. |
| Draft values remain visible | Clear `draftValues` after successful saves. |
| Wrong row is updated | Confirm `key-field="Id"` and each row has the correct `Id` property. |
| `Promise.all()` fails | At least one update rejected. Inspect the error; other updates may have succeeded. |
| Conflict error occurs | The record may have changed since it was read. Refresh and review the latest values before retrying. |
| `getListUi` is unsuitable | It is beta/evaluation-only in the screenshot. Choose a supported production data retrieval method. |

## 12. Interview Questions and Answers

### Q1. What is `updateRecord()` in LWC?
A function from `lightning/uiRecordApi` used to update an existing Salesforce record through UI API.

### Q2. From which module is it imported?
```javascript
import { updateRecord } from 'lightning/uiRecordApi';
```

### Q3. What is its syntax?
```javascript
updateRecord(recordInput, clientOptions);
```
The second parameter is optional. The function returns a Promise.

### Q4. What is `recordInput`?
An object containing a `fields` object. The fields object must include the record ID and the values to update.

### Q5. Is `apiName` required in `updateRecord()`?
No. Include the record ID in `recordInput.fields.Id`. This differs from the input used by `createRecord()`.

### Q6. What is `clientOptions`?
An optional object that can contain options such as `ifUnmodifiedSince` for conflict detection.

### Q7. What does `updateRecord()` return?
A Promise that resolves with the updated record or rejects with an error.

### Q8. What is `ifUnmodifiedSince`?
An option that checks whether the record has changed since the supplied `LastModifiedDate`, helping avoid overwriting another user's changes.

### Q9. What is inline editing?
Editing a supported datatable cell directly without opening a separate edit form.

### Q10. How do you enable inline editing?
Set `editable: true` in the relevant column definition.

### Q11. What is `event.detail.draftValues`?
An array containing the changed values for edited rows, including each row's key field.

### Q12. Why is `key-field="Id"` important?
It tells the datatable which property uniquely identifies each row. It must match the case and name of the ID property in the row data.

### Q13. Why use `Promise.all()`?
To wait for multiple asynchronous update operations to finish before running the success handler.

### Q14. Does `Promise.all()` make multiple updates one Salesforce transaction?
No. It coordinates JavaScript Promises but does not make separate `updateRecord()` calls an atomic transaction.

### Q15. What happens if one update in `Promise.all()` fails?
The combined Promise rejects and `.catch()` runs. Other update operations may still have succeeded.

### Q16. Difference between `createRecord()` and `updateRecord()`?
`createRecord()` creates a new record. `updateRecord()` modifies an existing record and requires its ID.

### Q17. Difference between `updateRecord()` and Apex `update` DML?
`updateRecord()` uses UI API for client-side record updates and respects UI API access rules. Apex `update` is server-side DML and is useful for complex server-side logic or multi-record transactions.

### Q18. Does `updateRecord()` bypass validation rules?
No. Applicable Salesforce validation rules and platform rules still apply.

### Q19. What permissions are required to update a Contact?
The user needs Edit permission on Contact and access to the fields being updated. Applicable record access and business rules must also be satisfied.

### Q20. Why clear `draftValues` after a successful update?
To remove saved edits from the datatable's draft state so they are no longer shown as unsaved changes.

### Q21. What is the purpose of `getValue()`?
It extracts a field value from the UI API record structure, avoiding repeated access logic.

### Q22. What is `getListUi`?
The list-view wire adapter used in the screenshot to retrieve list-view records and metadata. The screenshot labels the related List UI API as beta/evaluation-only, so do not assume it is suitable for production.
