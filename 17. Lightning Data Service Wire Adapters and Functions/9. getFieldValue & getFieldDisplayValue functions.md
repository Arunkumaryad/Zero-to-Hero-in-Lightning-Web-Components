# `getFieldValue` and `getFieldDisplayValue` Functions in LWC

## 1. Overview

This folder explains two helper functions used with Salesforce Lightning Data Service (LDS) in Lightning Web Components:

- `getFieldValue()`
- `getFieldDisplayValue()`

Both functions are imported from `lightning/uiRecordApi`. They are commonly used with the `getRecord` wire adapter to read field values from a Salesforce record.

The example follows the screenshots and retrieves an Account record's:

- Account Name
- Account Owner Name
- Annual Revenue

It then displays the Account Name and Owner using `getFieldValue()`, and Annual Revenue using `getFieldDisplayValue()`.

## 2. Definitions From the Screenshots

### `getFieldValue`

> Use this to get a field’s value from a record.

**Syntax:**

```javascript
import { getFieldValue } from 'lightning/uiRecordApi';

getFieldValue(record, field);
```

### `getFieldDisplayValue`

> Use this to get a field’s value in formatted and localized format from a record.

**Syntax:**

```javascript
import { getFieldDisplayValue } from 'lightning/uiRecordApi';

getFieldDisplayValue(record, field);
```

The descriptions above preserve the meaning of the screenshot text, with minor grammar corrections.

## 3. Difference Between the Two Functions

| Function | What it returns | Typical use |
|---|---|---|
| `getFieldValue(record, field)` | The field's raw value. | When you need the actual value for calculations, comparisons, or logic. |
| `getFieldDisplayValue(record, field)` | The formatted display value, when one is available. | When you want to show a value to a user in a localized or formatted form. |

### Example

For an Annual Revenue currency field:

- `getFieldValue()` can return a numeric value such as `34567855443`.
- `getFieldDisplayValue()` can return a formatted value such as `$34,567,855,443`, depending on the org's currency and locale settings.

**Important:** A display value may not be available for every field. `getFieldDisplayValue()` can return `undefined`; use `getFieldValue()` as a fallback when appropriate.

## 4. How These Functions Work With `getRecord`

The `getRecord` wire adapter retrieves a record. The helper functions then read individual field values from the returned record data.

The overall flow is:

1. Import `getRecord`, `getFieldValue`, and `getFieldDisplayValue`.
2. Import the required Salesforce field references.
3. Receive the current record ID through `@api recordId`.
4. Call `getRecord` with the record ID and requested fields.
5. When data is returned, use the helper functions to read the fields.
6. Display the values in the HTML template.

### JavaScript — `getRecordDemo.js`

This code follows the screenshot: it uses `getRecord` with explicit field references, `getFieldValue()` for Name and Owner, and `getFieldDisplayValue()` for Annual Revenue.

```javascript
import { LightningElement, wire, api } from 'lwc';

import {
    getRecord,
    getFieldValue,
    getFieldDisplayValue
} from 'lightning/uiRecordApi';

import NAME_FIELD from '@salesforce/schema/Account.Name';
import OWNER_NAME_FIELD from '@salesforce/schema/Account.Owner.Name';
import ANNUAL_REVENUE_FIELD from '@salesforce/schema/Account.AnnualRevenue';

export default class GetRecordDemo extends LightningElement {
    name;
    ownerName;
    annualRevenue;

    // Salesforce provides the current record ID on a record page.
    @api recordId;

    @wire(getRecord, {
        recordId: '$recordId',
        fields: [NAME_FIELD, OWNER_NAME_FIELD, ANNUAL_REVENUE_FIELD]
    })
    accountHandler({ data, error }) {
        if (data) {
            console.log('getRecord data:', data);

            // Get raw field values.
            this.name = getFieldValue(data, NAME_FIELD);
            this.ownerName = getFieldValue(data, OWNER_NAME_FIELD);

            // Get the formatted Annual Revenue value.
            // Fall back to the raw value if a display value is unavailable.
            this.annualRevenue =
                getFieldDisplayValue(data, ANNUAL_REVENUE_FIELD) ??
                getFieldValue(data, ANNUAL_REVENUE_FIELD);
        } else if (error) {
            console.error('Error retrieving Account:', error);

            this.name = undefined;
            this.ownerName = undefined;
            this.annualRevenue = undefined;
        }
    }
}
```

## 6. Explanation of the Code

### A. Import modules from LWC and UI Record API

```javascript
import { LightningElement, wire, api } from 'lwc';

import {
    getRecord,
    getFieldValue,
    getFieldDisplayValue
} from 'lightning/uiRecordApi';
```

- `LightningElement` is the base class for an LWC.
- `wire` connects the component to a Salesforce wire adapter.
- `api` exposes a public property. On a Lightning Record Page, Salesforce provides the current record ID through `recordId`.
- `getRecord` retrieves the record data.
- `getFieldValue` reads a field's raw value.
- `getFieldDisplayValue` reads a field's formatted display value when available.

### B. Import the Account fields

```javascript
import NAME_FIELD from '@salesforce/schema/Account.Name';
import OWNER_NAME_FIELD from '@salesforce/schema/Account.Owner.Name';
import ANNUAL_REVENUE_FIELD from '@salesforce/schema/Account.AnnualRevenue';
```

These are schema imports. They reference the Account Name, Account Owner Name relationship field, and Annual Revenue fields.

Using schema imports instead of manually typed field strings helps Salesforce validate field references and track dependencies.

### C. Declare the record ID

```javascript
@api recordId;
```

When this component is placed on an Account Lightning Record Page, Salesforce automatically supplies the ID of the Account currently being viewed.

### D. Retrieve the record with `getRecord`

```javascript
@wire(getRecord, {
    recordId: '$recordId',
    fields: [NAME_FIELD, OWNER_NAME_FIELD, ANNUAL_REVENUE_FIELD]
})
accountHandler({ data, error }) {
    // Read data or handle the error.
}
```

- `recordId` tells Salesforce which record to retrieve.
- `'$recordId'` makes the wire configuration reactive. If the record ID changes, the wire service provisions data for the new record.
- `fields` lists the fields the component needs.
- The wire handler receives an object containing `data` or `error`.

### E. Get the raw value with `getFieldValue()`

```javascript
this.name = getFieldValue(data, NAME_FIELD);
this.ownerName = getFieldValue(data, OWNER_NAME_FIELD);
```

This function reads the field's raw value from the record response. Use it when you need the underlying value for JavaScript logic or when the raw value is sufficient for display.

### F. Get the formatted value with `getFieldDisplayValue()`

```javascript
this.annualRevenue =
    getFieldDisplayValue(data, ANNUAL_REVENUE_FIELD) ??
    getFieldValue(data, ANNUAL_REVENUE_FIELD);
```

This function returns the field's formatted display value when Salesforce provides one. For currency, the formatted value can include separators and currency formatting based on org and user settings.

The `??` operator is the nullish coalescing operator. It uses the raw value only if the display value is `null` or `undefined`.

## 7. Why Do We Use These Functions?

### Use `getFieldValue()` when:

- You need a field's underlying value.
- You want to compare values in JavaScript.
- You need a value for calculations or conditional logic.
- You do not need Salesforce's localized display formatting.

### Use `getFieldDisplayValue()` when:

- You are presenting data to a user.
- You want Salesforce's formatted representation.
- You are displaying currency, dates, percentages, or other values for which a display representation is available.
- You want the display representation appropriate to the user's locale and org settings.

## 8. Important Points to Remember

1. Both functions are imported from `lightning/uiRecordApi`.
2. Both functions work with record data returned by supported UI API/LDS record operations, such as `getRecord`.
3. The first argument is the record response; the second argument is the field reference.
4. `getFieldValue()` returns the raw value.
5. `getFieldDisplayValue()` returns a formatted display value when available.
6. A display value is not guaranteed for every field.
7. The field must be included in the record request and accessible to the current user.
8. Use schema imports such as `@salesforce/schema/Account.Name` where possible.
9. These helper functions read values; they do not update Salesforce records.
10. `getRecord` uses Lightning Data Service/UI API, so a separate Apex query is not required for this example.

## 9. Deployment and Testing Steps

1. Open your Salesforce DX project in VS Code.
2. Navigate to `force-app/main/default/lwc`.
3. Create an LWC named `getRecordDemo`.
4. Add these three files:
   - `getRecordDemo.html`
   - `getRecordDemo.js`
   - `getRecordDemo.js-meta.xml`
5. Copy the relevant code from this README into each file.
6. Save the files.
7. Right-click the component folder and select **SFDX: Deploy This Source to Org**.
8. In Salesforce, open an Account record.
9. Select **Setup → Edit Page** to open the Account Lightning Record Page in Lightning App Builder.
10. Find `getRecordDemo` under Custom Components.
11. Drag the component onto the page.
12. Save and activate the page if required.
13. Open an Account record and verify the Name, Owner, and Annual Revenue values.

## 10. Troubleshooting

| Problem | Possible solution |
|---|---|
| No values appear | Confirm that the component is on a record page and `recordId` is populated. |
| `getRecord` returns an error | Check the record ID, object permissions, field-level security, and browser console. |
| A field value is undefined | Confirm that the field was requested and is accessible to the current user. |
| Owner name is missing | Verify the Owner relationship field reference and access. |
| Annual Revenue is not formatted | Check whether a display value is available; use `getFieldValue()` as a fallback. |
| Component does not appear in Lightning App Builder | Verify `isExposed` and the `lightning__RecordPage` target in the XML file. |
| Invalid field error | Check the schema import and field API name. |

## 11. Interview Questions and Answers

### Q1. What is `getFieldValue()` in LWC?
It is a helper function from `lightning/uiRecordApi` that reads the raw value of a specified field from a record response.

### Q2. What is `getFieldDisplayValue()`?
It is a helper function from `lightning/uiRecordApi` that returns the formatted display value of a field when one is available.

### Q3. From which module are these functions imported?
```javascript
import {
    getFieldValue,
    getFieldDisplayValue
} from 'lightning/uiRecordApi';
```

### Q4. What is the difference between `getFieldValue()` and `getFieldDisplayValue()`?
`getFieldValue()` returns the raw value. `getFieldDisplayValue()` returns the formatted display value when available.

### Q5. Do these functions retrieve the record by themselves?
No. They read values from a record response. In this example, `getRecord` retrieves the record and the helper functions read its fields.

### Q6. What are the parameters of `getFieldValue()`?
It accepts the record response and a field reference:
```javascript
getFieldValue(record, field);
```

### Q7. What are the parameters of `getFieldDisplayValue()`?
It accepts the record response and a field reference:
```javascript
getFieldDisplayValue(record, field);
```

### Q8. Why do we use schema imports?
Schema imports provide references to Salesforce objects and fields. They help with validation, dependency tracking, and safe renaming.

### Q9. Why is `getFieldDisplayValue()` useful for currency fields?
It can return a formatted currency value, including separators and currency formatting appropriate to the org/user settings.

### Q10. Can `getFieldDisplayValue()` return undefined?
Yes. A formatted display value is not available for every field or response. Use `getFieldValue()` as a fallback when appropriate.

### Q11. What does the `??` operator do in the example?
It is the nullish coalescing operator. It uses the fallback expression only when the value on the left is `null` or `undefined`.

### Q12. What is the purpose of `getRecord`?
It retrieves a Salesforce record and requested fields through Lightning Data Service/UI API.

### Q13. What is the purpose of `@api recordId`?
It exposes the record ID property so Salesforce can provide the current record's ID when the component is placed on a record page.

### Q14. Do these helper functions update records?
No. They only read values from the record response. Use `updateRecord` or another supported record update mechanism to modify a record.

### Q15. Do we need Apex to use these helper functions?
No. For supported objects and fields, `getRecord` and these helpers can retrieve and read data through LDS/UI API without an Apex controller.

### Q16. What happens if a field is not included in the `getRecord` request?
The field value will not be available in the response for the helper to read. Include the field in the `fields` or supported layout configuration.

### Q17. What is the difference between a raw value and a display value?
A raw value is the underlying data returned for a field. A display value is its user-facing formatted representation, when available.

### Q18. When would you choose `getFieldValue()` instead of `getFieldDisplayValue()`?
Choose `getFieldValue()` for calculations, comparisons, and business logic that needs the underlying value. Choose `getFieldDisplayValue()` when you need the formatted value for presentation.
