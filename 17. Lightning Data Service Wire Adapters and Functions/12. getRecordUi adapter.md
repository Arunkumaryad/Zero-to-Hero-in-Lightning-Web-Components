# `getRecordUi` Wire Adapter in Lightning Web Components

## 1. Overview

This folder demonstrates Salesforce's `getRecordUi` wire adapter in a Lightning Web Component (LWC). The supplied example retrieves an Account record's UI data and displays Account Number, Annual Revenue, Account Name, and Phone.

## 2. Definition From the Screenshot

> **getRecordUi** — Use this wire adapter to get layout information, metadata, and data to build UI for one or more records.

The screenshot defines these parameters:

- **recordIds** — IDs of records to load.
- **layoutType** — Supports two values: Compact or Full.
- **Modes** — Used with layout. Values are Create, Edit, and View (default).
- **optionalFields** — A field name or an array of field names. If a field is accessible to the user, it is included in the response; otherwise, the adapter does not throw an error for that inaccessible optional field.

> **Current API note:** `getRecordUi` is a legacy/deprecated UI API adapter in current Salesforce guidance. For new LWC development, prefer `getRecord` for record data and the appropriate metadata adapters separately. Verify the current status in the Salesforce reference for your target release.

## 3. What Is `getRecordUi`?

`getRecordUi` is a UI API wire adapter that provides a combined response containing record data, layout information, and object metadata. It was designed to help components construct a record interface using Salesforce layout configuration.

## 4. Syntax From the Screenshot

```javascript
import { LightningElement, wire } from 'lwc';
import { getRecordUi } from 'lightning/uiRecordApi';

export default class Example extends LightningElement {
    @wire(getRecordUi, {
        recordIds: string | string[],
        layoutTypes: string | string[],
        modes: string | string[],
        optionalFields?: string | string[]
    })
    propertyOrFunction;
}
```

The type notation above explains the parameter types; it is not literal JavaScript to paste into a component.

## 5. Parameters Explained

| Parameter | Description |
|---|---|
| `recordIds` | A record ID or an array of record IDs to load. |
| `layoutTypes` | Layout type or types to retrieve, such as `Compact` or `Full`. |
| `modes` | Layout mode or modes: `Create`, `Edit`, or `View`. |
| `optionalFields` | Optional field API name or names. An inaccessible optional field does not by itself cause the request to fail. |

The screenshot uses the plural configuration names `layoutTypes` and `modes`. Do not confuse them with similarly named parameters in other UI API adapters.

## 7. Complete Example Based on the Screenshots

### JavaScript — `getRecordUiDemo.js`

```javascript
import { LightningElement, wire, api } from 'lwc';
import { getRecordUi } from 'lightning/uiRecordApi';

export default class GetRecordUiDemo extends LightningElement {
    formFields = [
        { fieldName: 'AccountNumber', label: 'Account Number' },
        { fieldName: 'AnnualRevenue', label: 'Annual Revenue' },
        { fieldName: 'Name', label: 'Account Name' },
        { fieldName: 'Phone', label: 'Phone' }
    ];

    @api recordId;
    error;

    @wire(getRecordUi, {
        recordIds: '$recordId',
        layoutTypes: ['Full'],
        modes: ['View']
    })
    accountRecordUiHandler({ data, error }) {
        if (data && data.records && data.records[this.recordId]) {
            const record = data.records[this.recordId];

            this.formFields = this.formFields.map((item) => {
                const field = record.fields[item.fieldName];
                return {
                    ...item,
                    value: field ? (field.displayValue ?? field.value) : ''
                };
            });
            this.error = undefined;
            console.log('getRecordUi response:', data);
        } else if (error) {
            this.error = error;
            console.error('getRecordUi error:', error);
        }
    }
}
```

The screenshot's original mapping reads `.value` directly. This version prefers `displayValue` when Salesforce supplies it, then falls back to the raw `value`.

## 8. Code Explanation

1. **Imports:** `LightningElement` is the component base class, `wire` connects the component to a data source, and `api` exposes a public property. `getRecordUi` is imported from `lightning/uiRecordApi`.
2. **Field configuration:** `formFields` lists the field API names and labels to display.
3. **Record ID:** `@api recordId` receives the current record ID when the component is placed on a record page.
4. **Wire configuration:** `$recordId` makes the configuration reactive; `layoutTypes: ['Full']` requests the Full layout; `modes: ['View']` requests View mode.
5. **Response:** `data.records` is keyed by record ID. The code selects the current record and reads the requested fields.
6. **Mapping:** `map()` creates a display array, retaining each label and adding its field value. `...item` is the JavaScript spread operator.
7. **Template:** `for:each` renders each field. `key` gives each repeated element a stable identifier.

## 10. Troubleshooting

| Problem | What to check |
|---|---|
| `recordId` is undefined | Confirm the component is on a Lightning Record Page and `@api recordId` is declared. |
| No record data appears | Check the wire response, browser console, and record ID. |
| A field is blank | Confirm the field API name and the user's field-level access. |
| `data.records[this.recordId]` is undefined | Confirm the ID matches a key in the response and data has loaded. |
| Component is missing in App Builder | Check `isExposed` and the `lightning__RecordPage` target. |
| Adapter is unavailable/deprecated | Check current Salesforce documentation and use recommended record-data APIs for new work. |

## 11. Modern Alternative: `getRecord`

For new development, Salesforce recommends `getRecord` for record data instead of starting new work with the legacy `getRecordUi` adapter. Example:

```javascript
import { LightningElement, api, wire } from 'lwc';
import { getRecord, getFieldValue } from 'lightning/uiRecordApi';
import ACCOUNT_NUMBER_FIELD from '@salesforce/schema/Account.AccountNumber';
import ANNUAL_REVENUE_FIELD from '@salesforce/schema/Account.AnnualRevenue';
import ACCOUNT_NAME_FIELD from '@salesforce/schema/Account.Name';
import PHONE_FIELD from '@salesforce/schema/Account.Phone';

const FIELDS = [
    ACCOUNT_NUMBER_FIELD,
    ANNUAL_REVENUE_FIELD,
    ACCOUNT_NAME_FIELD,
    PHONE_FIELD
];

export default class AccountRecordDetails extends LightningElement {
    @api recordId;
    record;
    error;

    @wire(getRecord, { recordId: '$recordId', fields: FIELDS })
    wiredAccount({ data, error }) {
        if (data) {
            this.record = data;
            this.error = undefined;
        } else if (error) {
            this.error = error;
            this.record = undefined;
        }
    }

    get accountNumber() {
        return getFieldValue(this.record, ACCOUNT_NUMBER_FIELD);
    }
    get annualRevenue() {
        return getFieldValue(this.record, ANNUAL_REVENUE_FIELD);
    }
    get accountName() {
        return getFieldValue(this.record, ACCOUNT_NAME_FIELD);
    }
    get phone() {
        return getFieldValue(this.record, PHONE_FIELD);
    }
}
```

Use `getObjectInfo` for object metadata and `getPicklistValues` / `getPicklistValuesByRecordType` for picklist metadata. This separates record retrieval from UI construction.

## 12. Interview Questions and Answers

### Q1. What is `getRecordUi`?
A UI API wire adapter that provides record data together with layout information and metadata to help construct a record UI.

### Q2. From which module is it imported?
```javascript
import { getRecordUi } from 'lightning/uiRecordApi';
```

### Q3. What is `recordIds`?
The record ID or array of record IDs to retrieve.

### Q4. What is `layoutTypes`?
The layout type or types requested, such as `Full` or `Compact`.

### Q5. Which modes are shown in the screenshot?
`Create`, `Edit`, and `View`; the screenshot identifies `View` as the default.

### Q6. What is `optionalFields`?
Additional field API name(s) that can be returned when accessible to the user. An inaccessible optional field does not by itself fail the request.

### Q7. What is the difference between Full and Compact layouts?
They request different Salesforce layout presentations. Full generally contains more record fields, while Compact is a smaller summary-oriented layout.

### Q8. Why is `$recordId` used?
The `$` prefix makes the wire configuration reactive. When the property changes, the wire service provisions data using the new ID.

### Q9. Why is `@api recordId` required?
It exposes a public property through which Salesforce passes the current record ID on a record page.

### Q10. What does the wire function receive?
An object containing `data` and `error`. The component checks which result is available.

### Q11. What is `data.records`?
A collection of returned records keyed by record ID. Each record includes field data and other UI API response information.

### Q12. Why use `data.records[this.recordId]`?
To select the returned record matching the current component's record ID.

### Q13. Why use `map()`?
To create a display array by preserving each field's label and API name and adding its corresponding value.

### Q14. What is the difference between `value` and `displayValue`?
`value` is the underlying field value. `displayValue` is a formatted, user-friendly value when Salesforce provides one.

### Q15. What is Field-Level Security (FLS)?
FLS controls whether a user can view or edit a field. UI API respects the user's access when returning record data.

### Q16. What is the difference between `getRecordUi` and `getRecord`?
`getRecordUi` combines record data with layout information and metadata. `getRecord` focuses on retrieving record data for specified fields.

### Q17. What does `getFieldValue` do?
It extracts a field's raw value from a record response returned by `getRecord`.

### Q18. Why prefer schema imports over hard-coded field strings?
Schema imports provide stronger compile-time checking and help Salesforce track field dependencies during deployment and refactoring.

### Q19. What does `lightning__RecordPage` do?
It makes the component available for placement on Lightning Record Pages in Lightning App Builder.

### Q20. Is `getRecordUi` recommended for new development?
Prefer `getRecord` for record data and the appropriate metadata adapters separately. Check Salesforce's latest reference for the exact deprecation status.
