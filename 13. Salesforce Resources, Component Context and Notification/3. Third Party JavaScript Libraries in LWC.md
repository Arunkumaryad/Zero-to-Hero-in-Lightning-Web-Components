# Third Party JavaScript Libraries in LWC

## Overview

This project demonstrates how to use a **third-party JavaScript library in Lightning Web Components (LWC)** by uploading the library as a Salesforce **Static Resource** and loading it with `lightning/platformResourceLoader`.

The training example uses **Moment.js** to format the current date.

### Flow

```text
Third-Party JavaScript Library
        ↓
    Static Resource
        ↓
      moment.zip
        ↓
@salesforce/resourceUrl
        ↓
platformResourceLoader
        ↓
     loadScript()
        ↓
   Moment.js loaded
        ↓
moment().format('LLLL')
        ↓
    Date displayed
```

---

## 1. What is a Third-Party JavaScript Library?

A **third-party JavaScript library** is reusable JavaScript functionality created and maintained outside your own application's code.

Examples include libraries for:

- Date/time handling
- Charts
- Data visualization
- Rich text editing
- Utility functions
- File processing
- Other specialized functionality

In this example, **Moment.js** is used for date formatting.

---

## 2. Why Use a Third-Party Library?

A library can provide ready-made functionality instead of requiring developers to implement everything themselves.

For example:

```javascript
moment().format('LLLL')
```

can produce a readable long date/time such as:

```text
Friday, October 9, 2026 12:26 AM
```

The actual output depends on the current date/time.

## 5. Why Use a ZIP File?

A third-party library can contain multiple files. A ZIP lets you package the library and its related files as one Static Resource.

Example:

```text
moment.zip
└── moment/
    └── moment.min.js
```

Therefore the code can reference:

```javascript
MOMENT + '/moment/moment.min.js'
```

**Important:** The path must match the actual structure inside your ZIP file.

## 8. `loadScript()` Syntax

The training screenshot shows:

```javascript
loadScript(Reference to the component, fileUrl): Promise
```

Practical example:

```javascript
loadScript(
    this,
    MOMENT + '/moment/moment.min.js'
)
```

### Parameters

**First parameter**

```javascript
this
```

References the current LWC component.

**Second parameter**

```javascript
MOMENT + '/moment/moment.min.js'
```

Specifies the JavaScript file inside the Static Resource.

### Return value

`loadScript()` returns a **Promise**.

Therefore we can use:

```javascript
.then()
.catch()
```

## 9. Complete JavaScript from the Training Example

```javascript
import { LightningElement } from 'lwc';

import MOMENT from '@salesforce/resourceUrl/moment';

import { loadScript }
    from 'lightning/platformResourceLoader';

export default class ThirdPartyFiles extends LightningElement {

    currentDate = '';
    isLibLoaded = false;

    renderedCallback() {

        if (this.isLibLoaded) {
            return;
        } else {

            Promise.all([
                loadScript(
                    this,
                    MOMENT + '/moment/moment.min.js'
                )
            ])
            .then(() => {

                // success
                this.setDateOnScreen();

            })
            .catch(error => {

                console.error(error);

            });

            this.isLibLoaded = true;
        }
    }

    setDateOnScreen() {

        this.currentDate =
            moment().format('LLLL');

    }
}
```

---

## 11. Why `renderedCallback()`?

`renderedCallback()` is an LWC lifecycle hook that runs after the component has rendered.

The example uses it to start loading the external library.

Because lifecycle hooks can execute more than once, a guard is required:

```javascript
if (this.isLibLoaded) {
    return;
}
```

The idea is:

```text
First render
    ↓
Library not loaded
    ↓
loadScript()
    ↓
Library loaded
    ↓
isLibLoaded = true
    ↓
Later renders
    ↓
return
```

---

## 12. `Promise.all()`

The training code uses:

```javascript
Promise.all([
    loadScript(
        this,
        MOMENT + '/moment/moment.min.js'
    )
])
```

`Promise.all()` waits for all supplied Promises to complete.

It is especially useful when several resources must be loaded:

```javascript
Promise.all([
    loadScript(this, JS_FILE),
    loadStyle(this, CSS_FILE)
])
.then(() => {
    // All resources loaded
})
.catch(error => {
    console.error(error);
});
```

---

## 13. `.then()` and `.catch()`

### Success

```javascript
.then(() => {
    this.setDateOnScreen();
})
```

Runs after the library loads successfully.

### Error

```javascript
.catch(error => {
    console.error(error);
});
```

Handles loading failures.

Possible causes include:

- Incorrect Static Resource name
- Incorrect file path
- Missing JavaScript file
- Invalid ZIP structure
- Resource loading error

# Interview Preparation

## Q1. How do you use a third-party JavaScript library in LWC?

Upload it as a Static Resource, import the resource with `@salesforce/resourceUrl`, use `loadScript()` from `lightning/platformResourceLoader`, wait for the Promise to resolve, and then use the library.

---

## Q2. What is `lightning/platformResourceLoader`?

It is a Salesforce LWC module that provides `loadScript()` and `loadStyle()` for loading JavaScript and CSS from Static Resources.

---

## Q3. What is `loadScript()`?

`loadScript()` loads a JavaScript file from a Static Resource and returns a Promise.

```javascript
loadScript(this, fileUrl)
```

---

## Q4. What is `loadStyle()`?

`loadStyle()` loads a CSS file from a Static Resource and returns a Promise.

```javascript
loadStyle(this, fileUrl)
```

---

## Q5. Why use `renderedCallback()`?

It runs after the component has rendered and can be used to initiate loading of external JavaScript/CSS resources. Since it may execute multiple times, use a guard to prevent duplicate loading.

---

## Q6. Why use a Boolean flag?

Example:

```javascript
if (this.isLibLoaded) {
    return;
}
```

It prevents the same library from being loaded repeatedly.

---

## Q7. What does `loadScript()` return?

A Promise.

Therefore:

```javascript
.then()
.catch()
```

can be used.

---

## Q8. Why use `Promise.all()`?

It allows multiple asynchronous resource-loading operations to be handled together and continues when all have completed.

---

## Q9. What is `@salesforce/resourceUrl`?

It is an LWC scoped module used to reference a Salesforce Static Resource.

---

## Q10. Why upload a third-party library as a Static Resource?

It provides a Salesforce-managed way to store and load reusable JavaScript/CSS resources.

---

## Q11. What happens if `loadScript()` fails?

The Promise is rejected and the `.catch()` block can handle the error.

```javascript
.catch(error => {
    console.error(error);
});
```

---

## Q12. Why must the ZIP path be correct?

`loadScript()` needs the exact path to the JavaScript file inside the Static Resource.

# Common Mistakes

### 1. Wrong resource name

Correct:

```javascript
import MOMENT
    from '@salesforce/resourceUrl/moment';
```

### 2. Wrong ZIP path

If the ZIP contains:

```text
moment/moment.min.js
```

use:

```javascript
MOMENT + '/moment/moment.min.js'
```

### 3. Calling the library too early

Do not call:

```javascript
moment()
```

before `loadScript()` finishes.

Correct:

```javascript
loadScript(...)
    .then(() => {
        this.currentDate =
            moment().format('LLLL');
    });
```

### 4. No loading guard

Without a guard, `renderedCallback()` can initiate repeated loads.

Use:

```javascript
if (this.isLibLoaded) {
    return;
}
```

### 5. No error handling

Use:

```javascript
.catch(error => {
    console.error(error);
});
```

# Troubleshooting Checklist

If the library does not work, check:

```text
1. Static Resource exists.
2. Static Resource name is correct.
3. ZIP is valid.
4. JS file exists inside ZIP.
5. Path inside ZIP is correct.
6. loadScript() is imported correctly.
7. `this` is passed as the first parameter.
8. Library is used only after successful loading.
9. Duplicate loading is prevented.
10. Browser console has no errors.
11. Component is deployed to the correct org.
12. Component is exposed to the required Lightning target.
```

# Best-Practice Version

For production code, it is preferable to mark the library as loaded only after `loadScript()` succeeds:

```javascript
renderedCallback() {

    if (this.isLibLoaded) {
        return;
    }

    loadScript(
        this,
        MOMENT + '/moment/moment.min.js'
    )
    .then(() => {

        this.isLibLoaded = true;

        this.setDateOnScreen();

    })
    .catch(error => {

        console.error(
            'Unable to load Moment.js:',
            error
        );

    });
}
```

This is safer than setting:

```javascript
this.isLibLoaded = true;
```

before the asynchronous load has completed.
