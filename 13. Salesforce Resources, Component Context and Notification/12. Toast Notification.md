# Toast Notifications in Salesforce Lightning Web Components (LWC)

## Overview
A **toast notification** is a short popup message used to give a user feedback about an action or event in Salesforce. Toasts can communicate success, an error, information, or a warning.

This README documents the `ShowToastNotification` LWC shown in the training screenshots. It includes the screenshot definitions, code, explanations, setup instructions, examples, and interview questions.

## 1. Actual Definition from the Screenshot

The screenshot defines a toast as:

> **“Toast is a popup that alert user with some information. Toast can be of success, error, info or warning.”**

In simple words, a toast is a temporary message that appears in the Salesforce UI to tell a user what happened—for example, whether a record was saved successfully or an error occurred.

## 2. `ShowToastEvent` Syntax from the Screenshot

```javascript
import { ShowToastEvent } from 'lightning/platformShowToastEvent';

const evt = new ShowToastEvent({
    title: "toast title",
    message: "toast message",
    variant: "toast variant" // success, info, warning or error
});
this.dispatchEvent(evt);
```

### Property explanations
- **`title`** — Short heading displayed in the toast.
- **`message`** — Main message displayed in the toast.
- **`variant`** — Determines the toast type: `success`, `info`, `warning`, or `error`.
- **`this.dispatchEvent(evt)`** — Dispatches the event so Salesforce can display the toast.

### Additional options mentioned in the screenshot
- **`messageData`** — URL and label values that replace `{index}` placeholders in the message string.
- **`mode`** — Determines how persistent the toast is:
  1. `dismissible` (default) — Remains visible until the user clicks the close button or three seconds have elapsed, whichever comes first.
  2. `pester` — Visible for three seconds.
  3. `sticky` — Remains visible until the user clicks the close button.

Timing and availability can vary by Salesforce UI/container. Check current Salesforce documentation for the exact behavior in the environment where the component runs.

## 4. JavaScript from the Screenshot

```javascript
import { LightningElement } from 'lwc';
import { ShowToastEvent } from 'lightning/platformShowToastEvent';

export default class ShowToastNotification extends LightningElement {

    toastHandler() {
        this.showToast('Success', '{0} Account Created Successfully {1}', 'success');
    }

    toastHandlerTwo() {
        this.showToast('Error', 'An error occurred while creating the account', 'error');
    }

    toastHandlerThree() {
        this.showToast('Warning', 'This is a warning message', 'warning');
    }

    toastHandlerFour() {
        this.showToast('Info', 'Summer 27 is now Available', 'info');
    }

    showToast(title, message, variant) {
        const event = new ShowToastEvent({
            title: title,
            message: message,
            variant: variant,
            messageData: [
                'Salesforce',
                {
                    url: 'https://www.salesforce.com',
                    label: 'Click Here'
                }
            ]
        });
        this.dispatchEvent(event);
    }
}
```

### Explanation, step by step
1. Import `LightningElement` to create the LWC class.
2. Import `ShowToastEvent` to create a toast event.
3. Each handler calls `showToast()` with a title, message, and variant.
4. `showToast()` creates a `ShowToastEvent` object.
5. `messageData` supplies values for `{0}` and `{1}` in the success message:
   - `{0}` is replaced by `Salesforce`.
   - `{1}` is replaced by a clickable link labelled **Click Here**, pointing to `https://www.salesforce.com`.
6. `dispatchEvent()` sends the event to Salesforce, which renders the toast.

**Note:** The example's success message is illustrative; it does not create an Account record. A real save operation must be implemented separately.

## 7. Deploy and Test Step by Step

1. Open your Salesforce DX project in VS Code.
2. Go to `force-app/main/default/lwc/`.
3. Create a folder named `showToastNotification`.
4. Add the HTML, JavaScript, and metadata XML files.
5. Save all files.
6. Deploy from the project terminal:

   ```bash
   sf project deploy start --source-dir force-app/main/default/lwc/showToastNotification
   ```

7. In Salesforce, open **Setup → Lightning App Builder**.
8. Create or edit a Lightning App Page.
9. Find **Show Toast Notification Demo** in the custom components list.
10. Drag it onto the page, click **Save**, and activate the page if needed.
11. Open the page and click each button.
12. Confirm that the appropriate Success, Error, Warning, or Info toast appears.

| Warning | Warning | `warning` | This is a warning message |
| Info | Info | `info` | Summer 27 is now Available |

The Success toast uses `messageData`, so the message includes `Salesforce` and a clickable **Click Here** link.

## 9. Toast Variants

- **`success`** — Indicates that an action completed successfully.
- **`error`** — Indicates that an action failed or an error occurred.
- **`warning`** — Alerts the user to a potential issue or something requiring attention.
- **`info`** — Shares general information.

Choose the variant that accurately reflects the operation's outcome. Do not display a success toast before an operation has actually succeeded.

## 10. `messageData` and Message Placeholders

```javascript
message: '{0} Account Created Successfully {1}',
messageData: [
    'Salesforce',
    {
        url: 'https://www.salesforce.com',
        label: 'Click Here'
    }
]
```

- `{0}` is replaced with `Salesforce`.
- `{1}` is replaced with the second item, a link labelled `Click Here`.
- `url` specifies the link destination.
- `label` specifies the link text.

`messageData` is useful when a toast message needs a dynamic value or clickable link.

## 11. Toast Modes

| Mode | Meaning in the screenshot |
|---|---|
| `dismissible` | Default mode; the toast can be closed by the user and is also subject to the default timeout described in the screenshot. |
| `pester` | The toast is shown for a short period (three seconds in the screenshot). |
| `sticky` | The toast stays visible until the user closes it. |

To set a mode, add it to the event configuration:

```javascript
const event = new ShowToastEvent({
    title: 'Saved',
    message: 'The record was saved.',
    variant: 'success',
    mode: 'sticky'
});
this.dispatchEvent(event);
```

The screenshot's sample JavaScript does not explicitly set `mode`; it uses the default behavior. Exact behavior may depend on the Salesforce UI/container.

## 12. Important Notes and Best Practices

- A toast communicates feedback; it does not create, update, or delete records by itself.
- Dispatch a success toast only after the save or server operation succeeds.
- Use error toasts to explain failures in user-friendly language.
- Keep titles and messages short and clear.
- Use `messageData` for placeholders and links where useful.
- Choose a variant that matches the actual outcome.
- `lightning/platformShowToastEvent` is supported in many Lightning Experience contexts. In environments such as Lightning Web Runtime or standalone LWR apps, check Salesforce's current guidance because toast support and recommended APIs can differ.
- Use an API version supported by the target org.

# Interview Questions and Answers

## Q1. What is a toast notification in Salesforce?
A toast is a temporary popup message that provides feedback to a user about an action or event.

## Q2. Which event is used to show a toast in this LWC example?
The example imports `ShowToastEvent` from `lightning/platformShowToastEvent`.

## Q3. What are the toast variants?
The variants shown in the training material are `success`, `error`, `warning`, and `info`.

## Q4. What is the purpose of `dispatchEvent()`?
It dispatches the `ShowToastEvent` so Salesforce can display the notification.

## Q5. What is the difference between a toast title and message?
The title is the short heading; the message provides the details.

## Q6. What is `messageData`?
`messageData` provides values that replace indexed placeholders such as `{0}` and `{1}` in the toast message. It can also provide link data.

## Q7. What is the purpose of `variant`?
It determines the type of toast displayed, such as success or error.

## Q8. What are the toast modes?
The screenshot lists `dismissible`, `pester`, and `sticky`. They control how long the toast remains visible and whether the user must dismiss it.

## Q9. Does a success toast create an Account record?
No. A toast only displays a message. Creating the record requires separate logic, such as Lightning Data Service or Apex.

## Q10. How do you show an error toast?
Create a `ShowToastEvent` with an appropriate title, message, and `variant: 'error'`, then dispatch the event.

## Q11. Why show a success toast after saving a record?
Only showing it after a successful save ensures the user receives accurate feedback. If the save fails, display an error instead.

## Q12. What is `lightning__AppPage` in the metadata file?
It exposes the LWC so it can be placed on a Lightning App Page in Lightning App Builder.

## Q13. Can toast notifications contain links?
Yes. The example uses `messageData` with a URL and label to create a link in the toast message.

## Q14. What happens if a toast message is too long?
Long messages are harder to scan and may be truncated or displayed awkwardly depending on the UI. Keep toast messages concise and put detailed errors in a more appropriate UI when necessary.

## Q15. Is a toast a replacement for form validation?
No. Use appropriate field-level validation and error handling for forms. A toast can provide additional summary feedback.

# Scenario-Based Interview Questions

### Scenario 1: Show a message after creating an Account
After the Account creation operation succeeds, dispatch a `ShowToastEvent` with a success variant. If the operation fails, show an error toast instead.

### Scenario 2: Include a clickable link in a toast
Use indexed placeholders in `message`, and provide the corresponding URL and label in `messageData`.

### Scenario 3: Keep an important message visible
Use `mode: 'sticky'` when the user must explicitly close the notification. Avoid using sticky mode for every routine message.

### Scenario 4: Show a warning before the user proceeds
Use the warning variant to communicate a potential issue. If the user must take an action before proceeding, implement validation or confirmation separately; a toast alone does not block the action.

### Scenario 5: The toast does not appear
Check the import path, event configuration, and whether `this.dispatchEvent(event)` runs. Confirm that the current Salesforce UI/container supports the toast API being used.
