# Images from Static Resources

## 📌 Overview

This folder demonstrates how to **upload an image as a Salesforce Static Resource and display that image inside a Lightning Web Component (LWC)**.

The training example uses:

```text
Static Resource Name: User_Image
Description: Image of the User
File: user Image.jpg
Cache Control: Public
```

The LWC imports the Static Resource using:

```javascript
@salesforce/resourceUrl
```

and uses the resulting resource URL in the `<img>` tag.

---

# 1. What is a Static Resource?

## Definition from the training screenshot

> **Import static resources from the `@salesforce/resourceUrl` scoped module. Static resources can be archives (such as `.zip` and `.jar` files), images, style sheets, JavaScript, and other files.**

The syntax shown in the training material is:

```javascript
import myResource from '@salesforce/resourceUrl/resourceReference';
```

### Meaning of the Syntax

The screenshot explains:

```text
myResource
→ A name that refers to the static resource.

resourceReference
→ The name of the static resource.
```

A Static Resource name:

- Can contain only underscores and alphanumeric characters.
- Must be unique in the org.
- Must begin with a letter.
- Must not contain spaces.
- Must not end with an underscore.
- Must not contain two consecutive underscores.

# 4. Static Resource Naming Rules

The training screenshot specifically highlights the naming rules.

### Valid

```text
User_Image
CompanyLogo
My_Image_01
SalesforceLogo
```

### Invalid

```text
User Image
```

❌ Contains a space.

```text
1UserImage
```

❌ Does not begin with a letter.

```text
User_Image_
```

❌ Ends with an underscore.

```text
User__Image
```

❌ Contains two consecutive underscores.

```text
User-Image
```

❌ Contains a hyphen.

# 5. Cache Control

The Static Resource creation page contains a **Cache Control** setting.

The example uses:

```text
Public
```

### Public

The resource can be cached by browsers and other clients.

### Private

The resource is cached only in the current user's browser.

Choose the setting according to the resource's intended caching behavior and sensitivity.

# 10. Understanding the JavaScript

## Import `LightningElement`

```javascript
import { LightningElement } from 'lwc';
```

This imports the base LWC class.

The component extends it:

```javascript
export default class StaticImages
    extends LightningElement {
```

---

## Import the Static Resource

```javascript
import USER_IMAGE
    from '@salesforce/resourceUrl/User_Image';
```

This is the most important line.

The scoped module:

```text
@salesforce/resourceUrl
```

provides a reference/URL to the Static Resource.

Here:

```text
User_Image
```

must match the Salesforce Static Resource name.

---

## Assign the Resource

```javascript
userImage = USER_IMAGE;
```

The imported resource reference is assigned to the LWC property:

```text
userImage
```

That property can then be used in the template.

```javascript

```

is the imported JavaScript variable, while:

```javascript
userImage
```

is the LWC property exposed to the HTML template.

# 12. Why Use `@salesforce/resourceUrl`?

`@salesforce/resourceUrl` is an LWC scoped module used to reference Salesforce Static Resources.

Example:

```javascript
import IMAGE
    from '@salesforce/resourceUrl/User_Image';
```

This is preferable to hardcoding a Salesforce resource URL.

### Benefits

- Salesforce manages the resource URL.
- Better portability between orgs.
- Easier deployment.
- Avoids hardcoded resource paths.
- Follows the LWC resource import pattern.

---

# 13. Resource Name vs JavaScript Variable

Consider:

```javascript
import USER_IMAGE
    from '@salesforce/resourceUrl/User_Image';
```

### `USER_IMAGE`

This is the JavaScript variable.

### `User_Image`

This is the actual Salesforce Static Resource name.

You could also write:

```javascript
import IMAGE_URL
    from '@salesforce/resourceUrl/User_Image';
```

The Salesforce resource is still:

```text
User_Image
```

Only the JavaScript variable changed.

# 20. Static Resource vs Content Asset

| Static Resource | Content Asset |
|---|---|
| Developer-oriented resource | Content-oriented resource |
| Commonly used by code | Commonly used for managed content |
| Can contain JS/CSS/images/files | Used for reusable digital content |
| Referenced using Salesforce resource mechanisms | Accessed through Salesforce content mechanisms |

For this particular example, **Static Resource** is appropriate because the image is directly imported and referenced by LWC code.

---

# 21. Static Resource vs Salesforce Files

| Static Resource | Salesforce Files |
|---|---|
| Developer/application resource | User/business content |
| Used by code/components | Used for document/file management |
| Good for JS/CSS/images | Good for business documents |
| Deployed as metadata | Managed as Salesforce Files/content |

# 22. Common Mistakes

## Mistake 1 — Wrong Resource Name

If the Static Resource is:

```text
User_Image
```

this is incorrect:

```javascript
import USER_IMAGE
    from '@salesforce/resourceUrl/UserImage';
```

Correct:

```javascript
import USER_IMAGE
    from '@salesforce/resourceUrl/User_Image';
```

---

## Mistake 2 — Using Spaces

Do not create:

```text
User Image
```

Use:

```text
User_Image
```

---

## Mistake 3 — Wrong HTML Property

JavaScript:

```javascript
userImage = USER_IMAGE;
```

HTML:

```html
<img src={userImage}>
```

The template should use the component property.

---

## Mistake 4 — Forgetting to Expose the Component

If you want the LWC available in Lightning App Builder:

```xml
<isExposed>true</isExposed>
```

and:

```xml
<target>lightning__AppPage</target>
```

are required.

# 24. Interview Questions

## Q1. What is a Static Resource?

**Answer:** A Static Resource is a Salesforce resource used to store reusable files such as images, JavaScript, CSS, ZIP archives, JAR files, and other static content.

## Q2. How do you access a Static Resource in LWC?

```javascript
import RESOURCE
    from '@salesforce/resourceUrl/ResourceName';
```

## Q3. What is `@salesforce/resourceUrl`?

It is an LWC scoped module used to reference a Salesforce Static Resource and obtain its resource URL/reference.

## Q4. What types of files can be stored?

```text
Images
CSS
JavaScript
ZIP files
JAR files
Other static files
```

## Q5. What is the difference between `USER_IMAGE` and `User_Image`?

```text
USER_IMAGE
→ JavaScript variable

User_Image
→ Salesforce Static Resource name
```

## Q6. What are Static Resource naming rules?

The name:

- Must be unique.
- Must start with a letter.
- Can contain alphanumeric characters and underscores.
- Cannot contain spaces.
- Cannot end with an underscore.
- Cannot contain consecutive underscores.

## Q7. Can Static Resources contain multiple files?

Yes. A ZIP archive can contain multiple files.

For example:

```text
MyLibrary.zip
├── js/
│   └── library.js
├── css/
│   └── library.css
└── images/
    └── logo.png
```

The Static Resource can be imported and the required file can be referenced by its path.

## Q8. How do you display an image from a Static Resource?

```javascript
import IMAGE
    from '@salesforce/resourceUrl/User_Image';

userImage = IMAGE;
```

Then:

```html
<img src={userImage} alt="User Image">
```

## Q9. What is Cache Control?

Cache Control determines how Salesforce Static Resource content is cached.

The common options are:

```text
Public
Private
```

## Q10. Why avoid hardcoding a resource URL?

Because Salesforce manages the resource reference, making the component easier to deploy and move between environments.
