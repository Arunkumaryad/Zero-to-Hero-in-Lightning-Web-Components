# Fetch Record ID and Object API Name in Salesforce LWC

## Overview

This README explains how to get the current record's ID and the current object's API name in a Lightning Web Component (LWC) placed on a Lightning record page.

The examples are based on the provided training screenshots and include the original definitions, code explanations, setup steps, output, best practices, and interview questions.

## 1. Actual Definitions from the Screenshot

The screenshot gives these definitions:

> **`@api recordId`** — If a component with a `recordId` property is used on a Lightning record page, the page sets the property to the ID of the current record.

> **`@api objectApiName`** — If a component with an `objectApiName` property is used on a Lightning record page, the page sets the property to the API name of the current object.

### In simple words

- **`recordId`** contains the ID of the record currently open, such as a particular Account, Contact, or Opportunity.
- **`objectApiName`** contains the API name of the object for that record, such as `Account`, `Contact`, or `Opportunity`.
- **`@api`** makes a property public so Salesforce or a parent component can provide its value.

For example, when this component is placed on an Account record page, Salesforce supplies that Account's record ID and the object API name `Account`.

## 2. JavaScript Code from the Screenshot

```javascript
import { LightningElement, api } from 'lwc';

export default class RecordIdAndObjectName extends LightningElement {
    @api recordId;
    @api objectApiName;
}
```

### Explanation

- `import { LightningElement, api } from 'lwc';` imports the base LWC class and the `api` decorator.
- `@api recordId;` declares a public property for the current record ID.
- `@api objectApiName;` declares a public property for the current object's API name.
- Salesforce populates these properties when the component is placed in a supported record-page context.

The values are supplied by the Lightning page context; the component does not need to query Salesforce just to obtain these two values.

## 3. HTML Template Code from the Screenshot

```html
<template>
    <lightning-card title="RecordId And ObjectApiName Demo">
        <p><strong>Record Id : </strong>{recordId}</p>
        <p><strong>ObjectAPIName is : </strong>{objectApiName}</p>
    </lightning-card>
</template>
```

### Explanation

- `<template>` contains the component's markup.
- `<lightning-card>` displays a card with a title.
- `{recordId}` displays the current record ID supplied to the component.
- `{objectApiName}` displays the current object's API name.
- `<strong>` makes the labels bold.

The screenshot's output shows an Account record ID and `Account` as the object API name. Your record ID will differ.

## 4. Component Metadata XML from the Screenshot

The screenshot uses API version `67.0` and exposes the component for Lightning record pages:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<LightningComponentBundle xmlns="http://soap.sforce.com/2006/04/metadata">
    <apiVersion>67.0</apiVersion>
    <isExposed>true</isExposed>
    <targets>
        <target>lightning__RecordPage</target>
    </targets>
</LightningComponentBundle>
```

Use an API version supported by your Salesforce org. `67.0` is retained here because it is the version shown in your screenshot.

`lightning__RecordPage` exposes the component so it can be added to Lightning record pages through Lightning App Builder.

## 5. Component Folder Structure

In a Salesforce DX project, create this folder and its three component files:

```text
force-app/main/default/lwc/recordIdAndObjectName/
├── recordIdAndObjectName.html
├── recordIdAndObjectName.js
└── recordIdAndObjectName.js-meta.xml
```

### `recordIdAndObjectName.js`

```javascript
import { LightningElement, api } from 'lwc';

export default class RecordIdAndObjectName extends LightningElement {
    @api recordId;
    @api objectApiName;
}
```

```html
<template>

        <div class="slds-p-around_medium">

        </div>
```

```xml

    <apiVersion>67.0</apiVersion>

        <target>lightning__RecordPage</target>
```

## 6. Deploy and Test Step by Step

1. Open your Salesforce DX project in VS Code.
2. Go to `force-app/main/default/lwc/`.
3. Create a folder named `recordIdAndObjectName`.
4. Create the HTML, JavaScript, and metadata XML files using the code above.
5. Save all files.
6. Deploy the component from your Salesforce DX project terminal:

   ```bash
   sf project deploy start --source-dir force-app/main/default/lwc/recordIdAndObjectName
   ```

7. In Salesforce, open an Account record.
8. Click the gear icon and select **Edit Page**, or open **Setup → Lightning App Builder** and edit the relevant record page.
9. Find **RecordId And ObjectApiName Demo** in the custom components list.
10. Drag it onto the page, then click **Save** and activate the page if needed.
11. Return to the record page and refresh it.
12. Confirm that the component displays the record ID and `Account` as the object API name.
13. Repeat on a Contact or Opportunity record page to see the object API name change.

## 8. When Are These Properties Useful?

Use `recordId` and `objectApiName` when a component needs to know the record context in which it is running. Examples include:

- Showing the current record ID for debugging.
- Loading data related to the record.
- Calling Apex with the current record ID when appropriate.
- Reusing a component across Account, Contact, and Opportunity record pages.
- Applying object-specific UI behavior based on `objectApiName`.

If you call Apex or access record data, ensure the operation respects Salesforce sharing, object permissions, and field-level security.

## 9. Important Notes and Best Practices

- Declare the properties as public using `@api`.
- Salesforce supplies the values when the component is placed in a supported Lightning record-page context.
- `recordId` and `objectApiName` may be undefined outside a context that supplies them.
- The object API name is not the record's label or name. For example, the API name can be `Account`, while the record name can be `Acme Ltd`.
- The record ID identifies one record; the object API name identifies the type of record.
- Do not hardcode record IDs. Use the page-provided value.
- Use an API version supported by your target org.

# Interview Questions and Answers

## Q1. What is `recordId` in LWC?

`recordId` is a public property that receives the ID of the current record when the component is used in a supported Lightning record-page context.

## Q2. What is `objectApiName` in LWC?

`objectApiName` is a public property that receives the API name of the object associated with the current record, such as `Account` or `Contact`.

## Q3. What are the definitions shown in the training screenshot?

- **`@api recordId`:** If a component with a `recordId` property is used on a Lightning record page, the page sets the property to the ID of the current record.
- **`@api objectApiName`:** If a component with an `objectApiName` property is used on a Lightning record page, the page sets the property to the API name of the current object.

## Q4. Why do we use the `@api` decorator?

`@api` makes a property public, allowing a parent component or Salesforce page context to provide its value.

## Q5. Do we need Apex to get the current record ID?

No. In a supported record-page context, Salesforce supplies `recordId`. Apex may be needed for other server-side data or business logic, not simply to obtain this ID.

## Q6. What is the difference between `recordId` and `objectApiName`?

- `recordId` identifies one specific record.
- `objectApiName` identifies the object type to which that record belongs.

For example, an Account record has a particular record ID, while its object API name is `Account`.

## Q7. What does `lightning__RecordPage` do in the metadata file?

It exposes the component so it can be added to Lightning record pages through Lightning App Builder.

## Q8. Will `recordId` always have a value?

No. It is supplied when the component is used in a supported context that provides the current record. Outside such a context, it can be undefined.

## Q9. Can the same component be used on Account and Contact record pages?

Yes, provided its logic supports both objects. `objectApiName` identifies the current object, and `recordId` identifies the current record.

## Q10. Is `objectApiName` the same as the record name?

No. `objectApiName` is the object's API name, such as `Account`. The record name is a field value, such as `Acme Ltd`.

## Q11. How can you use `recordId` to retrieve related data?

Pass the ID to an appropriate UI API wire adapter or Apex method, depending on the requirement. Apply Salesforce security controls and handle loading and error states.

## Q12. Why might the values be blank when testing the component?

Check that the component is placed on a Lightning record page that supplies the context, that the page is saved and activated, and that you opened an actual record page.

## Q13. Why is `@api` used instead of a normal class property?

A normal property is internal to the component by default. `@api` exposes the property publicly so Salesforce or a parent component can set it.

## Q14. Does `recordId` provide the record's field data?

No. It provides the record identifier. Use UI API, Lightning Data Service, or Apex to retrieve the fields you need.

## Q15. What is the purpose of the HTML expression `{recordId}`?

It binds the template to the JavaScript property and displays its current value.

# Scenario-Based Interview Questions

### Scenario 1: Display the current Account ID

Declare `@api recordId;` in JavaScript and display `{recordId}` in the HTML template. Add the component to an Account record page.

### Scenario 2: Use one component for multiple objects

Declare `@api objectApiName;` and use its value to determine the current object context. Make sure the component's data and business logic support each object where it is placed.

### Scenario 3: Pass the record ID to Apex

Use the public `recordId` value as an input to an Apex method when server-side processing is required. Validate the input and enforce sharing and data-access rules on the server.

### Scenario 4: `recordId` is undefined

Verify that the component is on a record page that provides record context. If the component can also be used elsewhere, handle the undefined value rather than assuming it is always present.

# One-Line Interview Definitions

- **`@api`:** Decorator that exposes a public property or method in an LWC.
- **`recordId`:** ID of the current record supplied by a supported record-page context.
- **`objectApiName`:** API name of the object associated with the current record context.
- **`lightning__RecordPage`:** Metadata target for exposing a component on Lightning record pages.
- **Lightning App Builder:** Salesforce tool for configuring Lightning pages and placing components.
- **UI API / Lightning Data Service:** Salesforce capabilities for working with record data from the client.
- **Apex:** Salesforce server-side programming language used for custom business logic and data operations.
