# Custom Labels in Salesforce Lightning Web Components (LWC)

## Overview

This guide explains how to create Salesforce Custom Labels and use them in Lightning Web Components (LWC). Custom Labels store reusable text values that can be translated into supported languages. They help developers build multilingual applications and avoid hard-coding user-facing text in components.

The screenshots demonstrate creating two labels, importing them into an LWC, and displaying their values inside a Lightning card.

## 2. What Is a Custom Label?

A **Custom Label** is a reusable text value stored in Salesforce Setup. Developers can reference it from supported Salesforce technologies, including Lightning Web Components and Apex, rather than hard-coding text in code.

### Why use Custom Labels?

- **Translation:** Display text in a user's supported language.
- **Reusability:** Reuse the same text in multiple components.
- **Maintainability:** Update label text centrally in Salesforce Setup.
- **Consistency:** Keep messages, headings, instructions, and error text consistent across the application.

Examples include button labels, page headings, help messages, confirmation messages, and validation or error messages.

## 3. Create Custom Labels in Salesforce

The screenshots show two labels: `customLabelOne` and `customLabelTwo`.

1. Open **Setup** in Salesforce.
2. Search for **Custom Labels** in Quick Find.
3. Open **Custom Labels** under **User Interface**.
4. Click **New Custom Label**.
5. Enter the label details:
   - **Short Description:** A readable description for administrators.
   - **Name:** The API name used in code, such as `customLabelOne`.
   - **Language:** The language of the default label value.
   - **Value:** The text that should be displayed.
   - **Categories:** Optional categorization for organizing labels.
6. Save the label.
7. Repeat the steps to create `customLabelTwo`.

### Example label values

| Field | Label One | Label Two |
|---|---|---|
| Short Description | `customLabelOne` | `customLabelTwo` |
| Name | `customLabelOne` | `customLabelTwo` |
| Value | A paragraph of sample text | A second paragraph of sample text |

The screenshots use Lorem Ipsum sample paragraphs as the values. For a real application, use meaningful text such as `Welcome to our application` or `Please contact support if you need help`.

**Protected Component:** This option is shown in Setup. Its behavior relates to protecting label access in managed-package scenarios; it is not required for the basic LWC import example.

## 4. Import Custom Labels into LWC

The screenshots show the following JavaScript imports:

```javascript
import { LightningElement } from 'lwc';
import DESCRIPTION_ONE from '@salesforce/label/c.customLabelOne';
import DESCRIPTION_TWO from '@salesforce/label/c.customLabelTwo';
```

`DESCRIPTION_ONE` and `DESCRIPTION_TWO` are local JavaScript names. The references after `@salesforce/label/` identify the actual Salesforce labels.

> If the org has a namespace, use the correct namespace and label API name. In an org without a namespace, the standard form is `@salesforce/label/c.labelName`.

## 5. Code Shown in the Screenshots

### `customLabelDemo.js`

The screenshots first show the labels assigned to separate class properties:

```javascript
import { LightningElement } from 'lwc';
import DESCRIPTION_ONE from '@salesforce/label/c.customLabelOne';
import DESCRIPTION_TWO from '@salesforce/label/c.customLabelTwo';

export default class CustomLabelDemo extends LightningElement {
    descriptionOne = DESCRIPTION_ONE;
    descriptionTwo = DESCRIPTION_TWO;
}
```

**Explanation:**

- `LightningElement` is the base class for an LWC component.
- The two imports retrieve the Salesforce Custom Label values.
- `descriptionOne` and `descriptionTwo` expose the imported text to the HTML template.

### `customLabelDemo.html` — first version shown

```html
<template>
    <lightning-card title="Custom Label Demo">
        <p>{descriptionOne}</p>
    </lightning-card>
</template>
```

This version displays only the first label.

### `customLabelDemo.html` — version showing both labels

The screenshots also show this template:

```html
<template>
    <lightning-card title="Custom Label Demo">
        <p>{LABEL.descriptionOne}</p>
        <br><br>
        <p>{LABEL.descriptionTwo}</p>
    </lightning-card>
</template>
```

This template expects a JavaScript object named `LABEL`. The corresponding JavaScript version shown in the screenshot is:

```javascript
import { LightningElement } from 'lwc';
import DESCRIPTION_ONE from '@salesforce/label/c.customLabelOne';
import DESCRIPTION_TWO from '@salesforce/label/c.customLabelTwo';

export default class CustomLabelDemo extends LightningElement {
    LABEL = {
        descriptionOne: DESCRIPTION_ONE,
        descriptionTwo: DESCRIPTION_TWO
    };
}
```

**Important:** Use one matching pattern. If the JavaScript defines `descriptionOne` and `descriptionTwo` as direct properties, use `{descriptionOne}` and `{descriptionTwo}` in HTML. If the JavaScript defines the `LABEL` object, use `{LABEL.descriptionOne}` and `{LABEL.descriptionTwo}`.

For clarity and maintainability, the complete example below uses the `LABEL` object and displays both labels.

### `customLabelDemo.js-meta.xml`

The screenshots use API version `67.0` and expose the component on a Lightning App Page:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<LightningComponentBundle xmlns="http://soap.sforce.com/2006/04/metadata">
    <apiVersion>67.0</apiVersion>
    <isExposed>true</isExposed>
    <targets>
        <target>lightning__AppPage</target>
    </targets>
</LightningComponentBundle>
```

Use an API version supported by your Salesforce org. `67.0` is the version shown in the training screenshots.

## 8. Translation and Multilingual Applications

Custom Labels support translation through Salesforce translation features. When translations are configured and the user's language is supported, Salesforce can present the translated label value to that user.

A typical workflow is:

1. Create a Custom Label with a default language and value.
2. Enable/configure the required Salesforce translation features, where applicable.
3. Add translations for the supported languages.
4. Ensure users have the appropriate language settings.
5. Reference the label from the LWC using `@salesforce/label`.

Do not create separate hard-coded strings in JavaScript for every language unless there is a specific reason to do so. Custom Labels centralize user-facing text and make translation easier.

## 9. Common Mistakes and Troubleshooting

### Wrong label API name

The import reference must match the label's API name. For example:

```javascript
import DESCRIPTION_ONE from '@salesforce/label/c.customLabelOne';
```

Check the **Name** field in Setup, not only the Short Description or Value.

### Incorrect namespace

The screenshot's general syntax refers to a namespace and label name. In an org without a namespace, use the `c` form shown above. If working with a namespaced package, use the correct namespace.

### Mismatched HTML and JavaScript properties

If JavaScript declares `descriptionOne`, reference `{descriptionOne}`. If JavaScript declares `LABEL.descriptionOne`, reference `{LABEL.descriptionOne}`.

### Label not found during deployment

Check that the label metadata exists in the target org/project and that the import path matches the API name. Deploy required label metadata along with the component when needed.

### Text does not appear translated

Check that the translation exists, the relevant translation features are configured, and the user's language is set appropriately. A label's default language value is shown when no applicable translation is available.

### Using labels for dynamic business data

Custom Labels are for reusable text and translation, not for storing changing business records such as Account names, customer addresses, or transaction amounts. Use Salesforce records for dynamic business data.

# Interview Questions and Answers

## Q1. What is a Custom Label in Salesforce?

A Custom Label is a reusable text value stored in Salesforce that can be referenced in code and translated into supported languages.

## Q2. Why do we use Custom Labels in LWC?

They help avoid hard-coded user-facing text, support translation, improve reuse, and allow administrators to maintain text values centrally.

## Q3. What is the import syntax for a Custom Label in LWC?

```javascript
import labelName from '@salesforce/label/labelReference';
```

For example:

```javascript
import WELCOME_MESSAGE from '@salesforce/label/c.Welcome_Message';
```

The API name in this example must match a real Custom Label in the org.

## Q4. What does `@salesforce/label/c.customLabelOne` mean?

It references the Custom Label with API name `customLabelOne` in the org's standard `c` namespace.

## Q5. What is the difference between Short Description and Name?

**Short Description** helps people understand the label's purpose. **Name** is the API name used to reference the label in code.

## Q6. Can Custom Labels be translated?

Yes. Custom Labels can be translated into languages supported by Salesforce when the required translation features and translations are configured.

## Q7. Can we use Custom Labels in Apex and LWC?

Yes. Custom Labels can be referenced from supported Salesforce technologies, including Apex and Lightning Web Components, using the syntax appropriate to each technology.

## Q8. What is the difference between a Custom Label and a Custom Metadata Type?

A Custom Label stores user-facing text and supports translation. Custom Metadata Types store application configuration records, such as rules, mappings, and settings, that can be deployed as metadata.

## Q9. Why should we avoid hard-coding messages in an LWC?

Hard-coded messages are harder to maintain and translate. Custom Labels allow the text to be reused and localized without changing component code for each translation.

## Q10. What is the purpose of `LABEL = { ... }` in the JavaScript example?

It groups imported label values into one object so the template can access them as `LABEL.descriptionOne` and `LABEL.descriptionTwo`.

## Q11. What happens if a label import uses the wrong API name?

The component may fail to compile or deploy because Salesforce cannot resolve the label reference. Verify the label's API name and namespace.

## Q12. Can a Custom Label store a long paragraph?

Yes, within Salesforce's current label value limit. The training screenshot notes up to 1,000 characters per label; verify current platform limits if designing for a specific org.

## Q13. What is the advantage of centralizing messages in labels?

It improves consistency and makes updates easier. If multiple components use the same label, the shared text can be maintained centrally.

# Scenario-Based Interview Questions

## Scenario 1: Your component must show a welcome message in the user's language

**Solution:** Create a Custom Label, configure translations for the required languages, and import the label into the LWC using `@salesforce/label`.

## Scenario 2: A label import cannot be resolved

**Solution:** Confirm that the label exists, check its API name and namespace, and make sure the relevant label metadata is available in the target org.

## Scenario 3: Two paragraphs must appear in a Lightning card

**Solution:** Import both labels into JavaScript, expose them as properties or through a `LABEL` object, and bind them in the template.

## Scenario 4: An administrator needs to update a help message

**Solution:** Store the message in a Custom Label rather than hard-coding it in the component. The administrator can update the label value in Setup, subject to the org's permissions and deployment process.

## Scenario 5: The label appears in its default language rather than a translation

**Solution:** Verify the translation exists, confirm the translation configuration, and check the user's language settings.

# One-Line Interview Definitions

- **Custom Label:** A reusable Salesforce text value that can be referenced in code and translated.
- **`@salesforce/label`:** The scoped module used by LWC to import Custom Labels.
- **Label API Name:** The identifier used in code to reference a Custom Label.
- **Short Description:** Human-readable information about the label's purpose.
- **Translation:** A language-specific version of a label's text.
- **Multilingual application:** An application that presents suitable translated content to users in different languages.
- **Hard-coded text:** Text written directly in component code rather than maintained as a reusable value.
- **Custom Metadata Type:** A metadata-based way to store deployable application configuration records.
