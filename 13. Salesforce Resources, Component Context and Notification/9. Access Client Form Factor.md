# Access Client Form Factor in Salesforce LWC

## Overview

This README explains how to access the form factor of the client device running Salesforce in a browser using Lightning Web Components (LWC).

The training screenshots demonstrate the `@salesforce/client/formFactor` scoped module, a simple LWC that displays the detected form factor, and a Lightning App Page target.

## 1. Actual Definition from the Screenshot

The screenshot states:

> To access the form factor of the hardware the browser is running on, import the `@salesforce/client/formFactor` scoped module.

### Syntax shown in the screenshot

```javascript
import formFactorPropertyName from '@salesforce/client/formFactor';
```

### Possible values shown in the screenshot

- `Large` — A desktop client.
- `Medium` — A tablet client.
- `Small` — A phone client.

The form factor describes the general device category of the client running Salesforce. It is useful when a component needs to adapt its behavior or presentation for desktop, tablet, or phone users.

## 2. What Is `@salesforce/client/formFactor`?

`@salesforce/client/formFactor` is a Salesforce scoped module that provides the current client form factor as a string. The value can be used in an LWC to tailor the component's behavior or display to the device category.

| Value | Meaning |
|---|---|
| `Large` | Desktop client |
| `Medium` | Tablet client |
| `Small` | Phone client |

The value describes the client form factor recognized by Salesforce; it is not a precise screen-width measurement. Do not use it as a substitute for responsive CSS when the goal is simply to make a layout fit different screen sizes.

## 3. Example from the Training Screenshots

The screenshot's JavaScript code is:

```javascript
import { LightningElement } from 'lwc';
import FORM_FACTOR from '@salesforce/client/formFactor';

export default class FormFactorDemo extends LightningElement {
    formFactor = FORM_FACTOR;
}
```

### Explanation

- `LightningElement` is the base class for an LWC.
- `FORM_FACTOR` imports the client form factor from Salesforce.
- `formFactor = FORM_FACTOR` stores the imported value in a property.
- The template can display that property using `{formFactor}`.

The JavaScript import identifier (`FORM_FACTOR`) is a developer-chosen name. It could be named differently, but uppercase is commonly used for imported constants.

## 4. HTML Code from the Training Screenshot

The screenshot shows:

```html
<template>
    <lightning-card title="Form Factor Demo">
        <p>Form Factor : {formFactor}</p>
    </lightning-card>
</template>
```

### Explanation

- `<template>` is the root template element for an LWC.
- `<lightning-card>` displays a card with the title **Form Factor Demo**.
- `{formFactor}` is a template expression that displays the value assigned in JavaScript.
- In the screenshot's output, the displayed value is `Large`, meaning Salesforce identified the client as a desktop client.

## 5. Component Metadata XML from the Screenshot

The screenshot uses API version `67.0` and exposes the component on a Lightning App Page.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<LightningComponentBundle xmlns="http://soap.sforce.com/2006/04/metadata">
    <apiVersion>67.0</apiVersion>
    <isExposed>true</isExposed>
    <targets>
        <target>lightning__AppPage</target>
    </targets>

```

Use an API version supported by your target Salesforce org. `67.0` is the version shown in the training screenshot.

## 7. Deploy and Test Step by Step

1. Open your Salesforce DX project in VS Code.
2. Navigate to `force-app/main/default/lwc/`.
3. Create a folder named `formFactorDemo`.
4. Create the HTML, JavaScript, and metadata XML files shown above.
5. Save all three files.
6. Deploy the component to your Salesforce org. For example, from the project terminal:

   ```bash
   sf project deploy start
   ```

7. In Salesforce, open **Setup → Lightning App Builder**.
8. Create a new Lightning App Page or edit an existing one.
9. Find **Form Factor Demo** in the custom components list and drag it onto the page.
10. Save and activate the page if needed.
11. Open the page in Salesforce on the desktop, tablet, or phone client to see the reported form factor.

The exact value depends on the Salesforce client and device context. The training screenshot shows `Large`.

## 8. When Is Form Factor Useful?

You might use the form factor when:

- A component should show a compact experience on phones.
- A particular action is better suited to desktop or tablet.
- You want to display a device-specific message.
- You need to choose between two UI approaches based on the recognized client category.

### Example: display a device-specific message

```javascript
import { LightningElement } from 'lwc';
import FORM_FACTOR from '@salesforce/client/formFactor';

export default class DeviceMessage extends LightningElement {
    formFactor = FORM_FACTOR;

    get deviceMessage() {
        if (this.formFactor === 'Small') {
            return 'You are using a phone client.';
        }

        if (this.formFactor === 'Medium') {
            return 'You are using a tablet client.';
        }

        return 'You are using a desktop client.';
    }
}
```

```html
<template>
    <lightning-card title="Device Information">
        <div class="slds-p-around_medium">
            <p>Form factor: {formFactor}</p>
            <p>{deviceMessage}</p>
        </div>
    </lightning-card>
</template>
```

## 9. Best Practices and Important Notes

- Use `@salesforce/client/formFactor` when you need to know Salesforce's recognized client category.
- Use SLDS and responsive CSS for layouts that should adapt naturally to available screen space.
- Do not assume `Large`, `Medium`, or `Small` is a precise screen resolution or viewport width.
- Test in the actual Salesforce clients you support.
- Keep critical business logic and security independent of device form factor.
- The module provides a form-factor value; it does not itself resize the component or make the page responsive.

# Interview Questions and Answers

## Q1. What is form factor in Salesforce LWC?

Form factor identifies the general client device category that Salesforce recognizes, such as desktop, tablet, or phone.

## Q2. Which module is used to access the form factor?

```javascript
import FORM_FACTOR from '@salesforce/client/formFactor';
```

## Q3. What are the possible form factor values?

- `Large` — Desktop client.
- `Medium` — Tablet client.
- `Small` — Phone client.

## Q4. What does `@salesforce/client/formFactor` return?

It provides a string representing the current Salesforce client form factor.

## Q5. How do you display the form factor in an LWC?

Import the module in JavaScript, assign it to a component property, and display the property in the template using `{formFactor}`.

## Q6. Does form factor automatically make an LWC responsive?

No. It only provides the client form-factor value. Use SLDS and responsive CSS to create layouts that adapt to available space.

## Q7. What is the difference between form factor and responsive design?

Form factor identifies the general device category. Responsive design adjusts the layout to fit the available viewport using flexible layouts, SLDS, and CSS.

## Q8. When would you use form factor in a real project?

Use it when the component needs device-specific behavior or content, such as a simplified message or a phone-specific interaction.

## Q9. Is `Large` a screen-width measurement?

No. It is a form-factor category, not an exact measurement of the screen or browser viewport.

## Q10. What does `formFactor = FORM_FACTOR` do?

It stores the imported form-factor string in a JavaScript property so that the template or other component logic can use it.

## Q11. Can the value be used in conditional logic?

Yes. JavaScript can compare the value with `Large`, `Medium`, or `Small` and choose an appropriate behavior or message.

## Q12. What is the purpose of the component metadata XML file?

The `*-meta.xml` file defines component metadata, including whether the component is exposed in the builder and which Salesforce page types can use it.

## Q13. Why should you still use SLDS?

SLDS provides Salesforce design-system styles and responsive layout utilities. Form factor alone does not make a component's layout responsive.

## Q14. Should security depend on form factor?

No. Device category should not be used as an authorization mechanism. Enforce security using Salesforce's access-control features and server-side checks.

## Q15. How can you test form-factor behavior?

Deploy the component and open it in the Salesforce desktop, tablet, and phone experiences you support. Confirm the returned category and test the resulting UI.

# Scenario-Based Interview Questions

### Scenario 1: Show a simpler message on phones

**Approach:** Import `FORM_FACTOR`, compare it with `Small`, and expose a getter that returns the appropriate message. Use responsive styling for the layout itself.

### Scenario 2: The component displays `Large` when you expected a phone

**Approach:** Verify which Salesforce client is running the component, and test within the supported Salesforce phone experience. Do not infer the form factor only from the physical screen size.

### Scenario 3: The page is too wide on a phone

**Approach:** Use SLDS grid and responsive utilities, flexible widths, and appropriate component layout. Form factor can support optional device-specific behavior, but it does not replace responsive styling.

### Scenario 4: A developer wants to hide sensitive data on phones only

**Approach:** Do not rely on form factor for security. Enforce access using permissions, sharing, and server-side authorization. Use form factor only for presentation choices.
