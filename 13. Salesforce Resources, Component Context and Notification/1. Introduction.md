# 1. Images from Static Resources

## Definition

**Static resources are files that you upload to Salesforce so that they can be referenced and used by Lightning components and other Salesforce functionality.**

Static resources can contain:

- Images
- JavaScript files
- CSS files
- ZIP files
- Other static assets

For example:

```text
myResource
├── logo.png
├── icon.png
└── css/
```

---

## Why Use Static Resources?

Static Resources are useful when you want to store reusable files inside Salesforce.

Examples:

```text
Company Logo
Custom JavaScript Library
Custom CSS
Images
Icons
Fonts
```

---

## Upload a Static Resource

Go to:

```text
Setup
→ Static Resources
→ New
```

Provide:

```text
Name
Description
File
Cache Control
```

---

## Use an Image from Static Resource in LWC

Import the resource:

```javascript
import { LightningElement } from 'lwc';
import IMAGE_RESOURCE from '@salesforce/resourceUrl/myResource';

export default class StaticResourceDemo extends LightningElement {

    imageUrl = IMAGE_RESOURCE + '/logo.png';

}
```

HTML:

```html
<template>

    <lightning-card title="Static Resource Image">

        <img
            src={imageUrl}
            alt="Company Logo"
        />

    </lightning-card>

</template>
```

### Flow

```text
Static Resource
      ↓
@salesforce/resourceUrl
      ↓
LWC JavaScript
      ↓
HTML
      ↓
Image
```

# 2. Using Third-Party JavaScript

## Definition

**Third-party JavaScript libraries are external JavaScript libraries that can be uploaded as Static Resources and loaded into an LWC when their functionality is required.**

Examples may include:

```text
Chart libraries
Date libraries
Utility libraries
PDF libraries
Other JavaScript libraries
```

---

## Upload the Library

Example:

```text
Setup
→ Static Resources
→ New
```

Upload:

```text
thirdPartyLibrary.js
```

or a ZIP containing the library.

---

## Load the Library in LWC

Use:

```javascript
import { loadScript } from 'lightning/platformResourceLoader';
import LIBRARY from '@salesforce/resourceUrl/thirdPartyLibrary';
```

Then:

```javascript
renderedCallback() {

    if (this.libraryLoaded) {
        return;
    }

    this.libraryLoaded = true;

    loadScript(
        this,
        LIBRARY
    )
    .then(() => {

        console.log(
            'Library Loaded'
        );

    })
    .catch(error => {

        console.error(
            'Error loading library',
            error
        );

    });
}
```

---

## Why `renderedCallback()`?

The third-party library should be loaded after the component is rendered.

A Boolean flag prevents loading the library repeatedly:

```javascript
if (this.libraryLoaded) {
    return;
}
```

# 3. Using Third-Party CSS Library

## Definition

**Third-party CSS libraries can be uploaded as Static Resources and loaded into an LWC when external styling functionality is required.**

Examples:

```text
Custom CSS Framework
Animation Library
UI Styling Library
```

---

## Load CSS

Import:

```javascript
import { loadStyle } from 'lightning/platformResourceLoader';
import CSS_LIBRARY from '@salesforce/resourceUrl/myCssLibrary';
```

Then:

```javascript
renderedCallback() {

    if (this.cssLoaded) {
        return;
    }

    this.cssLoaded = true;

    loadStyle(
        this,
        CSS_LIBRARY
    )
    .then(() => {

        console.log(
            'CSS Loaded'
        );

    })
    .catch(error => {

        console.error(
            error
        );

    });
}
```

---

## JavaScript vs CSS Resource Loader

| Requirement | API |
|---|---|
| Load JavaScript | `loadScript()` |
| Load CSS | `loadStyle()` |

Both are imported from:

```javascript
lightning/platformResourceLoader
```

# 4. Access Content Asset Files

## Definition

**Content Assets allow files such as images, documents, and other assets to be stored and reused in Salesforce experiences and Lightning applications.**

Content Assets can be managed from:

```text
Setup
→ Digital Experiences / Salesforce CMS / Content Assets
```

The exact setup location can depend on the Salesforce features enabled in the org.

---

## Difference Between Static Resources and Content Assets

| Static Resource | Content Asset |
|---|---|
| Developer-oriented resources | Content-oriented assets |
| JS/CSS/images/files | Images/files/content |
| Commonly used by code | Commonly used by UI/content |
| Imported with resource URL APIs | Accessed through supported Salesforce content mechanisms |

# 5. Internationalization

## Definition

**Internationalization is the process of designing an application so that it can support different languages, locales, number formats, date formats, currencies, and regional settings.**

Common internationalization requirements include:

```text
Language
Date
Time
Currency
Number format
Locale
```

For example:

```text
India
₹1,00,000

United States
$100,000

Europe
€100,000
```

---

## Why Internationalization Matters

A Salesforce application may be used by users from different countries.

Instead of hardcoding:

```javascript
"Hello"
```

you can design the application to support localized values.

Salesforce also provides internationalization-related features and browser/user locale information.

# 6. Access Labels

This topic refers to **Salesforce Custom Labels**.

## Definition

**Custom Labels are reusable text values that can be accessed from Salesforce code and components, and they can support translation for different languages.**

Custom Labels are useful for:

```text
Messages
Error text
Button labels
Instructions
UI text
Notifications
```

---

## Create a Custom Label

Go to:

```text
Setup
→ Custom Labels
→ New Custom Label
```

Example:

```text
Name:
Welcome_Message

Value:
Welcome to Salesforce
```

---

## Access Custom Label in LWC

Import it:

```javascript
import WELCOME_MESSAGE
    from '@salesforce/label/c.Welcome_Message';
```

Then:

```javascript
welcomeMessage = WELCOME_MESSAGE;
```

HTML:

```html
<template>

    <lightning-card>

        <p>{welcomeMessage}</p>

    </lightning-card>

</template>
```

---

## Why Use Custom Labels?

Avoid hardcoding:

```javascript
welcomeMessage = 'Welcome to Salesforce';
```

Instead use:

```javascript
import WELCOME_MESSAGE
    from '@salesforce/label/c.Welcome_Message';
```

Benefits:

- Reusable
- Centralized
- Easier maintenance
- Translation support
- Better application configuration

# 7. Permission Check

## Definition

**Permission checks are used to determine whether the current user has access to a particular Salesforce object, field, feature, or custom permission before displaying or performing an operation.**

This is important for:

```text
Security
User experience
Conditional UI
Business logic
```

---

## Custom Permission in LWC

A Custom Permission can be referenced in LWC.

Example:

```javascript
import HAS_ACCESS
    from '@salesforce/customPermission/My_Custom_Permission';
```

Then:

```javascript
if (HAS_ACCESS) {

    console.log(
        'User has permission'
    );

} else {

    console.log(
        'User does not have permission'
    );
}
```

---

## Important Point

A UI permission check should not be considered a replacement for server-side security.

Salesforce security should still be enforced through appropriate:

```text
Object permissions
Field-Level Security
Sharing
CRUD/FLS checks
Apex security
```

# 8. Get Current User Information

## Definition

**The current user information feature allows an LWC to access information about the user who is currently running the component.**

A common approach is:

```javascript
import USER_ID
    from '@salesforce/user/Id';
```

Example:

```javascript
import { LightningElement } from 'lwc';
import USER_ID from '@salesforce/user/Id';

export default class CurrentUserDemo
    extends LightningElement {

    userId = USER_ID;

}
```

HTML:

```html
<template>

    <lightning-card title="Current User">

        <p>
            Current User Id:
            {userId}
        </p>

    </lightning-card>

</template>
```

---

## Getting More User Information

If you need fields such as:

```text
Name
Email
Profile
Department
Title
```

you can retrieve the required user record fields through appropriate Salesforce APIs such as:

```text
UI API
LDS
Apex
```

For example, with LDS:

```javascript
import { getRecord } from 'lightning/uiRecordApi';
import USER_ID from '@salesforce/user/Id';
```

# 9. Access Client Form Factor

## Definition

**Client form factor identifies the type of device or client on which the Lightning component is being displayed.**

Common form factors include:

```text
Large
Medium
Small
```

This can be used to build responsive or device-specific behavior.

---

## Example

```javascript
import FORM_FACTOR
    from '@salesforce/client/formFactor';
```

Then:

```javascript
if (FORM_FACTOR === 'Small') {

    console.log(
        'Mobile Device'
    );

} else if (FORM_FACTOR === 'Medium') {

    console.log(
        'Tablet Device'
    );

} else {

    console.log(
        'Desktop / Large Device'
    );
}
```

---

## Why Use Form Factor?

You may want to change:

```text
Layout
Number of columns
Buttons
Navigation
Information displayed
```

depending on the user's device.

# 10. Fetch Record Id and Object Name

This is especially important when an LWC is placed on a Salesforce Record Page.

## Definition

**A record-aware LWC can receive the current record ID through the `recordId` property, and Salesforce can provide the current object's information through the appropriate UI API or page context.**

---

## Get Record Id

Use:

```javascript
import { LightningElement, api } from 'lwc';

export default class RecordContextDemo
    extends LightningElement {

    @api recordId;

}
```

The platform provides the record ID when the component is used in a supported record context.

---

## Get Object Information

A common UI API approach is:

```javascript
import {
    getObjectInfo
} from 'lightning/uiObjectInfoApi';

import ACCOUNT_OBJECT
    from '@salesforce/schema/Account';

@wire(
    getObjectInfo,
    {
        objectApiName: ACCOUNT_OBJECT
    }
)
objectInfo;
```

The object information can then be used to work with:

```text
Object API Name
Label
Fields
Record Types
Other metadata
```

---

## Record Context Flow

```text
Salesforce Record Page
        ↓
LWC
        ↓
@api recordId
        ↓
Current Record ID
```

# 14. Complete Toast Example

```javascript
import { LightningElement } from 'lwc';

import {
    ShowToastEvent
} from 'lightning/platformShowToastEvent';

export default class ToastDemo
    extends LightningElement {

    showSuccess() {

        this.dispatchEvent(
            new ShowToastEvent({
                title: 'Success',
                message:
                    'Operation completed successfully',
                variant: 'success'
            })
        );
    }

    showError() {

        this.dispatchEvent(
            new ShowToastEvent({
                title: 'Error',
                message:
                    'Operation failed',
                variant: 'error'
            })
        );
    }
}
```

# 16. Static Resource vs Content Asset

This is an important interview topic.

| Static Resource | Content Asset |
|---|---|
| Mainly developer resources | Mainly content/assets |
| JS/CSS/images/files | Images/files/content |
| Can be imported into LWC | Used through Salesforce content mechanisms |
| Useful for third-party libraries | Useful for reusable content |
| Developer controlled | Content/admin oriented |

---

# 17. Custom Label vs Static Resource

| Custom Label | Static Resource |
|---|---|
| Stores text | Stores files/assets |
| Good for messages | Good for JS/CSS/images |
| Supports translations | Used for reusable resources |
| Imported using `@salesforce/label` | Imported using `@salesforce/resourceUrl` |

Example:

```javascript
import LABEL
    from '@salesforce/label/c.My_Label';
```

versus:

```javascript
import RESOURCE
    from '@salesforce/resourceUrl/My_Resource';
```

# 18. Toast vs Lightning Message Service

These solve different problems.

### Toast

Used to notify the current user:

```text
Success
Error
Warning
Info
```

### LMS

Used to communicate between components:

```text
LWC
Aura
Visualforce
```

Therefore:

```text
Toast = User Notification

LMS = Component Communication
```

# 20. Common Mistakes

## Mistake 1 — Hardcoding messages

Avoid:

```javascript
message = 'Record saved successfully';
```

when the message needs to be reusable or translatable.

Prefer Custom Labels.

---

## Mistake 2 — Loading a library repeatedly

Incorrect:

```javascript
renderedCallback() {
    loadScript(this, LIBRARY);
}
```

Better:

```javascript
renderedCallback() {

    if (this.libraryLoaded) {
        return;
    }

    this.libraryLoaded = true;

    loadScript(
        this,
        LIBRARY
    );
}
```

---

## Mistake 3 — Treating UI checks as security

Hiding a button does not replace Salesforce security.

Always enforce actual access using Salesforce security mechanisms.

---

## Mistake 4 — Assuming `recordId` is always available

`recordId` is provided in supported record contexts. A component used elsewhere may not automatically have a record ID.

---

## Mistake 5 — Using the wrong resource loader

Remember:

```text
JavaScript → loadScript()

CSS → loadStyle()
```

# 23. One-Line Interview Definitions

**Static Resource:** Salesforce resource used to store reusable files such as images, CSS, JavaScript, and ZIP packages.

**`@salesforce/resourceUrl`:** LWC module used to reference a Static Resource.

**`loadScript()`:** Loads third-party JavaScript from a Static Resource.

**`loadStyle()`:** Loads third-party CSS from a Static Resource.

**Content Asset:** Salesforce-managed content resource used to store and reuse digital content/assets.

**Internationalization:** Designing an application to support different languages, locales, currencies, dates, numbers, and regional settings.

**Custom Label:** Reusable Salesforce text that can be referenced from code and supports translation.

**Custom Permission:** Salesforce permission mechanism that can be checked to conditionally enable functionality.

**`@salesforce/user/Id`:** Provides the current user's Salesforce ID in LWC.

**`@salesforce/client/formFactor`:** Provides the current Lightning client form factor.

**`@api recordId`:** Receives the current record ID when an LWC is used in a supported record context.

**`getObjectInfo`:** UI API wire adapter used to retrieve Salesforce object metadata.

**Toast Notification:** Temporary message displayed to communicate success, error, warning, or information.
