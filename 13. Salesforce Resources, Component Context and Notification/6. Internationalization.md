# Internationalization in Salesforce Lightning Web Components (LWC)

## Overview

This guide explains how to use **internationalization properties** in Lightning Web Components (LWC) to adapt components for users who work with different languages, locales, currencies, and writing directions.

The example from the training screenshots formats a number as a currency using Salesforce's locale and currency settings. It displays the value as **$5,557,876.90** in the example org.

## 1. Actual Definition from the Training Screenshot

The screenshot states:

It also states:

### Syntax shown in the screenshot

```javascript
import internationalizationPropertyName
    from '@salesforce/i18n/internationalizationProperty';
```

This is a general syntax pattern. Replace `internationalizationPropertyName` with the property you want to import, and replace `internationalizationProperty` with the supported property name.

## 2. What Is Internationalization?

**Internationalization (often abbreviated as i18n)** means designing an application so it can work for users in different regions and languages without needing a separate codebase for each region.

In LWC, Salesforce provides internationalization properties through the `@salesforce/i18n` module. These properties help a component adapt to the current user's settings, such as:

- Locale and number formatting
- Currency
- Language
- Text direction, such as left-to-right or right-to-left
- Date and time presentation

**Simple example:** The same number may be displayed as `5,557,876.90` in one locale and with different separators in another locale. Currency formatting may also differ by locale and currency.

## 3. Code Shown in the Screenshots

### `internationalization.html`

The screenshot shows:

```html
<template>
    <lightning-card title="Internalization Demo">
        <p dir={dir}>{formattedNumber}</p>
    </lightning-card>
</template>
```

The title in the screenshot is spelled **Internalization Demo**. The topic itself is **Internationalization**.

**Explanation:**

- `<lightning-card>` displays the content inside a Lightning card.
- `dir={dir}` binds the component's `dir` property to the HTML `dir` attribute.
- `{formattedNumber}` displays the formatted currency value from JavaScript.

### `internationalization.js`

The screenshot shows:

```javascript
import { LightningElement } from 'lwc';
import LOCALE from '@salesforce/i18n/locale';
import CURRENCY from '@salesforce/i18n/currency';
import DIR from '@salesforce/i18n/dir';

export default class Internationalization extends LightningElement {
    dir = DIR;
    number = 5557876.897;

    formattedNumber = new Intl.NumberFormat(LOCALE, {
        style: 'currency',
        currency: CURRENCY,
        currencyDisplay: 'symbol'
    }).format(this.number);
}
```

**Explanation:**

- `LOCALE` provides the current user's Salesforce locale.
- `CURRENCY` provides the user's currency ISO code as exposed by Salesforce internationalization settings.
- `DIR` provides the text direction, such as `ltr` or `rtl`.
- `number` is the numeric value to format.
- `Intl.NumberFormat` formats the number according to the selected locale and currency.
- `style: 'currency'` requests currency formatting.
- `currency: CURRENCY` selects the currency code.
- `currencyDisplay: 'symbol'` displays a currency symbol where supported.
- `.format(this.number)` returns the formatted string.

The screenshot's number is `5557876.897`. Currency formatting commonly rounds it to two decimal places, producing a result like `$5,557,876.90` in the example environment. Exact output depends on the user's locale, currency, and currency formatting rules.

## 4. Complete Example to Practise

### `internationalization.html`

```html
<template>
    <lightning-card title="Internationalization Demo">
        <div class="slds-p-around_medium">
            <p dir={dir}>{formattedNumber}</p>
        </div>
    </lightning-card>
</template>
```

### `internationalization.js`

```javascript
import { LightningElement } from 'lwc';

import LOCALE from '@salesforce/i18n/locale';
import CURRENCY from '@salesforce/i18n/currency';
import DIR from '@salesforce/i18n/dir';

export default class Internationalization extends LightningElement {
    dir = DIR;
    number = 5557876.897;

    formattedNumber = new Intl.NumberFormat(LOCALE, {
        style: 'currency',
        currency: CURRENCY,
        currencyDisplay: 'symbol'
    }).format(this.number);
}
```

### `internationalization.js-meta.xml`

```xml
<?xml version="1.0" encoding="UTF-8"?>
<LightningComponentBundle xmlns="http://soap.sforce.com/2006/04/metadata">
    <apiVersion>67.0</apiVersion>
    <isExposed>true</isExposed>
    <targets>
        <target>lightning__AppPage</target>
    </targets>
</LightningComponentBundle>
```

> **Note:** In this example, the formatted value is initialized when the component instance is created. If the underlying number needs to change later, consider using a getter for `formattedNumber` so the value is recalculated when the number changes.

### Alternative using a getter

```javascript
import { LightningElement } from 'lwc';

import LOCALE from '@salesforce/i18n/locale';
import CURRENCY from '@salesforce/i18n/currency';
import DIR from '@salesforce/i18n/dir';

export default class Internationalization extends LightningElement {
    dir = DIR;
    number = 5557876.897;

    get formattedNumber() {
        return new Intl.NumberFormat(LOCALE, {
            style: 'currency',
            currency: CURRENCY,
            currencyDisplay: 'symbol'
        }).format(this.number);
    }
}
```

## 5. Important Internationalization Properties

The screenshot specifically demonstrates `locale`, `currency`, and `dir`.

| Property | Purpose |
|---|---|
| `@salesforce/i18n/locale` | The current user's locale, used to format values according to regional conventions. |
| `@salesforce/i18n/currency` | The currency code provided by the user's Salesforce internationalization settings. |
| `@salesforce/i18n/dir` | The current text direction, usually `ltr` or `rtl`. |

Other supported internationalization properties can provide information such as the user's language, time zone, and first day of the week. Always check the Salesforce documentation for the current supported property list and any property-specific limitations.

9. Find **Internationalization** in the custom components list and drag it onto the page.
10. Save and activate the page if required.
11. Open the page and verify that the currency value appears in the card.

## 7. Locale, Language, Currency, and Time Zone

These settings are related but do not mean the same thing.

- **Language:** Affects the language used for supported Salesforce UI text and translations.
- **Locale:** Controls regional formatting conventions such as number and date presentation.
- **Currency:** Determines the currency code used in currency formatting. Salesforce org currency configuration and individual user settings can affect currency behavior.
- **Time zone:** Affects how date-time values are interpreted or displayed in time-aware features.
- **Text direction (`dir`):** Indicates whether text should flow left-to-right (`ltr`) or right-to-left (`rtl`).

An application should not assume that every user uses English, US date formats, the dollar sign, or left-to-right text.

## 8. Common Mistakes and Troubleshooting

### Using a hard-coded locale

Hard-coding `en-US` may cause values to display in US formatting even for users with different locale settings. Import `LOCALE` when the component should follow the current Salesforce user's locale.

### Hard-coding a currency symbol

A literal `$` is not suitable for every currency. Use the currency code and `Intl.NumberFormat` for locale-aware currency display.

### Confusing locale with currency

Locale controls regional formatting conventions. Currency identifies the currency to format. They are separate settings.

### Using the wrong import path

The screenshot's import pattern is:

```javascript
import internationalizationPropertyName
    from '@salesforce/i18n/internationalizationProperty';
```

For the example, the imports are:

```javascript
import LOCALE from '@salesforce/i18n/locale';
import CURRENCY from '@salesforce/i18n/currency';
import DIR from '@salesforce/i18n/dir';
```

### Forgetting to bind the value in HTML

JavaScript defines `formattedNumber`, and HTML references it as `{formattedNumber}`. The property names must match.

### Incorrect currency configuration

`Intl.NumberFormat` expects a valid currency code when `style: 'currency'` is used. If formatting fails, inspect the imported currency value and the browser console.

# Interview Questions and Answers

## Q1. What is internationalization?

Internationalization (i18n) is the practice of designing software so it can support different languages, regions, number formats, currencies, time zones, and text directions without rewriting the application for each locale.

## Q2. How does Salesforce LWC support internationalization?

LWC provides the `@salesforce/i18n` scoped module, which exposes supported properties related to the current user's internationalization settings. JavaScript's `Intl` APIs can use these values to format numbers, currencies, and dates.

## Q3. What is the import syntax shown in the screenshot?

```javascript
import internationalizationPropertyName
    from '@salesforce/i18n/internationalizationProperty';
```

Replace the placeholders with the desired supported property name.

## Q4. What does `@salesforce/i18n/locale` return?

It provides the current user's locale identifier, which can be used for locale-sensitive formatting.

## Q5. What does `@salesforce/i18n/currency` provide?

It provides the currency code exposed through Salesforce's internationalization settings. Use it with `Intl.NumberFormat` to format a number as currency.

## Q6. What does `@salesforce/i18n/dir` provide?

It provides the current text direction, such as `ltr` (left-to-right) or `rtl` (right-to-left).

## Q7. What is `Intl.NumberFormat`?

`Intl.NumberFormat` is a JavaScript API for formatting numbers according to a locale. It supports decimal, percentage, and currency formatting.

## Q8. What is the purpose of `style: 'currency'`?

It tells `Intl.NumberFormat` to format the value as a currency amount.

## Q9. What does `currencyDisplay: 'symbol'` do?

It requests a currency symbol, such as `$` or `€`, where the locale and currency support one.

## Q10. What is the difference between language and locale?

Language relates to the language used for text. Locale includes regional conventions such as number and date formats. Two users can use the same language but different locales.

## Q11. Why should you avoid hard-coding `$` or a number format?

Users may work with different currencies and regional conventions. Locale-aware formatting improves correctness and usability for a global audience.

## Q12. Why use `dir={dir}` in the template?

It binds the text direction property to the HTML `dir` attribute, helping the content follow the current direction setting.

## Q13. Why does the screenshot display `$5,557,876.90`?

The JavaScript formats `5557876.897` as a currency using the imported locale and currency. The displayed symbol, separators, and decimal places depend on the user's settings and currency rules.

# Scenario-Based Interview Questions

## Scenario 1: A user in another country sees an unexpected number format

**How would you handle it?**

Import `@salesforce/i18n/locale` and use `Intl.NumberFormat` with that locale rather than hard-coding a locale string.

## Scenario 2: A component always shows the dollar symbol

**What would you change?**

Avoid hard-coded symbols. Import the currency property and use `Intl.NumberFormat` with `style: 'currency'` and the appropriate currency code.

## Scenario 3: The component must support right-to-left text

**What would you do?**

Use the supported `@salesforce/i18n/dir` property and bind it to the HTML `dir` attribute, as shown in the screenshot.

## Scenario 4: A formatted value does not update when the number changes

**What would you check?**

If the formatted value was assigned only once during initialization, it may not recalculate when the number changes. Use a getter or another reactive calculation pattern so formatting runs again when needed.
