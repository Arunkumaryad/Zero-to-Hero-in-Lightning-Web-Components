# Accessing Elements in the Component (LWC)

This document explains how to **access DOM elements rendered by an LWC component** using the `template` property, the rules around using `querySelector`, and how to manually attach a native HTML element as a child using the `lwc:dom="manual"` directive.

---

## 📌 Accessing Elements in LWC

> 🔎 **Definition (from training material):**
> To access elements **rendered by a component**, use the **`template`** property.

Every LWC component has access to a special `template` property (referenced as `this.template` inside the component's JS class), which represents the component's own **Shadow DOM** (as covered in the *Shadow DOM* documentation). Using this property, you can query and manipulate the elements that your component has rendered.

### Available Methods

```javascript
this.template.querySelector(selector);
this.template.querySelectorAll(selector);
element.template.querySelectorAll(selector);
```

| Method | Description |
|---|---|
| `this.template.querySelector(selector)` | Returns the **first matching element** within the component's own template that matches the given CSS `selector` |
| `this.template.querySelectorAll(selector)` | Returns **all matching elements** within the component's own template that match the given CSS `selector` |
| `element.template.querySelectorAll(selector)` | Same as above, but called from a specific `element`'s own `template` reference |

> ⚠️ **Note (from training material):** **Don't use ID selector with `querySelector`.**
>
> This means you should avoid writing something like `this.template.querySelector('#myId')`. Since IDs in LWC templates get transformed/scoped internally, it's safer and more reliable to query using **class names** or **tag names** instead of IDs.

## 📌 `lwc:dom="manual"` Directive

> 🔎 **Definition (from training material):**
> Add this directive to a **native HTML element** to attach an **HTML element as a child**.

By default, LWC's rendering engine fully controls the DOM inside a component's template — you're not supposed to manually inject or manipulate DOM nodes that LWC itself is managing. However, sometimes you need to programmatically insert plain HTML content (e.g., using `innerHTML`) into a specific spot in the template. For this exact scenario, LWC provides the **`lwc:dom="manual"`** directive.

- You add `lwc:dom="manual"` to a **native HTML element** (like a `<div>`).
- This tells the LWC engine: *"I will manually manage the children of this element using JavaScript — don't try to control this part of the DOM yourself."*
- Only **after** adding this directive are you allowed to safely use plain DOM APIs (like `innerHTML`, `appendChild`, etc.) to insert content into that element from your JavaScript controller.

## 🧩 Full Code Example

### JavaScript Controller (`helloQuerySelectorDemo.js`)

```javascript
import { LightningElement } from 'lwc';

export default class HelloQuerySelectorDemo extends LightningElement {
    user = ['John', 'Jane', 'Doe', 'Smith', 'Alice', 'Bob', 'Charlie'];

    fetchDetails() {
        const element = this.template.querySelector('h1');
        element.style.border = '2px solid green';
        console.log('Element:', element);
        console.log('Element Text:', element.innerText);

        const userElement = this.template.querySelectorAll('.name');
        Array.from(userElement).forEach(item => {
            console.log('line 11 users: ', item.innerText);
            item.setAttribute('title', item.innerText);
        });

        const childElement = this.template.querySelector('.name');
        childElement.innerHTML = '<p>Hey I am a Child element.</p>';
    }
}
```

**Line-by-line Explanation:**

- `user = ['John', 'Jane', 'Doe', 'Smith', 'Alice', 'Bob', 'Charlie'];` — a simple array of user names, which will be looped over in the template (using `for:each`, as covered in the *Template Looping* documentation).

- **`fetchDetails()`** — this method runs when a button is clicked, and it demonstrates several ways of accessing elements:

  1. **`const element = this.template.querySelector('h1');`**
     Selects the **first `<h1>` element** rendered inside this component's template.

  2. **`element.style.border = '2px solid green';`**
     Directly manipulates the selected `<h1>` element's **inline CSS style**, giving it a green border.

  3. **`console.log('Element:', element);`** and **`console.log('Element Text:', element.innerText);`**
     Logs the selected DOM element itself, and its **text content**, to the browser console — useful for debugging.

  4. **`const userElement = this.template.querySelectorAll('.name');`**
     Selects **all elements** with the CSS class `name` (these are the repeated `<div>` elements generated by the `for:each` loop in the template).

  5. **`Array.from(userElement).forEach(item => { ... });`**
     Since `querySelectorAll` returns a **NodeList** (not a true array), `Array.from()` converts it into a real array so we can use `.forEach()` on it. For **each** matched `.name` element:
     - `console.log('line 11 users: ', item.innerText);` — logs the text of that item (i.e., each user's name).
     - `item.setAttribute('title', item.innerText);` — dynamically sets a `title` **HTML attribute** on each element, equal to its own text — meaning if you hover over a name in the browser, a tooltip showing that same name will appear.

  6. **`const childElement = this.template.querySelector('.name');`**
     Selects the **first** element with the class `name` (only the first match, since `querySelector` — unlike `querySelectorAll` — always returns a single element).

  7. **`childElement.innerHTML = '<p>Hey I am a Child element.</p>';`**
     Replaces the **inner HTML** of that first `.name` element with a new paragraph — demonstrating that you can programmatically inject new markup into an existing rendered element.

### HTML Template (`helloQuerySelectorDemo.html`)

```html
<template>
    <lightning-card title="Query Selector">
        <div class="slds-m-around_medium">
            <h1>Hey I am Heading.</h1> <br>
            <template for:each={user} for:item="user">
                <div class="name" key={user}>{user}</div>
            </template>
            <br>
            <div class="child" lwc:dom="manual"></div>
            <lightning-button variant="brand" label="Brand" title="Fetch Details" onclick={fetchDetails}></lightning-button>
        </div>
    </lightning-card>
</template>
```

**Explanation:**
- `<h1>Hey I am Heading.</h1>` — this is the element targeted by `this.template.querySelector('h1')` in the JS controller — it gets a green border once `fetchDetails()` runs.
- `<template for:each={user} for:item="user"> <div class="name" key={user}>{user}</div> </template>` — loops through the `user` array and renders a `<div class="name">` for **each** user name. These are the elements targeted by `this.template.querySelectorAll('.name')`.
- `<div class="child" lwc:dom="manual"></div>` — this `<div>` is decorated with **`lwc:dom="manual"`**, meaning LWC will **not** manage its children itself — this is the correct, safe way to allow JavaScript to later inject content into it manually (though in this example, the manual injection actually happens on the first `.name` div via `childElement.innerHTML`).
- `<lightning-button variant="brand" label="Brand" title="Fetch Details" onclick={fetchDetails}></lightning-button>` — a Lightning button that, when clicked, triggers the `fetchDetails()` method described above.

## 🎯 Step-by-Step Execution Flow

1. Page loads → displays the heading *"Hey I am Heading."* and a list of names (`John`, `Jane`, `Doe`, `Smith`, `Alice`, `Bob`, `Charlie`), each in its own `<div class="name">`.
2. User clicks the **"Brand"** button → `fetchDetails()` runs.
3. The `<h1>` heading gets a **green border** applied via `element.style.border`.
4. Each name `<div>` gets a **`title` attribute** added, matching its own text (so hovering shows a native tooltip).
5. The **first** `.name` div's content is **replaced** with a new paragraph: *"Hey I am a Child element."*

## 📊 Summary Table

| Concept | Explanation |
|---|---|
| **`this.template`** | Represents the component's own rendered DOM (Shadow DOM); the starting point for querying elements |
| **`querySelector(selector)`** | Returns the **first** matching element |
| **`querySelectorAll(selector)`** | Returns **all** matching elements (as a NodeList) |
| **ID selectors** | ❌ **Avoid** using ID selectors (`#id`) with `querySelector` in LWC |
| **`lwc:dom="manual"`** | Directive added to a native HTML element to tell LWC that its children will be **manually managed** via JavaScript |
| **`Array.from(nodeList)`** | Converts a NodeList (returned by `querySelectorAll`) into a real JavaScript array so array methods like `.forEach()` can be used |

---

## ✅ Quick Recap

- To access elements rendered by an LWC component, always start from **`this.template`**.
- Use `this.template.querySelector(selector)` for a **single element**, and `this.template.querySelectorAll(selector)` for **multiple elements**.
- **Avoid ID selectors** with `querySelector` in LWC — prefer class or tag selectors instead.
- To manually attach/manage a native HTML element's children via JavaScript, decorate that element with the **`lwc:dom="manual"`** directive first.
- `querySelectorAll` returns a **NodeList**, not an array — use `Array.from()` to convert it before using array methods like `.forEach()`.
