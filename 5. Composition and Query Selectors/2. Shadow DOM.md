# Shadow DOM in LWC

This document explains the **DOM** and **Shadow DOM** concepts — the foundational browser concepts that Lightning Web Components are built on top of, including **encapsulation**, its **benefits**, and a **practical demonstration** using plain JavaScript.

---

## 📌 What is DOM?

> 🔎 **Definition (from training material):**
> **Document Object Model (DOM)** is a **programming API for HTML and XML documents**. It defines the **logical structure of documents** and the way a document is **accessed and manipulated**.
> Basically, **the DOM is a tree structure representation of a web page**.

In simple words — when a browser loads an HTML page, it converts that HTML into a **tree of objects** (called nodes), where each HTML tag becomes a **node** in that tree. JavaScript can then use the DOM API to **read, add, modify, or remove** any part of that tree, which is how dynamic web pages work.

### Example: HTML → DOM Tree

**HTML Code:**
```html
<html>
  <head>
    <title>Zero to Hero</title>
  </head>
  <body>
    <h1>Heading</h1>
    <a href="https://salesforcetroop.com">Link</a>
  </body>
</html>
```

**Corresponding DOM Tree Structure:**
```
Document
   │
   ▼
Root Element: <html>
   │
   ├──▶ Element: <head>
   │        │
   │        ▼
   │    Element: <title>
   │        │
   │        ▼
   │    Text: "Sample document"
   │
   └──▶ Element: <body>
            │
            ├──▶ Element: <h1>
            │        │
            │        ▼
            │    Text: "Heading"
            │
            └──▶ Element: <a>
                     │
                     ▼
                 Attribute: href
```

**How to read this tree:**
- The **`Document`** is the top-most object representing the entire page.
- Its **Root Element** is always `<html>`.
- The `<html>` element branches into two main child elements: **`<head>`** and **`<body>`**.
- `<head>` further contains the **`<title>`** element, which contains the **text node** `"Sample document"`.
- `<body>` branches into **`<h1>`** (containing the text `"Heading"`) and **`<a>`** (which has an **attribute** called `href`).

This tree-like, parent-child, nested relationship is exactly what the DOM represents — and it's this structure that JavaScript (and LWC internally) uses to access and manipulate elements on the page.

## 📌 What is Shadow DOM?

> 🔎 **Definition (from training material):**
> **Shadow DOM brings encapsulation concept to HTML** which enables you to **link a hidden separated DOM to an element**.

> 🔎 **Benefits of Shadow DOM (from training material):**
> **DOM queries, event propagation, and CSS rules cannot go to the other side of the shadow boundary**, thus creating **encapsulation**.

In simple words — normally, everything in a webpage's DOM is part of **one big shared tree** (called the **Light DOM**), which means CSS styles and JavaScript queries from anywhere on the page can affect or reach into any element. The **Shadow DOM** creates a **separate, hidden mini-DOM tree** attached to a specific element, and this hidden tree is **isolated/protected** from the rest of the page — styles and scripts from outside **cannot leak in**, and elements inside the shadow tree **cannot leak out**.

This isolation is called **encapsulation**, and it's the exact same principle that **Lightning Web Components use internally** to keep each component's markup and styles separate from other components on the page.

### Visualizing Light DOM vs Shadow DOM

```
┌─────────────────────────────┐        ┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐
│         Light DOM            │          Shadow DOM (hidden)
│                               │        │                          │
│         Element               │
│            │                  │        │                          │
│      ┌─────┴─────┐            │
│      ▼           ▼            │        │                          │
│  Element    Shadow Host ───────┼──────▶ Shadow Root
│                                │        │      │                   │
│                                │             ┌──┴──┐
│                                │        │     ▼     ▼             │
│                                │      Element  Element
│                                │        │                          │
└───────────────────────────────┘        └ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘
```

**Key parts of this diagram:**
- **Light DOM** — the normal, visible DOM tree of the page. It contains a regular `Element` and a special element called the **Shadow Host**.
- **Shadow Host** — the element in the Light DOM that acts as the "attachment point" for a Shadow DOM. It's the bridge between the visible page and the hidden shadow tree.
- **Shadow Root** — the **root node** of the hidden Shadow DOM tree, attached to the Shadow Host. Everything inside the Shadow Root (its own `Element` children) is **isolated** from the Light DOM.
- Because of this boundary, **CSS rules, DOM queries, and events from the Light DOM cannot cross into the Shadow DOM**, and vice versa — this is the "shadow boundary" mentioned in the definition.

## 🧩 Practical Example: Creating a Shadow DOM

### HTML + JavaScript Code (Plain HTML Demo)

```html
<!DOCTYPE html>
<html>
    <head>
        <title>Shadow DOM</title>
    </head>
    <body>
        <div>
            <p>Thanks for choosing Zero to Hero Course</p>
        </div>
        <div id="host"></div>

        <script>
            const elem = document.querySelector('#host')
            const shadowRoot = elem.attachShadow({mode:'open'})
            shadowRoot.innerHTML = '<p>I am shadow DOM</p>'
        </script>
    </body>
</html>
```

**Explanation, line by line:**
- `<div><p>Thanks for choosing Zero to Hero Course</p></div>` — this is a **normal paragraph** that lives in the regular **Light DOM**.
- `<div id="host"></div>` — an **empty `div`** with the id `host`. This will become our **Shadow Host** — the attachment point for the hidden Shadow DOM.
- `const elem = document.querySelector('#host')` — selects the `host` div from the Light DOM using its `id`.
- `const shadowRoot = elem.attachShadow({mode:'open'})` — this is the key line: it **attaches a Shadow DOM** to the `elem` (`#host`). The `attachShadow()` method creates a new **Shadow Root** on that element.
  - `{mode:'open'}` means the shadow tree **can be accessed from outside JavaScript** (e.g., via `elem.shadowRoot`). The alternative, `{mode:'closed'}`, would make the shadow tree completely inaccessible from outside scripts.
- `shadowRoot.innerHTML = '<p>I am shadow DOM</p>'` — inserts a new `<p>` element **inside the Shadow Root** — this paragraph now lives in the **isolated Shadow DOM**, separate from the rest of the page's Light DOM.

**Result:** The page visually shows two paragraphs — *"Thanks for choosing Zero to Hero Course"* (Light DOM) and *"I am shadow DOM"* (Shadow DOM) — but they exist in **two structurally separate trees**.

## 🧩 Demonstrating Encapsulation — Why `querySelectorAll` Can't See Inside the Shadow DOM

### Extended Code Example

```html
<body>
    <div>
        <p>Thanks for choosing Zero to Hero Course</p>
    </div>
    <div id="host"></div>
    <button onclick="fetchPtag()">Click me</button>

    <script>
        const elem = document.querySelector('#host')
        const shadowRoot = elem.attachShadow({mode:'open'})
        shadowRoot.innerHTML = '<p>I am shadow DOM</p>'

        function fetchPtag(){
            let tags = document.querySelectorAll('p')
            console.log(tags)
        }
    </script>
</body>
```

**Explanation:**
- A new **`<button onclick="fetchPtag()">Click me</button>`** is added — clicking it runs the `fetchPtag()` function.
- Inside `fetchPtag()`, `document.querySelectorAll('p')` attempts to find **all `<p>` tags on the page**, starting the search from the main `document` (Light DOM).
- `console.log(tags)` prints whatever `<p>` elements were found.

**What actually happens when you click the button:**
- `document.querySelectorAll('p')` will **only find the `<p>` tag in the Light DOM** (*"Thanks for choosing Zero to Hero Course"*).
- It will **NOT find** the `<p>` tag inside the Shadow DOM (*"I am shadow DOM"*), because — exactly as defined earlier — **DOM queries cannot go to the other side of the shadow boundary**.

This is a **live, practical proof of encapsulation**: even though the shadow paragraph is visually rendered on the page, a normal `document.querySelectorAll()` call from **outside** the shadow tree simply **cannot see it**. To access it, you would need to specifically query through the `shadowRoot` itself (e.g., `shadowRoot.querySelectorAll('p')`).

## ✅ Quick Recap

- The **DOM** is a tree-structure representation of a web page, used by JavaScript to read and manipulate HTML content.
- The **Shadow DOM** attaches a **separate, hidden DOM tree** to an element, creating **encapsulation** — styles, queries, and events cannot cross the shadow boundary.
- You create a Shadow DOM using `element.attachShadow({mode: 'open' | 'closed'})`, which returns a `shadowRoot` you can populate with its own isolated markup.
- A regular `document.querySelectorAll()` call **cannot** see elements inside a Shadow DOM — this was demonstrated practically using the `fetchPtag()` example, which only returns the Light DOM's `<p>` tag.
- Understanding Shadow DOM is essential for LWC, since **every Lightning Web Component is internally backed by its own Shadow DOM**, which is exactly why component styles and markup stay isolated from one another.
