# LWC, Aura and Visualforce Page Communication Using LMS

## 📌 Overview

This project demonstrates **communication between Lightning Web Components (LWC), Aura Components, and Visualforce Pages using Salesforce Lightning Message Service (LMS)**.

The main idea is to use a **Lightning Message Channel** as a common communication channel between different Salesforce UI technologies.

LMS can be used for communication between:

- LWC ↔ LWC
- LWC ↔ Aura
- Aura ↔ LWC
- Aura ↔ Aura
- LWC ↔ Visualforce
- Visualforce ↔ LWC
- Aura ↔ Visualforce
- Visualforce ↔ Aura

The training example in this project focuses on using a Visualforce Page with LMS APIs to publish, subscribe, and unsubscribe from a message channel.

# 1. What is Lightning Message Service?

### Definition

**Lightning Message Service (LMS) is a Salesforce service that enables communication between Lightning components and Visualforce Pages through a Lightning Message Channel.**

It provides a common communication mechanism so that different Salesforce UI technologies can exchange messages without requiring a direct parent-child relationship.

### Basic architecture

```text
                     Lightning Message Channel
                     SampleMessageChannel__c
                              |
             +----------------+----------------+
             |                |                |
             v                v                v
            LWC             Aura          Visualforce
             |                |                |
             +----------------+----------------+
                              |
                         Message Payload
```

---

# 2. Why Use LMS?

Different Salesforce UI technologies have different component communication mechanisms.

For example:

- LWC can use `@api` and Custom Events.
- Aura can use attributes and events.
- Visualforce can use JavaScript.
- LMS provides a common messaging mechanism for these technologies.

Therefore, when an LWC, Aura component, and Visualforce Page need to communicate without a direct component hierarchy, **LMS is a strong choice**.

---

# 3. Lightning Message Channel

A **Lightning Message Channel** is the metadata component that defines the channel used by Lightning Message Service to exchange messages.

The message channel used in this project is:

```text
SampleMessageChannel__c
```

Metadata:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<LightningMessageChannel
    xmlns="http://soap.sforce.com/2006/04/metadata">

    <masterLabel>SampleMessageChannel</masterLabel>

    <isExposed>true</isExposed>

    <description>Message Channel to Pass Data</description>

    <lightningMessageFields>
        <fieldName>lmsData</fieldName>
        <description>This is the field to pass data</description>
    </lightningMessageFields>

</LightningMessageChannel>
```

### Important elements

| Element | Purpose |
|---|---|
| `masterLabel` | Label of the message channel |
| `isExposed` | Makes the channel available for use |
| `description` | Describes the purpose of the channel |
| `lightningMessageFields` | Defines message fields |
| `fieldName` | Name of a field in the message payload |

```javascript
sforce.one.publish(SAMPLEMC, payload);
```

### Explanation

The Visualforce Page uses:

```javascript
sforce.one.publish()
```

to publish a message through the Lightning Message Channel.

Syntax:

```javascript
sforce.one.publish(messageChannel, payload);
```

In this project:

```javascript
sforce.one.publish(SAMPLEMC, message);
```

The first argument is the Message Channel reference.

The second argument is the message payload.

# 6. Subscribe to a Message

### Actual definition

> **Subscribe a Message**

The screenshot shows:

```javascript
subscriptionToMC =
    sforce.one.subscribe(
        SAMPLEMC,
        msgHandler,
        {scope: "APPLICATION"}
    );
```

### Explanation

The Visualforce Page subscribes to the message channel using:

```javascript
sforce.one.subscribe()
```

The syntax is:

```javascript
sforce.one.subscribe(
    messageChannel,
    messageHandler,
    subscriberOptions
);
```

Parameters:

| Parameter | Meaning |
|---|---|
| `SAMPLEMC` | Message Channel reference |
| `msgHandler` | Function called when a message is received |
| `{scope: "APPLICATION"}` | Application-level subscription scope |

The returned subscription is stored in:

```javascript
subscriptionToMC
```

This reference is later used when unsubscribing.

# 7. Unsubscribe from a Message

### Actual definition

> **unsubscribe a Message**

The screenshot shows:

```javascript
sforce.one.unsubscribe(subscriptionToMC);
```

### Explanation

When the Visualforce Page no longer needs to receive messages, use:

```javascript
sforce.one.unsubscribe()
```

Example:

```javascript
if (subscriptionToMC) {
    sforce.one.unsubscribe(subscriptionToMC);
    subscriptionToMC = null;
}
```

The subscription reference is important because `unsubscribe()` needs the existing subscription.

# 9. Message Payload

The message sent by the Visualforce Page follows this structure:

```javascript
const message = {
    lmsData: {
        value: data
    }
};
```

For example:

```javascript
const message = {
    lmsData: {
        value: "Hello I am VFPage"
    }
};
```

The subscriber can then access:

```javascript
message.lmsData.value
```


# 10. Complete Visualforce Page

The training screenshot contains the following Visualforce Page structure.

```xml
<apex:page lightningStylesheets="true">

    <apex:slds>

        <div class="slds-scope">

            <div class="slds-p-around_medium">

                <label>Enter Publish Message</label>

                <input
                    type="text"
                    class="slds-input"
                    id="messageField"/>

                <div class="slds-p-top_small slds-p-bottom_small">

                    <button
                        class="slds-button slds-button_neutral"
                        onclick="publishHandler()">
                        Publish
                    </button>

                    <button
                        class="slds-button slds-button_neutral"
                        onclick="subscriberHandler()">
                        Subscribe
                    </button>

                    <button
                        class="slds-button slds-button_neutral"
                        onclick="unsubscriberHandler()">
                        Unsubscribe
                    </button>

                </div>

                <p>Message Received</p>

                <div id="receivedMessage"></div>

            </div>

        </div>

    </apex:slds>

    <script>

        let SAMPLEMC =
            "{!$MessageChannel.SampleMessageChannel__c}";

        let subscriptionToMC;

        function publishHandler() {

            let data =
                document.getElementById("messageField").value;

            const message = {
                lmsData: {
                    value: data
                }
            };

            sforce.one.publish(
                SAMPLEMC,
                message
            );
        }

        function subscriberHandler() {

            if (!subscriptionToMC) {

                subscriptionToMC =
                    sforce.one.subscribe(
                        SAMPLEMC,
                        msgHandler,
                        {
                            scope: "APPLICATION"
                        }
                    );
            }
        }

        function unsubscriberHandler() {

            if (subscriptionToMC) {

                sforce.one.unsubscribe(
                    subscriptionToMC
                );

                subscriptionToMC = null;
            }
        }

        function msgHandler(message) {

            let receivedMessage =
                document.getElementById(
                    "receivedMessage"
                );

            receivedMessage.innerHTML =
                message &&
                message.lmsData
                    ? message.lmsData.value
                    : "No Data Send";
        }

    </script>

</apex:page>
```

# 30. LMS vs Custom Event vs `@api`

| Feature | `@api` | Custom Event | LMS |
|---|---|---|---|
| Parent → Child | ✅ | ❌ | ✅ |
| Child → Parent | ❌ | ✅ | ✅ |
| Unrelated LWC | ❌ | ❌ | ✅ |
| LWC ↔ Aura | ❌ | ❌ | ✅ |
| LWC ↔ Visualforce | ❌ | ❌ | ✅ |
| Requires direct hierarchy | Usually | Yes | No |
| Common message channel | ❌ | ❌ | ✅ |
| Best for decoupled communication | ❌ | ❌ | ✅ |

# 31. Common Mistakes

## Mistake 1 – Wrong Message Channel

Make sure:

```text
SampleMessageChannel__c
```

is the correct channel API name.

---

## Mistake 2 – Forgetting `$MessageChannel`

Visualforce must obtain the Message Channel reference using:

```javascript
"{!$MessageChannel.SampleMessageChannel__c}"
```

---

## Mistake 3 – Publishing the wrong payload

If the subscriber expects:

```javascript
message.lmsData.value
```

the publisher should send:

```javascript
{
    lmsData: {
        value: "Hello"
    }
}
```

---

## Mistake 4 – Not storing the subscription

Do not discard the value returned by:

```javascript
sforce.one.subscribe()
```

Store it:

```javascript
subscriptionToMC =
    sforce.one.subscribe(...);
```

because it is required for:

```javascript
sforce.one.unsubscribe(subscriptionToMC);
```

---

## Mistake 5 – Duplicate subscriptions

If Subscribe is clicked multiple times, duplicate subscriptions can be created.

Use:

```javascript
if (!subscriptionToMC) {
    subscriptionToMC =
        sforce.one.subscribe(...);
}
```

---

## Mistake 6 – Incorrect scope

Be consistent with the intended scope:

```javascript
scope: "APPLICATION"
```

for Visualforce.

# 34. One-Line Interview Definitions

**Lightning Message Service:** Salesforce service used for communication between Lightning components and Visualforce Pages through message channels.

**Lightning Message Channel:** Metadata component that defines the channel used for LMS message exchange.

**`$MessageChannel`:** Visualforce global variable used to get the reference of a Lightning Message Channel.

**`sforce.one.publish()`:** Visualforce API used to publish a message through an LMS channel.

**`sforce.one.subscribe()`:** Visualforce API used to subscribe to an LMS message channel.

**`sforce.one.unsubscribe()`:** Visualforce API used to remove a Visualforce LMS subscription.

**Message Payload:** The data object passed through the Message Channel.

**Application Scope:** A scope used to make the subscription operate at the application level.
