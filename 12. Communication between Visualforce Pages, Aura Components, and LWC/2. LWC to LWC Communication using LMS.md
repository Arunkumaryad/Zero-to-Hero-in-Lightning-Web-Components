# LWC to LWC Communication Using Lightning Message Service (LMS)

## 📌 Overview

**Lightning Message Service (LMS)** is a Salesforce mechanism used to communicate between Lightning components, especially when the components are not directly related in the component hierarchy.

LMS can be used to communicate between:

- LWC to LWC
- Aura to LWC
- LWC to Aura
- Components placed in different areas of a Lightning application

### Why do we need LMS?

Normally, parent-child communication can be handled using `@api` properties and custom events. However, when components are unrelated or are not in the same direct hierarchy, LMS is a better solution.

Example:

```text
             LWC A
            /     \
         LWC B   LWC C

             LWC X
            /     \
         LWC Y   LWC Z
```

LWC B and LWC Y cannot easily communicate through normal parent-child communication because they belong to different component hierarchies.

LMS provides a common communication channel.

# 1. Lightning Message Service (LMS)

**Definition:**

Lightning Message Service is a Salesforce service that enables communication between Lightning components using a message channel.

It allows components to communicate without requiring a direct parent-child relationship.

The basic communication pattern is:

```text
Publisher Component
       |
       | publish()
       ↓
Lightning Message Channel
       |
       | subscribe()
       ↓
Subscriber Component
```

The publisher sends a message, and any subscribed component can receive it.

---

# 2. Message Channel

A **Lightning Message Channel** is the communication channel through which components publish and receive messages.

The message channel is created as metadata in Salesforce.

Example:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<LightningMessageChannel xmlns="http://soap.sforce.com/2006/04/metadata">
    <masterLabel>SampleMessageChannel</masterLabel>
    <isExposed>true</isExposed>
    <description>Message Channel to Pass Data</description>

    <lightningMessageFields>
        <fieldName>lmsData</fieldName>
        <description>This is the field to pass data</description>
    </lightningMessageFields>
</LightningMessageChannel>
```

### Important parts

| Element | Purpose |
|---|---|
| `masterLabel` | Label/name of the message channel |
| `isExposed` | Makes the message channel available for use |
| `description` | Describes the purpose of the channel |
| `lightningMessageFields` | Defines the fields that can be included in the message |
| `fieldName` | Name of the message field |

---

# 3. Reference a Message Channel in LWC

First, import the message channel into the LWC JavaScript file.

```javascript
import SAMPLEMC from '@salesforce/messageChannel/SampleMessageChannel__c';
```

### Explanation

`SAMPLEMC` is the JavaScript reference to the Salesforce Lightning Message Channel.

The general syntax is:

```javascript
import MESSAGE_CHANNEL_NAME
from '@salesforce/messageChannel/MessageChannelName__c';
```

The message channel name must match the metadata message channel created in Salesforce.

---

# 4. Import LMS APIs

The required LMS APIs can be imported from `lightning/messageService`.

```javascript
import {
    APPLICATION_SCOPE,
    publish,
    subscribe,
    unsubscribe,
    MessageContext
} from 'lightning/messageService';
```

### Important LMS APIs

| API | Purpose |
|---|---|
| `publish()` | Sends a message |
| `subscribe()` | Subscribes to a message channel |
| `unsubscribe()` | Removes an existing subscription |
| `MessageContext` | Provides the context required by LMS |
| `APPLICATION_SCOPE` | Allows subscription across the application |

---

# 5. MessageContext

The `MessageContext` wire adapter is used to obtain the information/context required by Lightning Message Service.

```javascript
@wire(MessageContext)
context;
```

### Definition from the training material

**MessageContext Wire Adapter is used to get information of all LWC using LMS.**

### Practical meaning

`MessageContext` provides the context needed by LMS APIs such as:

```javascript
publish()
```

and

```javascript
subscribe()
```

Without the required message context, the component cannot properly interact with LMS.

---

# 6. Publishing a Message

To send a message, use the `publish()` method.

```javascript
publish(this.context, SAMPLEMC, message);
```

The training material explains the parameters as:

```javascript
publish(messageContext, messageChannel, message)
```

### Parameters

| Parameter | Meaning |
|---|---|
| `this.context` | Message Context object |
| `SAMPLEMC` | Reference to the Message Channel |
| `message` | Data that needs to be published |

Example:

```javascript
const message = {
    lmsData: {
        value: this.inputValue
    }
};

publish(this.context, SAMPLEMC, message);
```

### Simple flow

```text
User enters data
      ↓
publishMessage()
      ↓
Create message object
      ↓
publish()
      ↓
Message Channel
```

---

# 7. Subscribe to a Message Channel

A subscriber uses the `subscribe()` method to listen for messages.

Example:

```javascript
this.subscription = subscribe(
    this.context,
    SAMPLEMC,
    (message) => {
        this.handleMessage(message);
    },
    {
        scope: APPLICATION_SCOPE
    }
);
```

The training material describes the syntax as:

```javascript
subscribe(
    messageContext,
    messageChannel,
    listener,
    subscriberOptions
)
```

### Parameters

| Parameter | Meaning |
|---|---|
| `this.context` | Context of the current Lightning Web Component using LMS |
| `SAMPLEMC` | Reference to the Message Channel |
| `listener` | Function that receives messages |
| `subscriberOptions` | Options controlling the subscription |

---

# 8. Application Scope

`APPLICATION_SCOPE` allows a component to receive messages published through the application scope.

Example:

```javascript
{
    scope: APPLICATION_SCOPE
}
```

This is commonly used when the subscriber needs to receive messages from components across the Lightning application rather than only from a narrower message context.

---

# 9. Handling the Received Message

When a message is received, the listener calls a handler method.

```javascript
handleMessage(message) {
    this.receivedMessage =
        message.lmsData.value
            ? message.lmsData.value
            : 'No Message Published';
}
```

The message structure in this example is:

```javascript
{
    lmsData: {
        value: 'Hello from Publisher'
    }
}
```

Therefore:

```javascript
message.lmsData.value
```

contains the actual value sent by the publisher.

---

# 10. Unsubscribe from a Message Channel

When a component no longer needs the subscription, use `unsubscribe()`.

```javascript
unsubscribe(this.subscription);
this.subscription = null;
```

### Why unsubscribe?

Unsubscribing helps prevent unnecessary message handling and avoids maintaining a subscription when the component no longer needs it.

# 12. Publisher Component – JavaScript

```javascript
import { LightningElement, wire } from 'lwc';

import SAMPLEMC
    from '@salesforce/messageChannel/SampleMessageChannel__c';

import {
    publish,
    MessageContext
} from 'lightning/messageService';

export default class LmsComponentA extends LightningElement {

    @wire(MessageContext)
    context;

    inputValue = '';

    inputHandler(event) {
        this.inputValue = event.target.value;
    }

    publishMessage() {

        const message = {
            lmsData: {
                value: this.inputValue
            }
        };

        publish(this.context, SAMPLEMC, message);
    }
}
```

# 16. Subscriber Component – JavaScript

```javascript
import { LightningElement, wire } from 'lwc';

import SAMPLEMC
    from '@salesforce/messageChannel/SampleMessageChannel__c';

import {
    subscribe,
    MessageContext,
    APPLICATION_SCOPE,
    unsubscribe
} from 'lightning/messageService';

export default class LmsComponentX extends LightningElement {

    @wire(MessageContext)
    context;

    receivedMessage;

    subscription;

    connectedCallback() {
        this.subscribeMessage();
    }

    subscribeMessage() {

        this.subscription = subscribe(
            this.context,
            SAMPLEMC,
            (message) => {
                this.handleMessage(message);
            },
            {
                scope: APPLICATION_SCOPE
            }
        );
    }

    handleMessage(message) {

        this.receivedMessage =
            message.lmsData.value
                ? message.lmsData.value
                : 'No Message Published';
    }

    unsubscribeMessage() {

        unsubscribe(this.subscription);

        this.subscription = null;
    }
}
```

---

# 17. Subscriber Component – Explanation

## `connectedCallback()`

```javascript
connectedCallback() {
    this.subscribeMessage();
}
```

`connectedCallback()` is a lifecycle hook.

It runs when the component is inserted into the DOM.

Here it is used to start the LMS subscription.

---

## `subscribeMessage()`

```javascript
this.subscription = subscribe(
    this.context,
    SAMPLEMC,
    (message) => {
        this.handleMessage(message);
    },
    {
        scope: APPLICATION_SCOPE
    }
);
```

This creates the subscription.

The returned subscription is stored in:

```javascript
this.subscription
```

This is important because the same subscription reference is required when unsubscribing.

---

## `handleMessage()`

```javascript
handleMessage(message) {

    this.receivedMessage =
        message.lmsData.value
            ? message.lmsData.value
            : 'No Message Published';
}
```

This method extracts the published value and stores it in:

```javascript
receivedMessage
```

The HTML automatically displays the value.

---

## `unsubscribeMessage()`

```javascript
unsubscribeMessage() {

    unsubscribe(this.subscription);

    this.subscription = null;
}
```

This removes the subscription.

After this point, the component will no longer receive messages through that subscription.

# 28. Important LMS Concepts for Interviews

## 1. What is LMS?

Lightning Message Service is used for communication between Lightning components using a message channel.

---

## 2. Why use LMS instead of Custom Events?

Custom events are primarily used for communication from child to parent in a component hierarchy.

LMS is useful when components are unrelated or need a common communication mechanism.

---

## 3. What is a Message Channel?

A message channel is a Salesforce metadata component that provides the channel through which messages are published and received.

Example:

```text
SampleMessageChannel__c
```

---

## 4. What is `publish()`?

`publish()` sends a message through a Lightning Message Channel.

Syntax:

```javascript
publish(messageContext, messageChannel, message);
```

---

## 5. What is `subscribe()`?

`subscribe()` registers a component as a listener for messages from a Lightning Message Channel.

Syntax:

```javascript
subscribe(
    messageContext,
    messageChannel,
    listener,
    subscriberOptions
);
```

---

## 6. What is `unsubscribe()`?

`unsubscribe()` removes an existing LMS subscription.

```javascript
unsubscribe(this.subscription);
```

---

## 7. What is MessageContext?

`MessageContext` provides the context required by LMS APIs.

Example:

```javascript
@wire(MessageContext)
context;
```

---

## 8. Why store the subscription?

The subscription reference is needed when removing the subscription.

```javascript
this.subscription = subscribe(...);
```

Later:

```javascript
unsubscribe(this.subscription);
```

---

## 9. What is `APPLICATION_SCOPE`?

`APPLICATION_SCOPE` allows the subscriber to receive messages from the application scope.

Example:

```javascript
{
    scope: APPLICATION_SCOPE
}
```

---

## 10. Where should subscription usually be initialized?

A common approach is to subscribe from:

```javascript
connectedCallback()
```

Example:

```javascript
connectedCallback() {
    this.subscribeMessage();
}
```

# 29. Interview Scenario-Based Questions

### Scenario 1

**Two unrelated LWCs need to communicate. What would you use?**

Answer:

Use Lightning Message Service with a Lightning Message Channel.

---

### Scenario 2

**A child needs to send data to its parent. Would you use LMS?**

Usually, no.

A custom event is normally the simpler choice:

```javascript
this.dispatchEvent(
    new CustomEvent('message', {
        detail: value
    })
);
```

LMS is more appropriate when components need to communicate without relying on a direct component hierarchy.

---

### Scenario 3

**What happens if you publish a message before a component subscribes?**

The subscriber does not receive that previously published message merely because it subscribes later. LMS should be treated as message-based communication rather than a persistent message store.

---

### Scenario 4

**How do you stop receiving LMS messages?**

Use:

```javascript
unsubscribe(this.subscription);
```

and clear the reference:

```javascript
this.subscription = null;
```

---

### Scenario 5

**Where is the LMS message structure defined?**

The message channel metadata defines the message fields.

Example:

```xml
<lightningMessageFields>
    <fieldName>lmsData</fieldName>
</lightningMessageFields>
```

# 30. LMS vs Custom Event vs Public Property

| Feature | `@api` | Custom Event | LMS |
|---|---|---|---|
| Parent → Child | ✅ | ❌ | ✅ |
| Child → Parent | ❌ | ✅ | ✅ |
| Unrelated Components | ❌ | ❌ | ✅ |
| Requires Direct Hierarchy | Usually | Yes | No |
| Uses Message Channel | ❌ | ❌ | ✅ |
| Cross-component communication | Limited | Limited | Strong |
| Best use case | Component API | Parent-child event | Decoupled communication |

# 31. Common Mistakes

### Mistake 1 – Wrong Message Channel import

Incorrect:

```javascript
import SAMPLEMC from '@salesforce/messageChannel/WrongChannel__c';
```

Make sure the API name matches the actual message channel.

---

### Mistake 2 – Not using MessageContext

The LMS context must be available.

```javascript
@wire(MessageContext)
context;
```

---

### Mistake 3 – Wrong message structure

If the subscriber expects:

```javascript
message.lmsData.value
```

the publisher must send a compatible structure:

```javascript
{
    lmsData: {
        value: this.inputValue
    }
}
```

---

### Mistake 4 – Not storing subscription

Do not unnecessarily write:

```javascript
subscribe(...);
```

without retaining the returned subscription if you later need to unsubscribe.

Prefer:

```javascript
this.subscription = subscribe(...);
```

---

### Mistake 5 – Forgetting to unsubscribe

If a component no longer needs the subscription, unsubscribe from it.

# 33. One-Line Interview Definitions

**LMS:** A Salesforce service used for communication between Lightning components through message channels.

**Message Channel:** A metadata component that defines the channel through which LMS messages are exchanged.

**publish():** Sends data through a message channel.

**subscribe():** Registers a listener to receive messages from a message channel.

**unsubscribe():** Removes an existing subscription.

**MessageContext:** Provides the context required to interact with LMS.

**APPLICATION_SCOPE:** Allows a subscription to receive messages at application scope.

**Publisher:** The component that sends the LMS message.

**Subscriber:** The component that receives the LMS message.
