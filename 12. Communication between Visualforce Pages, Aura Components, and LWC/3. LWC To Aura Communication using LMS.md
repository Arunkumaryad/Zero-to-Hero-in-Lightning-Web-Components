# LWC To Aura Communication using LMS

## Overview

This project demonstrates **LWC to Aura communication using Salesforce
Lightning Message Service (LMS)**.

**Lightning Message Service (LMS)** is a Salesforce service that enables
communication between Lightning components through a Lightning Message
Channel.

LMS can be used for:

-   LWC ↔ LWC
-   LWC ↔ Aura
-   Aura ↔ LWC
-   Aura ↔ Aura

It is especially useful when components are unrelated or do not have a
direct parent-child relationship.

## Communication Architecture

``` text
             SampleMessageChannel__c
                       |
          +------------+------------+
          |                         |
          v                         v
      LWC Component A         Aura Component X
        Publisher                Publisher
          |                         |
          +------------+------------+
                       |
                       v
                LMS Message Channel
                       |
             +---------+---------+
             |                   |
             v                   v
        LWC Subscriber      Aura Subscriber
```

# 1. Lightning Message Service

### Definition

**Lightning Message Service is a Salesforce service used to communicate
between Lightning components using a Lightning Message Channel.**

It allows components to communicate without requiring a direct
parent-child relationship.

------------------------------------------------------------------------

# 2. Why Use LMS?

Normal LWC communication can use:

-   `@api`
-   Custom Events

But these approaches are most useful when components have a direct
hierarchy.

LMS is appropriate when communication is required between independent or
loosely coupled components.

For example:

``` text
LWC A  <---- LMS ---->  Aura X
```

------------------------------------------------------------------------

# 3. Lightning Message Channel

A **Lightning Message Channel** is the metadata definition that provides
the communication channel used by LMS.

Example:

``` xml
<?xml version="1.0" encoding="UTF-8"?>
<LightningMessageChannel xmlns="http://soap.sforce.com/2006/04/metadata">
    <masterLabel>SampleMessageChannel</masterLabel>
    <isExposed>true</isExposed>
    <description>Message Channel to Pass Data</description>

    <lightningMessageFields>
        <fieldName>lmsData</fieldName>
        <description>This is the field to pass data</description>
    </lightningMessageFields>
</LightningMessageChannel>
```

### Important elements

  Element                    Purpose
  -------------------------- -------------------------------------
  `masterLabel`              Label of the message channel
  `isExposed`                Makes the channel available for use
  `description`              Describes the channel
  `lightningMessageFields`   Defines fields in the message
  `fieldName`                Name of the message field

# 4. Actual Definition from the Screenshot

The screenshot states:

> **Add lightning:messageChannel component to Aura Component**

The code shown is:

``` xml
<lightning:messageChannel
    type="SampleMessageChannel__c"
    aura:id="SampleMessageChannel"
    onMessage="{!c.handleMessage}"
    scope="APPLICATION"/>
```

### Meaning

`type` identifies the message channel:

``` xml
type="SampleMessageChannel__c"
```

`aura:id` gives the channel an Aura ID:

``` xml
aura:id="SampleMessageChannel"
```

This allows the controller to find it with:

``` javascript
component.find("SampleMessageChannel")
```

`onMessage` specifies the controller action that handles incoming
messages:

``` xml
onMessage="{!c.handleMessage}"
```

`scope="APPLICATION"` configures application-level message scope.

# 7. Aura Controller

Complete controller from the example:

``` javascript
({
    handleMessage: function(component, message) {

        console.log('LMS Message Received >>>>', message);

        if (message) {

            var lmsData = message.getParam('lmsData');

            console.log('LMS Data >>>>', lmsData);

            if (lmsData) {
                component.set(
                    'v.messageReceived',
                    lmsData.value
                );
            }
        }
    },

    inputHandler: function(component, event) {

        console.log(
            'Input Handler Called >>>>>>>',
            event.target.value
        );

        component.set(
            'v.messageValue',
            event.target.value
        );
    },

    publishMessage: function(component) {

        var msg = component.get('v.messageValue');

        var message = {
            lmsData: {
                value: msg
            }
        };

        console.log(
            'Publishing Message >>>>',
            message
        );

        component
            .find('SampleMessageChannel')
            .publish(message);
    }
})
```

# 9. `handleMessage()` Explained

```javascript
handleMessage: function(component, message) {

    if (message) {

        var lmsData =
            message.getParam('lmsData');

        if (lmsData) {

            component.set(
                'v.messageReceived',
                lmsData.value
            );
        }
    }
}
```

Flow:

```text
LMS message
    ↓
handleMessage()
    ↓
message.getParam("lmsData")
    ↓
lmsData.value
    ↓
component.set()
    ↓
v.messageReceived
    ↓
UI
```

# 17. Why `aura:id` Is Important

The Aura component contains:

```xml
aura:id="SampleMessageChannel"
```

The controller then finds the channel with:

```javascript
component.find("SampleMessageChannel")
```

Therefore, these two names must match.

```text
aura:id
   ↓
component.find()
```

If the ID is incorrect, the controller cannot correctly reference the message channel.

# 18. Application Scope

Aura:

```xml
scope="APPLICATION"
```

LWC equivalent:

```javascript
APPLICATION_SCOPE
```

Example:

```javascript
{
    scope: APPLICATION_SCOPE
}
```

Application scope is useful when the message needs to be available across the Lightning application.

# 22. Important LMS APIs / Features

| API / Feature | Purpose |
|---|---|
| `publish()` | Sends a message |
| `subscribe()` | Registers a listener in LWC |
| `unsubscribe()` | Removes an LWC subscription |
| `MessageContext` | Provides LMS context in LWC |
| `APPLICATION_SCOPE` | Application-level LWC subscription |
| `lightning:messageChannel` | Connects Aura to LMS |
| `onMessage` | Handles incoming Aura messages |
| `message.getParam()` | Reads an Aura message parameter |
| `component.find()` | Finds the Aura message channel |

# 23. LMS vs Custom Event vs `@api`

| Feature | `@api` | Custom Event | LMS |
|---|---|---|---|
| Parent → Child | ✅ | ❌ | ✅ |
| Child → Parent | ❌ | ✅ | ✅ |
| Unrelated LWC | ❌ | ❌ | ✅ |
| LWC ↔ Aura | ❌ | ❌ | ✅ |
| Direct hierarchy required | Usually | Yes | No |
| Message Channel | ❌ | ❌ | ✅ |
| Best for decoupled communication | ❌ | ❌ | ✅ |

### Interview rule

If asked:

> Two unrelated Lightning components need to communicate. What would you use?

Answer:

> **Lightning Message Service with a Lightning Message Channel, because LMS provides decoupled communication between Lightning components, including LWC and Aura.**

# 24. Interview Questions

## 1. What is Lightning Message Service?

LMS is a Salesforce service that enables communication between Lightning components through Lightning Message Channels.

## 2. Can LMS communicate between LWC and Aura?

Yes.

```text
LWC ↔ LWC
LWC ↔ Aura
Aura ↔ LWC
Aura ↔ Aura
```

## 3. What is a Lightning Message Channel?

It is a Salesforce metadata component that defines the channel through which LMS messages are exchanged.

## 4. How do you add LMS to an Aura component?

Use:

```xml
<lightning:messageChannel
    type="SampleMessageChannel__c"

```

Use:

```javascript
component
    .find("SampleMessageChannel")
    .publish(message);
```

## 6. How does Aura receive a message?

Use:

```xml
onMessage="{!c.handleMessage}"
```

and implement:

```javascript
handleMessage: function(component, message) {
    // process message
}
```

## 7. How do you read the payload in Aura?

Use:

```javascript
message.getParam("lmsData")
```

and then:

```javascript
message.getParam("lmsData").value
```

## 8. Why use `aura:id`?

It allows the controller to locate the message channel:

```javascript
component.find("SampleMessageChannel")
```

## 9. What is Application Scope?

Application scope allows LMS communication at the application level.

Aura:

```xml
scope="APPLICATION"
```

LWC:

```javascript
APPLICATION_SCOPE
```

## 10. Can the same message channel be used by LWC and Aura?

Yes. The same Lightning Message Channel can act as the common communication channel.

# 26. Common Mistakes

### Mistake 1 – Wrong Message Channel API Name

Make sure:

```text
SampleMessageChannel__c
```

matches the actual message channel API name.

### Mistake 2 – Wrong `aura:id`

If the component has:

```xml
aura:id="SampleMessageChannel"
```

use:

```javascript
component.find("SampleMessageChannel")
```

### Mistake 3 – Incorrect payload

If the receiver expects:

```javascript
lmsData.value
```

send:

```javascript
{
    lmsData: {
        value: "Hello"
    }
}
```

### Mistake 4 – Missing `onMessage`

Aura must specify:

```xml
onMessage="{!c.handleMessage}"
```

to invoke the controller when a message is received.

### Mistake 5 – Wrong API for the framework

Aura:

```javascript
message.getParam("lmsData")
```

LWC:

```javascript
message.lmsData
```

# 28. One-Line Interview Definitions

**LMS:** Salesforce service used for communication between Lightning components through message channels.

**Lightning Message Channel:** Metadata component that defines the channel used for LMS communication.

**`lightning:messageChannel`:** Aura component used to connect an Aura component to a Lightning Message Channel.

**`onMessage`:** Aura handler that specifies the controller action executed when a message is received.

**`message.getParam()`:** Aura method used to retrieve a parameter from the LMS message payload.

**`component.find()`:** Aura method used to locate a component using its `aura:id`.

**`publish()`:** Sends a message through the message channel.

**`subscribe()`:** Registers a listener to receive messages in LWC.

**`unsubscribe()`:** Removes an existing LWC LMS subscription.

**`APPLICATION_SCOPE`:** Application-level scope used for an LWC LMS subscription.
