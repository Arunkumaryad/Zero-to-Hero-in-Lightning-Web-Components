# Modules import and export

> **JavaScript Modules** allow you to split your code into multiple files and share variables, functions, classes, or objects between them. This makes your code organized, reusable, and easier to maintain.

Modules are widely used in **Lightning Web Components (LWC)** because every LWC component is built using JavaScript modules.

---

# 📖 Overview

As applications grow, writing all the code in a single JavaScript file becomes difficult to manage.

JavaScript Modules solve this problem by allowing developers to:

- Export variables and functions from one file.
- Import them into another file.
- Reuse the same code in multiple places.

Modules improve **code organization, readability, maintainability, and reusability**.

# 📖 Actual Definition (Based on the Video)

## Export

**Exporting** - Use **export** keyword to export many variables or many methods from a file.

Example:

```javascript
export const name = "nikhil";

export function getName() {
    return "nikhil";
}
```

---

## Default Export

**Default export** - Use **export default** keyword to export only one variable or a method from a file.

Example:

```javascript
export default user = "salesforce";
```

---

## Import

**Importing** - Use **import** keyword to import variable or method from a given file path or module.

### Multiple imports

```javascript
import { name, getName } from './filepath';
```

### Imports all exported members

```javascript
import * as Utils from './filepath';
```

### Imports a module with a default member

```javascript
import user from './filepath';
```

# What is a JavaScript Module?

A **module** is simply a JavaScript file that contains reusable code.

For example,

```
math.js
```

can contain

```javascript
function add(a, b) {
    return a + b;
}
```

Another file can reuse it instead of writing the same function again.

# Export

## Definition

The **export** keyword is used to make variables, functions, classes, or objects available for use in another JavaScript file.

A file can have **multiple named exports**.

---

## Syntax

```javascript
export const variableName = value;
```

or

```javascript
export function functionName() {

}
```

---

## Example

### utils.js

```javascript
export const name = "Nikhil";

export function getName() {
    return "Nikhil";
}
```

---

# Multiple Named Exports

A file can export many variables and functions.

```javascript
export const company = "Salesforce";

export const city = "Noida";

export function greet() {
    return "Welcome";
}
```

---

# Default Export

## Definition

The **default export** allows you to export **only one value** (variable, function, class, or object) as the default member of a module.

Each JavaScript file can have **only one default export**.

---

## Syntax

```javascript
export default value;
```

---

## Example

```javascript
const user = "Salesforce";

export default user;
```

---

# Import

## Definition

The **import** keyword is used to use exported variables, functions, classes, or objects from another JavaScript file.

---

## Syntax

```javascript
import { variable } from "./file";
```

---

# Import Named Export

Suppose

### utils.js

```javascript
export const company = "Salesforce";
```

Another file

```javascript
import { company } from "./utils.js";

console.log(company);
```

Output

```
Salesforce
```

---

# Import Multiple Members

If multiple items are exported,

```javascript
export const name = "Arun";

export const city = "Delhi";

export function greet() {

}
```

Import them like this:

```javascript
import { name, city, greet } from "./utils.js";
```

---

# Import All Members

Instead of importing each member individually, you can import everything.

Syntax

```javascript
import * as Utils from "./utils.js";
```

Example

```javascript
import * as Utils from "./utils.js";

console.log(Utils.name);

Utils.greet();
```

Output

```
Arun
```

---

# Import Default Export

Suppose

```javascript
export default "Salesforce";
```

Import

```javascript
import company from "./utils.js";

console.log(company);
```

Output

```
Salesforce
```

Notice that curly braces `{}` are **not** used with default imports.

---

# Named Export vs Default Export

| Named Export | Default Export |
|--------------|----------------|
| Uses `export` keyword | Uses `export default` keyword |
| Multiple exports allowed | Only one default export per file |
| Imported using `{}` | Imported without `{}` |
| Name must match while importing | Import name can be anything |

---

# Complete Example

### utils.js

```javascript
export const company = "Salesforce";

export const city = "Noida";

export function greet() {
    return "Welcome";
}

const user = "Arun";

export default user;
```

---

### app.js

```javascript
import user, { company, city, greet } from "./utils.js";

console.log(user);

console.log(company);

console.log(city);

console.log(greet());
```

Output

```
Arun

Salesforce

Noida

Welcome
```

# Best Practices

✅ Export only what is needed.

✅ Use named exports when exporting multiple members.

✅ Use default export only when a file has one main functionality.

✅ Keep module files small and focused.

✅ Use meaningful names for exported members.

# Common Mistakes

## Mistake 1

Importing named export without braces.

❌ Wrong

```javascript
import company from "./utils";
```

If it is a named export.

---

### Correct

```javascript
import { company } from "./utils";
```

---

## Mistake 2

Using braces with default export.

❌ Wrong

```javascript
import { user } from "./utils";
```

---

### Correct

```javascript
import user from "./utils";
```

---

## Mistake 3

Using multiple default exports.

❌ Wrong

```javascript
export default user;

export default company;
```

A module can have only **one** default export.

# Key Takeaways

- JavaScript modules help organize and reuse code across multiple files.
- Use the **export** keyword to export multiple variables or functions.
- Use **export default** to export one primary member from a module.
- Use the **import** keyword to access exported members in another file.
- Named exports require curly braces `{}`, while default exports do not.
- LWC heavily relies on modules to import Apex methods, labels, navigation utilities, static resources, and other Salesforce APIs.

---

# Summary

JavaScript Modules are a powerful feature that allows developers to split code into separate, reusable files. The `export` keyword is used to expose variables and functions, while the `import` keyword is used to use them in other files. Named exports allow multiple members to be shared, whereas `export default` is used when a module has a single primary member. In **Lightning Web Components (LWC)**, modules are essential for importing Apex methods, Salesforce resources, labels, and framework utilities, making applications more modular, maintainable, and scalable.
