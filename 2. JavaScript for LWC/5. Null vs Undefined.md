# Null vs Undefined

> `null` and `undefined` are two special values in JavaScript that represent the absence of a value. Although they may appear similar, they are used in different situations and behave differently during comparisons.

---

# 📖 Overview

In JavaScript, developers often confuse **`null`** and **`undefined`** because both represent "no value". However, they have different meanings:

- **undefined** means a variable has been declared but has not been assigned any value.
- **null** is an intentional assignment that represents an empty or unknown value.

Understanding the difference between these two values is essential for writing clean and bug-free JavaScript code.

# What is Undefined?

A variable that has been declared but has **not been assigned a value** automatically gets the value **`undefined`**.

### Example

```javascript
var x;

console.log(x);
```

Output

```
undefined
```

### Explanation

- Variable exists.
- No value has been assigned.
- JavaScript automatically assigns `undefined`.

---

# What is Null?

`null` is a value assigned **intentionally** by the developer to indicate that a variable currently has **no value**.

### Example

```javascript
var y = null;

console.log(y);
```

Output

```
null
```

### Explanation

Here, the developer explicitly assigns `null` to indicate an empty or unknown value.

---

# Difference Between Undefined and Null

| Feature | undefined | null |
|----------|-----------|------|
| Meaning | Variable declared but not assigned | Empty or unknown value assigned intentionally |
| Assigned By | JavaScript automatically | Developer explicitly |
| typeof | `"undefined"` | `"object"` |
| Purpose | Indicates missing initialization | Indicates intentional absence of value |


Output


---

```javascript
var y = null;

console.log(typeof y);
```

Output


> **Note:** Although `null` is not an object, JavaScript returns `"object"` because of a historical language design bug that has been preserved for backward compatibility.

# Equality Comparison

JavaScript provides two equality operators.

---

## 1. Equality Operator (`==`)

The `==` operator compares **only the values**.

It performs **type conversion (type coercion)** if the data types are different.

### Syntax

```javascript
value1 == value2
```

### Example

```javascript
console.log(100 == "100");
```

Output

```
true
```

Explanation:

- `"100"` is converted to the number `100`.
- Values become equal.

---

### Another Example

```javascript
console.log(undefined == null);
```

Output

```
true
```

Because JavaScript considers both values loosely equal.

---

## 2. Strict Equality Operator (`===`)

The `===` operator compares **both value and data type**.

No type conversion is performed.

### Syntax

```javascript
value1 === value2
```

### Example

```javascript
console.log(100 === "100");
```

Output

```
false
```

Explanation:

- Values appear the same.
- Data types are different.
- Comparison returns `false`.

---

### Null vs Undefined

```javascript
console.log(undefined === null);
```

Output

```
false
```

Explanation:

- Values are different.
- Data types are also different.

# When Should You Use Undefined?

Use `undefined` when:

- A variable has not yet received a value.
- A function does not explicitly return anything.
- A property does not exist on an object.

Example

```javascript
let age;

console.log(age);
```

Output

```
undefined
```

---

# When Should You Use Null?

Use `null` when you intentionally want to indicate that a variable has **no value**.

Example

```javascript
let user = null;
```

Meaning:

The variable exists, but currently does not refer to any user.

---

# Best Practices

✅ Use `null` to represent an intentionally empty value.

✅ Let JavaScript use `undefined` naturally for uninitialized variables.

✅ Prefer `===` over `==` for comparisons to avoid unexpected type coercion.

✅ Avoid assigning `undefined` manually unless there is a specific reason.

---

# Common Mistakes

❌ Assuming `null` and `undefined` are the same.

```javascript
null === undefined
```

Output

```
false
```

---

❌ Using `==` when strict comparison is intended.

```javascript
100 == "100"
```

Returns

```
true
```

This may lead to unexpected behavior.

---

❌ Expecting `typeof null` to return `"null"`.

```javascript
typeof null
```

Output

```
object
```

# Key Takeaways

- `undefined` means a variable has been declared but not initialized.
- `null` represents an intentionally assigned empty or unknown value.
- `typeof undefined` returns `"undefined"`.
- `typeof null` returns `"object"`.
- `==` compares values with type coercion.
- `===` compares both values and data types without type coercion.
- `undefined == null` is `true`.
- `undefined === null` is `false`.
- Use `===` for safer and more predictable comparisons.

---

# Summary

`null` and `undefined` are special values that represent the absence of a value, but they are used in different situations. **`undefined`** is automatically assigned by JavaScript when a variable has not been initialized, whereas **`null`** is explicitly assigned by the developer to indicate an intentional empty or unknown value. The `typeof` operator returns `"undefined"` for `undefined` and `"object"` for `null`. When comparing values, `==` performs loose comparison with type coercion, while `===` performs strict comparison without type coercion. Understanding these differences is essential for writing reliable JavaScript and Lightning Web Components (LWC) code.
