# Conditional Rendering in LWC

This document explains **Directives** and **Conditional Rendering** in Lightning Web Components (LWC) — how to show or hide parts of your template based on a JavaScript expression, using the `if:true` and `if:false` directives.

---

## 📌 What is a Directive?

> 🔎 **Definition (from training material):**
> **Directives are special HTML attributes.** The LWC programming model has a few custom directives that let you **manipulate the DOM using markup**.

In LWC, we have **two special directives for conditional rendering**:
1. **`if:true`**
2. **`if:false`**

These directives let you decide, directly inside your HTML template, whether a block of markup should be **rendered (added to the DOM)** or **not rendered at all**, based on the value of a JavaScript expression.

---

## 1️⃣ `if:true` Directive

> 🔎 **Definition (from training material):**
> Use this directive to **render DOM elements in a template, if the expression is `true`**.

### Syntax
```html
<template if:true={expression}>
    Show me when expression is true
</template>
```

### Rules for the expression:
- The expression **can be a JavaScript identifier (property)** — e.g., `{isVisible}`.
- The expression **can be a JavaScript dot notation** that accesses a property from an object — e.g., `{user.fullName}`.
- **You can't use a ternary operator** inside the expression.
- **To compute the value of the expression, use a getter** in the JavaScript class (since computed expressions are not allowed directly in the template — see the *Getters in LWC* documentation).

---

## 2️⃣ `if:false` Directive

> 🔎 **Definition (from training material):**
> Use this directive to **render DOM elements in a template, if the expression is `false`**.

### Syntax
```html
<template if:false={expression}>
    Show me when the expression is false
</template>
```

### Rules for the expression:
- The expression **can be a JavaScript identifier (property)** — e.g., `{isVisible}`.
- The expression **can be a JavaScript dot notation** that accesses a property from an object — e.g., `{user.fullName}`.
- **You can't use a ternary operator** inside the expression.
- **To compute the value of the expression, use a getter** in the JavaScript class.

> ⚡ Notice that `if:true` and `if:false` follow the **exact same rules** — the only difference is **which value of the expression causes the block to render**.

---

## ⚠️ Falsy Values in JavaScript

Since `if:true` and `if:false` directly depend on whether an expression evaluates to a **truthy** or **falsy** value, it's important to know what JavaScript treats as **falsy**:

```javascript
// falsy values
x = 0, false, undefined, null, ""
```

Any of these values (`0`, `false`, `undefined`, `null`, or an empty string `""`) will be treated as **false** by `if:true`/`if:false` — meaning:
- `if:true={x}` → block will **NOT** render if `x` is any of the above.
- `if:false={x}` → block **WILL** render if `x` is any of the above.

Everything else (non-zero numbers, non-empty strings, objects, arrays, `true`) is considered **truthy**.

## 🧩 Full Code Example

### JavaScript Controller (`conditionalRendering.js`)

```javascript
import { LightningElement } from 'lwc';

export default class ConditionalRendering extends LightningElement {
    isVisible = false;
    name;

    handleClick() {
        this.isVisible = true;
    }

    handleNameChange(event) {
        this.name = event.target.value;
    }

    get handleName() {
        return this.name === 'hello';
    }
}
```

**Explanation:**
- `isVisible = false;` — a property initialized to `false`. This controls whether the first conditional block is shown.
- `name;` — an (initially undefined) property that will hold whatever the user types.
- `handleClick()` — runs when the **"Show Data"** button is clicked. It sets `this.isVisible = true;`, which will cause the `if:true={isVisible}` block to render.
- `handleNameChange(event)` — runs on every keystroke (`onkeyup`) in the "Enter Name" input. It updates `this.name` with the current input value using `event.target.value`.
- `get handleName() { return this.name === 'hello'; }` — this is a **getter** (as required by the directive rules, since we can't use expressions like `{name === 'hello'}` directly in the template). It returns `true` only when the user has typed exactly `"hello"`, and `false` otherwise. This getter is then used with `if:true` in the template.

### HTML Template (`conditionalRendering.html`)

```html
<template>
    <lightning-card title="Conditional Rendering">
        <div class="slds-m-around_small">
            <button class="slds-button slds-button_brand" title="Show Data" onclick={handleClick}>
                Show Data
            </button>
            <template if:true={isVisible}>
                <div>This is My first Conditional Rendering Example</div>
            </template>
            <template if:false={isVisible}>
                <div>You can not see this values.</div>
            </template>

            <lightning-input type="text" label="Enter Name" onkeyup={handleNameChange}></lightning-input>
            <template if:true={handleName}>
                <div>Hurray! you have typed correctly!.</div>
            </template>
        </div>
    </lightning-card>
</template>
```

**Explanation:**
- **"Show Data" button** — bound to `handleClick` via `onclick`. Clicking it sets `isVisible` to `true`.
- **First `<template if:true={isVisible}>` block** — renders *"This is My first Conditional Rendering Example"* **only when** `isVisible` is `true` (i.e., **after** the button is clicked).
- **Second `<template if:false={isVisible}>` block** — renders *"You can not see this values."* **only when** `isVisible` is `false` (i.e., **before** the button is clicked, since it starts as `false`).
  > 🔎 Note: Only **one** of these two blocks is ever visible at a time, since `isVisible` can't be both `true` and `false` simultaneously — this is a common pattern for building simple show/hide toggles.
- **`lightning-input` for "Enter Name"** — bound to `handleNameChange` via `onkeyup`, which updates the `name` property as the user types.
- **`<template if:true={handleName}>` block** — renders *"Hurray! you have typed correctly!."* **only when** the `handleName` getter returns `true` — i.e., only when the user has typed exactly `"hello"` into the input field.

---

## 🎯 Step-by-Step Execution Flow

1. **On page load:** `isVisible = false`, so:
   - The `if:true={isVisible}` block is **hidden**.
   - The `if:false={isVisible}` block is **shown** → *"You can not see this values."*
2. **User clicks "Show Data":** `handleClick()` sets `isVisible = true`.
   - The `if:true={isVisible}` block now **renders** → *"This is My first Conditional Rendering Example"*
   - The `if:false={isVisible}` block now **hides**.
3. **User types "hello" into "Enter Name":** On each keystroke, `handleNameChange` updates `name`.
   - Once `name` becomes exactly `"hello"`, the `handleName` getter returns `true`.
   - The `if:true={handleName}` block **renders** → *"Hurray! you have typed correctly!."*

## 📊 Summary Table

| Directive | Renders block when... | Syntax |
|---|---|---|
| **`if:true`** | The expression evaluates to a **truthy** value | `<template if:true={expression}>...</template>` |
| **`if:false`** | The expression evaluates to a **falsy** value | `<template if:false={expression}>...</template>` |

| Rule | Applies to Both Directives |
|---|---|
| Expression type | Must be a valid JS identifier (property) or dot notation (`user.fullName`) |
| Ternary operator | ❌ Not allowed inside the expression |
| Computed values | Must be computed using a **getter** in the JS class |
| Falsy values | `0`, `false`, `undefined`, `null`, `""` |

## ✅ Quick Recap

- **Directives** are special HTML attributes that let you manipulate the DOM using markup — LWC provides `if:true` and `if:false` for **conditional rendering**.
- `if:true={expr}` renders the block only when `expr` is **truthy**; `if:false={expr}` renders the block only when `expr` is **falsy**.
- Both directives only accept a **property or dot-notation expression** — no ternary operators, no inline computed expressions. For any computation, use a **getter**.
- Common falsy values to remember: `0`, `false`, `undefined`, `null`, `""`.
- A very common pattern is using `if:true` and `if:false` on the **same property** to build simple toggle-style UI (show one block, hide the other).
