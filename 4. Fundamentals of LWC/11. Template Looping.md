# Template Looping in LWC

This document explains **Template Looping** in Lightning Web Components (LWC) — how to render the same set of elements repeatedly for different data, using `for:each` and `iterator`.

---

## 📌 What is Template Looping?

> 🔎 **Definition (from training material):**
> There are many scenarios in which we have to **render the same set of elements** with mostly the **same styling** with **different data** in the HTML. To solve this issue, we have **template looping** in the LWC.

In simple words — instead of manually writing the same HTML block again and again for every item in a list (like a list of cars, employees, or CEOs), template looping lets you write the block **once** and have LWC automatically repeat it for **each item** in your array.

### Template Looping Types
1. **`for:each`**
2. **`iterator`**

Both achieve looping, but they're used in slightly different situations — explained below.

---

## 1️⃣ `for:each` Loop

> 🔎 **Definition (from training material):** Below is the syntax of the `for:each` loop.

### Syntax
```html
<template for:each={array} for:item="currentItem" for:index="index">
    -----Here your repeatable template comes-----
</template>
```

### Attributes

| Sno. | Attribute | Description |
|---|---|---|
| 1. | `for:each={array}` | `for:each` takes the **array** as an input |
| 2. | `for:item="currentItem"` | `currentItem` is the value of the current element. `currentItem` is an **alias** and can be **any name**. `for:item` holds the `currentItem`. |
| 3. | `for:index="index"` | `index` is the current element **index** in the array. `for:index` holds the `index`. |

---

## 🔑 What is `key` and Its Importance

> 🔎 **Definition (from training material):**
> - A **`key`** is a special string attribute you need to include to the **first element inside the template** when creating lists of elements.
> - **Keys help the LWC engine identify which items have changed, are added, or are removed.**
> - The best way to pick a key is to use a **string that uniquely identifies a list item among its siblings**.

### ⚠️ Important Notes about `key`:
- A **key must be a number or string** — it **can't be an object**.
- You **can't use the index as a value for the key**.

> 💡 Why this matters: If LWC can't uniquely tell items apart (e.g., if you reuse the array index as the key), it may **re-render items incorrectly** when the list changes — leading to bugs like the wrong data showing under the wrong row. Always use a value that is genuinely unique to that item (like an ID).

## 🧩 `for:each` — Full Code Example

### JavaScript Controller (`looping.js`)

```javascript
import { LightningElement } from 'lwc';

export default class Looping extends LightningElement {
    carList = ['Ford', 'Chevrolet', 'Toyota', 'Honda', 'Nissam', 'Mazda', 'Hyundai', 'Kia'];
}
```

**Explanation:**
- `carList` is a simple **array of strings** — a list of car brand names.

### HTML Template (`looping.html`)

```html
<template>
    <lightning-card title="for each loop examples">
        <div class="slds-m-around_small">
            <template for:each={carList} for:item="car">
                <div key={car}>{car}</div>
            </template>
        </div>
    </lightning-card>
</template>
```

**Explanation:**
- `<template for:each={carList} for:item="car">` — loops through every item in the `carList` array. On each iteration, the current item is stored in the alias `car`.
- `<div key={car}>{car}</div>` — this is the **first element inside the template**, so it **must** have a `key`. Here, `car` itself (the string value, e.g., `"Ford"`) is used as the key since each car name in this list is unique.
- `{car}` inside the `<div>` displays the current car name.
- **Result:** This renders a separate `<div>` for every car in the list:
  ```
  Ford
  Chevrolet
  Toyota
  Honda
  Nissam
  Mazda
  Hyundai
  Kia
  ```

## 2️⃣ `iterator` Loop

> 🔎 **Definition (from training material):**
> To apply a **special behavior to the first or last item** in a list, we prefer `iterator` **over** `for:each`.

This is the key reason to choose `iterator` instead of `for:each` — it gives you built-in access to **whether the current item is the first or last** in the list, which `for:each` does not provide directly.

### Syntax
```html
<template iterator:iteratorName={array}>
    -----Here your repeatable template comes-----
</template>
```

### Attributes

| Sno. | Attribute | Description |
|---|---|---|
| 1. | `iterator` | It's a **keyword** to tell the template that it's an **iterator loop** |
| 2. | `iteratorName` | `iteratorName` is the **value of the current element** in the loop. `iteratorName` is an **alias** and can be **any name** |
| 3. | `array` | `array` is the **data** on which we want to apply the loop |

---

## 🧩 Properties of `iterator`

> 🔎 **Definition (from training material):** Using **iterator name** you can access the following properties:

| Property | Description | Example |
|---|---|---|
| **`value`** | The **value of the item** in the list. Use this property to access the properties of the array. | `iteratorName.value.propertyName` |
| **`index`** | The **index of the item** in the list. | `iteratorName.index` |
| **`first`** | A **boolean value** indicating whether this item is the **first** item in the list. | `iteratorName.first` |
| **`last`** | A **boolean value** indicating whether this item is the **last** item in the list. | `iteratorName.last` |

---

## 🧩 `iterator` — Full Code Example

### JavaScript Controller (`looping.js`)

```javascript
import { LightningElement } from 'lwc';

export default class Looping extends LightningElement {
    carList = ['Ford', 'Chevrolet', 'Toyota', 'Honda', 'Nissam', 'Mazda', 'Hyundai', 'Kia'];

    ceoList = [
        {
            id: 1,
            company: 'Google',
            name: 'Sundar Pichai',
        },
        {
            id: 2,
            company: 'Apple',
            name: 'Tim Cook',
        },
        {
            id: 3,
            company: 'Facebook',
            name: 'Mark Zuckerberg',
        },
        {
            id: 4,
            company: 'Amazon',
            name: 'Jeff Bezos',
        }
    ];
}
```

**Explanation:**
- `ceoList` is an **array of objects**, where each object has an `id`, `company`, and `name`. This is a perfect use case for `iterator`, since we want to display a heading before the **first** item and a footer message after the **last** item.

### HTML Template (`looping.html`)

```html
<template>
    <lightning-card title="Iterator examples">
        <div class="slds-m-around_small">
            <template iterator:ceo={ceoList}>
                <div key={ceo.value.id}>
                    <ul class="slds-has-dividers_around-space">
                        <template if:true={ceo.first}>
                            <div class="slds-box slds-theme_shade">
                                <strong>
                                    List of top Companies and there CEO's.
                                </strong>
                            </div>
                        </template>
                        <li class="slds-item">
                            <strong>{ceo.value.company}</strong> <br/>
                            {ceo.value.name}
                        </li>
                        <template if:true={ceo.last}>
                            <div class="slds-box slds-theme_shade">
                                <strong>
                                    Thanks for Reading the lists.
                                </strong>
                            </div>
                        </template>
                    </ul>
                </div>
            </template>
        </div>
    </lightning-card>
</template>
```

**Explanation:**
- `<template iterator:ceo={ceoList}>` — loops through `ceoList`, using `ceo` as the **iterator alias**.
- `<div key={ceo.value.id}>` — the **first element inside the template**, so it needs a `key`. Here, `ceo.value.id` (the unique `id` field of each CEO object) is used — a much safer choice than using the array index.
- `<template if:true={ceo.first}>` — this block renders **only for the first item** in the list, using the `ceo.first` boolean property. It shows a heading: *"List of top Companies and there CEO's."*
- `<li class="slds-item"><strong>{ceo.value.company}</strong> <br/> {ceo.value.name}</li>` — this line runs for **every** item, displaying the `company` and `name` fields via `ceo.value.company` and `ceo.value.name` (using the `value` property to access object fields).
- `<template if:true={ceo.last}>` — this block renders **only for the last item** in the list, using the `ceo.last` boolean property. It shows a footer message: *"Thanks for Reading the lists."*

**Rendered Output (conceptually):**
```
List of top Companies and there CEO's.

Google
Sundar Pichai

Apple
Tim Cook

Facebook
Mark Zuckerberg

Amazon
Jeff Bezos

Thanks for Reading the lists.
```

Notice how the heading appears **only once, before the first item**, and the "Thanks for Reading" message appears **only once, after the last item** — this special first/last behavior is exactly what `iterator` is best suited for.

## 📊 Summary Table

| Concept | `for:each` | `iterator` |
|---|---|---|
| **Purpose** | Basic repeated rendering of a list | Repeated rendering **with special handling for first/last items** |
| **Syntax** | `for:each={array} for:item="currentItem" for:index="index"` | `iterator:iteratorName={array}` |
| **Access current item** | Directly via the `for:item` alias (e.g., `{car}`) | Via `iteratorName.value` (e.g., `{ceo.value.name}`) |
| **Access index** | Via `for:index` alias | Via `iteratorName.index` |
| **First item detection** | ❌ Not built-in | ✅ `iteratorName.first` (boolean) |
| **Last item detection** | ❌ Not built-in | ✅ `iteratorName.last` (boolean) |
| **`key` requirement** | Required on the first element inside the template | Required on the first element inside the template |

---

## ✅ Quick Recap

- **Template looping** solves the problem of repeating the same HTML structure for different data — LWC offers **`for:each`** and **`iterator`** for this.
- **`for:each`** is the simpler, general-purpose loop: `for:each={array} for:item="currentItem" for:index="index"`.
- **`iterator`** is preferred when you need **special behavior on the first or last item** in the list, using `iteratorName.first` and `iteratorName.last`.
- The **`iterator`** alias also exposes `value` (the item's data) and `index` (its position).
- **Always add a `key`** to the first element inside a looping template — it must be a **unique string/number**, and **never** the array index — so LWC can correctly track added, removed, or changed items.
