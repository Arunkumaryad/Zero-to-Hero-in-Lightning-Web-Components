# 1. Component Naming Convention

> **The folder and its files must follow these naming rules.**

A Lightning Web Component has a specific naming convention that must be followed when creating the component.

The component:

- Must begin with a lowercase letter.
- Can contain alphanumeric characters.
- Can contain underscore.
- Must be unique in the namespace.
- Can't include whitespace.
- Can't end with an underscore.
- Can't contain two consecutive underscores.
- Can't contain a hyphen (dash).

---

# 2. Naming Rules Explained

## 2.1 Must Begin with a Lowercase Letter

The component name must start with a lowercase letter.

### ✅ Correct

    helloWorld
    myComponent
    accountDetails
    contactList

### ❌ Incorrect

    HelloWorld
    MyComponent
    AccountDetails

The first character must be lowercase.

---

## 2.2 Alphanumeric or Underscore Characters

The component name can contain alphanumeric characters and underscores.

### Alphanumeric means:

- `a-z`
- `A-Z`
- `0-9`

### ✅ Correct

    helloWorld
    account123
    account_details
    contactList2

### ❌ Incorrect

    account-details
    account details
    account.details

---

## 2.3 Must Be Unique in the Namespace

The component name must be unique in the namespace.

For example, you should not create two components with the same name:

    myComponent
    myComponent

Instead, use meaningful and unique names:

    accountDetails
    contactDetails
    opportunityDetails

---

## 2.4 Cannot Include Whitespace

Whitespace or spaces are not allowed in an LWC component name.

### ❌ Incorrect

    hello world
    account details
    my component

### ✅ Correct

    helloWorld
    accountDetails
    myComponent

Use camelCase instead of spaces.

---

## 2.5 Cannot End with an Underscore

A component name cannot end with an underscore.

### ❌ Incorrect

    helloWorld_
    accountDetails_

### ✅ Correct

    helloWorld
    accountDetails

---

## 2.6 Cannot Contain Two Consecutive Underscores

Two consecutive underscores are not allowed.

### ❌ Incorrect

    hello__world
    account__details

### ✅ Correct

    hello_world
    account_details

Only use a single underscore when required.

---

## 2.7 Cannot Contain a Hyphen

A hyphen or dash (`-`) is not allowed in the component name.

### ❌ Incorrect

    hello-world
    account-details
    my-component

### ✅ Correct

    helloWorld
    accountDetails
    myComponent

---

# 3. Two Ways to Create Component

There are two common ways to create a Lightning Web Component.

### 1. Using Terminal

We can create an LWC component using Salesforce CLI from the terminal.

### 2. Using Command Palette

We can create an LWC component directly from Visual Studio Code using the Salesforce Command Palette.

Both methods create the required LWC component structure.

---

# 4. Method 1 - Using Terminal

The LWC component can be created using the Salesforce CLI command.

### Current Salesforce CLI Command

    sf lightning generate component --type lwc --name helloWorld

### Legacy SFDX Command

The training material may use the older SFDX command:

    sfdx force:lightning:component:create --type lwc -n helloWorld

---

## Command Explanation

    sf

Salesforce CLI command.

    lightning

Specifies Lightning-related commands.

    generate component

Creates a component.

    --type lwc

Specifies that the component type is Lightning Web Component.

    --name helloWorld

Specifies the name of the component.

---

## Example

    sf lightning generate component --type lwc --name helloWorld

This creates a Lightning Web Component named:

    helloWorld

---

# 5. Method 2 - Using Command Palette

We can also create an LWC component using Visual Studio Code's Command Palette.

## Steps

### Step 1

Open the Salesforce project in Visual Studio Code.

### Step 2

Open Command Palette.

Use:

    Ctrl + Shift + P

### Step 3

Search for:

    SFDX: Create Lightning Web Component

### Step 4

Press:

    Enter

### Step 5

Enter the desired component name.

Example:

    helloWorld

### Step 6

Press:

    Enter

### Step 7

Choose the default folder/path when prompted.

The LWC component will then be created automatically.

---

# 6. What Gets Created

When we create an LWC component, Salesforce creates a component folder.

For example:

    helloWorld/
    │
    ├── helloWorld.html
    ├── helloWorld.js
    ├── helloWorld.js-meta.xml
    └── helloWorld.css

The CSS file can be added when component-specific styling is required.

---

# 7. Understanding Generated Files

## 7.1 HTML File

Example:

    helloWorld.html

The HTML file contains the UI/template of the component.

Example:

    <template>
        <lightning-card title="Hello World">
            <p>Hello Salesforce!</p>
        </lightning-card>
    </template>

### Purpose

The HTML file is responsible for:

- Component UI
- HTML structure
- Lightning Base Components
- Displaying data

---

## 7.2 JavaScript File

Example:

    helloWorld.js

The JavaScript file contains the component's logic.

Example:

    import { LightningElement } from 'lwc';

    export default class HelloWorld extends LightningElement {

    }

### Purpose

The JavaScript file is responsible for:

- Component logic
- Variables
- Methods
- Event handling
- Calling Apex
- Processing data

---

## 7.3 Metadata XML File

Example:

    helloWorld.js-meta.xml

The metadata XML file controls the component's metadata and where the component can be used.

Example:

    <?xml version="1.0" encoding="UTF-8"?>
    <LightningComponentBundle xmlns="http://soap.sforce.com/2006/04/metadata">

        <apiVersion>XX.0</apiVersion>

        <isExposed>true</isExposed>

        <targets>
            <target>lightning__HomePage</target>
        </targets>

    </LightningComponentBundle>

### Purpose

The metadata file controls:

- API version
- Component exposure
- Lightning page targets
- Where the component can be used

---

## 7.4 CSS File

Example:

    helloWorld.css

The CSS file is used for component-specific styling.

Example:

    p {
        font-size: 20px;
    }

### Purpose

The CSS file is responsible for:

- Styling
- Fonts
- Spacing
- Layout
- Component-specific appearance

---

# 10. Interview Questions

## Q1. What is an LWC component?

A Lightning Web Component is a reusable UI component built using HTML, JavaScript, CSS, and Salesforce's Lightning Web Components programming model.

---

## Q2. What naming convention should an LWC component follow?

An LWC component name:

1. Must begin with a lowercase letter.
2. Can contain alphanumeric characters.
3. Can contain underscores.
4. Must be unique in the namespace.
5. Cannot contain whitespace.
6. Cannot end with an underscore.
7. Cannot contain two consecutive underscores.
8. Cannot contain a hyphen.

---

## Q3. Can an LWC component name start with an uppercase letter?

No.

### ❌ Incorrect

    HelloWorld

### ✅ Correct

    helloWorld

---

## Q4. Can we use spaces in an LWC component name?

No.

### ❌ Incorrect

    hello world

### ✅ Correct

    helloWorld

---

## Q5. Can an LWC component name contain a hyphen?

No.

### ❌ Incorrect

    hello-world

### ✅ Correct

    helloWorld

---

## Q6. Can an LWC component name contain an underscore?

Yes.

Example:

    account_details

However, the component cannot end with an underscore and cannot contain two consecutive underscores.

---

## Q7. What files are commonly present in an LWC component?

A typical LWC component can contain:

    componentName/
    │
    ├── componentName.html
    ├── componentName.js
    ├── componentName.js-meta.xml
    └── componentName.css

---

## Q8. What is the purpose of the HTML file?

The HTML file defines the component's UI/template.

---

## Q9. What is the purpose of the JavaScript file?

The JavaScript file contains the component's logic and behavior.

---

## Q10. What is the purpose of the JavaScript Metadata XML file?

The metadata XML file defines component metadata and controls where the component can be exposed.

---

## Q11. How can we create an LWC from VS Code?

    SFDX: Create Lightning Web Component
