# 1. Component Folder Structure

A Lightning Web Component is stored inside its own component folder.

For example, if the component name is:

    helloWorld

The component folder can contain:

    helloWorld/
    │
    ├── helloWorld.html
    ├── helloWorld.js
    ├── helloWorld.js-meta.xml
    ├── helloWorld.css
    ├── helloWorld.svg
    ├── moreSharedCode.js
    │
    └── __tests__/
        └── helloWorld.test.js

An LWC folder keeps the component's UI, JavaScript logic, metadata, styling, shared code, and tests organized together.

# 4. Default Files

The default files shown in the screenshot are:

    helloWorld.html
    helloWorld.js
    helloWorld.js-meta.xml

These are the main files of an LWC component.

---

## 4.1 HTML File

### `helloWorld.html`

The HTML file contains the UI/template of the component.

Example:

    <template>
        <lightning-card title="Hello World">
            <div class="slds-p-around_medium">
                Hello Salesforce!
            </div>
        </lightning-card>
    </template>

### Purpose

The HTML file is responsible for:

- Component UI
- HTML structure
- Lightning Base Components
- Displaying data
- Template markup

---

## 4.2 JavaScript File

### `helloWorld.js`

The JavaScript file contains the component's logic.

Example:

    import { LightningElement } from 'lwc';

    export default class HelloWorld extends LightningElement {

    }

### Purpose

The JavaScript file is responsible for:

- Component logic
- Variables
- Properties
- Methods
- Event handling
- Calling Apex
- Processing data
- User interactions

---

## 4.3 Metadata XML File

### `helloWorld.js-meta.xml`

The metadata XML file controls the component's metadata and where the component can be used.

Example:

    <?xml version="1.0" encoding="UTF-8"?>
    <LightningComponentBundle xmlns="http://soap.sforce.com/2006/04/metadata">

        <apiVersion>XX.0</apiVersion>

        <isExposed>true</isExposed>

        <targets>
            <target>lightning__HomePage</target>
        </targets>

    </LightningComponentBundle>

### Purpose

The metadata file controls:

- API version
- Component exposure
- Lightning page targets
- Where the component can be used
- Component configuration

# 6. Additional JavaScript Files

The screenshot shows:

    moreSharedCode.js

The definition shown in the screenshot is:

> **Any number of JS files you can add.**

Additional JavaScript files can be used for reusable or shared JavaScript logic.

Example:

    helloWorld/
    │
    ├── helloWorld.html
    ├── helloWorld.js
    ├── helloWorld.js-meta.xml
    ├── moreSharedCode.js
    ├── helper.js
    └── utils.js

### Example

`moreSharedCode.js`

    export function calculateTotal(price, quantity) {
        return price * quantity;
    }

The main component can import it:

    import { LightningElement } from 'lwc';
    import { calculateTotal } from './moreSharedCode';

    export default class HelloWorld extends LightningElement {

        total = calculateTotal(100, 5);

    }

This keeps reusable logic separate from the main component JavaScript file.

    accountDetails

    accountDetails/
    │
    ├── accountDetails.html

    ├── accountDetails.js-meta.xml

    ├── accountDetails.svg
    ├── helper.js

    └── __tests__/
        └── accountDetails.test.js

## `accountDetails.html`

    <template>

        <lightning-card title="Account Details">

            <div class="slds-p-around_medium">
                Account Information
            </div>

        </lightning-card>

    </template>

**Responsibility:**

    HTML → UI / Template

---

## `accountDetails.js`

    import { LightningElement } from 'lwc';

    export default class AccountDetails extends LightningElement {

    }

**Responsibility:**

    JavaScript → Component Logic

---

## `accountDetails.js-meta.xml`

    <?xml version="1.0" encoding="UTF-8"?>

    <LightningComponentBundle
        xmlns="http://soap.sforce.com/2006/04/metadata">

    Metadata XML → Configuration / Exposure

---

## `accountDetails.css`

    .title {
        font-weight: bold;
    }

**Responsibility:**

    CSS → Styling

---

## `helper.js`

        return `${firstName} ${lastName}`;
    }

    Additional JS → Helper / Shared Code

---

Location:

    __tests__/accountDetails.test.js

          │     ↓

          │
          ├── Additional JS
          │     ↓
          │    Shared Code

              Testing

    JS    → Logic

    CSS   → Styling

# 13. Key Takeaways

- Every LWC component has its own folder.
- The HTML file contains the component UI/template.
- The JavaScript file contains component logic.
- The `.js-meta.xml` file contains component metadata/configuration.
- CSS can be used for component-specific styling.
- SVG can be included as an SVG resource.
- Additional JavaScript files can be added for shared/helper code.
- Test files are placed inside the `__tests__` folder.
- The test file uses the component name with the `.test.js` extension.
- The folder structure keeps UI, logic, metadata, styling, shared code, and testing organized.
