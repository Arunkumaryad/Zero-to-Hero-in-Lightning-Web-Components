# Different Naming Conventions Available in LWC

This document explains the different **naming conventions** used in **Lightning Web Components (LWC)** development. Understanding these conventions is important because Salesforce (and JavaScript in general) expects specific casing styles for different parts of a component — using the wrong case can even break your component.

---

## 📌 What is a Naming Convention?

A naming convention is a set of rules used to decide how to name things (files, folders, variables, classes, HTML tags, etc.) in a consistent and readable way. In LWC, there are **3 main naming conventions** that every developer must know.

---

## 1. camelCase

> **Definition:** Each word in the middle of the phrase begins with a capital letter, but the **first word starts with a lowercase letter**.

- The first letter of the entire name is **small**.
- Every new word after that starts with a **capital letter**.
- There are **no spaces, underscores, or hyphens** between words.

**Example:**
```
helloWorld
```

**Where it is used in LWC:**
- **Component Name** (the folder/file name of the component itself)
  - Example: `helloWorld`, `contactList`, `schoolBookSellerWizard`

---

## 2. PascalCase

> **Definition:** It is the same as camelCase, except the **first letter is also always capitalized**.

- Every word (including the first one) starts with a **capital letter**.
- No spaces, underscores, or hyphens between words.

**Example:**
```
HelloWorld
```

**Where it is used in LWC:**
- **Component Class Name** (the JavaScript class defined inside the `.js` file)
  - Example:
    ```javascript
    export default class HelloWorld extends LightningElement {
        // your code
    }
    ```

---

## 3. kebab-case

> **Definition:** The phrase is converted to **all lowercase letters**, with a **hyphen (-)** separating each word.

- Everything is in **small letters**.
- Words are separated using a **hyphen (`-`)** instead of spaces or capital letters.

**Example:**
```
hello-world
```

**Where it is used in LWC:**
- **Component reference** (when calling/using the component inside HTML)
- **HTML attribute names**
  - Example:
    ```html
    <c-hello-world></c-hello-world>
    ```

---

## 📊 Summary Table

| Case Name   | Example      | Where It Is Used                                      |
|-------------|--------------|---------------------------------------------------------|
| camelCase   | `helloWorld` | Component Name (folder/file name)                       |
| PascalCase  | `HelloWorld` | Component Class Name (inside JS file)                    |
| kebab-case  | `hello-world`| Component reference & HTML attribute name (used in HTML) |

---

## 🧩 Practical Example

Let's say you are creating a component called **Hello World**. Here is how each naming convention applies to it:

**Folder/File structure (camelCase):**
```
helloWorld/
 ├── helloWorld.js
 ├── helloWorld.html
 ├── helloWorld.js-meta.xml
 └── helloWorld.css
```

**Inside `helloWorld.js` (PascalCase for the class name):**
```javascript
import { LightningElement } from 'lwc';

export default class HelloWorld extends LightningElement {
    greeting = 'Hello, World!';
}
```

**Using the component in another component's HTML (kebab-case):**
```html
<template>
    <c-hello-world></c-hello-world>
</template>
```

---

## ✅ Quick Tip to Remember

- **camelCase** → for the **component name** (small first letter)
- **PascalCase** → for the **class name** (capital first letter)
- **kebab-case** → for using the component in **HTML** (all small + hyphens)

Following these conventions correctly ensures your LWC components work properly and stay consistent with Salesforce's framework standards.
