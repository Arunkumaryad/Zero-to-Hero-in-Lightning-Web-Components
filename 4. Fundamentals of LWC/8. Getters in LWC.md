# Getters in LWC

This document explains **Getters** in Lightning Web Components (LWC) — what they are, why we need them, and when to use them, based on the limitations of what a template can and cannot do directly.

---

## 📌 What is a Getter and When to Use It?

As covered earlier in *"Things to Remember"*, **LWC templates do not allow computed expressions**. This means you **cannot** write logic like array indexing or arithmetic operations directly inside the curly braces `{ }` in your HTML.

### ❌ Not Allowed in Template

```javascript
// JavaScript
users = ["John", "Mike", "Smith"]
num1 = 10
num2 = 20
```

```html
<!-- These are INVALID in the template -->
<div>users[0]</div>
<div>{num1 * num2}</div>
```

- `users[0]` — you **cannot** access an array element by index directly in the template.
- `{num1 * num2}` — you **cannot** perform a **computed expression** (like multiplication) directly inside `{ }`.

> 🔎 This restriction is exactly what was mentioned earlier under "Things to remember": *LWC doesn't allow computed expressions like `Names[2]` or `{2+2}`*.

### ✅ The Solution: Getters

To work around this limitation, LWC provides **getter methods**. A getter is a special JavaScript function that **computes and returns a value**, and it can be referenced in the template **exactly like a normal property** — without parentheses `()`.

```javascript
// Example 1
users = ["John", "Mike", "Smith"]
get firstUser() {
    return this.users[0];
}

// Example 2
num1 = 10
num2 = 20
get sumOfNumbers() {
    return this.num1 * this.num2;
}
```

```html
<!-- Template -->
<div>{firstUser}</div>
<div>{sumOfNumbers}</div>
```

Notice:
- In the template, you write `{firstUser}` — **not** `{firstUser()}`. Even though `firstUser` is a method, LWC treats a getter like a **read-only property** when referenced in HTML.
- The **actual computation** (`this.users[0]` or `this.num1 * this.num2`) happens **inside the JavaScript controller**, not inside the template — which is exactly why getters solve the "no computed expressions" restriction.

## 🧩 Full Code Example

### JavaScript Controller (`helloWorld.js`)

```javascript
import { LightningElement, track } from 'lwc';

export default class HelloWorld extends LightningElement {
    fullName = 'Arun Kumar';
    title = 'Salesforce Developer';

    // Getters examples
    users = ['Arun', 'Aman', 'Ravi', 'Kundan', 'Ramesh'];

    num1 = 10;
    num2 = 20;

    get firstUser() {
        return this.users[0];
    }

    get sum() {
        return this.num1 + this.num2;
    }

    handleClick(event) {
        // ...
    }
}
```

**Explanation:**
- `users = ['Arun', 'Aman', 'Ravi', 'Kundan', 'Ramesh'];` — a normal array property holding a list of names.
- `num1 = 10;` and `num2 = 20;` — normal numeric properties.
- `get firstUser() { return this.users[0]; }` — a **getter** that returns the **first element** of the `users` array (`'Arun'`). Since array indexing (`users[0]`) is not allowed directly in the template, we compute it here in JS and expose it as `firstUser`.
- `get sum() { return this.num1 + this.num2; }` — a **getter** that returns the **sum** of `num1` and `num2` (`10 + 20 = 30`). Since arithmetic expressions are not allowed directly in the template, this getter does the calculation on the controller side.
- The `get` keyword before a method name is what makes it a **JavaScript getter** — it allows the method to be **accessed like a property** (without `()`), both from other JS code and from the HTML template.

> 💡 Note: In the screenshot, the template refers to `{sum}` — so the getter is named `sum`, and it returns `this.num1 + this.num2`.

### HTML Template (`helloWorld.html`)

```html
<template>
    <lightning-card title="@track Properties">
        <div class="slds-m-around_small">
            <lightning-input type="text" label="Enter Title" onkeyup={handleChange}></lightning-input>
            <div>{address.city} is my city</div>
        </div>
    </lightning-card>

    <lightning-card title="Getters in LWC">
        <div class="slds-m-around_small">
            <p>First user is : {firstUser}</p>
            <p>sum of {num1} and {num2} is : {sum}</p>
        </div>
    </lightning-card>
</template>
```

**Explanation:**
- The **"Getters in LWC"** card displays two lines:
  1. `First user is : {firstUser}` — calls the `firstUser` getter, which returns `this.users[0]` → displays **"Arun"**.
  2. `sum of {num1} and {num2} is : {sum}` — displays the raw values of `num1` (10) and `num2` (20) directly (since these are plain properties, not expressions), and then calls the `sum` getter to display the **computed result** → **30**.
- Notice how `{num1}` and `{num2}` are used directly (allowed, since they're plain properties), but the **calculation** `num1 + num2` is only possible through the `sum` getter — **not** by writing `{num1 + num2}` directly in the template.

## 📊 Summary Table

| Concept | Explanation |
|---|---|
| **Getter** | A JavaScript method (defined using the `get` keyword) that computes and returns a value, and can be accessed in the template like a normal property |
| **Why needed** | LWC templates **don't allow computed expressions** (like `users[0]` or `num1 * num2`) directly inside `{ }` |
| **Syntax** | `get propertyName() { return computedValue; }` |
| **Usage in Template** | Referenced without parentheses, e.g. `{firstUser}`, `{sum}` |
| **Where computation happens** | Entirely inside the JS controller — the template just displays the returned value |

---

## ✅ Quick Recap

- LWC templates **cannot** run computed expressions or array-index access directly (e.g. `{users[0]}` or `{num1 * num2}` are invalid).
- **Getters** solve this problem — define a method with the `get` keyword in your JS class, perform the computation there, and `return` the result.
- In the template, reference the getter **just like a property**, without `()` — e.g., `{firstUser}` or `{sum}`.
- Getters keep your templates clean and push all logic/computation into the JavaScript controller, which is the recommended LWC best practice.
