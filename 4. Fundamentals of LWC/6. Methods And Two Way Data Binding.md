# Methods and Two-Way Data Binding in LWC

This document explains **Two-Way Data Binding** in Lightning Web Components (LWC) — how a value can flow from the Controller to the Template, and also flow back from the Template to the Controller using **event-handling methods**.

---

## 📌 What is Two-Way Data Binding?

In the previous topic (*Local Properties and Data Binding*), we saw **one-way data binding**, where a value flows only from the **Controller (JS) → Template (HTML)**.

**Two-way data binding** extends this concept — it allows data to flow in **both directions**:
1. **Controller → Template**: The controller passes property values (like `fullname` and `title`) to the template so they can be displayed.
2. **Template → Controller**: Any change made in the template (like typing in an input field) is passed back to the controller, and the controller's property is updated with the new value.

> 🔎 **Definition (from training material):**
> - The **controller passes the `fullname` and `title` property value to the template**.
> - **Any change in the template passes the value back to the controller and updates the controller property.**

---

## 🔄 Visualizing Two-Way Data Binding

```
                    Template (HTML)
   ┌─────────────────────────────────────────────────┐
   │  My name is {fullname}   and my title is {title} │
   └─────────────────────────────────────────────────┘
              ▲                        │   ▲
              │ (fullname & title      │   │ (Title = "Admin"
              │  passed to template)   │   │  passed back on change)
              │                        ▼   │
   ┌─────────────────────────────────────────────────┐
   │  fullname = "Salesforce Troop"                    │
   │  title = "Salesforce developer"  →  title = "Admin"│
   └─────────────────────────────────────────────────┘
                    Controller (JS)
```

- **Downward flow (Controller → Template):** `fullname` and `title` are defined in the JS controller and displayed in the HTML using `{fullname}` and `{title}`.
- **Upward flow (Template → Controller):** When the user changes a value in the template (e.g., types into an input box), that change is captured through an **event**, and the controller property (`title`) is updated to reflect the new value (`"Admin"`).

This bidirectional flow is what makes it **"two-way"** data binding.

---

## 🧩 How It Works: Methods (Event Handlers)

To achieve the "Template → Controller" part of two-way binding, LWC uses **JavaScript methods called through DOM events** (like `onkeyup`, `onclick`, `onchange`, etc.). These methods read the value entered by the user in the HTML and update the corresponding local property in the JS class.

### JavaScript Controller (`helloWorld.js`)

```javascript
import { LightningElement } from 'lwc';

export default class HelloWorld extends LightningElement {
    fullName = 'Arun Kumar';
    title = 'Salesforce Developer';

    handleClick(event) {
        this.title = event.target.value;
    }
}
```

**Explanation:**
- `fullName` and `title` are **local properties**, initialized with default values.
- `handleClick(event)` is a **method** that runs whenever the bound event (in this case, `onkeyup`) is fired.
- `event` is the **event object** automatically passed to the method by LWC — it contains details about what triggered the event.
- `event.target` refers to the **HTML element** that triggered the event (here, the `lightning-input`).
- `event.target.value` gets the **current value typed by the user** inside that input field.
- `this.title = event.target.value;` updates the `title` property in the controller with the new value — this is what completes the "two-way" flow.

### HTML Template (`helloWorld.html`)

```html
<template>
    <lightning-card title="Zero to Hero LWC">
        <div class="slds-m-around_small">
            <lightning-input type="text" label="Enter Title" onkeyup={handleClick}></lightning-input>
            <div>{fullName} is a {title}</div>
        </div>
    </lightning-card>
</template>
```

**Explanation:**
- `<lightning-card title="Zero to Hero LWC">` – wraps the content in a styled Salesforce Lightning card component with a title.
- `<div class="slds-m-around_small">` – applies SLDS (Salesforce Lightning Design System) margin spacing around the content.
- `<lightning-input type="text" label="Enter Title" onkeyup={handleClick}>` – a text input field. The `onkeyup` event is bound to the `handleClick` method, meaning **every time a key is released** while typing in this field, `handleClick` runs automatically.
- `<div>{fullName} is a {title}</div>` – displays the live values of `fullName` and `title`. Since `title` updates every time the user types, this text updates **in real time**.

---

## 🎯 Step-by-Step Flow of Execution

1. Page loads → `fullName = 'Arun Kumar'` and `title = 'Salesforce Developer'` are shown:
   > *Arun Kumar is a Salesforce Developer*
2. User starts typing `"Admin"` into the **Enter Title** input box.
3. On every key release (`onkeyup`), the `handleClick(event)` method is triggered.
4. Inside `handleClick`, `event.target.value` captures whatever text is currently in the input box.
5. `this.title = event.target.value;` updates the controller's `title` property.
6. Since `title` is bound in the template using `{title}`, the UI **automatically re-renders** to show the new value:
   > *Arun Kumar is a Admin*

This is **two-way data binding in action** — template changes flow back to update the controller, and controller changes flow forward to update the template.

## 📊 Summary Table

| Concept | Explanation |
|---|---|
| **One-way binding** | Data flows only from Controller (JS) → Template (HTML) |
| **Two-way binding** | Data flows both ways — Controller → Template, and Template → Controller (via events) |
| **Method** | A JavaScript function inside the component class, triggered by a DOM event |
| **event.target** | Refers to the HTML element that triggered the event |
| **event.target.value** | Retrieves the current value of that element (e.g., text typed by the user) |
| **onkeyup** | An event handler attribute that fires the method every time a key is released in an input field |

---

## ✅ Quick Recap

- **Two-way data binding** means values can flow **both ways** — from JS to HTML, and from HTML back to JS.
- To pass a value back to the controller, we use **event-bound methods** like `handleClick(event)`.
- Inside the method, `event.target.value` is used to read the current input value.
- Updating `this.propertyName` inside the method automatically re-renders any place in the template where that property is used.
- Common events used for this include `onkeyup`, `onchange`, and `onclick`.
