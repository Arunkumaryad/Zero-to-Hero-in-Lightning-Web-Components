# Refresh Apex in LWC using `refreshApex()`

This project demonstrates how to fetch Contact records from Apex, display them in a Lightning Datatable, edit selected fields inline, save the changes using `updateRecord` from `lightning/uiRecordApi`, and refresh the displayed data without reloading the entire page.

The documentation follows the supplied screenshots and covers the agenda, source code, explanation of each important line, implementation steps, execution flow, and Salesforce interview questions.

## Agenda

The screenshots introduce these topics:

1. How to fetch data in LWC.
2. How to create a datatable with inline editing.
3. How to update a record using `uiRecordApi`.
4. How to refresh a record without refreshing the page.
5. Complete demo.

## 1. What Is `refreshApex()`?

**Definition:** `refreshApex()` is a function imported from `@salesforce/apex` that refreshes data previously provisioned by an Apex method through the `@wire` service. It asks the framework to obtain fresh data from the server and update the wired result.

In this demo, `getContactList` is called through `@wire`. After the user edits and saves Contact records, `refreshApex(this.contacts)` refreshes the wired Contact data so that the datatable displays the latest values without a full browser or page refresh.

> Important: `refreshApex()` is used with a value provisioned by an Apex wire. It is not used to refresh data returned by an imperative Apex call. For Lightning Data Service record data, use the appropriate Lightning Data Service refresh mechanism.

---

## 2. What We Are Building

The component is named **Refresh Apex Demo**. It displays up to ten Contact records in a `lightning-datatable`.

The datatable contains:

- First Name — inline editable.
- Last Name — inline editable.
- Email — displayed as an email column.

When a user edits First Name or Last Name and saves the changes:

1. The datatable emits the `onsave` event.
2. The component reads the draft values.
3. The draft values are converted into record input objects.
4. `updateRecord()` is called for each edited record.
5. `Promise.all()` waits for all update requests to finish.
6. A success toast is displayed.
7. Draft values are cleared.
8. `refreshApex(this.contacts)` refreshes the wired Contact list.
9. The datatable displays the latest Contact values.

## 3. Apex Controller

**File: `refreshContactController.cls`**

The screenshot contains this Apex code:

```apex
public with sharing class refreshContactController {
    @AuraEnabled(cacheable=true)
    public static List<Contact> getContactList() {
        try {
            return [
                SELECT Id, FirstName, LastName, Email
                FROM Contact
                LIMIT 10
            ];
        } catch (Exception e) {
            throw new AuraHandledException(e.getMessage());
        }
    }
}
```

### Explanation

| Code | Explanation |
|---|---|
| `public with sharing class refreshContactController` | Declares a public Apex class and enforces record-level sharing rules. |
| `@AuraEnabled(cacheable=true)` | Exposes the method to Lightning components and allows the read-only result to be cached. |
| `public static` | The method is public and static, as required for an Apex method exposed to LWC. |
| `List<Contact>` | The method returns a list of Contact records. |
| `getContactList()` | Method called by the LWC to retrieve Contact data. |
| `SELECT Id, FirstName, LastName, Email` | Retrieves the Contact record ID, first name, last name, and email. |
| `FROM Contact` | Queries the Contact object. |
| `LIMIT 10` | Returns at most ten Contact records. |
| `try/catch` | Handles an exception that occurs while executing the query. |
| `AuraHandledException` | Sends a handled exception message back to the Lightning component. |

### Why is `cacheable=true` used?

The Apex method only reads Contact records and does not perform DML. Therefore, it can be marked `cacheable=true`.

Apex methods used with `@wire` must be cacheable. A cacheable method must be read-only and must not insert, update, or delete records.

### Why use `with sharing`?

`with sharing` enforces record-level sharing rules for the running user. It does not automatically enforce object-level permissions or field-level security. Add suitable CRUD/FLS checks or user-mode operations where required.

## 4. JavaScript Controller

**File: `refreshDemoLwc.js`**

The JavaScript screenshot contains the following code:

```javascript
import { LightningElement, wire } from 'lwc';
import getContactList from '@salesforce/apex/refreshContactController.getContactList';
import { updateRecord } from 'lightning/uiRecordApi';
import { ShowToastEvent } from 'lightning/platformShowToastEvent';
import { refreshApex } from '@salesforce/apex';

const columns = [
    { label: 'First Name', fieldName: 'FirstName', editable: true },
    { label: 'Last Name', fieldName: 'LastName', editable: true },
    { label: 'Email', fieldName: 'Email', type: 'email' }
];

export default class RefreshDemoLwc extends LightningElement {
    columns = columns;
    draftValues = [];

    @wire(getContactList)
    contacts;

    handleSave(event) {
        console.log(event.detail.draftValues);

        const recordInputs = event.detail.draftValues.slice().map(draft => {
            const fields = Object.assign({}, draft);
            return { fields };
        });

        console.log('recordInputs', recordInputs);

        const promises = recordInputs.map(recordInput => updateRecord(recordInput));

        Promise.all(promises).then(() => {
            this.showToastMsg('Success', 'Contact updated successfully');
            this.draftValues = [];
            refreshApex(this.contacts);
        }).catch(error => {
            this.showToastMsg('Error', 'Error in updating contact', 'error');
        });
    }

    showToastMsg(title, message, variant) {
        const event = new ShowToastEvent({
            title: title,
            message: message,
            variant: variant || 'Success'
        });
        this.dispatchEvent(event);
    }
}
```

```javascript

```

Imports `refreshApex()` to refresh data provisioned by an Apex wire.

### Fetch Contact data using `@wire`

```javascript

```

The `@wire` decorator calls the Apex method and provisions its result to the `contacts` property.

The wired property is an object containing `data` and `error` information. The HTML uses `contacts.data` to access the returned records.

### Handle inline save

```javascript
handleSave(event) {
    console.log(event.detail.draftValues);
```

The datatable fires the `onsave` event when the user clicks Save. `event.detail.draftValues` contains the edited field values and the record IDs.

Example draft data:

```javascript
[
    {
        Id: '003XXXXXXXXXXXXXXX',
        FirstName: 'John',
        LastName: 'Bond'
    }
]
```

The IDs above are illustrative only.

### Convert draft values into record inputs

```javascript
const recordInputs = event.detail.draftValues.slice().map(draft => {
    const fields = Object.assign({}, draft);
    return { fields };
});
```

Explanation:

- `slice()` creates a shallow copy of the draft values array.
- `map()` processes each edited record.
- `Object.assign({}, draft)` copies the draft properties into a new object.
- `return { fields }` creates the record input shape expected by `updateRecord()`.

The resulting structure looks like this:

```javascript
[
    {
        fields: {
            Id: '003XXXXXXXXXXXXXXX',
            FirstName: 'John',
            LastName: 'Bond'
        }
    }
]
```

### Update records using `updateRecord()`

```javascript
const promises = recordInputs.map(recordInput => updateRecord(recordInput));
```

This calls `updateRecord()` for every edited record. Each call returns a Promise.

`updateRecord()` uses Lightning Data Service to update the record. The input must contain a `fields` object, including the record `Id` and the fields to update.

### Wait for all updates using `Promise.all()`

```javascript
Promise.all(promises).then(() => {
    this.showToastMsg('Success', 'Contact updated successfully');
    this.draftValues = [];
    refreshApex(this.contacts);
}).catch(error => {
    this.showToastMsg('Error', 'Error in updating contact', 'error');
});
```

- `Promise.all(promises)` waits until all update Promises resolve.
- `.then()` runs when all updates succeed.
- `showToastMsg()` displays a success notification.
- `this.draftValues = []` clears the saved draft values.
- `refreshApex(this.contacts)` refreshes the wired Contact list.
- `.catch()` runs if an update Promise rejects and displays an error toast.

**Important:** `Promise.all()` rejects if any one of its Promises rejects. It does not roll back updates that have already succeeded. If some records update successfully and another fails, the successful updates are not automatically undone.

### Display toast notification

```javascript
showToastMsg(title, message, variant) {
    const event = new ShowToastEvent({
        title: title,
        message: message,
        variant: variant || 'Success'
    });
    this.dispatchEvent(event);
}
```

This method creates and dispatches a toast event.

- `title` — heading of the toast.
- `message` — message displayed to the user.
- `variant` — toast style, such as `success`, `error`, `warning`, or `info`.
- `variant || 'Success'` — uses the supplied variant or the default value if one is not provided.
- `dispatchEvent()` sends the toast event so Salesforce can display it.

## 10. Important Concepts

### A. `@wire`

`@wire` is a decorator that provisions data from a Salesforce data source to a component property or function. It is commonly used to retrieve data reactively.

### B. `lightning-datatable`

`lightning-datatable` displays records in rows and columns. It supports features such as sorting, row selection, and inline editing when the columns are configured accordingly.

### C. Inline Editing

Inline editing allows users to edit supported field values directly in a datatable without opening a separate record edit form.

### D. Draft Values

Draft values are the changes a user has made in the datatable but has not yet saved. They are available through `event.detail.draftValues` in the save event.

### E. `updateRecord()`

`updateRecord()` is imported from `lightning/uiRecordApi`. It updates a record through Lightning Data Service.

Expected input shape:

```javascript
{
    fields: {
        Id: 'RECORD_ID',
        FirstName: 'Updated First Name'
    }
}
```

### F. `Promise.all()`

`Promise.all()` accepts an array of Promises and resolves when all of them resolve. It rejects if any one of them rejects.

### G. `ShowToastEvent`

`ShowToastEvent` displays a toast notification to communicate success, error, warning, or informational messages.

### H. `refreshApex()`

`refreshApex()` refreshes data previously provisioned by an Apex wire. Pass the complete wired result, not only its `data` property.

Correct:

```javascript
refreshApex(this.contacts);
```

Incorrect for this wired-property example:

```javascript
refreshApex(this.contacts.data);
```

### I. Lightning Data Service

Lightning Data Service provides client-side access to Salesforce records and handles record data caching and synchronization for supported components and APIs. `updateRecord()` is part of the UI Record API and uses Lightning Data Service.

## 11. `refreshApex()` vs. `updateRecord()`

| Feature | `refreshApex()` | `updateRecord()` |
|---|---|---|
| Main purpose | Refreshes data provisioned by an Apex wire | Updates a Salesforce record |
| Import | `@salesforce/apex` | `lightning/uiRecordApi` |
| Input | The wired Apex result object | A record input object containing `fields` |
| Typical use | Refresh a wired list after a record change | Save changes to a record |
| Performs DML? | No; it refreshes data | Yes; it updates the record |

These functions solve different problems. In this demo, `updateRecord()` saves the edited Contact records, and `refreshApex()` reloads the wired Contact list.

---

## 12. `@wire` vs. Imperative Apex

| Feature | `@wire` Apex | Imperative Apex |
|---|---|---|
| Invocation | Framework provisions data reactively | JavaScript invokes the method explicitly |
| Timing | Reacts to configuration and parameter changes | Developer controls when the call happens |
| Return handling | Wired property/function receives data and error | Returns a Promise |
| Common use | Read data that should be provisioned reactively | Button actions, searches, and DML operations |
| Cacheable | Required for Apex methods used with `@wire` | Not required for methods that perform changes; read-only methods can be cacheable |

## 13. Interview Questions and Answers

**Q1. What is `refreshApex()` in LWC?**  
`refreshApex()` refreshes data previously provisioned by an Apex method through the `@wire` service.

**Q2. Why do we use `refreshApex()`?**  
To refresh wired Apex data after a record is changed, without requiring a full page reload.

**Q3. From which module do we import `refreshApex()`?**  
From `@salesforce/apex`.

```javascript
import { refreshApex } from '@salesforce/apex';
```

**Q4. What parameter should be passed to `refreshApex()`?**  
Pass the complete wired result object, such as `this.contacts`, not only `this.contacts.data`.

**Q5. Can `refreshApex()` refresh data returned by an imperative Apex call?**  
No. It is intended to refresh data provisioned by the Apex wire service.

**Q6. What is the purpose of `@wire`?**  
It provisions data from an Apex method or supported Salesforce data source to a component property or function.

**Q7. Why is `cacheable=true` used in the Apex method?**  
The method reads data and is used with `@wire`. Wired Apex methods must be cacheable, and cacheable methods must be read-only.

**Q8. What is `lightning-datatable`?**  
It is a standard Lightning base component used to display records in a table.

**Q9. How do you enable inline editing in a datatable?**  
Set `editable: true` in the column definition for the fields that users should be able to edit.

**Q10. What are draft values?**  
They are the edited values that have not yet been saved. The datatable provides them through `event.detail.draftValues`.

**Q11. Which event is used to save inline edits?**  
The `onsave` event.

**Q12. What is `updateRecord()`?**  
It is a UI Record API function imported from `lightning/uiRecordApi` that updates a Salesforce record.

**Q13. What is the required input structure for `updateRecord()`?**  
An object containing a `fields` property. The `fields` object must include the record `Id` and the fields to update.

**Q14. Why do we use `map()` in `handleSave()`?**  
To convert each draft record into the input structure expected by `updateRecord()` and create an update Promise for each record.

**Q15. What does `Object.assign({}, draft)` do?**  
It copies the enumerable properties from `draft` into a new object.

**Q16. What is `Promise.all()`?**  
It waits for all Promises in an array to resolve. It rejects if any Promise rejects.

**Q17. Does `Promise.all()` make multiple record updates one atomic transaction?**  
No. The updates are separate requests. If one fails, previously successful updates are not automatically rolled back.

**Q18. Why do we clear `draftValues` after saving?**  
To clear the saved draft changes from the datatable.

**Q19. What is `ShowToastEvent`?**  
It is an event used to display toast notifications to users.

**Q20. How can you show an error toast?**  
Dispatch a `ShowToastEvent` with `variant: 'error'`.

**Q21. What is the difference between `updateRecord()` and `refreshApex()`?**  
`updateRecord()` saves a record. `refreshApex()` refreshes data previously provisioned by an Apex wire.

**Q22. What is the difference between `refreshApex()` and a browser page refresh?**  
`refreshApex()` refreshes the wired Apex data for the component. A browser page refresh reloads the whole page.

**Q23. Can we use `refreshApex()` with `getRecord` from `lightning/uiRecordApi`?**  
No. `refreshApex()` is for Apex wire results. For Lightning Data Service record data, use the appropriate LDS refresh mechanism.

**Q24. What does `key-field="Id"` do in a datatable?**  
It identifies the unique field used to identify each row.

**Q25. Why is `type: 'email'` specified for the Email column?**  
It tells the datatable to render the field using its email data type.

**Q26. What does `with sharing` do?**  
It enforces record-level sharing rules for the running user.

**Q27. Does `with sharing` enforce CRUD and FLS?**  
No. Appropriate object and field permission enforcement is also needed.

**Q28. Can the same datatable support editing multiple rows?**  
Yes. The save event can contain draft values for multiple rows. The component can create an update request for each row.

**Q29. What happens if one `updateRecord()` Promise fails in this example?**  
`Promise.all()` rejects and the catch block displays an error toast. Other updates that already succeeded are not automatically rolled back.

**Q30. How would you improve this example for production?**  
Add explicit error details, loading feedback, permission checks, and robust handling for partial success. Also consider refreshing the wired data after successful updates and testing with users who have different record and field permissions.

## 14. Common Mistakes and Solutions

| Mistake | Solution |
|---|---|
| Not importing `refreshApex` | Import it from `@salesforce/apex`. |
| Passing `contacts.data` to `refreshApex()` | Pass the full wired result, `this.contacts`. |
| Forgetting `cacheable=true` on a wired Apex method | Add `@AuraEnabled(cacheable=true)` to the read-only Apex method. |
| Not setting `key-field` | Set `key-field="Id"` for Contact records. |
| Forgetting `editable: true` | Enable editing on the required column definitions. |
| Not handling the `onsave` event | Add `onsave={handleSave}` to the datatable. |
| Passing the wrong shape to `updateRecord()` | Pass `{ fields: { Id: recordId, ...changedFields } }`. |
| Not clearing draft values | Set `this.draftValues = []` after successful save. |
| Assuming `Promise.all()` is a transaction | Remember that separate successful updates are not automatically rolled back if another update fails. |
| Assuming `with sharing` enforces CRUD/FLS | Add appropriate object and field permission checks. |

## 15. Important Notes and Improvements

The README preserves the approach shown in the screenshots. For production use, consider these additional points:

1. **Handle wired errors:** The screenshot template checks `contacts.data`, but it does not display `contacts.error`. Add an error state and user-friendly error message.
2. **Show loading feedback:** Use a loading property and `lightning-spinner` while records are being saved or refreshed.
3. **Use the refresh Promise:** `refreshApex()` returns a Promise. You can await it if later logic must wait until the refresh completes.
4. **Handle partial success:** `Promise.all()` rejects when any request fails, but other record updates may already have succeeded. For independent updates, consider `Promise.allSettled()` and report which records succeeded or failed.
5. **Enforce permissions:** Ensure users have the required object and field permissions. Record sharing alone does not grant CRUD/FLS access.
6. **Consider the toast API environment:** `ShowToastEvent` is supported in standard Lightning Experience contexts; check platform support if using an environment with different toast capabilities.

### Optional: Wait for the refresh to complete

The screenshot calls `refreshApex(this.contacts)` without awaiting it. If subsequent code needs to run only after refreshed data is available, use:

```javascript
await refreshApex(this.contacts);
```

This must be inside an `async` function. For example:

```javascript
async handleSave(event) {
    try {
        const recordInputs = event.detail.draftValues.map(draft => ({
            fields: { ...draft }
        }));

        await Promise.all(
            recordInputs.map(recordInput => updateRecord(recordInput))
        );

        this.draftValues = [];
        await refreshApex(this.contacts);
        this.showToastMsg(
            'Success',
            'Contact updated successfully',
            'success'
        );
    } catch (error) {
        this.showToastMsg(
            'Error',
            'Error in updating contact',
            'error'
        );
    }
}
```

This is an optional alternative, not the exact code in the screenshot.

## Conclusion

This demo shows how to fetch Contact records using a wired Apex method, display them in a Lightning Datatable, edit First Name and Last Name inline, and save the changes using `updateRecord()` from `lightning/uiRecordApi`.

After successful updates, `refreshApex(this.contacts)` refreshes the data provisioned by the Apex wire. This updates the datatable without requiring a full page refresh.

**Key interview point:**

```javascript
refreshApex(this.contacts);
```

Pass the complete wired Apex result object to `refreshApex()`. Use `updateRecord()` to save the record changes and `refreshApex()` to refresh the wired list.
