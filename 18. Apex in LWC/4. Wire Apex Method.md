# Wire Apex Methods in Lightning Web Components (LWC)

This folder explains how to call an Apex method from a Lightning Web Component (LWC) using the `@wire` service. It covers both approaches shown in the supplied screenshots:

1. Wire an Apex method to a property.
2. Wire an Apex method to a function.

The examples use an Apex method named `getAccountList` from the `AccountController` class.

---

## 1. What Are Wire Apex Methods?

### Definition from the screenshot

> We can wire an Apex method in two ways:
>
> 1. Wire an Apex Method to a Property
> 2. Wire an Apex Method to a Function

In simple words, the `@wire` service connects an Apex method to an LWC component. Salesforce provisions the method's response to the component. The component can then display or process the returned data.

The screenshot also shows two broad ways to call Apex from LWC:

- **Wire Apex Methods** — use `@wire` for reactive data provisioning.
- **Call Apex Methods Imperatively** — call the imported Apex method directly from JavaScript when you want to control when it runs.

This folder focuses on the wire approach.

---

## 2. Syntax From the Screenshot

```javascript
import apexMethodName from '@salesforce/apex/Namespace.Classname.apexMethodReference';

@wire(apexMethodName, { apexMethodParams })
propertyOrFunction;
```

### Explanation of the syntax

| Term | Meaning |
|---|---|
| `apexMethodName` | A symbol that identifies the Apex method. |
| `@wire` | Decorator that connects an Apex method to a component property or function. |
| `apexMethodParams` | An object with properties that match the parameters of the Apex method. |
| `propertyOrFunction` | The component property or function that receives the wire result. |
| `Namespace` | Namespace of a managed package, when applicable. |
| `Classname` | Name of the Apex class. |
| `apexMethodReference` | Name of the Apex method to import. |

### Important note from the screenshot

> If a parameter value is `null`, the method is called, but if the value is `undefined`, the method isn't called.

This distinction matters when using reactive parameters:

- `null` is an intentional value and the Apex method is invoked with `null`.
- `undefined` means the parameter is not ready, so the wire service does not invoke the Apex method.

## 3. Apex Class Used in the Example

The screenshots use the following Apex class.

**File: `AccountController.cls`**

```apex
public with sharing class AccountController {
    @AuraEnabled(cacheable=true)
    public static List<Account> getAccountList() {
        try {
            return [
                SELECT Id, Name, Type, Industry
                FROM Account
                LIMIT 5
            ];
        } catch (Exception e) {
            throw new AuraHandledException(e.getMessage());
        }
    }
}
```

### Explanation

- `public` — makes the class accessible.
- `with sharing` — enforces the running user's record-level sharing rules.
- `@AuraEnabled(cacheable=true)` — exposes the method to Lightning components and marks it as cacheable.
- `public static` — Apex methods exposed to LWC must be `static` and `public` or `global`.
- `List<Account>` — the method returns a list of Account records.
- `SELECT Id, Name, Type, Industry FROM Account LIMIT 5` — retrieves up to five Account records and the specified fields.
- `try/catch` — catches an exception and returns it as an `AuraHandledException`.

**Why is `cacheable=true` used?**

Apex methods used with `@wire` must be read-only and marked with `@AuraEnabled(cacheable=true)`. A cacheable method must not perform DML or otherwise change data.

The JavaScript screenshot contains these imports:

```javascript
import { LightningElement, wire } from 'lwc';
import getAccountList from '@salesforce/apex/AccountController.getAccountList';
```

### Explanation

- `LightningElement` is the base class for an LWC component.
- `wire` is imported from `lwc` so that the `@wire` decorator can be used.
- `getAccountList` imports the Apex method from `AccountController`.

The import path follows this format:

```javascript
import methodName from '@salesforce/apex/ClassName.methodName';
```

For a class in a managed package namespace, include the namespace:

```javascript
import methodName from '@salesforce/apex/PackageNamespace.ClassName.methodName';
```

## 5. Way One: Wire an Apex Method to a Property

### Definition

When an Apex method is wired to a property, Salesforce provisions the result to that property. The property receives a wire result object containing `data` and `error`.

### JavaScript example

```javascript
import { LightningElement, wire } from 'lwc';
import getAccountList from '@salesforce/apex/AccountController.getAccountList';

export default class ApexWirePropertyDemo extends LightningElement {
    // Wire Apex method to a property
    @wire(getAccountList)
    accounts;
}
```

### HTML example

```html
<template>
    <lightning-card title="Apex wire to Property Demo">
        <div class="slds-p-around_medium">
            <template lwc:if={accounts.data}>
                <template for:each={accounts.data} for:item="account">
                    <div
                        class="slds-box slds-box_xx-small"
                        key={account.Id}
                    >
                        <p><strong>Name:</strong> {account.Name}</p>
                        <p><strong>Type:</strong> {account.Type}</p>
                        <p><strong>Industry:</strong> {account.Industry}</p>
                    </div>
                </template>
            </template>

            <template lwc:if={accounts.error}>
                <p class="slds-text-color_error">
                    Unable to load Account records.
                </p>
            </template>
        </div>
    </lightning-card>
</template>
```

### How it works

1. `@wire(getAccountList)` calls the Apex method through the wire service.
2. The result is assigned to the `accounts` property.
3. The response is available as `accounts.data` when successful.
4. If the request fails, the error is available as `accounts.error`.
5. The HTML template loops through `accounts.data` and displays each Account.

### Important point

The property wire result has this general shape:

```javascript
{
    data: /* returned data */,
    error: /* error information */
}
```

## 6. Way Two: Wire an Apex Method to a Function

### Definition

When an Apex method is wired to a function, the wire service invokes that function whenever a new result is available. The function receives an object containing `data` and `error`.

This approach is useful when you need to process or transform the returned data before displaying it.

### JavaScript example based on the screenshot

```javascript
import { LightningElement, wire } from 'lwc';
import getAccountList from '@salesforce/apex/AccountController.getAccountList';

export default class ApexWireFunctionDemo extends LightningElement {
    accountList;

    // Wire Apex method to a function
    @wire(getAccountList)
    accountHandler({ data, error }) {
        if (data) {
            this.accountList = data.map(item => {
                let newType =
                    item.Type === 'Customer - Direct'
                        ? 'Direct'
                        : item.Type === 'Customer - Channel'
                            ? 'Channel'
                            : '_____';

                return { ...item, newType };
            });
        }

        if (error) {
            console.error(error);
        }
    }
}
```

### Explanation of the function

```javascript
@wire(getAccountList)
accountHandler({ data, error }) {
```

The Apex method is wired to the `accountHandler` function. The function uses JavaScript destructuring to access `data` and `error`.

```javascript
if (data) {
```

Checks whether the Apex method returned data successfully.

```javascript
this.accountList = data.map(item => {
```

Uses JavaScript's `map()` method to create a new array from the returned Account records.

```javascript
let newType =
    item.Type === 'Customer - Direct'
        ? 'Direct'
        : item.Type === 'Customer - Channel'
            ? 'Channel'
            : '_____';
```

Converts the Account Type values for display:

- `Customer - Direct` becomes `Direct`.
- `Customer - Channel` becomes `Channel`.
- Any other value becomes `_____`.

```javascript
return { ...item, newType };
```

Uses the spread operator (`...item`) to retain the original Account fields and adds a new property called `newType`.

```javascript
if (error) {
    console.error(error);
}
```

Logs an error if the Apex request fails.

### HTML example

```html
<template>
    <lightning-card title="Apex wire to Function Demo">
        <div class="slds-p-around_medium">
            <template lwc:if={accountList}>
                <template for:each={accountList} for:item="account">
                    <div
                        class="slds-box slds-box_xx-small"
                        key={account.Id}
                    >
                        <p><strong>Name:</strong> {account.Name}</p>
                        <p><strong>Type:</strong> {account.newType}</p>
                        <p><strong>Industry:</strong> {account.Industry}</p>
                    </div>
                </template>
            </template>
        </div>
    </lightning-card>
</template>
```

### How it works

1. `@wire(getAccountList)` invokes the Apex method.
2. Salesforce passes the result to `accountHandler`.
3. The function checks whether `data` is available.
4. `map()` processes the returned Account records.
5. A new `newType` property is added to every Account.
6. The HTML template displays the transformed records.

## 7. Property vs. Function: Comparison

| Feature | Wire to Property | Wire to Function |
|---|---|---|
| Syntax | `@wire(method) property;` | `@wire(method) functionName({ data, error }) {}` |
| Result | Stored on the property | Passed to the function |
| Access data | `property.data` | `data` parameter |
| Access error | `property.error` | `error` parameter |
| Data transformation | Usually done in a getter or other JavaScript logic | Can be done directly in the wired function |
| Best suited for | Displaying returned data directly | Processing or transforming returned data |

**Which approach should you use?**

- Use a **property** when you simply need to display the Apex response.
- Use a **function** when you need to transform the response, perform additional JavaScript logic, or handle the result in a custom way.

## 8. Important: Use Separate Wire Demonstrations

The JavaScript screenshot shows both of these declarations:

```javascript
@wire(getAccountList)
accounts;

@wire(getAccountList)
accountHandler({ data, error }) {
    // Process response
}
```

This illustrates both approaches in one file. For a clean project, it is easier to understand and maintain them as separate examples/components:

- `apexWirePropertyDemo` — property-based wire.
- `apexWireFunctionDemo` — function-based wire.

If you keep both wires in one component, Salesforce creates two wire configurations for the same Apex method. That can cause duplicate data provisioning and unnecessary work. Do not combine them unless you specifically need two independent wire subscriptions.

The two examples in this README are therefore shown separately.

## 9. Reactive Parameters in `@wire`

The screenshot's syntax includes `apexMethodParams`:

```javascript
@wire(apexMethodName, { apexMethodParams })
propertyOrFunction;
```

When an Apex method accepts parameters, pass them as an object. The property names must match the parameters of the Apex method.

### Apex example

```apex
public with sharing class AccountController {
    @AuraEnabled(cacheable=true)
    public static List<Account> getAccountsByIndustry(String industryName) {
        return [
            SELECT Id, Name, Type, Industry
            FROM Account
            WHERE Industry = :industryName
            LIMIT 10
        ];
    }
}
```

### LWC JavaScript example

```javascript
import { LightningElement, wire } from 'lwc';
import getAccountsByIndustry
    from '@salesforce/apex/AccountController.getAccountsByIndustry';

export default class AccountIndustryDemo extends LightningElement {
    selectedIndustry = 'Technology';
    accounts;
    error;

    @wire(getAccountsByIndustry, { industryName: '$selectedIndustry' })
    wiredAccounts({ data, error }) {
        if (data) {
            this.accounts = data;
            this.error = undefined;
        } else if (error) {
            this.accounts = undefined;
            this.error = error;
        }
    }
}
```

### What does `$selectedIndustry` mean?

The `$` prefix makes `selectedIndustry` a reactive reference. When its value changes, the wire service provisions the Apex method again with the new value.

### `null` vs. `undefined`

As stated in the screenshot:

| Parameter value | Wire behaviour |
|---|---|
| `null` | The Apex method is called with a null parameter value. |
| `undefined` | The Apex method is not called until the parameter has a defined value. |

This is useful when a component should wait until the user has selected or entered a value before calling Apex.

1. Open your Salesforce DX project in VS Code.
2. Create the Apex class `AccountController`.
3. Add the `getAccountList()` method shown in this README.
4. Save the Apex class.
5. Create the `apexWirePropertyDemo` LWC.

12. Drag the component onto the page, save, and activate the page if required.
13. Open the page and verify that Account Name, Type, and Industry are displayed.

### Before testing

- Make sure the Apex class and method names match the import statement.
- Confirm that the method has `@AuraEnabled(cacheable=true)`.
- Confirm that the running user has access to the Apex class.
- Make sure Account records exist and the user can access them.
- Check the browser console if an error occurs.

## 13. Interview Questions and Answers

### Q1. What is the `@wire` service in LWC?

`@wire` is a framework service that provisions data to a component. It can connect an LWC to a Salesforce data source or an Apex method.

### Q2. In how many ways can we wire an Apex method?

Two ways:

1. Wire an Apex method to a property.
2. Wire an Apex method to a function.

### Q3. What is the difference between property-based and function-based wiring?

With property-based wiring, the result is stored in a property as an object containing `data` and `error`. With function-based wiring, the result is passed to a function as `{ data, error }`, allowing the component to process the response.

### Q4. What is the syntax for wiring an Apex method to a property?

```javascript
@wire(getAccountList)
accounts;
```

### Q5. What is the syntax for wiring an Apex method to a function?

```javascript
@wire(getAccountList)
accountHandler({ data, error }) {
    if (data) {
        // Process data
    } else if (error) {
        // Handle error
    }
}
```

### Q6. Why do we use `@AuraEnabled(cacheable=true)`?

It exposes the Apex method to Lightning components and enables caching. It is required when an Apex method is called using `@wire`.

### Q7. Can a wired Apex method perform DML operations?

No. A method used with `@wire` must be read-only and cacheable. Use an imperative Apex call for operations that create, update, or delete records.

### Q8. What is the purpose of `data` and `error`?

- `data` contains the successful response from the Apex method.
- `error` contains error information when the request fails.

### Q9. What happens if the Apex method returns no records?

The method can return an empty list. The component should handle that case and optionally display a “No records found” message.

### Q10. Can we transform data received from a wired Apex method?

Yes. A function-based wire is useful for transforming data using methods such as `map()` before assigning it to a component property.

### Q11. What is the purpose of the spread operator (`...`) in the example?

It copies the existing properties of an Account object into a new object. The example then adds the `newType` property:

```javascript
return { ...item, newType };
```

### Q12. What is the purpose of JavaScript `map()`?

`map()` creates a new array by applying a function to every item in the original array. It is useful for transforming records received from Apex.

### Q13. What does the `$` symbol mean in a wire parameter?

It makes the parameter reactive. When the referenced component property changes, the wire service provisions the Apex method again.

### Q14. What is the difference between `null` and `undefined` in a wire parameter?

A `null` parameter value invokes the Apex method with null. An `undefined` parameter value prevents the method from being invoked.

### Q15. Can we use the same Apex method in multiple LWC components?

Yes. Multiple LWC components can import and use the same exposed Apex method, subject to access and security requirements.

### Q16. Can we use both property and function wire approaches in one component?

A component can have multiple wire declarations. However, using the same method twice creates separate wire subscriptions. Use separate components or one approach unless two subscriptions are actually required.

### Q17. What is the difference between `@wire` and an imperative Apex call?

`@wire` provisions data reactively. An imperative call is explicitly invoked from JavaScript and returns a Promise.

### Q18. Why is `with sharing` used in the Apex class?

It enforces record-level sharing rules for the running user. It does not automatically enforce object-level or field-level permissions.

### Q19. What happens when a reactive wire parameter changes?

The wire service provisions the Apex method again with the updated parameter value.

### Q20. How do you debug an Apex wire method?

Check the `error` response, browser console, Apex class access, method annotation, import path, parameter names, and the user's record access.

## 14. Common Mistakes

| Mistake | How to avoid it |
|---|---|
| Forgetting to import `wire` from `lwc` | Add `import { LightningElement, wire } from 'lwc';`. |
| Incorrect Apex import path | Verify the Apex class and method names. |
| Missing `@AuraEnabled` | Add the annotation to the Apex method. |
| Using a non-static Apex method | Declare the exposed Apex method as `static`. |
| Using `@wire` with a non-cacheable method | Add `cacheable=true` and ensure the method is read-only. |
| Using the wrong parameter name | Match the JavaScript parameter object's property name with the Apex method parameter name. |
| Using `undefined` when expecting an Apex call | Check that the reactive parameter has a defined value. |
| Not handling errors | Check the `error` property or function parameter. |
| Using the same wire twice without a reason | Prefer one wire subscription per required data flow. |
| Missing a `key` in a `for:each` loop | Use a unique key such as `account.Id`. |

## 15. Quick Revision Notes

- Apex methods can be wired to a property or a function.
- Use `@wire` to connect an Apex method to an LWC.
- Import Apex methods from `@salesforce/apex`.
- Apex methods used with `@wire` must be `static`, `public` or `global`, annotated with `@AuraEnabled(cacheable=true)`, and read-only.
- Property-based wiring exposes `property.data` and `property.error`.
- Function-based wiring receives `{ data, error }`.
- Use function-based wiring when you need to transform data.
- Use `$` before a property name to pass a reactive parameter.
- A `null` parameter invokes the method; an `undefined` parameter does not.
- Use imperative Apex for operations that modify records.

## Conclusion

The `@wire` service provides two ways to connect an Apex method to an LWC: property-based wiring and function-based wiring. Use property-based wiring when you want to access the returned `data` and `error` directly. Use function-based wiring when you need to process or transform the response before displaying it. For methods that change Salesforce data, use an imperative Apex call instead of a wired method.
