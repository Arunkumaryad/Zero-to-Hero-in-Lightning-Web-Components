# Wire Apex Method With Parameters in LWC

This folder demonstrates how to pass a parameter from a Lightning Web Component (LWC) to an Apex method using the `@wire` service. A user selects an Account Type from a combobox, and the component automatically retrieves Accounts that match the selected Type.

The examples below are based on the supplied screenshots and include explanations, setup instructions, and Salesforce interview questions.

---

## 1. What Is a Wire Apex Method With Parameters?

A **wired Apex method with parameters** is an Apex method connected to an LWC using the `@wire` decorator, where the component passes values to the Apex method through a parameter object.

When a reactive parameter changes, the wire service provisions the Apex method again using the updated value.

### Main idea

1. The user selects an Account Type from a combobox.
2. The selected value is stored in a JavaScript property named `selectedType`.
3. The `@wire` decorator passes that value to the Apex method.
4. Apex filters Account records using the selected Type.
5. The component displays the matching Account Name and Type.

## 2. Apex Class From the Screenshot

**File: `AccountController.cls`**

The screenshot shows this Apex method:

```apex
public with sharing class AccountController {
    @AuraEnabled(cacheable=true)
    public static List<Account> filterAccountByType(String type) {
        try {
            return [
                SELECT Id, Name, Type
                FROM Account
                WHERE Type = :type
                LIMIT 5
            ];
        } catch (Exception e) {
            throw new AuraHandledException(e.getMessage());
        }
    }
}
```

### Explanation

| Code | Explanation |
|---|---|
| `public with sharing class AccountController` | Defines a public Apex class that enforces record-level sharing rules. |
| `@AuraEnabled(cacheable=true)` | Exposes the method to Lightning components and allows the result to be cached. |
| `public static` | The method is public and static, as required for an Apex method exposed to LWC. |
| `List<Account>` | The method returns a list of Account records. |
| `filterAccountByType(String type)` | Accepts a String parameter named `type`. |
| `WHERE Type = :type` | Filters Account records where the Type field matches the supplied parameter. |
| `LIMIT 5` | Returns at most five matching records. |
| `AuraHandledException` | Sends a handled exception message back to the Lightning component. |

### Why use `cacheable=true`?

The Apex method is called using `@wire`, so it must be read-only and annotated with `@AuraEnabled(cacheable=true)`. Do not perform DML operations in a cacheable method.

### Why use `with sharing`?

`with sharing` enforces record-level sharing rules for the running user. It does not, by itself, enforce object-level permissions or field-level security.

## 4. JavaScript Code From the Screenshot

**File: `wireApexWithParams.js`**

```javascript
import { LightningElement, wire } from 'lwc';
import filterAccountByType
    from '@salesforce/apex/AccountController.filterAccountByType';

export default class WireApexWithParams extends LightningElement {
    selectedType = '';

    @wire(filterAccountByType, { type: '$selectedType' })
    filteredAccounts;

    get typeOptions() {
        return [
            { label: 'Customer - Direct', value: 'Customer - Direct' },
            { label: 'Customer - Channel', value: 'Customer - Channel' },
            { label: 'Channel Partner / Reseller', value: 'Channel Partner / Reseller' },
            { label: 'Installation Partner', value: 'Installation Partner' },
            { label: 'Technology Partner', value: 'Technology Partner' }
        ];
    }

    typeHandler(event) {
        this.selectedType = event.target.value;
    }
}
```

### Explanation step by step

#### 1. `selectedType = '';`

```javascript
selectedType = '';
```

This property stores the Account Type selected by the user in the combobox.

The screenshot initializes it as an empty string. An empty string is a defined value, so the wire can run initially with an empty parameter. If you want the Apex method to wait until the user selects a value, initialize the property as `undefined` instead:

```javascript
selectedType;
```

#### 2. Wire the Apex method with a parameter

```javascript
@wire(filterAccountByType, { type: '$selectedType' })
filteredAccounts;
```

This is the most important line in this example.

- `filterAccountByType` is the Apex method being called.
- `{ type: '$selectedType' }` passes the component's `selectedType` property to the Apex method's `type` parameter.
- The `$` prefix makes `selectedType` reactive.
- `filteredAccounts` stores the wire result, including `data` and `error`.

**Important:** The JavaScript parameter name `type` must match the Apex method parameter name `type`. The `$selectedType` value is the component property whose current value is passed to that parameter.

#### 3. `get typeOptions()`

```javascript
get typeOptions() {
    return [
        { label: 'Customer - Direct', value: 'Customer - Direct' },
        { label: 'Customer - Channel', value: 'Customer - Channel' },
        { label: 'Channel Partner / Reseller', value: 'Channel Partner / Reseller' },
        { label: 'Installation Partner', value: 'Installation Partner' },
        { label: 'Technology Partner', value: 'Technology Partner' }
    ];
}
```

This getter returns the options displayed in the `lightning-combobox`.

Each option contains:

- `label` — the text displayed to the user.
- `value` — the value stored in `selectedType` when the option is selected.

#### 4. `typeHandler(event)`

```javascript
typeHandler(event) {
    this.selectedType = event.target.value;
}
```

This event handler runs when the user changes the combobox selection. It updates `selectedType` with the newly selected value.

Because `selectedType` is reactive in the `@wire` configuration, changing it causes the wire service to provision the Apex method with the new parameter value.

## 5. HTML Code From the Screenshot

**File: `wireApexWithParams.html`**

```html
<template>
    <lightning-card title="Apex Wire Demo with Params">
        <div class="slds-var-p-around_medium">
            <lightning-combobox
                name="type"
                label="Choose Your Type"
                value={selectedType}
                options={typeOptions}
                onchange={typeHandler}>
            </lightning-combobox>

            <template if:true={filteredAccounts.data}>
                <template
                    for:each={filteredAccounts.data}
                    for:item="account">
                    <div
                        class="slds-box slds-box_xx-small"
                        key={account.Id}>
                        <p><strong>Name:</strong> {account.Name}</p>
                        <p><strong>Type:</strong> {account.Type}</p>
                    </div>
                </template>
            </template>
        </div>
    </lightning-card>
</template>
```

### Explanation of HTML

| Attribute / Element | Purpose |
|---|---|
| `lightning-card` | Displays the component inside a Salesforce Lightning card. |
| `lightning-combobox` | Displays a dropdown list of Account Type options. |
| `name="type"` | Identifies the combobox input. |
| `label="Choose Your Type"` | Displays the label above the dropdown. |
| `value={selectedType}` | Shows the currently selected value. |
| `options={typeOptions}` | Supplies the dropdown options from JavaScript. |
| `onchange={typeHandler}` | Calls the JavaScript handler when the user changes the selection. |
| `if:true={filteredAccounts.data}` | Displays the records section when data is available. |
| `for:each` | Iterates through the returned Account records. |
| `key={account.Id}` | Provides a unique key for each rendered record. |

The template displays each matching Account's Name and Type.

## 10. Important Concepts to Understand

### A. `@wire`

`@wire` is a framework decorator that provisions data to an LWC property or function. It can call an Apex method and automatically provide updated results when reactive parameters change.

### B. Reactive parameter (`$`)

In this example:

```javascript
@wire(filterAccountByType, { type: '$selectedType' })
filteredAccounts;
```

The `$` prefix tells the wire service to observe `selectedType`. When its value changes, the wire service provisions the Apex method again.

### C. Parameter mapping

Apex method:

```apex
public static List<Account> filterAccountByType(String type)
```

LWC wire configuration:

```javascript
{ type: '$selectedType' }
```

The object property `type` matches the Apex parameter name. The value `$selectedType` refers to the LWC property.

### D. `null` vs. `undefined`

For a reactive Apex wire parameter:

- If the value is `null`, the Apex method is invoked with a null value.
- If the value is `undefined`, the Apex method is not invoked.

An empty string (`''`) is neither `null` nor `undefined`. It is a defined value and can cause the method to run with an empty string.

### E. `data` and `error`

The wired property receives a result object:

```javascript
filteredAccounts.data
filteredAccounts.error
```

- `data` contains the returned records when the request succeeds.
- `error` contains error information when the request fails.

### F. `cacheable=true`

The method must be read-only and cacheable when used with `@wire`. Do not use a wired cacheable method to insert, update, or delete records.

### G. `lightning-combobox`

`lightning-combobox` is a standard Lightning base component used to display a dropdown. Its `options` property accepts an array of objects with `label` and `value`.

### H. `onchange`

The `onchange` event handler captures the new selection:

```javascript
typeHandler(event) {
    this.selectedType = event.target.value;
}
```

Updating the reactive property causes the Apex wire to run again.

## 12. Optional Improvement: Display Errors and Empty Results

The screenshot displays the records when `filteredAccounts.data` is available. For a more complete user experience, you can also display loading, empty-result, and error states.

For example, add these properties and getter to the component:

```javascript
get hasAccounts() {
    return this.filteredAccounts?.data?.length > 0;
}

get hasNoAccounts() {
    return this.filteredAccounts?.data?.length === 0;
}
```

Then use conditional template blocks:

```html
<template if:true={hasAccounts}>
    <template for:each={filteredAccounts.data} for:item="account">
        <div key={account.Id} class="slds-box slds-box_xx-small">
            <p><strong>Name:</strong> {account.Name}</p>
            <p><strong>Type:</strong> {account.Type}</p>
        </div>
    </template>
</template>

<template if:true={hasNoAccounts}>
    <p>No Account records found for the selected Type.</p>
</template>

<template if:true={filteredAccounts.error}>
    <p class="slds-text-color_error">
        An error occurred while loading Account records.
    </p>
</template>
```

These are enhancements, not additional code shown in the original screenshots. In a production component, also consider a proper loading indicator and user-friendly error handling.

## 13. Interview Questions and Answers

### Q1. What is a wired Apex method with parameters in LWC?

It is an Apex method called through `@wire` with a parameter object. The component can pass values to Apex and receive the response reactively.

### Q2. How do you pass parameters to an Apex method using `@wire`?

Pass an object as the second argument to `@wire`. The object's property names must match the Apex method's parameter names.

Example:

```javascript
@wire(filterAccountByType, { type: '$selectedType' })
filteredAccounts;
```

### Q3. What is the purpose of the `$` symbol?

The `$` symbol makes a component property reactive. When the property changes, the wire service provisions the Apex method again with the updated value.

### Q4. What is the difference between `null` and `undefined` in a wire parameter?

- `null`: the Apex method is called with a null parameter.
- `undefined`: the Apex method is not called.

### Q5. Does an empty string prevent the Apex method from being called?

No. An empty string (`''`) is a defined value. The wire can invoke the Apex method with an empty string.

### Q6. Why must the JavaScript parameter name match the Apex parameter name?

The wire parameter object maps values to Apex method parameters by name. In this example, `type` in JavaScript maps to `String type` in Apex.

### Q7. What is the purpose of `@AuraEnabled(cacheable=true)`?

It exposes the Apex method to LWC and enables caching. It is required when calling Apex through `@wire`.

### Q8. Can a wired Apex method perform DML?

No. A wired Apex method must be read-only and cacheable. Use an imperative Apex call for insert, update, and delete operations.

### Q9. What is the difference between `@wire` and imperative Apex?

`@wire` provisions data reactively. An imperative Apex call is invoked explicitly from JavaScript and returns a Promise.

### Q10. What is the purpose of `lightning-combobox`?

It displays a dropdown list of options. Each option has a `label` shown to the user and a `value` used by the component.

### Q11. What does the `onchange` event do?

It runs the specified JavaScript handler when the user changes the combobox selection.

### Q12. Why do we use `event.target.value`?

It retrieves the newly selected value from the combobox event.

### Q13. What happens when the user selects a different Account Type?

The event handler updates `selectedType`. Because it is a reactive wire parameter, the wire service provisions the Apex method again with the new value.

### Q14. What does `filteredAccounts.data` contain?

It contains the Account records returned by the Apex method when the request succeeds.

### Q15. What does `filteredAccounts.error` contain?

It contains error information if the Apex request fails.

### Q16. Why is `LIMIT 5` used in the SOQL query?

It restricts the query to a maximum of five matching Account records. It is useful for a small demonstration and is not a complete pagination strategy.

### Q17. Why is `with sharing` used?

It enforces record-level sharing rules for the current user. Object permissions and field-level security must also be handled where required.

### Q18. Can the same Apex method be used by multiple LWC components?

Yes. Multiple components can import the same exposed Apex method, provided the user has the required access.

### Q19. What is a getter in LWC JavaScript?

A getter is a JavaScript method accessed like a property. In this example, `typeOptions` returns the array of combobox options.

### Q20. How would you troubleshoot if the combobox selection does not filter records?

Check the `onchange` handler, the `selectedType` value, the `$` reactive reference, the parameter name mapping, the Apex import path, Apex class access, the SOQL field and picklist values, and the wire error.

## 14. Common Mistakes and Their Solutions

| Mistake | Solution |
|---|---|
| Apex parameter is named `type`, but the wire object uses another name | Use `{ type: '$selectedType' }` so the names match. |
| Missing `$` before the reactive property | Use `'$selectedType'` to make the parameter reactive. |
| Using `undefined` when expecting the method to run | Assign a defined value to the parameter. |
| Assuming `''` prevents the method from running | Remember that an empty string is a defined value. |
| Incorrect Apex import path | Verify the class and method names in the import. |
| Missing `@AuraEnabled(cacheable=true)` | Add the annotation to the read-only Apex method. |
| Apex method performs DML | Use an imperative Apex call for data changes. |
| Not handling wire errors | Check `filteredAccounts.error` and show an appropriate message. |
| Combobox option has no `value` | Each option should have both `label` and `value`. |
| Missing a unique loop key | Use `key={account.Id}` in the `for:each` loop. |

## Conclusion

Wiring an Apex method with parameters allows an LWC component to retrieve records based on user input. In this example, the user selects an Account Type from a combobox. The selected value is stored in `selectedType`, passed reactively to the Apex method through `@wire`, and used in a SOQL `WHERE` condition. When the selection changes, the wire service provisions the method again and the component displays the matching Account records.
