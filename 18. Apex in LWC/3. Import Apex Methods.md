# Import Apex Methods

This folder explains how to import an Apex method into a Lightning Web Component (LWC) JavaScript file. The documentation follows the supplied screenshots and adds beginner-friendly explanations, working examples, and interview questions.

---

## 1. What Does “Import Apex Methods” Mean?

In LWC, an Apex method is imported into the component's JavaScript file using a Salesforce-scoped module path.

After importing the method, the component can call it using either:
- the `@wire` service (for reactive, read-only data), or
- an imperative JavaScript call (when the component needs to control when the method runs).

### Definition shown in the screenshot

> Use default import syntax in JavaScript to import an Apex method via the `@salesforce/apex` scoped packages.

In simple words, use JavaScript's default `import` statement to bring an Apex method into your LWC. The import path identifies the Apex class and the method that you want to use.

---

## 2. Syntax From the Screenshot

The screenshot shows this syntax:

```javascript
import apexMethodName from '@salesforce/apex/Namespace.Classname.apexMethodReference';
```

### Explanation of each part shown in the screenshot

| Term | Definition from the screenshot / explanation |
|---|---|
| `apexMethodName` | A symbol that identifies the Apex method. It is the local JavaScript name used to refer to the imported method. |
| `apexMethodReference` | The name of the Apex method to import. |
| `Classname` | The name of the Apex class. |
| `Namespace` | If the class is in the same namespace as the component, don't specify a namespace. If the class is in a managed package, specify the namespace of the managed package. |

### Important points

- The import uses a **default import**, so there are no curly braces around the imported method name.
- The import path starts with `@salesforce/apex/`.
- The class name and method name are separated by a period.
- Include a namespace only when the Apex class belongs to a different namespace, such as a managed package.
- The local JavaScript identifier can be named differently from the Apex method, although using the same name is usually clearer.

## 4. Understand the Import Path

Consider this import:

```javascript
import getAccountList from '@salesforce/apex/AccountController.getAccountList';
```

| Part | Meaning |
|---|---|
| `@salesforce/apex` | Salesforce scoped module used to import Apex methods. |
| `AccountController` | Apex class name. |
| `getAccountList` | Apex method name. |
| `getAccountList` (before `from`) | Local JavaScript identifier used in this component. |

### With a namespace

If an Apex class is in a managed package namespace, the import path includes that namespace:

```javascript
import getAccountList from '@salesforce/apex/PackageNamespace.AccountController.getAccountList';
```

Replace `PackageNamespace` with the actual namespace of the managed package.

### Without a namespace

For a class in the same namespace as the component, omit the namespace:

```javascript
import getAccountList from '@salesforce/apex/AccountController.getAccountList';
```

## 5. Apex Method Being Imported

The import statement refers to an Apex class and method. For example, the following Apex class exposes `getAccountList`:

**`AccountController.cls`**

```apex
public with sharing class AccountController {
    @AuraEnabled(cacheable=true)
    public static List<Account> getAccountList() {
        return [
            SELECT Id, Name, Type, Industry
            FROM Account
            LIMIT 5
        ];
    }
}
```

### Requirements for an Apex method called by LWC

- The method must be `static`.
- The method must be declared `public` or `global`.
- The method must have the `@AuraEnabled` annotation.
- If the method is called using `@wire`, it must be cacheable: `@AuraEnabled(cacheable=true)`.
- A cacheable method must not perform DML or otherwise change data.

## 7. Example: Call the Imported Apex Method with `@wire`

Use `@wire` when you want Salesforce to provision read-only data reactively.

### JavaScript — `apexWireDemo.js`

```javascript
import { LightningElement, wire } from 'lwc';
import getAccountList from '@salesforce/apex/AccountController.getAccountList';

export default class ApexWireDemo extends LightningElement {
    accounts;
    error;

    @wire(getAccountList)
    wiredAccounts({ data, error }) {
        if (data) {
            this.accounts = data;
            this.error = undefined;
        } else if (error) {
            this.accounts = undefined;
            this.error = error;
            console.error('Error loading Accounts:', error);
        }
    }
}
```

### HTML — `apexWireDemo.html`

```html
<template>
    <lightning-card title="Account List">
        <div class="slds-p-around_medium">
            <template lwc:if={accounts}>
                <template for:each={accounts} for:item="account">
                    <div key={account.Id} class="slds-p-vertical_x-small">
                        <p><strong>Account Name:</strong> {account.Name}</p>
                        <p><strong>Type:</strong> {account.Type}</p>
                        <p><strong>Industry:</strong> {account.Industry}</p>
                    </div>
                </template>
            </template>

            <template lwc:if={error}>
                <p class="slds-text-color_error">
                    Unable to load Account records.
                </p>
            </template>
        </div>
    </lightning-card>
</template>
```

### How it works

1. The Apex method is imported into the JavaScript file.
2. `@wire(getAccountList)` calls the imported Apex method.
3. When data is returned, it is stored in `this.accounts`.
4. If the call fails, the error is stored in `this.error`.
5. The HTML template displays the Account data or an error message.

## 8. Example: Call the Imported Apex Method Imperatively

Use an imperative call when you want to decide exactly when the Apex method runs, such as after a button click.

The same read-only Apex method can be called imperatively.

### JavaScript — `apexWireDemo.js`

```javascript
import { LightningElement } from 'lwc';
import getAccountList from '@salesforce/apex/AccountController.getAccountList';

export default class ApexWireDemo extends LightningElement {
    accounts;
    error;

    async handleLoadAccounts() {
        try {
            this.accounts = await getAccountList();
            this.error = undefined;
        } catch (error) {
            this.accounts = undefined;
            this.error = error;
            console.error('Error loading Accounts:', error);
        }
    }
}
```

### HTML — `apexWireDemo.html`

```html
<template>
    <lightning-card title="Load Accounts">
        <div class="slds-p-around_medium">
            <lightning-button
                label="Load Accounts"
                variant="brand"
                onclick={handleLoadAccounts}>
            </lightning-button>

            <template lwc:if={accounts}>
                <template for:each={accounts} for:item="account">
                    <p key={account.Id}>{account.Name}</p>
                </template>
            </template>

            <template lwc:if={error}>
                <p class="slds-text-color_error">
                    Unable to load Account records.
                </p>
            </template>
        </div>
    </lightning-card>
</template>
```

### How it works

1. The user clicks **Load Accounts**.
2. `handleLoadAccounts()` executes.
3. The imported Apex method is called with `await`.
4. The returned records are assigned to `this.accounts`.
5. If the Promise rejects, the `catch` block handles the error.

## 9. Wire vs. Imperative Apex

| Wire Apex | Imperative Apex |
|---|---|
| Uses the `@wire` decorator. | Calls the imported method directly. |
| Reactive data provisioning. | Runs when explicitly invoked. |
| Apex method must be cacheable. | Can call cacheable read methods or non-cacheable methods. |
| Suitable for read-only data. | Suitable for reads and operations such as insert, update, and delete. |
| Provides `data` and `error`. | Returns a Promise. |

**Remember:** Importing an Apex method does not itself execute the method. The component must call it using `@wire` or an imperative JavaScript call.

## 10. Interview Questions and Answers

### Q1. How do you import an Apex method into LWC?

Use the default import syntax:

```javascript
import methodName from '@salesforce/apex/ClassName.methodName';
```

### Q2. What is `@salesforce/apex`?

It is the Salesforce-scoped module path used to import Apex methods into an LWC JavaScript file.

### Q3. Why do we use a default import?

The Apex method is imported as a default export from its Salesforce Apex module reference. Therefore, the import syntax does not use curly braces.

### Q4. What is the format of an Apex import statement?

```javascript
import localMethodName from '@salesforce/apex/ClassName.apexMethodName';
```

For a namespaced class:

```javascript
import localMethodName from '@salesforce/apex/Namespace.ClassName.apexMethodName';
```

### Q5. What is a namespace in Salesforce?

A namespace is a unique prefix associated with a Salesforce package. It helps identify components and classes that belong to that package.

### Q6. When should we include a namespace in the import path?

Include the namespace when importing an Apex class from a managed package namespace. For a class in the same namespace as the component, omit it.

### Q7. Can the local imported method name be different from the Apex method name?

Yes. The identifier before `from` is the local JavaScript name. For clarity, it is generally best to use the Apex method's name.

### Q8. Does importing an Apex method execute it?

No. Importing only makes the method available in the JavaScript module. It runs when invoked through `@wire` or an imperative call.

### Q9. What are the requirements for an Apex method to be imported into LWC?

The method must be `static`, `public` or `global`, and annotated with `@AuraEnabled`.

### Q10. What is the difference between importing an Apex method and calling it?

Importing creates a reference to the Apex method in JavaScript. Calling executes the method and retrieves its result.

### Q11. What is the difference between wired and imperative Apex?

Wired Apex is reactive and is used for cacheable, read-only methods. Imperative Apex is explicitly invoked and returns a Promise.

### Q12. Can we import multiple Apex methods in one JavaScript file?

Yes. Import each Apex method separately:

```javascript
import getAccountList from '@salesforce/apex/AccountController.getAccountList';
import getContactList from '@salesforce/apex/ContactController.getContactList';
```

### Q13. Can we call an Apex method from LWC without `@AuraEnabled`?

No. The Apex method must be exposed using `@AuraEnabled`.

### Q14. What happens if the class or method name in the import path is incorrect?

The LWC compilation or deployment can fail because Salesforce cannot resolve the Apex method reference.

### Q15. Can an imported Apex method accept parameters?

Yes. Pass parameters when calling it imperatively, or provide a parameter object to the wired Apex method. The parameter names must match the Apex method's parameter names.

### Q16. What is the purpose of `cacheable=true`?

It marks a read-only Apex method as cacheable and is required for using the method with `@wire`.

### Q17. Can a method with `cacheable=true` perform DML?

No. Cacheable methods must not change data.

### Q18. What is the purpose of `LightningElement`?

It is the base class that an LWC component extends to use the standard component lifecycle and framework functionality.

### Q19. What does `await` do in an imperative Apex call?

It waits for the Apex Promise to resolve before continuing execution. If the Promise rejects, control moves to the `catch` block.

### Q20. What should you check if an Apex import is not working?

Check the Apex class name, method name, namespace, `@AuraEnabled` annotation, static access, class access permissions, and deployment status.

## 11. Common Mistakes

| Mistake | Correct approach |
|---|---|
| Using an incorrect import path | Verify the class and method names. |
| Adding curly braces around the Apex method import | Use a default import without curly braces. |
| Including a namespace when it is not needed | Omit it for a class in the same namespace. |
| Omitting a managed package namespace | Include the package namespace when required. |
| Importing a private or non-static Apex method | Use a `public` or `global`, static method. |
| Missing `@AuraEnabled` | Add the annotation to the Apex method. |
| Assuming import automatically runs Apex | Invoke it using `@wire` or imperatively. |
| Using `@wire` with a non-cacheable method | Use `@AuraEnabled(cacheable=true)` for a wired Apex method. |

- Use a JavaScript default import to import an Apex method.

## Conclusion

To use an Apex method in LWC, import it with JavaScript's default import syntax and the `@salesforce/apex` module path. The path identifies the Apex class and method, and may include a namespace when the class belongs to a managed package. After importing, call the method using `@wire` for reactive, cacheable read operations or imperatively when you need to control when it runs.
