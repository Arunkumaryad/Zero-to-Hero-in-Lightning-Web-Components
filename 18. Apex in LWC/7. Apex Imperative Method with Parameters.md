# Apex Imperative Method with Parameters in LWC

This folder demonstrates how to call an Apex method **imperatively with parameters** from a Lightning Web Component (LWC). The example provides an Account search box. As the user types, the component waits for one second and then calls Apex with the entered search text. Apex searches Account names and returns up to five matching records.

This README is based on the supplied screenshots. It includes the definitions, screenshot code, step-by-step explanations, implementation instructions, and Salesforce interview questions.

---

## 1. Definition: Imperative Apex with Parameters

**Imperative Apex with parameters** means invoking an Apex method directly from an LWC's JavaScript and passing values to that method at the time of invocation.

In this example:

1. The user enters text in the **Search Account** input.
2. `searchHandler()` reads the entered value.
3. A timer waits for 1,000 milliseconds (one second).
4. `callApex()` invokes the Apex method.
5. JavaScript passes the search text as an object property named `searchKey`.
6. Apex uses the value in a SOQL `LIKE` condition.
7. Apex returns up to five matching Account records.
8. The component stores the response in `accounts` and displays Name, Type, and Industry.

Parameters make Apex methods reusable for dynamic operations such as searching, filtering, creating, and updating records.

## 2. Apex Class From the Screenshot

**File: `AccountController.cls`**

```apex
public with sharing class AccountController {
    @AuraEnabled(cacheable=true)
    public static List<Account> findAccounts(String searchKey) {
        try {
            String key = '%' + searchKey + '%';
            return [
                SELECT Id, Name, Type, Industry
                FROM Account
                WHERE Name LIKE :key
                LIMIT 5
            ];
        } catch (Exception e) {
            throw new AuraHandledException(e.getMessage());
        }
    }
}
```

### Explanation

| Code | Meaning |
|---|---|
| `public with sharing class AccountController` | Declares a public Apex class and enforces record-level sharing rules. |
| `@AuraEnabled(cacheable=true)` | Exposes the method to Lightning components and marks this read-only method as cacheable. |
| `public static` | The method is public and static, as required for an Apex method exposed to LWC. |
| `List<Account>` | The method returns a list of Account records. |
| `findAccounts(String searchKey)` | Defines the method and its String parameter. |
| `String key = '%' + searchKey + '%';` | Adds `%` wildcards before and after the search text. |
| `SELECT Id, Name, Type, Industry` | Retrieves the specified Account fields. |
| `FROM Account` | Queries the Account object. |
| `WHERE Name LIKE :key` | Matches Account Names against the pattern stored in `key`. The colon binds the Apex variable into SOQL. |
| `LIMIT 5` | Returns at most five matching records. |
| `try/catch` | Handles exceptions raised while executing the method. |
| `AuraHandledException` | Sends a handled exception message back to the Lightning component. |

### Understanding `LIKE` and `%`

SOQL `LIKE` performs text pattern matching. `%` represents zero or more characters.

- `%tech%` — contains `tech`.
- `tech%` — starts with `tech`.
- `%tech` — ends with `tech`.

For example, if `searchKey` is `tech`, the Apex code creates `%tech%`, which can match an Account Name containing that text.

### Understanding `:key`

The colon (`:`) binds an Apex variable into a SOQL query. Using a bind variable is preferable to concatenating user input directly into dynamic SOQL.

### Why `cacheable=true`?

The method only reads Account records and does not perform DML, so it can be cacheable. A cacheable method must be read-only. Methods that insert, update, or delete records must not be marked `cacheable=true`.

### Why `with sharing`?

`with sharing` enforces record-level sharing rules for the running user. It does not automatically enforce object-level permissions or field-level security. Add appropriate CRUD/FLS checks or user-mode operations when required.

## 4. JavaScript Code From the Screenshot

**File: `apexImperativeWithParamsDemo.js`**

```javascript
import { LightningElement } from 'lwc';
import findAccounts from '@salesforce/apex/AccountController.findAccounts';

export default class ApexImperativeWithParamsDemo extends LightningElement {
    searchKey = '';
    accounts;
    timer;

    searchHandler(event) {
        window.clearTimeout(this.timer);
        this.searchKey = event.target.value;
        this.timer = setTimeout(() => {
            this.callApex();
        }, 1000);
    }

    callApex() {
        findAccounts({ searchKey: this.searchKey }).then(result => {
            this.accounts = result;
        }).catch(error => {
            console.error(error);
        });
    }
}
```

### Explanation step by step

**1. Store the search text**

```javascript
searchKey = '';
```

Stores the text entered by the user. It starts as an empty string.

**2. Store the returned records**

```javascript
accounts;
```

Stores the Account records returned by Apex. The HTML template uses this property to display the results.

**3. Store the timer identifier**

```javascript
timer;
```

Stores the identifier returned by `setTimeout()`. It is used by `clearTimeout()` to cancel a pending timer.

**4. Handle input changes**

```javascript
searchHandler(event) {
    window.clearTimeout(this.timer);
    this.searchKey = event.target.value;
    this.timer = setTimeout(() => {
        this.callApex();
    }, 1000);
}
```

- `window.clearTimeout(this.timer)` cancels the previous pending timer, if one exists.
- `event.target.value` reads the latest text from the search input.
- `this.searchKey` stores that text.
- `setTimeout()` schedules `callApex()` after 1,000 milliseconds.
- If the user types again before the timer finishes, the old timer is cancelled and a new one starts.

**5. Call Apex and pass the parameter**

```javascript
callApex() {
    findAccounts({ searchKey: this.searchKey }).then(result => {
        this.accounts = result;
    }).catch(error => {
        console.error(error);
    });
}
```

The key line is:

```javascript
findAccounts({ searchKey: this.searchKey })
```

For imperative Apex calls, parameters are passed as a JavaScript object. The object's property name must match the Apex method parameter name.

Apex declaration:

```apex
public static List<Account> findAccounts(String searchKey)
```

JavaScript invocation:

```javascript
findAccounts({ searchKey: this.searchKey })
```

- `.then(result => { ... })` handles a successful response.
- `this.accounts = result` stores the returned records.
- `.catch(error => { ... })` handles a rejected Promise.

**Important:** Pass an object, not a bare string.

Correct:

```javascript
findAccounts({ searchKey: this.searchKey });
```

Incorrect:

```javascript
findAccounts(this.searchKey);
```

## 5. What Is Debouncing?

The screenshot uses `clearTimeout()` and `setTimeout()` to delay the Apex call until the user pauses typing. This technique is called **debouncing**.

Without debouncing, typing a word could trigger an Apex request for every keystroke. With the one-second delay:

1. The user types a character.
2. A one-second timer starts.
3. If another character is typed before the timer finishes, the old timer is cancelled.
4. A new one-second timer starts.
5. Apex is called after the user stops typing for one second.

| Function | Purpose |
|---|---|
| `setTimeout(callback, delay)` | Schedules a function to run after the specified delay. |
| `clearTimeout(timerId)` | Cancels a timer that has not run yet. |
| `1000` | Delay in milliseconds; 1,000 ms equals one second. |

Debouncing reduces unnecessary calls while the user is typing. It does **not** cancel an Apex request that has already started.

## 11. Important Concepts

### Imperative Apex
Apex is invoked explicitly from JavaScript. The developer controls when the call is made.

### Passing Parameters to Apex
Parameters are passed as an object. Its property names must match the Apex method's parameter names.

```javascript
findAccounts({ searchKey: this.searchKey });
```

### SOQL `LIKE`
`LIKE` performs pattern matching on text fields. `%` matches zero or more characters.

### SOQL Bind Variables
The colon in `WHERE Name LIKE :key` binds the Apex variable `key` into the query.

### Promise
A Promise represents the eventual success or failure of an asynchronous operation. `.then()` handles success and `.catch()` handles failure.

### Debouncing
Debouncing delays execution until a specified period has passed without another triggering event. It is useful for search boxes.

### `setTimeout()`
Schedules a callback to execute after a specified delay.

### `clearTimeout()`
Cancels a pending timer created by `setTimeout()`.

### `event.target.value`
Reads the current value of the input that triggered the event.

### `cacheable=true`
Marks a read-only Apex method as cacheable. It is required for Apex methods used with `@wire`, but optional for imperative read-only calls. A cacheable method must not perform DML.

### `with sharing`
Enforces record-level sharing. It does not automatically enforce CRUD or field-level security.

## 12. `@wire` vs. Imperative Apex

| Feature | `@wire` Apex | Imperative Apex |
|---|---|---|
| Invocation | Framework provisions the method reactively | JavaScript invokes the method explicitly |
| Timing | Reacts to configuration and parameter changes | Developer decides when to call it |
| Return handling | Wired property/function receives `{ data, error }` | Returns a Promise |
| Parameters | Supplied through wire configuration | Passed as an object to the imported method |
| Common use | Automatically loading or refreshing read data | Search, button clicks, user actions, and DML |
| Cacheable | Required for Apex methods used with `@wire` | Not required for methods that perform changes; read-only methods can be cacheable |

## 13. Interview Questions and Answers

**Q1. What is imperative Apex in LWC?**  
Imperative Apex invokes an Apex method directly from JavaScript at a time chosen by the developer.

**Q2. How do you pass parameters to an imperative Apex method?**  
Pass a JavaScript object whose property names match the Apex method's parameter names.

```javascript
findAccounts({ searchKey: this.searchKey });
```

**Q3. Why are parameters passed as an object?**  
The LWC Apex invocation mechanism maps object property names to Apex method parameter names.

**Q4. What happens if the JavaScript parameter name does not match the Apex parameter name?**  
The parameter may not be mapped correctly, and Apex may receive a null value or the invocation may fail. Keep the names consistent.

**Q5. What is the purpose of `@AuraEnabled`?**  
It exposes an Apex method so Lightning components can invoke it.

**Q6. Why is the method marked `cacheable=true`?**  
It performs a read-only operation. Cacheable methods must not perform DML.

**Q7. Can a method that performs DML use `cacheable=true`?**  
No. A cacheable method must be read-only.

**Q8. What does `String key = '%' + searchKey + '%';` do?**  
It adds wildcard characters around the search text so the query can find Account Names containing it.

**Q9. What is the use of `LIKE` in SOQL?**  
It performs pattern matching on text fields.

**Q10. What does `%` mean in a SOQL `LIKE` pattern?**  
It matches zero or more characters.

**Q11. What does `WHERE Name LIKE :key` mean?**  
It filters Account records by matching the Name field against the Apex variable `key`.

**Q12. What is a bind variable in SOQL?**  
An Apex variable referenced in SOQL with a colon prefix. It avoids directly concatenating user input into dynamic query text.

**Q13. What is debouncing?**  
It delays a function call until a specified period has passed without another triggering event.

**Q14. Why use `clearTimeout()`?**  
It cancels the previous pending timer so that the latest scheduled search call runs after the user pauses typing.

**Q15. What is the purpose of `setTimeout()`?**  
It schedules a function to execute after a specified delay.

**Q16. Why is `1000` passed to `setTimeout()`?**  
The delay is in milliseconds. 1,000 milliseconds equals one second.

**Q17. Does debouncing cancel an Apex request that has already started?**  
No. `clearTimeout()` cancels a pending timer, not an Apex request already sent.

**Q18. What is the difference between debouncing and throttling?**  
Debouncing waits until events stop for a specified period. Throttling limits how often a function can run during a period.

**Q19. What does `event.target.value` return?**  
The current value of the input that triggered the event.

**Q20. What does `.then()` do?**  
It handles the successful resolution of a Promise.

**Q21. What does `.catch()` do?**  
It handles a rejected Promise.

**Q22. What does `this.accounts = result` do?**  
It stores the records returned by Apex in a component property for the template to display.

**Q23. Why is `LIMIT 5` used?**  
It restricts the query result to at most five records for this demonstration.

**Q24. Can imperative Apex perform insert, update, and delete operations?**  
Yes. Imperative Apex is commonly used for DML because the developer controls when the method is invoked. Such methods must not be cacheable.

**Q25. What is the purpose of `with sharing`?**  
It enforces record-level sharing rules for the current user.

**Q26. Does `with sharing` enforce field-level security?**  
No. Use appropriate CRUD/FLS checks or user-mode operations for object and field permissions.

**Q27. Can `async`/`await` replace `.then()`/`.catch()`?**  
Yes. Both approaches handle Promises.

```javascript
async callApex() {
    try {
        this.accounts = await findAccounts({
            searchKey: this.searchKey
        });
    } catch (error) {
        console.error(error);
    }
}
```

**Q28. What happens when the search input is empty in the screenshot's implementation?**  
The pattern becomes `%%`, which can match any Account Name that is not null. The query still returns at most five records.

**Q29. How can you avoid searching when the input is empty?**  
Check the input before invoking Apex:

```javascript
if (!this.searchKey.trim()) {
    this.accounts = [];
    return;
}
```

**Q30. How would you improve error handling?**  
Store the error in a component property and display a user-friendly message or toast instead of only logging it.

## 14. Common Mistakes and Solutions

| Mistake | Solution |
|---|---|
| Incorrect Apex import path | Verify the class and method names. |
| Missing `@AuraEnabled` | Add the annotation to expose the method to LWC. |
| Passing a bare string | Pass `{ searchKey: this.searchKey }`. |
| Parameter name mismatch | Match the JavaScript property to the Apex parameter. |
| Forgetting wildcard characters | Add `%` around the search text for a contains-style search. |
| Not using a bind variable | Use `:key` in the SOQL query. |
| Calling Apex on every keystroke | Use debouncing. |
| Not clearing the previous timer | Call `clearTimeout(this.timer)` before starting a new timer. |
| Not handling Promise rejection | Add `.catch()` or use `try/catch` with `async`/`await`. |
| Using `cacheable=true` on a DML method | Remove `cacheable=true` from methods that modify records. |
| Assuming `with sharing` enforces all permissions | Add CRUD/FLS enforcement where required. |

## 15. Optional Improvements for a Real Project

The code above preserves the screenshot's implementation. For a production-ready search component, consider:

1. **Handle empty input:** Clear the results or avoid calling Apex when the search text is blank.
2. **Show loading feedback:** Set an `isLoading` property while Apex is running and display a spinner.
3. **Show user-friendly errors:** Display an error message or toast instead of relying only on `console.error()`.
4. **Prevent stale results:** If multiple Apex requests overlap, an older response could arrive after a newer response. Track request sequence numbers so only the latest search response is displayed.
5. **Enforce permissions:** `with sharing` handles record-level sharing, but CRUD and FLS should also be enforced.
6. **Clean up timers:** Clear a pending timer when the component is disconnected.

Example empty-input check (an optional enhancement, not part of the screenshot code):

```javascript
searchHandler(event) {
    window.clearTimeout(this.timer);
    this.searchKey = event.target.value;

    if (!this.searchKey.trim()) {
        this.accounts = [];
        return;
    }

    this.timer = setTimeout(() => {
        this.callApex();
    }, 1000);
}
```
