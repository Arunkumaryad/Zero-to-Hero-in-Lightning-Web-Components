# Call Apex Methods Imperatively in LWC

This folder demonstrates how to call an Apex method **imperatively** from a Lightning Web Component (LWC). The component retrieves Account records only when the user clicks a button, then displays the Account Names.

The documentation follows the supplied screenshots and includes the definitions, Apex code, JavaScript, HTML, component metadata, implementation steps, explanations, and interview questions.

---

## 1. What Does Calling Apex Imperatively Mean?

**Imperative Apex** means calling an Apex method explicitly from JavaScript at a time chosen by the developer, usually in response to a user action such as clicking a button.

Unlike `@wire`, which provisions data reactively, an imperative Apex call is made by invoking the imported Apex method directly. The call returns a JavaScript `Promise`, which can be handled with `.then()` and `.catch()` or with `async`/`await`.

### Simple example

1. The user opens the LWC.
2. The component displays a **Call Apex Method** button.
3. The user clicks the button.
4. The JavaScript event handler calls the Apex method.
5. Apex queries Account records and returns the result.
6. The component stores the result in `accounts`.
7. The HTML displays the Account Names.

---

## 2. When Should We Use Imperative Apex?

The first screenshot lists these situations for using imperative Apex instead of `@wire`:

1. **To call a method that isn't annotated with `cacheable=true`**, which includes methods that insert, update, or delete data.
2. **To control when the invocation occurs.**
3. **To work with objects that aren't supported by User Interface API**, such as Task and Event.
4. **To call a method from an ES6 module that doesn't extend `LightningElement`.**

### In simple words

Use imperative Apex when you need to decide exactly when Apex runs, such as after a button click, or when calling an Apex method that performs a data modification.

**Important:** An imperative Apex method that only reads data can also be marked `@AuraEnabled(cacheable=true)`. The method in this example is cacheable, but it is still called imperatively because JavaScript invokes it directly from the click handler.

## 3. Apex Class From the Screenshot

**File: `AccountController.cls`**

The screenshot shows the following Apex class and method:

```apex
public with sharing class AccountController {
    @AuraEnabled(cacheable=true)
    public static List<Account> getAccountList() {
        try {
            return [
                SELECT Id, Name, Type, Industry
                FROM Account
                LIMIT 5
            ];
        } catch (Exception e) {
            throw new AuraHandledException(e.getMessage());
        }
    }
}
```

### Explanation of the Apex code

| Code | Explanation |
|---|---|
| `public with sharing class AccountController` | Declares a public Apex class and enforces record-level sharing rules. |
| `@AuraEnabled(cacheable=true)` | Exposes the method to Lightning components and marks this read-only method as cacheable. |
| `public static` | The method is public and static, as required for an Apex method exposed to LWC. |
| `List<Account>` | The method returns a list of Account records. |
| `getAccountList()` | The name of the Apex method imported into JavaScript. |
| `SELECT Id, Name, Type, Industry` | Retrieves the selected fields from Account. |
| `FROM Account` | Specifies the Account object. |
| `LIMIT 5` | Returns at most five records. |
| `try/catch` | Handles exceptions that occur while executing the query. |
| `AuraHandledException` | Sends a handled exception message back to the Lightning component. |

### Why is `cacheable=true` used here?

The method only reads Account records. It does not insert, update, or delete data, so it can be marked cacheable.

Apex methods called imperatively can be cacheable or non-cacheable, depending on the operation. Methods that modify data must not be marked `cacheable=true`.

### Why use `with sharing`?

`with sharing` enforces record-level sharing rules for the running user. It does not automatically enforce object-level permissions or field-level security. Apply appropriate CRUD/FLS checks or user-mode operations when required.

## 5. JavaScript Code From the Screenshot

**File: `apexImperativeDemo.js`**

```javascript
import { LightningElement } from 'lwc';
import getAccountList
    from '@salesforce/apex/AccountController.getAccountList';

export default class ApexImperativeDemo extends LightningElement {
    accounts;

    handleClick() {
        getAccountList().then(result => {
            console.log('Accounts retrieved: ', result);
            this.accounts = result;
        }).catch(error => {
            console.error('Error retrieving accounts: ', error);
        });
    }
}
```

### Explanation step by step

#### 1. Store the returned records

```javascript
accounts;
```

This property stores the Account records returned by Apex. The HTML template uses this property to display the records.

#### 2. Handle the button click

```javascript
handleClick() {
    // Apex call
}
```

The `handleClick()` method is connected to the button's `onclick` event. It runs when the user clicks the button.

#### 3. Call the Apex method

```javascript
getAccountList()
```

This directly invokes the imported Apex method. No `@wire` decorator is used.

#### 4. Handle a successful response with `.then()`

```javascript
.then(result => {
    console.log('Accounts retrieved: ', result);
    this.accounts = result;
})
```

- `result` contains the records returned by Apex.
- `console.log()` prints the result in the browser developer console.
- `this.accounts = result` stores the records in the component property.

#### 5. Handle errors with `.catch()`

```javascript
.catch(error => {
    console.error('Error retrieving accounts: ', error);
})
```

If the Apex call fails, the Promise rejects and the `.catch()` block handles the error.

### Important point

An imperative Apex method returns a Promise. The result is not assigned immediately when the method is called. Use `.then()` or `async`/`await` to handle the asynchronous response.

## 8. Another Promise Syntax Shown in the First Screenshot

The first screenshot also illustrates a `fetchData()` method that calls `getAccountList()` and handles both success and failure:

```javascript
fetchData() {
    getAccountList()
        .then((result) => {
            this.accounts = result;
            this.error = undefined;
        })
        .catch((error) => {
            this.error = error;
            this.accounts = undefined;
        });
}
```

### Explanation

- On success, the returned records are stored in `this.accounts`.
- `this.error = undefined` clears any previous error.
- On failure, the error is stored in `this.error`.
- `this.accounts = undefined` clears any previous records.

This is an alternative way to write the same Promise-based handling pattern. The main JavaScript screenshot uses `handleClick()` and logs the result or error to the console.

## 12. `@wire` vs. Imperative Apex

| Feature | `@wire` Apex | Imperative Apex |
|---|---|---|
| Invocation | Framework provisions the method | Developer invokes the method explicitly |
| Control over timing | Reactive to configuration and parameters | Full control over when the call is made |
| Return handling | Wired property or wired function receives `{ data, error }` | Returns a Promise |
| Common use | Automatically loading or refreshing read data | Button clicks, user actions, and data modifications |
| Cacheable annotation | Required for Apex methods used with `@wire` | Not required for methods that perform changes; read-only methods can be cacheable |
| Parameters | Passed through the wire configuration object | Passed as an object to the imported method |
| Re-invocation | Reactive changes can cause reprovisioning | Call the method again explicitly |

### Example: Wire Apex

```javascript
@wire(getAccountList)
accounts;
```

### Example: Imperative Apex

```javascript
handleClick() {
    getAccountList()
        .then(result => {
            this.accounts = result;
        })
        .catch(error => {
            this.error = error;
        });
}
```

## 13. Important Concepts to Understand

### A. Imperative Apex

Imperative Apex is a direct method invocation from JavaScript. It gives the developer control over when the Apex method is called.

### B. Promise

A Promise represents the eventual success or failure of an asynchronous operation.

A Promise can be handled using:

- `.then()` — runs when the operation succeeds.
- `.catch()` — runs when the operation fails.
- `.finally()` — runs after the Promise settles, whether it succeeds or fails.

### C. `async` and `await`

`async`/`await` is an alternative syntax for handling Promises.

Example:

```javascript
async handleClick() {
    try {
        this.accounts = await getAccountList();
        this.error = undefined;
    } catch (error) {
        this.error = error;
        this.accounts = undefined;
    }
}
```

This is an alternative implementation, not the exact syntax shown in the screenshot.

### D. `@AuraEnabled`

This annotation exposes an Apex method so that Lightning components can call it.

### E. `cacheable=true`

This annotation indicates that a method is read-only and its result can be cached. It is required for Apex methods used with `@wire`, but optional for imperative read-only Apex methods.

### F. `with sharing`

This enforces record-level sharing rules. It does not automatically enforce CRUD and field-level security.

### G. `this`

In an LWC class, `this` refers to the current component instance. It is used to access component properties and methods.

Example:

```javascript
this.accounts = result;
```

### H. `onclick`

The `onclick` event handler connects a button click to a JavaScript method.

### I. `for:each`

The LWC template directive iterates over an array and renders the specified markup for each item.

### J. `key`

A unique key helps LWC identify each item when rendering lists. Use a stable unique record identifier such as `account.Id`.

## 14. Interview Questions and Answers

### Q1. What is imperative Apex in LWC?

Imperative Apex is a way to call an Apex method directly from JavaScript at a specific time, such as when a user clicks a button.

### Q2. Why do we use imperative Apex?

We use it when we need control over when the Apex method runs, when performing DML operations, or when working with functionality not supported by the User Interface API.

### Q3. What is the difference between `@wire` and imperative Apex?

`@wire` provisions data reactively. Imperative Apex is invoked explicitly by JavaScript and returns a Promise.

### Q4. Does an imperative Apex method always need `cacheable=true`?

No. `cacheable=true` is not required for imperative methods that perform data changes. Read-only imperative methods can be marked cacheable, as in this example.

### Q5. Why can't a method that performs DML use `cacheable=true`?

A cacheable method must be read-only. Insert, update, and delete operations modify Salesforce data and therefore cannot be performed by a cacheable method.

### Q6. What does an imperative Apex call return?

It returns a JavaScript Promise.

### Q7. What is the purpose of `.then()`?

It handles the successful resolution of a Promise and receives the result returned by Apex.

### Q8. What is the purpose of `.catch()`?

It handles a rejected Promise, such as an error returned by the Apex call.

### Q9. What is the difference between `.then()` and `.catch()`?

`.then()` handles success, while `.catch()` handles failure.

### Q10. What is the purpose of `async` and `await`?

They provide a cleaner syntax for working with Promises. `await` pauses execution within an async function until the Promise settles.

### Q11. Why do we use `try/catch` with `async/await`?

The `try` block handles successful execution, while `catch` handles errors thrown by the awaited Promise.

### Q12. Why do we use `this.accounts = result`?

It stores the records returned by Apex in a component property so that the LWC template can display them.

### Q13. Why is `handleClick()` used?

It is the JavaScript event handler connected to the button. It invokes the Apex method when the user clicks the button.

### Q14. What is the purpose of `@AuraEnabled`?

It exposes an Apex method or property for use by Lightning components.

### Q15. Can imperative Apex methods accept parameters?

Yes. Pass an object whose property names match the Apex method parameter names.

Example:

```javascript
getAccountsByType({ accountType: this.selectedType });
```

The Apex method must have a matching parameter name, such as `String accountType`.

### Q16. Can we call multiple Apex methods imperatively?

Yes. You can invoke multiple methods and coordinate their Promises using `Promise.all()` or `Promise.allSettled()`, depending on the required error-handling behavior.

### Q17. What is the purpose of `with sharing`?

It enforces record-level sharing rules for the current user.

### Q18. Does `with sharing` enforce field-level security?

No. Use appropriate CRUD/FLS checks or user-mode operations to enforce object and field permissions.

### Q19. Why is `LIMIT 5` used in the query?

It restricts the query result to a maximum of five Account records for this demonstration.

### Q20. What happens if the Apex method throws an exception?

The Promise is rejected and the `.catch()` block can handle the error.

### Q21. What is the purpose of `lightning-button`?

It is a standard Lightning base component used to display a button.

### Q22. What does `onclick={handleClick}` mean?

It connects the button's click event to the JavaScript method named `handleClick`.

### Q23. Can an imperative Apex method be called without a button?

Yes. It can be called from any suitable JavaScript event or method, such as `connectedCallback()`, a form submission handler, or another user interaction.

### Q24. When should you use `Promise.all()`?

Use it when multiple independent asynchronous operations should run together and you want to continue after all of them succeed. `Promise.all()` rejects if any one of the Promises rejects.

### Q25. How would you display an error to the user instead of only logging it?

Store the error in a component property and display a message in the template, or dispatch a `ShowToastEvent` to show a toast notification.

## 15. Common Mistakes and Solutions

| Mistake | Solution |
|---|---|
| Incorrect Apex import path | Check the Apex class and method names. |
| Missing `@AuraEnabled` | Add the annotation to expose the method to LWC. |
| Using `cacheable=true` on a method that performs DML | Remove `cacheable=true` for methods that modify data. |
| Not handling Promise rejection | Add `.catch()` or use `try/catch` with `async`/`await`. |
| Not assigning the result to a component property | Store the result using `this.accounts = result`. |
| Calling the method without the correct parameters | Pass an object with parameter names matching the Apex method. |
| Missing `key` in a list | Use a unique key such as `account.Id`. |
| Expecting records before clicking the button | The method runs only when `handleClick()` invokes it. |
| Only logging errors | Store the error and display a useful message to the user. |
| Assuming `with sharing` enforces all permissions | Add CRUD and FLS enforcement where required. |
