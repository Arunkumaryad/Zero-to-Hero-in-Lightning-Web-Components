# Expose Apex Methods to LWC

This folder explains how to expose an Apex method so that a Lightning Web Component (LWC) can call it. The documentation is based on the supplied screenshots, with beginner-friendly explanations and interview preparation notes.

---

## 1. What Does “Expose Apex Methods to LWC” Mean?

Exposing an Apex method means making a server-side Apex method available for a Lightning Web Component to invoke.

An LWC cannot call an ordinary Apex method just because it exists in an Apex class. The method must meet Salesforce's requirements for access from Lightning components.

### Definition and requirements shown in the screenshot

The screenshot lists two requirements:

1. **Apex Method must be `static` and either `global` or `public`.**
2. **Method should be annotated with `@AuraEnabled`.**

In simple words:

- `static`: The method belongs to the Apex class, so it can be called without creating an instance of that class.
- `public` or `global`: The method has an access level that allows it to be exposed for use by Lightning components.
- `@AuraEnabled`: This annotation makes the method available to Lightning components, including LWC.

> Important: For a method called through `@wire`, the method must also use `@AuraEnabled(cacheable=true)`. A cacheable method must be read-only and must not perform DML.

## 2. Syntax From the Screenshot

The screenshot shows this Apex class:

```apex
public with sharing class AccountController {
    @AuraEnabled(cacheable=true)
    public static List<Account> getAccountList() {
        return [
            SELECT Id, Name, Type, Industry
            FROM Account
        ];
    }
}
```

### Explanation, line by line

| Code | Explanation |
|---|---|
| `public` | Makes the Apex class accessible to callers allowed by Salesforce. |
| `with sharing` | Enforces the current user's record-level sharing rules for operations in this class. |
| `class AccountController` | Declares an Apex class named `AccountController`. |
| `@AuraEnabled(cacheable=true)` | Exposes the method to Lightning components and marks it as cacheable/read-only. |
| `public static` | Declares a static method with public access. |
| `List<Account>` | The method returns a list of Account records. |
| `getAccountList()` | The name of the method that the LWC imports and calls. |
| `SELECT Id, Name, Type, Industry FROM Account` | Retrieves the specified fields from Account records. |

The method returns four fields for each Account: `Id`, `Name`, `Type`, and `Industry`.

## 3. Code From the Second Screenshot

The second screenshot shows the same class and method with a `try-catch` block and a query limit:

```apex
public with sharing class AccountController {
    @AuraEnabled(cacheable=true)
    public static List<Account> getAccountList() {
        try {
            return [
                SELECT Id, Name, Type, Industry
                FROM Account
                LIMIT 5
            ];
        } catch (Exception e) {
            throw new AuraHandledException(e.getMessage());
        }
    }
}
```

### What is different in this version?

1. `try` contains the SOQL query.
2. `LIMIT 5` restricts the result to a maximum of five Account records.
3. `catch (Exception e)` catches an exception raised in the `try` block.
4. `AuraHandledException` returns a handled error message that an LWC can receive.

### Why use `AuraHandledException`?

`AuraHandledException` is useful when you want to return a controlled error message from Apex to a Lightning component.

For example, the LWC can display an error toast when the Apex call fails.

**Production note:** The screenshot uses `e.getMessage()` directly. In production, avoid exposing sensitive internal exception details to users. Log technical details securely and return a safe, user-friendly message where appropriate.

## 4. Create the Apex Class in Salesforce

### Step 1: Open your Salesforce project

Open your Salesforce DX project in VS Code.

### Step 2: Create an Apex class

Create a class named:

```text
AccountController
```

Typical Salesforce DX path:

```text
force-app/main/default/classes/AccountController.cls
```

### Step 3: Add the Apex code

```apex
public with sharing class AccountController {
    @AuraEnabled(cacheable=true)
    public static List<Account> getAccountList() {
        try {
            return [
                SELECT Id, Name, Type, Industry
                FROM Account
                LIMIT 5
            ];
        } catch (Exception e) {
            throw new AuraHandledException(
                'Unable to retrieve Account records.'
            );
        }
    }
}
```

This version follows the screenshot's structure while returning a safe, generic error message.

### Step 4: Create the Apex class metadata file

If it is not generated automatically, create `AccountController.cls-meta.xml`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<ApexClass xmlns="http://soap.sforce.com/2006/04/metadata">
    <apiVersion>67.0</apiVersion>
    <status>Active</status>
</ApexClass>
```

Use an API version supported by your Salesforce project and org. The screenshots show API version `67.0` for the LWC bundle; the Apex class metadata should use a version supported by your org as well.

## 5. Call the Apex Method from LWC

Once the Apex method is exposed, import it into the LWC JavaScript file.

### Example folder structure

```text
force-app/
└── main/
    └── default/
        ├── classes/
        │   ├── AccountController.cls
        │   └── AccountController.cls-meta.xml
        └── lwc/
            └── accountList/
                ├── accountList.html
                ├── accountList.js
                └── accountList.js-meta.xml
```

### JavaScript — `accountList.js`

```javascript
import { LightningElement, wire } from 'lwc';
import getAccountList from '@salesforce/apex/AccountController.getAccountList';

export default class AccountList extends LightningElement {
    accounts;
    error;

    @wire(getAccountList)
    wiredAccounts({ data, error }) {
        if (data) {
            this.accounts = data;
            this.error = undefined;
        } else if (error) {
            this.accounts = undefined;
            this.error = error;
            console.error('Error retrieving Accounts:', error);
        }
    }
}
```

### HTML — `accountList.html`

```html
<template>
    <lightning-card title="Account List">
        <div class="slds-p-around_medium">
            <template lwc:if={accounts}>
                <template for:each={accounts} for:item="account">
                    <div key={account.Id} class="slds-p-vertical_x-small">
                        <p><strong>Name:</strong> {account.Name}</p>
                        <p><strong>Type:</strong> {account.Type}</p>
                        <p><strong>Industry:</strong> {account.Industry}</p>
                    </div>
                </template>
            </template>

            <template lwc:if={error}>
                <p class="slds-text-color_error">
                    Unable to load Account records.
                </p>
            </template>
        </div>
    </lightning-card>
</template>
```

### Metadata — `accountList.js-meta.xml`

```xml
<?xml version="1.0" encoding="UTF-8"?>
<LightningComponentBundle xmlns="http://soap.sforce.com/2006/04/metadata">
    <apiVersion>67.0</apiVersion>
    <isExposed>true</isExposed>
    <targets>
        <target>lightning__AppPage</target>
        <target>lightning__HomePage</target>
        <target>lightning__RecordPage</target>
    </targets>
</LightningComponentBundle>
```

The API version and targets can be adjusted to match your project and where you want to use the component.

## 6. Understand the Apex Import Statement

```javascript
import getAccountList from '@salesforce/apex/AccountController.getAccountList';
```

This import has three important parts:

- `@salesforce/apex`: Salesforce's module path for importing an Apex method.
- `AccountController`: The name of the Apex class.
- `getAccountList`: The name of the Apex method.

The imported method can then be called with `@wire` or imperatively.

## 7. Important Concepts

### `@AuraEnabled`

This annotation exposes an Apex method or property to Lightning components. For an Apex method, the method must be static and have `public` or `global` access.

### `cacheable=true`

This marks an Apex method as cacheable. It is required when calling an Apex method with `@wire`.

A cacheable method must not change data. Do not perform insert, update, delete, or other DML operations in a cacheable method.

### `with sharing`

This class declaration enforces record-level sharing rules for the current user.

Remember: `with sharing` does not automatically enforce object permissions or field-level security. Use appropriate security checks, such as user-mode SOQL/DML or `Security.stripInaccessible()`, as required.

### `static`

A static method belongs to the class rather than an instance of the class. LWC-exposed Apex methods must be static.

### `public` and `global`

These are Apex access modifiers. An LWC-exposed method must be declared `public` or `global`. Use the least permissive access level that meets the requirement.

### `List<Account>`

This is the return type in the screenshot. It means the method returns a collection of Account records.

### SOQL

SOQL (Salesforce Object Query Language) is used to retrieve Salesforce records. The example selects `Id`, `Name`, `Type`, and `Industry` from Account.

### `LIMIT 5`

This clause limits the query result to at most five records. It does not guarantee which five records are returned unless an `ORDER BY` clause is specified.

### `try-catch`

Apex uses `try-catch` to handle exceptions. Code that may fail is placed in the `try` block, and the `catch` block handles the exception.

### `AuraHandledException`

This exception type can return a handled error message to the Lightning component.

## 8. Wire vs. Imperative Apex — Related Interview Concept

The exposed method in this screenshot uses `@AuraEnabled(cacheable=true)`, so it can be called with `@wire`.

| Wire Apex | Imperative Apex |
|---|---|
| Uses the `@wire` decorator | Called directly from JavaScript |
| Reactive data provisioning | Runs when explicitly invoked |
| Requires `@AuraEnabled(cacheable=true)` | Uses `@AuraEnabled`; cacheable read methods may also be called imperatively |
| Read-only method | Can be used for read or write operations |
| Provides `data` and `error` | Returns a Promise |

**Example wire call:**

```javascript
@wire(getAccountList)
wiredAccounts({ data, error }) {
    // Handle the result
}
```

**Example imperative call:**

```javascript
async loadAccounts() {
    try {
        this.accounts = await getAccountList();
    } catch (error) {
        console.error(error);
    }
}
```

## 9. Interview Questions and Answers

### Q1. How do you expose an Apex method to LWC?

The Apex method must be `static`, declared `public` or `global`, and annotated with `@AuraEnabled`.

### Q2. What is the purpose of `@AuraEnabled`?

It exposes an Apex method or property so that Lightning components can access it.

### Q3. Why must an Apex method be static to call it from LWC?

LWC invokes the method through the Apex class. A static method can be called without creating an instance of that class.

### Q4. Can an Apex method exposed to LWC be private?

No. It must be declared `public` or `global` to be exposed to LWC.

### Q5. What is the purpose of `cacheable=true`?

It marks the method as read-only and allows its result to be cached. It is required when the Apex method is used with `@wire`.

### Q6. Can we perform DML in a method annotated with `@AuraEnabled(cacheable=true)`?

No. A cacheable Apex method must not modify data. Use an imperative call to a non-cacheable Apex method for DML operations.

### Q7. What is the difference between `@AuraEnabled` and `@AuraEnabled(cacheable=true)`?

`@AuraEnabled` exposes the method to Lightning components. Adding `cacheable=true` marks it as read-only and cacheable, and allows it to be used with `@wire`.

### Q8. What is `with sharing`?

It enforces record-level sharing rules for the Apex class. It does not automatically enforce object-level or field-level permissions.

### Q9. Does `with sharing` enforce CRUD and FLS?

No. Record-level sharing, object-level permissions, and field-level security are separate. Use appropriate checks or user-mode operations to enforce CRUD and FLS.

### Q10. What is the use of `AuraHandledException`?

It allows Apex to return a handled error message to a Lightning component.

### Q11. How do you import an Apex method in LWC?

```javascript
import methodName from '@salesforce/apex/ClassName.methodName';
```

### Q12. What does `List<Account>` mean?

It means the method returns a list (collection) of Account records.

### Q13. What is SOQL?

SOQL stands for Salesforce Object Query Language. It is used to retrieve records from Salesforce objects.

### Q14. What is the purpose of the `LIMIT` clause?

It restricts the maximum number of records returned by a SOQL query.

### Q15. Does `LIMIT 5` guarantee the same five records every time?

No. Without `ORDER BY`, the order is not guaranteed. Add an `ORDER BY` clause when a predictable order is required.

### Q16. What is the difference between `public` and `global`?

Both are access modifiers. `global` provides broader accessibility, commonly for APIs and cross-namespace use. Prefer `public` unless broader access is needed.

### Q17. Can we return an Account list from an Apex method to LWC?

Yes. An `@AuraEnabled` static method can return supported Apex data types, including a list of sObjects such as `List<Account>`.

### Q18. What is the difference between wired and imperative Apex?

Wired Apex is provisioned reactively by the wire service and is read-only. Imperative Apex is invoked explicitly from JavaScript and returns a Promise.

### Q19. Why should we avoid exposing raw exception messages in production?

Raw messages may reveal internal implementation or sensitive information. Return a safe message to the user and log diagnostic details appropriately.

### Q20. What should be considered before deploying an Apex method used by LWC?

Check class access, user permissions, record sharing, CRUD/FLS, input validation, error handling, governor limits, and test coverage.

## 10. Common Mistakes

| Mistake | Correct approach |
|---|---|
| Missing `@AuraEnabled` | Add `@AuraEnabled` to the method. |
| Method is not static | Declare the method `static`. |
| Method is private | Use `public` or `global`. |
| Using `@wire` without `cacheable=true` | Add `@AuraEnabled(cacheable=true)` for a read-only wired method. |
| Performing DML in a cacheable method | Use an imperative, non-cacheable method for data changes. |
| Import path has the wrong class or method name | Verify `@salesforce/apex/ClassName.methodName`. |
| Assuming `with sharing` enforces CRUD/FLS | Enforce object and field permissions separately. |
| Returning raw internal exception details | Return a safe message and log technical details securely. |

---

## 11. Quick Revision

- An Apex method exposed to LWC must be `static`.
- It must be `public` or `global`.
- It must have the `@AuraEnabled` annotation.
- Use `@AuraEnabled(cacheable=true)` for read-only methods called with `@wire`.
- Cacheable methods must not perform DML.
- `with sharing` enforces record-level sharing, not CRUD/FLS by itself.
- Use `AuraHandledException` to return a handled error message.
- Import Apex methods using `@salesforce/apex/ClassName.methodName`.
- Use SOQL to retrieve Salesforce records.
- Add `ORDER BY` when query result ordering matters.

## Conclusion

To call Apex from an LWC, expose the method with `@AuraEnabled`, declare it as `public` or `global`, and make it `static`. For reactive, read-only data, use `@AuraEnabled(cacheable=true)` with `@wire`. For operations that need explicit control or perform DML, use an imperative Apex call. Always consider record sharing, CRUD/FLS, exception handling, and governor limits.
