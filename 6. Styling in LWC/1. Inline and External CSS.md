# Inline and External CSS in LWC

This document explains **CSS in LWC**, and specifically focuses on the first two styling approaches covered in the course: **Inline Styling** and **External CSS**.

---

## 📌 CSS in LWC — Overview

> 🔎 **Definition (from training material):** CSS in LWC can be applied using the following approaches:

1. **Inline Styling**
2. **External CSS**
3. Using Lightning Design System
4. SLDS Design Token
5. Shared CSS in LWC
6. Dynamic Styling
7. Third-party CSS library
8. Applying CSS across shadow DOM

## 1️⃣ Inline Styling

**Inline styling** means applying CSS **directly on an HTML element** using the `style` attribute, right inside the template — without writing a separate CSS rule or class.

### Code Example (`inlineExternalCss.html`)

```html
<template>
    <lightning-card title="inline styling">
        <div class="slds-m-around_medium">
            <div style="color: red; font-size:20px;">Hello i am div</div>
        </div>
    </lightning-card>
</template>
```

**Explanation:**
- `<div style="color: red; font-size:20px;">Hello i am div</div>` — this is **inline styling** in action. The `style` attribute is applied **directly** on the `<div>` element, setting:
  - `color: red;` — makes the text color **red**.
  - `font-size: 20px;` — sets the font size to **20 pixels**.
- Because these styles are written **directly on the element**, they apply **only to this specific element** and don't need any separate CSS file or class name.

### When to Use Inline Styling
- Quick, **one-off styling** for a single element.
- Styles that need to be **dynamically calculated in JavaScript** and bound to the template (e.g., `style={computedStyle}` using a getter).
- **Not recommended** for styles that repeat across multiple elements or components — for that, External CSS (below) is the better approach.

## 2️⃣ External CSS

**External CSS** means writing your styles in a **separate `.css` file**, instead of directly inside the HTML tag. In LWC, every component can have its **own CSS file**, and LWC automatically applies it — you don't even need to manually import it.

### How It Works in LWC
- Every LWC component folder can contain a CSS file with the **exact same name** as the component.
  - Example: for a component named `inlineExternalCss`, the CSS file should be named `inlineExternalCss.css`.
- LWC **automatically scopes** this CSS file to **only** the component it belongs to — thanks to the **Shadow DOM** concept covered earlier (styles defined in one component's CSS file **will not leak out** and affect other components on the page).

### Example Structure
```
inlineExternalCss/
 ├── inlineExternalCss.js
 ├── inlineExternalCss.html
 ├── inlineExternalCss.css   ← External CSS file
 └── inlineExternalCss.js-meta.xml
```

### Example `inlineExternalCss.css`
```css
.highlight {
    color: red;
    font-size: 20px;
}
```

### Example `inlineExternalCss.html` (using the external class instead of inline style)
```html
<template>
    <lightning-card title="external css">
        <div class="slds-m-around_medium">
            <div class="highlight">Hello i am div</div>
        </div>
    </lightning-card>
</template>
```

**Explanation:**
- Instead of writing `style="color: red; font-size:20px;"` directly on the element (inline styling), the same visual result is achieved by:
  1. Defining a **CSS class** called `.highlight` inside the component's own `.css` file.
  2. Applying that class to the `<div>` using `class="highlight"`.
- LWC picks up this CSS file **automatically** (no import statement needed) and applies it **only within this component's Shadow DOM**.

### When to Use External CSS
- Styles that are used on **multiple elements** within the same component.
- Keeping your **HTML clean and readable**, separate from styling concerns.
- Any styling that benefits from **reusable class names** rather than repeating inline styles everywhere.
- This is generally considered **best practice** for most component styling, since it keeps markup and style concerns separated (similar to standard web development practices).

## 📊 Summary Table

| Approach | Where Styles Are Written | Scope | Best For |
|---|---|---|---|
| **Inline Styling** | Directly on the element, via the `style` attribute | Applies only to that single element | Quick, one-off, or dynamically computed styles |
| **External CSS** | A separate `.css` file with the same name as the component | Automatically scoped to the whole component (via Shadow DOM) | Reusable styles, multiple elements, cleaner markup |

---

## ✅ Quick Recap

- LWC supports **multiple ways** to apply CSS, starting with the two most fundamental: **Inline Styling** and **External CSS**.
- **Inline styling** uses the `style` attribute directly on an element — quick, but not reusable, and clutters the markup if overused.
- **External CSS** uses a dedicated `.css` file (same name as the component), which LWC **automatically scopes** to that component thanks to Shadow DOM — no manual import required.
- For anything beyond a quick one-off style, **External CSS is the recommended approach**, since it keeps your template clean and your styles reusable and organized.
- Later topics in this series will build on this foundation with **Lightning Design System (SLDS)**, **SLDS Design Tokens**, **Shared CSS**, **Dynamic Styling**, **Third-party CSS libraries**, and **Applying CSS across Shadow DOM**.
