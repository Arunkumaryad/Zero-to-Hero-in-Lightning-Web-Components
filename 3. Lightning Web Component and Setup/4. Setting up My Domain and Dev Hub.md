# Setting up My Domain and Dev Hub

This topic covers two important Salesforce setup features:

1. My Domain
2. Dev Hub

These features are important when working with Salesforce development, Salesforce DX, Scratch Orgs, and command-line development.

---

# 1. My Domain

## Definition from the Video

> Having a custom domain is more secure, some Salesforce features require it.

### Easy Explanation

**My Domain** gives your Salesforce Org a unique, custom domain name.

For example:

```text
https://yourcompany.my.salesforce.com
```

Instead of using only the generic Salesforce URL, your organization gets its own Salesforce-specific domain.

---

# 2. Why Do We Need My Domain?

My Domain is useful because:

- It gives your Salesforce Org a unique URL.
- It provides a more secure and branded experience.
- Some Salesforce features require My Domain.
- It is important for Salesforce development and customization.
- It provides a consistent domain for accessing your Salesforce Org.

In simple words:

```text
Salesforce Org
      ↓
    My Domain
      ↓
Unique Salesforce URL
```

# 12. Deploying the New Domain

After provisioning is complete, Salesforce displays:

```text
Step 3: Deploy Your New Domain
```

The screenshot states:

> Your new domain is provisioned. To start using it, deploy your new domain. After you deploy, users that visit your current domain are redirected to your new domain.

### Easy Explanation

Provisioning prepares the domain, but users do not start using the new domain until you deploy it.

The flow is:

```text
Domain Registered
       ↓
Domain Provisioned
       ↓
Deploy New Domain
       ↓
Users Start Using New Domain
```

Click:

```text
Deploy New Domain
```

---

# 14. Important My Domain Points

Remember these points:

- My Domain provides a custom domain for the Salesforce Org.
- It provides a more secure experience.
- Some Salesforce features require My Domain.
- The domain must first be registered.
- Salesforce provisions the domain after registration.
- After provisioning, the domain must be deployed.
- Users accessing the old/current domain can be redirected to the new domain after deployment.

# 16. What is Dev Hub?

**Dev Hub** is a Salesforce feature that is used to manage Salesforce development environments, particularly Scratch Orgs, from Salesforce CLI.

### Easy Explanation

Think of Dev Hub as the central Salesforce Org used to manage Scratch Orgs.

```text
                 Dev Hub
                    │
        ┌───────────┼───────────┐
        ↓           ↓           ↓
   Scratch Org  Scratch Org  Scratch Org
       1             2            3
```

Developers can use Salesforce CLI to create and manage Scratch Orgs through the Dev Hub.

---

# 17. Why Enable Dev Hub?

The screenshot specifically lists three purposes.

## 1. Create and Manage Orgs from the Command Line

Dev Hub allows developers to create and manage Scratch Orgs using Salesforce CLI.

Example:

```bash
sf org create scratch
```

The general development flow is:

```text
Salesforce CLI
      ↓
    Dev Hub
      ↓
Scratch Org
```

---

# 18. Scratch Org

The screenshot defines Scratch Orgs as:

> Scratch orgs are disposable Salesforce orgs that are used to support development and testing. They are fully configurable, allowing developers to emulate different Salesforce editions with different features and preferences.

### Easy Explanation

A Scratch Org is a temporary Salesforce environment that developers can create for development and testing.

For example:

```text
Developer
    ↓
Dev Hub
    ↓
Create Scratch Org
    ↓
Develop / Test
    ↓
Scratch Org can be deleted
```

Scratch Orgs are useful because developers can create separate environments for different development tasks.

---

# 19. Characteristics of Scratch Orgs

According to the screenshot, Scratch Orgs are:

### Disposable

They are temporary environments that can be created and deleted when they are no longer needed.

### Used for Development

Developers can use them to develop Salesforce features.

### Used for Testing

Developers can test changes before deploying them to another Salesforce environment.

### Fully Configurable

They can be configured according to the development requirements.

### Different Features and Preferences

Developers can configure Scratch Orgs to represent different Salesforce configurations.

---

# 20. View Information About Scratch Orgs

The second purpose shown in the screenshot is:

> View information about your scratch orgs

The screenshot further explains:

> Information includes details about requested scratch orgs, including whether they are active, expired or deleted.

### Easy Explanation

Dev Hub keeps information about Scratch Orgs.

A Scratch Org can have different states, such as:

```text
Active
Expired
Deleted
```

This allows developers to keep track of their Scratch Org environments.

---

# 21. Link Namespace Orgs

The third purpose shown in the screenshot is:

> Link namespace orgs

The screenshot explains:

> You can link namespace orgs to the Dev Hub for using scratch orgs with namespaces.

### Easy Explanation

A namespace can be associated with a Salesforce package or development setup.

Dev Hub allows namespace-related orgs to be linked so that Scratch Orgs can be used with namespaces.

# 26. My Domain vs Dev Hub

| My Domain | Dev Hub |
|---|---|
| Provides a custom Salesforce domain | Provides Scratch Org management capabilities |
| Related to Salesforce domain configuration | Related to Salesforce development |
| Configured from Setup → My Domain | Configured from Setup → Dev Hub |
| Domain is registered and provisioned | Dev Hub is enabled |
| New domain can be deployed to users | Scratch Orgs can be managed through CLI |
| Some Salesforce features require it | Important for Salesforce DX development |
