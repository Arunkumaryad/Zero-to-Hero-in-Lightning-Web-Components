A Salesforce Developer Org is an environment used by developers to learn, practice, develop, and test Salesforce features and customizations.

This folder explains how to set up a Salesforce Developer Org and prepare it for Salesforce development practice.

# 1. What is a Developer Org?

## Definition

> A Salesforce Developer Org is an environment used by developers to build, customize, learn, and test Salesforce applications and functionality.

### Easy Explanation

Think of a Developer Org as a **practice Salesforce environment**.

Instead of making changes directly in a company's Production Org, developers can use a Developer Org to:

- Learn Salesforce
- Practice Admin features
- Practice Apex
- Develop LWC
- Create custom objects
- Create custom fields
- Create Flows
- Test automation
- Practice SOQL
- Practice SOSL
- Test Salesforce configurations

For example:

```text
Developer Org
      │
      ├── Custom Objects
      ├── Custom Fields
      ├── Apex
      ├── LWC
      ├── Flows
      ├── Validation Rules
      ├── Reports
      └── Dashboards
```

# 2. Why Do We Need a Developer Org?

A Developer Org is useful because developers need a safe environment where they can experiment.

For example, suppose you want to practice:

```text
Create Account Object
        ↓
Create Custom Fields
        ↓
Create Apex Class
        ↓
Create LWC
        ↓
Create Flow
        ↓
Test Functionality
```

You should not perform all of these experiments directly in a Production Org.

Instead:

```text
Developer Org
     ↓
Practice
     ↓
Test
     ↓
Learn
```

# 4. Developer Org Signup

To create a Developer Org, you need to register for a Salesforce Developer environment.

The basic process is:

```text
Open Salesforce Developer Signup
          ↓
Enter Personal Information
          ↓
Choose Username
          ↓
Enter Email
          ↓
Complete Signup
          ↓
Verify Email
          ↓
Set Password
          ↓
Login
          ↓
Developer Org Ready
```

| Information | Purpose |

| First Name | User identification |
| Last Name | User identification |

| Username | Salesforce login identity |
| Company | Organization information |
| Country | Location information |
| Role | Developer-related information |

---

# 6. Salesforce Username

One of the most important things during Developer Org creation is the **Username**.

The username is used to log into Salesforce.

For example:

```text
arun.developer@example.com
```

### Important

A Salesforce username must be **globally unique across Salesforce**, not just unique inside your Developer Org.

Therefore, a username such as:

```text
arun@gmail.com
```

may already be taken.

You can use a unique format such as:

```text
arun.salesforce.dev@example.com
```

---

# 7. Email Verification

After completing registration, Salesforce sends a verification email to the registered email address.

The process is:

```text
Signup
  ↓
Verification Email
  ↓
Open Email
  ↓
Click Verification Link
  ↓
Set Password
```

Email verification is important because Salesforce uses the registered email address for account verification and communication.

---

# 8. Setting the Password

After verifying your email, Salesforce allows you to set your password.

Choose a strong password according to Salesforce's password requirements.

Example:

```text
Username:
arun.salesforce.dev@example.com

Password:
YourStrongPassword
```

> Never store your Salesforce password inside GitHub.

# 17. Developer Org vs Production Org

| Developer Org | Production Org |
|---|---|
| Mainly used for development and learning | Used by the actual business |
| Safe for experimentation | Contains real business data/configuration |
| Used for practice | Used by end users |
| Developers can test changes | Changes can affect business processes |
| Not the live business environment | Live environment |

### Simple Example

```text
Developer Org
     ↓
Development
     ↓
Testing
     ↓
Deployment
     ↓
Production Org
```

---

# 18. Developer Org vs Sandbox

A Developer Org and Sandbox are both development environments, but they are not the same.

| Developer Org | Sandbox |
|---|---|
| Separate Salesforce org | Copy/environment associated with a Production Org |
| Commonly used for learning and development | Commonly used for testing changes before Production |
| Starts with its own configuration | Created from Production |
| Useful for personal practice | Useful in real project development lifecycle |
| Does not represent a direct copy of Production | Can contain copied Production configuration/data depending on sandbox type |

A common project lifecycle is:

```text
Development
     ↓
Sandbox
     ↓
Testing
     ↓
UAT
     ↓
Production
```

# 23. Common Mistakes

### Mistake 1: Using a non-unique username

Salesforce usernames must be unique across Salesforce.

---

### Mistake 2: Forgetting the password

Keep your credentials secure.

---

### Mistake 3: Not verifying the email

The Developer Org setup may not be completed until email verification is performed.

---

### Mistake 4: Storing credentials in GitHub

Never commit:

```text
Password
Security Token
Client Secret
Access Token
```

to a public repository.

# 24. Interview Questions

## Q1. What is a Salesforce Developer Org?

A Developer Org is a Salesforce environment used primarily for learning, development, customization, and testing.

---

## Q2. Why do developers use a Developer Org?

Developers use it to safely practice Salesforce development without affecting a live Production environment.

---

## Q3. What can you practice in a Developer Org?

You can practice:

- Apex
- LWC
- SOQL
- Flows
- Objects
- Fields
- Validation Rules
- Security
- Automation

---

## Q4. Is Developer Org the same as Production Org?

No.

A Developer Org is primarily a development/learning environment, while Production is the live business environment.

---

## Q5. What is a Salesforce username?

A Salesforce username is the login identity used to access a Salesforce Org.

The username must be globally unique across Salesforce.

---

## Q6. What is Setup?

Setup is the Salesforce configuration area used by administrators and developers to configure and manage Salesforce functionality.

---

## Q7. Can we develop LWC in a Developer Org?

Yes. A Developer Org can be used to practice and develop Lightning Web Components.
