# Navigate to New Record With Default Values — Salesforce LWC

## 1. Overview

This project demonstrates two ways to navigate to the standard **New Contact** form from a Lightning Web Component (LWC):

1. **Navigate To New Record** — opens a blank New Contact form.
2. **Navigate To New Record With Default Values** — opens the New Contact form with selected fields prepopulated.

The component uses Salesforce's Navigation Service through `NavigationMixin` and uses `encodeDefaultFieldValues` to encode the initial field values.

## 2. Definitions and Syntax from the Training Screenshots

### Navigation Service

The Navigation Service allows Lightning components to navigate to supported Salesforce pages. In an LWC, import `NavigationMixin` from `lightning/navigation` and apply it to the component's base class.

```javascript
import { NavigationMixin } from 'lightning/navigation';

export default class MyCustomElement extends NavigationMixin(LightningElement) {}
```

To request navigation, call:

```javascript
this[NavigationMixin.Navigate](pageReference, [replace]);
```

- **`pageReference`**: An object describing the destination page.
- **`replace`**: An optional Boolean. Its default is `false`; when `true`, the current browser-history entry is replaced.

### PageReference

A PageReference is an object that describes the destination page. The screenshot uses this object:

```javascript
{
    type: 'standard__objectPage',
    attributes: {
        objectApiName: 'Contact',
        actionName: 'new'
    }
}
```

- `type: 'standard__objectPage'` identifies a standard object page.
- `objectApiName: 'Contact'` selects the Contact object.
- `actionName: 'new'` requests the new-record form.

### `encodeDefaultFieldValues`

The screenshot imports this utility:

```javascript
import { encodeDefaultFieldValues } from 'lightning/pageReferenceUtils';
```

It encodes field/value pairs into a string suitable for the PageReference `state.defaultFieldValues` property. This lets Salesforce prepopulate supported fields on the new-record form. It does **not** save the record automatically.

The screenshot's example values are:

```javascript
const defaultValues = encodeDefaultFieldValues({
    FirstName: 'Arun',
    LastName: 'Kumar',
    LeadSource: 'Others'
});
```

These are Contact field API names. `FirstName`, `LastName`, and `LeadSource` are supplied as initial values for the form.

## 5. JavaScript — `navigateToObjectPage.js`

The following code preserves the logic shown in the screenshot, with consistent formatting:

```javascript
import { LightningElement } from 'lwc';
import { NavigationMixin } from 'lightning/navigation';
import { encodeDefaultFieldValues } from 'lightning/pageReferenceUtils';

export default class NavigateToObjectPage extends NavigationMixin(LightningElement) {
    navigateToNewRecord() {
        this[NavigationMixin.Navigate]({
            type: 'standard__objectPage',
            attributes: {
                objectApiName: 'Contact',
                actionName: 'new'
            }
        });
    }

    navigateToNewRecordWithDefault() {
        const defaultValues = encodeDefaultFieldValues({
            FirstName: 'Arun',
            LastName: 'Kumar',
            LeadSource: 'Other'
        });

        this[NavigationMixin.Navigate]({
            type: 'standard__objectPage',
            attributes: {
                objectApiName: 'Contact',
                actionName: 'new'
            },
            state: {
                defaultFieldValues: defaultValues
            }
        });
    }
}
```

**Note about `LeadSource`:** The screenshot shows `'Others'`. Standard Salesforce Contact `LeadSource` picklist values depend on your org; a common standard value is `Other`. Use the exact active picklist value configured in your org. To match the screenshot exactly, change it to `'Others'` if that exact value exists in your org.

### JavaScript explanation

1. `LightningElement` is the base class for an LWC.
2. `NavigationMixin` adds the navigation methods.
3. `encodeDefaultFieldValues` encodes the values for the new-record form.
4. `navigateToNewRecord()` opens a blank New Contact form.
5. `navigateToNewRecordWithDefault()` prepares initial field values.
6. `FirstName`, `LastName`, and `LeadSource` are Contact field API names.
7. `state.defaultFieldValues` passes the encoded values to the destination form.

Use an API version supported by your Salesforce org. The `lightning__AppPage` target makes the component available in Lightning App Builder for Lightning App Pages.

## 7. Create, Deploy, and Test

1. Open your Salesforce DX project in VS Code.
2. Navigate to `force-app/main/default/lwc/`.
3. Create an LWC named `navigateToObjectPage`.
4. Add the HTML, JavaScript, and metadata code from this README.
5. Save all three files.
6. Deploy the component from VS Code, or run:

   ```bash
   sf project deploy start --source-dir force-app/main/default/lwc/navigateToObjectPage
   ```

7. In Salesforce, go to **Setup → Lightning App Builder**.
8. Create or open a Lightning App Page.
9. Drag the component onto the page.
10. Save and activate the page if required.
11. Open the page and test both buttons:
    - **Navigate To New Record** should open a blank New Contact form.
    - **Navigate To New Record With Default Values** should open the form with the configured default values.
12. Confirm the values are correct, then save the Contact only if you intend to create a record.

## 8. Troubleshooting

- **Component is missing from Lightning App Builder:** Confirm `<isExposed>true</isExposed>` and the `lightning__AppPage` target.
- **Button does not respond:** Confirm the `onclick` handler names match the JavaScript methods exactly.
- **Default values do not appear:** Check the `state.defaultFieldValues` property, field API names, and the target page's support for default field values.
- **Picklist value is not accepted:** Use an active value configured for the Contact `LeadSource` picklist in your org.
- **User cannot save the Contact:** Check Create permission for Contacts, required fields, validation rules, duplicate rules, and other save restrictions.
- **Deployment fails:** Check filenames, XML syntax, API version, and deployment errors in VS Code or the Salesforce CLI output.

## 9. Interview Topics to Know

### Navigation Service and `NavigationMixin`
Used by LWC to navigate to Salesforce pages. `NavigationMixin` is imported from `lightning/navigation` and applied to `LightningElement`.

### PageReference
An object that describes a destination page, typically with `type`, `attributes`, and optional `state`.

### `standard__objectPage`
A PageReference type for standard object pages. Here it opens a standard object's new-record form.

### `objectApiName` and `actionName`
`objectApiName` identifies the object (here, `Contact`); `actionName: 'new'` requests the new-record form.

### `encodeDefaultFieldValues`
Encodes field/value pairs for the `defaultFieldValues` PageReference state. It prepopulates fields; it does not create or save the record.

### PageReference `state`
Carries extra navigation parameters. In this example, `state.defaultFieldValues` passes the encoded initial values.

### Metadata targets
`lightning__AppPage` exposes the LWC for use on Lightning App Pages in Lightning App Builder.

## 10. Interview Questions and Answers

**Q1. What is the Navigation Service in LWC?**  
It lets Lightning components navigate to supported Salesforce pages and destinations.

**Q2. What is `NavigationMixin`?**  
A mixin from `lightning/navigation` that provides navigation functionality to an LWC.

**Q3. What is a PageReference?**  
A JavaScript object that describes the destination page and any supported navigation parameters.

**Q4. What is `standard__objectPage`?**  
A PageReference type used for supported standard object pages.

**Q5. What does `actionName: 'new'` do?**  
It requests the standard new-record form for the specified object.

**Q6. What does `encodeDefaultFieldValues()` do?**  
It encodes field/value pairs into the format expected by `state.defaultFieldValues`.

**Q7. Does `defaultFieldValues` save the record?**  
No. It only prefills supported fields in the form. The user must save the record.

**Q8. Why use field API names rather than labels?**  
The navigation state expects field API names, such as `FirstName`, not the UI label text.

**Q9. What is the difference between the two buttons in this project?**  
The first opens a blank New Contact form; the second passes default field values to prepopulate the form.

**Q10. What is the purpose of `lightning__AppPage` in the XML file?**  
It allows the component to be placed on a Lightning App Page through Lightning App Builder.

**Q11. What should be checked if a default picklist value does not appear?**  
Check the field API name and use an active picklist value available in the org.

**Q12. Can the same approach be used for another object?**  
Yes, if the object supports the standard new action and the user has the required access. Update `objectApiName` and supply field API names valid for that object.

## 11. Scenario-Based Interview Questions

**Scenario 1: The new form opens, but the first and last names are blank.**  
Verify that `FirstName` and `LastName` are valid field API names, that `encodeDefaultFieldValues()` is used, and that its result is assigned to `state.defaultFieldValues`.

**Scenario 2: A picklist default value is ignored.**  
Confirm that the value exactly matches an active picklist value in the org and is valid for the user's record type.

**Scenario 3: The component is not visible in App Builder.**  
Check `isExposed`, the metadata target, deployment status, and that you are editing a supported Lightning App Page.

**Scenario 4: The user wants a new Lead instead of a Contact.**  
Change `objectApiName` to `'Lead'` and update the default field names to fields supported by Lead.

**Scenario 5: The developer expects the record to be saved automatically.**  
Explain that navigation with default values only opens a prefilled form. Saving the record requires a separate supported record-creation process.
