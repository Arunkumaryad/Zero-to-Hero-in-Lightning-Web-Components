# Navigate To Aura Component

## 1. Overview

This example demonstrates how to navigate from a Lightning Web Component (LWC) to an Aura component and pass a value through URL state.

The LWC displays a **Navigate To Aura** button. When clicked, it navigates to an Aura component named `AuraNavigation` and passes a value under the URL state key `c__id`. The Aura component reads the PageReference, retrieves the value, and displays it.

### Topics covered

- Salesforce Navigation Service and `NavigationMixin`
- `standard__component` PageReference
- Navigating to an Aura component
- Passing values with PageReference `state`
- The `c__` prefix for custom URL state parameters
- Aura attributes, initialization handlers, and controller JavaScript
- LWC metadata targets

> **Important:** The screenshot's value `123456789` is a placeholder, not a valid Salesforce record ID. Replace it with a real record ID if you intend to pass an actual record identifier.

## 2. Definitions from the Screenshots

### Navigation Service

In an LWC JavaScript class, import the `lightning/navigation` module and use `NavigationMixin` in the component's base class.

```javascript
import { NavigationMixin } from 'lightning/navigation';

export default class MyCustomElement extends NavigationMixin(LightningElement) {}
```

To dispatch a navigation request, call the navigation service's method:

```javascript
this[NavigationMixin.Navigate](pageReference, [replace]);
```

- **`pageReference`** — an object describing the destination page.
- **`replace`** — an optional Boolean. It defaults to `false`. If `true`, the current browser-history entry is replaced.

### PageReference

A PageReference is an object that describes a navigation destination. It includes a `type`, destination `attributes`, and optional `state` values.

### `standard__component`

`standard__component` is a PageReference type used to navigate to a Lightning component by specifying its component name.

### PageReference `state`

The `state` property contains URL state parameters. Custom state keys must be namespaced. For a component in the default namespace, use the `c__` prefix, as in `c__id`.

```html
<template>
    <lightning-card title="Navigate To Aura">
        <lightning-button
            variant="brand"
            label="Navigate To Aura"
            onclick={navigateToAura}>
        </lightning-button>
    </lightning-card>
</template>
```

**Explanation**

- `lightning-card` displays the card title.
- `lightning-button` creates the action button.
- `variant="brand"` applies Salesforce's standard brand styling.
- `onclick={navigateToAura}` invokes the JavaScript method when clicked.

### 3.2 JavaScript — `navigateToAuraComponent.js`

The screenshot code, formatted for readability:

```javascript
import { LightningElement } from 'lwc';
import { NavigationMixin } from 'lightning/navigation';

export default class NavigateToAuraComponent extends NavigationMixin(LightningElement) {
    navigateToAura() {
        this[NavigationMixin.Navigate]({
            type: 'standard__component',
            attributes: {
                componentName: 'c__AuraNavigation'
            },
            state: {
                'c__id': '123456789'
            }
        });
    }
}
```

**Explanation, step by step**

1. `LightningElement` is the base class for an LWC.
2. `NavigationMixin` provides navigation methods.
3. `type: 'standard__component'` indicates navigation to a Lightning component.
4. `componentName: 'c__AuraNavigation'` identifies the Aura component. The `c__` prefix is used for a custom component in the default namespace in this navigation pattern.
5. `state: { 'c__id': '123456789' }` adds a custom URL state parameter named `c__id`.
6. `NavigationMixin.Navigate()` performs the navigation.

> **Security note:** URL state values are strings and may be visible in the URL. Do not put secrets or sensitive information in URL state.

### 3.3 Metadata — `navigateToAuraComponent.js-meta.xml`

## 4. Aura Target Component

The screenshot's Aura bundle is named `AuraNavigation` and contains files such as:

```text
AuraNavigation/
├── AuraNavigation.auradoc
├── AuraNavigation.cmp
├── AuraNavigation.cmp-meta.xml
├── AuraNavigation.css
├── AuraNavigation.design
├── AuraNavigation.svg
├── AuraNavigationController.js
├── AuraNavigationHelper.js
└── AuraNavigationRenderer.js
```

For this example, the essential files are the `.cmp`, `.cmp-meta.xml`, and controller JavaScript files.

### 4.1 Aura markup — `AuraNavigation.cmp`

This matches the screenshot:

```xml
<aura:component
    implements="flexipage:AvailableForAllPageTypes,lightning:isUrlAddressable"
    access="global">

    <aura:attribute name="id" type="String"/>

    <aura:handler name="init" value="{!this}" action="{!c.onload}"/>

    <div class="slds-card">
        <div>Hey, I am coming from LWC and My Record Id is : {!v.id}</div>
    </div>
</aura:component>
```

**Explanation**

- `flexipage:AvailableForAllPageTypes` makes the Aura component available for supported Lightning page types in App Builder.
- `lightning:isUrlAddressable` allows the Aura component to be addressed through a Lightning URL and exposes its PageReference.
- `access="global"` makes the component available outside its own namespace where supported.
- `<aura:attribute name="id" type="String"/>` declares an attribute named `id`.
- The `init` handler invokes `c.onload` when the component initializes.
- `{!v.id}` displays the value of the Aura component's `id` attribute.
- `slds-card` applies Salesforce Lightning Design System card styling.

### 4.2 Aura controller — `AuraNavigationController.js`

This matches the screenshot:

```javascript
({
    onload: function(component) {
        var myPageRef = component.get("v.pageReference");
        var id = myPageRef.state.c__id;
        component.set("v.id", id);
    }
})
```

**Explanation, step by step**

1. `component.get("v.pageReference")` retrieves the PageReference provided to the URL-addressable Aura component.
2. `myPageRef.state.c__id` reads the custom state parameter sent by the LWC.
3. `component.set("v.id", id)` assigns the value to the Aura component's `id` attribute.
4. The Aura markup displays it using `{!v.id}`.

**Robustness improvement:** In production code, check that `myPageRef` and `myPageRef.state` exist before reading `c__id`. The screenshot shows the minimal training example without those checks.

### 4.3 Aura component metadata — `AuraNavigation.cmp-meta.xml`

The screenshot's file list includes this metadata file. A typical Aura component metadata file can be:

## 6. Deploy and Test

1. Open your Salesforce DX project in VS Code.
2. Create the LWC bundle `navigateToAuraComponent` with its HTML, JavaScript, and metadata files.
3. Create the Aura bundle `AuraNavigation` with its markup, metadata, and controller.
4. Ensure the component name is exactly `c__AuraNavigation` in the LWC PageReference.
5. Save all files.
6. Deploy both bundles. For example, from the project root:

   ```bash
   sf project deploy start --source-dir force-app/main/default/lwc/navigateToAuraComponent
   sf project deploy start --source-dir force-app/main/default/aura/AuraNavigation
   ```

   You can also deploy the entire `force-app/main/default` directory.

7. Open **Setup → Lightning App Builder**.
8. Create or open a Lightning App Page and add the `navigateToAuraComponent` LWC.
9. Save and activate the page if required.
10. Open the page and click **Navigate To Aura**.
11. Confirm that the Aura component displays the passed value.

If a command fails because your project uses a different folder path, substitute the actual bundle path.

## 7. Troubleshooting

- **Aura component does not open:** Verify that the Aura bundle is deployed and `componentName` is `c__AuraNavigation`.
- **State value is missing:** Confirm the LWC uses `state: { 'c__id': '...' }` and the Aura controller reads `myPageRef.state.c__id`.
- **The displayed ID is undefined:** Confirm `lightning:isUrlAddressable` is implemented and the Aura component is opened through a PageReference that includes the state.
- **The LWC does not appear in App Builder:** Check `isExposed`, the `lightning__AppPage` target, and deployment status.
- **The displayed value is not a real record:** The screenshot uses `'123456789'` as a placeholder. Use a real Salesforce record ID if needed.
- **Security concern about URL state:** Do not put passwords, tokens, private customer data, or secrets in URL state. URLs can be visible in browser history, logs, and copied links.
- **API version error:** Change the metadata API version to one supported by your org.

## 8. Interview Topics

- **Navigation Service:** Salesforce's navigation mechanism for moving to pages and components from Lightning components.
- **`NavigationMixin`:** A mixin imported from `lightning/navigation` that provides navigation methods.
- **PageReference:** A structured object that describes a navigation destination.
- **`standard__component`:** PageReference type used to navigate to a Lightning component.
- **PageReference `state`:** Carries URL state parameters as key-value pairs.
- **`c__` prefix:** Namespace prefix for custom PageReference state parameters in the default namespace.
- **`lightning:isUrlAddressable`:** Aura interface that allows a component to be addressed through a URL and receive a PageReference.
- **`v.pageReference`:** Aura component value containing the current PageReference.
- **`component.get()` and `component.set()`:** Aura APIs used to read and update component attributes.
- **Aura init handler:** Runs initialization logic when an Aura component is created.
- **`@api` versus Aura attributes:** `@api` defines public properties in LWC; `<aura:attribute>` defines attributes in Aura.
- **URL-state security:** State parameters should not contain confidential values.

## 9. Interview Questions and Answers

**Q1. How do you navigate from LWC to an Aura component?**  
Use `NavigationMixin` with a PageReference of type `standard__component`, specifying the Aura component's name in `attributes.componentName`.

**Q2. What is `standard__component`?**  
It is a PageReference type used to navigate to a Lightning component.

**Q3. Why is the component name `c__AuraNavigation`?**  
The `c__` prefix identifies a custom component in the default namespace for this navigation pattern; `AuraNavigation` is the component name.

**Q4. How is the ID passed from LWC to Aura?**  
The LWC includes it in PageReference `state`, using the key `c__id`.

**Q5. Why must the state key use `c__`?**  
Custom PageReference state parameters require a namespace prefix. `c__` is the prefix for custom parameters in the default namespace.

**Q6. How does the Aura component read the state parameter?**  
It reads the PageReference from `v.pageReference` and accesses `myPageRef.state.c__id`.

**Q7. What does `lightning:isUrlAddressable` do?**  
It enables an Aura component to be addressed through a Lightning URL and provides access to the PageReference.

**Q8. What is the purpose of the Aura `init` handler?**  
It runs initialization logic when the component is created. Here, it calls `onload` to read the state parameter.

**Q9. How does the controller update the value displayed in the Aura markup?**  
It calls `component.set("v.id", id)`, and the markup renders `{!v.id}`.

**Q10. Can URL state be used to store sensitive data?**  
No. URL state can be exposed through browser history, logs, or copied URLs. Pass only non-sensitive values.

**Q11. Is `123456789` a valid Salesforce record ID?**  
It is a placeholder in the screenshot, not a valid Salesforce record ID.

**Q12. What is the difference between an LWC public property and an Aura attribute?**  
An LWC uses `@api` to expose a public property; Aura declares component attributes with `<aura:attribute>` and accesses them in markup using expressions such as `{!v.id}`.

## 10. Scenario-Based Interview Questions

**Scenario 1: The Aura component opens, but the ID shows as blank.**  
Check that the state key is `c__id` in both components and that the Aura component reads `v.pageReference` when it is available.

**Scenario 2: The Aura component cannot be found.**  
Verify that the Aura bundle name is `AuraNavigation`, the namespace prefix is correct, and deployment succeeded.

**Scenario 3: The value displays, but it is not a real Salesforce record ID.**  
Replace the placeholder with a real ID from the same Salesforce org. Displaying a string does not prove the record exists.

**Scenario 4: The value is missing on some navigation paths.**  
Make the Aura controller defensive by checking that the PageReference and its state exist before reading the parameter.

**Scenario 5: A developer wants to pass an access token through the URL.**  
Do not do this. URL parameters can be exposed in history, logs, and shared links. Use an appropriate secure authentication or server-side mechanism instead.
