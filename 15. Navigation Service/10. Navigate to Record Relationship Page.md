# Navigate to Record Relationship Page

## 1. Overview

This Lightning Web Component (LWC) demonstrates how to navigate to the related Contacts list for a specific Account using Salesforce's Navigation Service.

The component displays a **Navigate** button. When clicked, it opens the **Contacts** related list page for the Account identified in the JavaScript PageReference.

The example uses:
- `NavigationMixin` from `lightning/navigation`
- A PageReference of type `standard__recordRelationshipPage`
- `recordId`, `objectApiName`, `relationshipApiName`, and `actionName`

> **Important:** The screenshot uses a hardcoded Account record ID. Replace it with an Account ID that exists in your own Salesforce org. IDs are org-specific.

## 2. Definitions from the Screenshots

### Navigation Service

The Navigation Service allows an LWC to navigate to supported Salesforce pages. In the component's JavaScript class, import `NavigationMixin` from `lightning/navigation` and apply it to the component's base class.

```javascript
import { NavigationMixin } from 'lightning/navigation';

export default class MyCustomElement extends NavigationMixin(LightningElement) {}
```

To dispatch a navigation request, call:

```javascript
this[NavigationMixin.Navigate](pageReference, [replace]);
```

- **`pageReference`** — an object that describes the destination page.
- **`replace`** — an optional Boolean that defaults to `false`. If `true`, the current browser-history entry is replaced.

### PageReference

A PageReference is an object that describes a page to navigate to in Salesforce Lightning Experience, Experience Builder sites, or the Salesforce mobile app. It defines the destination through properties such as `type`, `attributes`, and optional `state`.

### `standard__recordRelationshipPage`

`standard__recordRelationshipPage` is a PageReference type used to navigate to a related list for a particular record.

The screenshot uses this PageReference structure:

```javascript
{
    type: 'standard__recordRelationshipPage',
    attributes: {
        recordId: '001bm00002PGRurAAH',
        objectApiName: 'Account',
        relationshipApiName: 'Contacts',
        actionName: 'view'
    }
}
```

- **`type: 'standard__recordRelationshipPage'`** — identifies the destination as a record relationship page.
- **`recordId`** — the ID of the parent record, in this example an Account.
- **`objectApiName: 'Account'`** — the API name of the parent object.
- **`relationshipApiName: 'Contacts'`** — the relationship API name for the related Contacts list.
- **`actionName: 'view'`** — opens the relationship page in view mode.

## 5. JavaScript — `navigateToRelatedRelationship.js`

The following is the screenshot's code, formatted for readability:

```javascript
import { LightningElement } from 'lwc';
import { NavigationMixin } from 'lightning/navigation';

export default class NavigateToRelatedRelationship extends NavigationMixin(LightningElement) {
    navigateToRelatedList() {
        this[NavigationMixin.Navigate]({
            type: 'standard__recordRelationshipPage',
            attributes: {
                recordId: '001bm00002PGRurAAH',
                objectApiName: 'Account',
                relationshipApiName: 'Contacts',
                actionName: 'view'
            }
        });
    }
}
```

### Code explanation

1. `LightningElement` is the base class for an LWC.
2. `NavigationMixin` adds navigation methods to the component.
3. `navigateToRelatedList()` runs when the button is clicked.
4. `NavigationMixin.Navigate()` sends the navigation request.
5. `standard__recordRelationshipPage` identifies the destination as a related-list page.
6. `recordId` identifies the parent Account.
7. `objectApiName` specifies the parent object, `Account`.
8. `relationshipApiName: 'Contacts'` specifies the Contacts relationship.
9. `actionName: 'view'` requests the relationship page in view mode.

### Recommended improvement: use the current Account record ID

If the component is placed on an Account record page, it is more reusable to receive the current record ID through `@api recordId` instead of hardcoding it:

```javascript
import { LightningElement, api } from 'lwc';
import { NavigationMixin } from 'lightning/navigation';

export default class NavigateToRelatedRelationship extends NavigationMixin(LightningElement) {
    @api recordId;

    navigateToRelatedList() {
        this[NavigationMixin.Navigate]({
            type: 'standard__recordRelationshipPage',
            attributes: {
                recordId: this.recordId,
                objectApiName: 'Account',
                relationshipApiName: 'Contacts',
                actionName: 'view'
            }
        });
    }
}
```

This version assumes the component is placed on an Account record page and Salesforce supplies the current Account ID. If it is placed on an App Page, `recordId` is not automatically supplied; provide an Account ID through another mechanism or use a record page.

## 6. Metadata — `navigateToRelatedRelationship.js-meta.xml`

The screenshot exposes the component on a Lightning App Page and uses API version `67.0`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<LightningComponentBundle xmlns="http://soap.sforce.com/2006/04/metadata">
    <apiVersion>67.0</apiVersion>
    <isExposed>true</isExposed>
    <targets>
        <target>lightning__AppPage</target>
    </targets>
</LightningComponentBundle>
```

Use an API version supported by your Salesforce org. The `lightning__AppPage` target makes the component available in Lightning App Builder for Lightning App Pages.

> If you want to use the improved `@api recordId` version on an Account record page, add `<target>lightning__RecordPage</target>` inside `<targets>`. Keep `lightning__AppPage` only if you also want to place it on App Pages.

## 7. Create, Deploy, and Test

1. Open your Salesforce DX project in VS Code.
2. Navigate to `force-app/main/default/lwc/`.
3. Create the LWC bundle and add the HTML, JavaScript, and metadata files.
4. Replace the hardcoded Account ID with a valid Account ID from your org, or use the improved `@api recordId` version on an Account record page.
5. Confirm `relationshipApiName` is `Contacts` for the Account-to-Contacts relationship.
6. Save the files.
7. Deploy from VS Code, or run:

   ```bash
   sf project deploy start --source-dir force-app/main/default/lwc/navigateToRelatedRelationship
   ```

8. Open **Setup → Lightning App Builder**.
9. Create or edit an App Page, or use an Account Record Page if you added the `lightning__RecordPage` target.
10. Drag the component onto the page, save, and activate if required.
11. Click **Navigate**.
12. Verify Salesforce opens the Contacts related list for the configured Account.

## 8. Troubleshooting

- **Navigation fails:** Verify that the Account ID exists in the current org and that the user can access it.
- **Wrong Account opens:** Check `recordId`. Use `this.recordId` on an Account record page to make the component context-aware.
- **`recordId` is undefined:** An App Page does not automatically supply a record ID. Use an Account Record Page or provide the ID another way.
- **Related list does not open:** Confirm the relationship API name is correct. For the standard Account-to-Contacts relationship, the screenshot uses `Contacts`.
- **Component is missing in App Builder:** Check `isExposed`, the appropriate metadata target, and deployment status.
- **Deployment fails:** Check the bundle/file names, JavaScript syntax, XML syntax, API version, and CLI output.

## 9. Interview Topics

### Navigation Service
A Salesforce service that lets Lightning components navigate to supported Salesforce pages using PageReference objects.

### `NavigationMixin`
A mixin imported from `lightning/navigation` that adds navigation methods to an LWC.

### PageReference
A structured object describing the destination page and its supported parameters.

### `standard__recordRelationshipPage`
A PageReference type used to navigate to a related list for a specific record.

### `recordId`
The unique Salesforce ID of the parent record whose related list should be opened.

### `objectApiName`
The API name of the parent object, such as `Account`.

### `relationshipApiName`
The API name of the relationship or related list, such as `Contacts`.

### `actionName`
The action requested for the relationship page. In this example, it is `view`.

### `@api`
A decorator that exposes a public property or method so it can receive values from a parent component or Salesforce page context.

## 10. Interview Questions and Answers

**Q1. What is the Navigation Service in LWC?**  
It allows an LWC to navigate to supported Salesforce pages without constructing URLs manually.

**Q2. What is `NavigationMixin`?**  
It is a mixin from `lightning/navigation` that adds navigation methods to an LWC.

**Q3. What is a PageReference?**  
An object describing a navigation destination through its type, attributes, and optional state.

**Q4. What does `standard__recordRelationshipPage` do?**  
It navigates to a related list for a specified record.

**Q5. What is `relationshipApiName`?**  
It identifies the related list or relationship to display, such as `Contacts` for Contacts related to an Account.

**Q6. Why is `recordId` important?**  
It identifies the parent record whose related list should be opened.

**Q7. Why should hardcoded record IDs be avoided?**  
Record IDs differ between orgs and records. Using `@api recordId` makes the component reusable on different Account records.

**Q8. What does `lightning__AppPage` do?**  
It makes the component available for placement on Lightning App Pages in Lightning App Builder.

**Q9. What target is needed to place this component on an Account record page?**  
`lightning__RecordPage`.

**Q10. Why might the related list fail to open for a user?**  
The record ID or relationship API name may be incorrect, or the user may lack access to the Account or related records.

## 11. Scenario-Based Interview Questions

**Scenario 1: The component opens the wrong Account's Contacts.**  
Check the hardcoded `recordId`; prefer `this.recordId` on an Account record page.

**Scenario 2: `this.recordId` is undefined.**  
Check where the component is placed. An App Page does not automatically provide a record ID.

**Scenario 3: The component is unavailable in Lightning App Builder.**  
Verify `isExposed`, the `lightning__AppPage` or `lightning__RecordPage` target, and successful deployment.

**Scenario 4: Navigation fails even though the Account exists.**  
Verify the relationship API name, the PageReference structure, the user's record access, and browser console errors.
