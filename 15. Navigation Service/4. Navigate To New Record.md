# Navigate to New Record in Salesforce LWC

## 1. Overview

This project demonstrates how to open the **New Contact** record form from a Lightning Web Component (LWC) when a user clicks a button.

The component uses Salesforce's **Navigation Service** and `NavigationMixin` from the `lightning/navigation` module. The destination is described using a PageReference object.

## 2. Definition and Syntax from the Training Screenshots

The training lesson uses the Navigation Service to request navigation from an LWC. In the component's JavaScript class, import the navigation module:

```javascript
import { NavigationMixin } from 'lightning/navigation';
```

Apply the `NavigationMixin` function to the component's base class:

```javascript
export default class MyCustomElement extends NavigationMixin(LightningElement) {}
```

To dispatch a navigation request, use:

```javascript
this[NavigationMixin.Navigate](pageReference, [replace]);
```

- **`pageReference`**: An object that defines the destination page.
- **`replace`**: A Boolean value that defaults to `false`. If `true`, the navigation replaces the current entry in browser history.

In the screenshot, the PageReference uses:

```javascript
{
    type: 'standard__objectPage',
    attributes: {
        objectApiName: 'Contact',
        actionName: 'new'
    }
}
```

This requests the standard **New Contact** page.

## 5. JavaScript: `navigateToObjectPage.js`

This follows the code shown in the screenshot, with consistent formatting and semicolons:

```javascript
import { LightningElement } from 'lwc';
import { NavigationMixin } from 'lightning/navigation';

export default class NavigateToObjectPage extends NavigationMixin(LightningElement) {
    navigateToNewRecord() {
        this[NavigationMixin.Navigate]({
            type: 'standard__objectPage',
            attributes: {
                objectApiName: 'Contact',
                actionName: 'new'
            }
        });
    }
}
```

### Explanation, line by line

1. `LightningElement` is the base class for an LWC.
2. `NavigationMixin` adds navigation methods to the component.
3. `extends NavigationMixin(LightningElement)` applies the mixin.
4. `navigateToNewRecord()` runs when the user clicks the button.
5. `this[NavigationMixin.Navigate](...)` asks Salesforce to navigate.
6. `type: 'standard__objectPage'` identifies a standard object page.
7. `objectApiName: 'Contact'` selects the Contact object.
8. `actionName: 'new'` requests the form for creating a new Contact.

**Important:** This example creates a new **Contact**. It does not create or save the record automatically; the user must complete and submit the Salesforce form.

## 6. Metadata: `navigateToObjectPage.js-meta.xml`

The screenshot uses API version `67.0` and exposes the component on a Lightning App Page.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<LightningComponentBundle xmlns="http://soap.sforce.com/2006/04/metadata">
    <apiVersion>67.0</apiVersion>
    <isExposed>true</isExposed>
    <targets>
        <target>lightning__AppPage</target>
    </targets>
</LightningComponentBundle>
```

Use an API version supported by your Salesforce org. The `lightning__AppPage` target allows the component to be added to a Lightning App Page through Lightning App Builder.

## 7. How to Create and Test the Component

1. Open your Salesforce DX project in VS Code.
2. Go to `force-app/main/default/lwc/`.
3. Create an LWC named `navigateToObjectPage`.
4. Add the HTML, JavaScript, and metadata files shown above.
5. Save the files.
6. Deploy the component from VS Code, or run:

   ```bash
   sf project deploy start --source-dir force-app/main/default/lwc/navigateToObjectPage
   ```

7. In Salesforce, open **Setup → Lightning App Builder**.
8. Create or open a Lightning App Page.
9. Drag the custom component onto the page.
10. Save and activate the page if required.
11. Open the page and click **Navigate To New Record**.
12. Confirm that Salesforce opens the standard New Contact form.
13. Enter the required Contact information and save if you want to create a record.

## 8. Troubleshooting

- **Component does not appear in Lightning App Builder:** Check `<isExposed>true</isExposed>` and the `lightning__AppPage` target.
- **Button does not work:** Confirm `onclick={navigateToNewRecord}` exactly matches the JavaScript method name.
- **Wrong object form opens:** Verify `objectApiName: 'Contact'`.
- **Page does not open:** Confirm the PageReference type and action name, and check the browser console.
- **Cannot save the Contact:** Check required fields, validation rules, duplicate rules, and the user's permissions to create Contacts.
- **Deployment fails:** Check the folder and filenames, XML syntax, and API version supported by the org.

## 9. Key Interview Concepts

### Navigation Service
A Salesforce service used by Lightning components to navigate to supported Salesforce pages and web destinations.

### `NavigationMixin`
A mixin imported from `lightning/navigation` that provides navigation capabilities to an LWC class.

### `PageReference`
A JavaScript object describing the destination page. It generally contains a `type`, `attributes`, and optionally `state`.

### `standard__objectPage`
A PageReference type for standard object pages, such as an object's list, new-record form, or other supported object actions.

### `objectApiName`
The API name of the object to open. In this example, the value is `'Contact'`.

### `actionName`
The object-page action to request. In this example, `'new'` requests the new-record form.

### `lightning__AppPage`
A metadata target that makes the component available to add to a Lightning App Page in Lightning App Builder.

## 10. Interview Questions and Answers

**Q1. What is Navigation Service in LWC?**  
It allows an LWC to navigate to supported Salesforce pages and web destinations.

**Q2. Which module provides `NavigationMixin`?**  
`lightning/navigation`.

**Q3. How do you apply `NavigationMixin`?**  
Extend `NavigationMixin(LightningElement)` in the component class.

**Q4. What is a PageReference?**  
A JavaScript object that describes a destination page using its type, attributes, and optional state.

**Q5. What does `standard__objectPage` mean?**  
It identifies a standard object page as the navigation destination.

**Q6. What does `objectApiName: 'Contact'` specify?**  
It specifies the Contact object.

**Q7. What does `actionName: 'new'` do?**  
It requests the standard form for creating a new record of the specified object.

**Q8. Does this code save a Contact automatically?**  
No. It opens the standard New Contact form. The user must enter details and save.

**Q9. What is the purpose of `onclick={navigateToNewRecord}`?**  
It invokes the JavaScript method when the button is clicked.

**Q10. Why is the metadata XML file required?**  
It defines the component's API version, exposure, and supported Lightning App Builder targets.

**Q11. What is the purpose of `lightning__AppPage`?**  
It makes the component available for placement on a Lightning App Page.

**Q12. What does the optional `replace` argument in navigation do?**  
When `true`, it replaces the current browser-history entry; otherwise, navigation normally adds an entry.

**Q13. Can this approach be used for another object?**  
Yes. Change `objectApiName` to the desired object's API name and ensure the `new` action is supported for that object.

## 11. Scenario-Based Interview Questions

**Scenario 1: The button is visible but nothing happens.**  
Check the click handler, JavaScript method name, deployment status, and browser console.

**Scenario 2: The user reaches the New Contact form but cannot save.**  
Check object-level Create permission, required fields, validation rules, duplicate rules, and any other save requirements.

**Scenario 3: The developer wants to open the New Lead form instead.**  
Change `objectApiName: 'Contact'` to `objectApiName: 'Lead'`, provided the user has access and the action is supported.

**Scenario 4: The component is missing in Lightning App Builder.**  
Check that it is exposed and that `lightning__AppPage` is included in the metadata targets.

**Scenario 5: The developer wants to prepopulate fields on the new-record form.**  
For supported object-page navigation, use the documented PageReference `state` parameters such as `defaultFieldValues`, encoding values with Salesforce's supported utility where appropriate. Confirm the target object and context support the feature.

This component displays a **Navigate To New Record** button.
