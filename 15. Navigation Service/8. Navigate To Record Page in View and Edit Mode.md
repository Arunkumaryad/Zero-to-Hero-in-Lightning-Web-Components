# Navigate To Record Page in View and Edit Mode

## 1. Overview

This project demonstrates how to navigate to a specific Salesforce Contact record in **View** mode or **Edit** mode using the Lightning Web Component (LWC) Navigation Service.

The component displays two buttons:
- **View Mode** — opens the specified Contact record in view mode.
- **Edit Mode** — opens the same Contact record in edit mode.

The implementation uses `NavigationMixin` from `lightning/navigation` and a PageReference of type `standard__recordPage`.

## 2. Definitions from the Screenshots

### Navigation Service

The Navigation Service allows an LWC to navigate to supported Salesforce pages. In the component's JavaScript file, import `NavigationMixin` from `lightning/navigation` and apply it to the component's base class.

```javascript
import { NavigationMixin } from 'lightning/navigation';

export default class MyCustomElement extends NavigationMixin(LightningElement) {}
```

To dispatch a navigation request, call:

```javascript
this[NavigationMixin.Navigate](pageReference, [replace]);
```

- **`pageReference`**: An object that describes the destination page.
- **`replace`**: An optional Boolean that defaults to `false`. If `true`, the current browser-history entry is replaced.

### PageReference

A PageReference is an object that describes a page to navigate to in Salesforce Lightning Experience, Experience Builder sites, or the Salesforce mobile app. It specifies the destination using properties such as `type`, `attributes`, and optional `state`.

### `standard__recordPage`

`standard__recordPage` is a PageReference type used to navigate to a Salesforce record page.

The screenshot uses this structure:

```javascript
{
    type: 'standard__recordPage',
    attributes: {
        recordId: '003bm00001eJ9JNAA0',
        objectApiName: 'Contact',
        actionName: 'view'
    }
}
```

- **`type: 'standard__recordPage'`** — identifies a record page.
- **`recordId`** — the Salesforce ID of the record to open.
- **`objectApiName: 'Contact'`** — identifies the object that owns the record.
- **`actionName: 'view'`** — requests the record's view page.
- **`actionName: 'edit'`** — requests the record's edit page.

> **Important:** The screenshot contains a hardcoded Contact record ID. Replace it with a valid Contact ID from your org before testing. A record ID from another org will not identify the same record in your org.

## 5. JavaScript — `navigateToRecordPage.js`

The screenshot's code is reproduced below with consistent formatting. Replace the sample ID with a Contact ID from your own org.

```javascript
import { LightningElement, api } from 'lwc';
import { NavigationMixin } from 'lightning/navigation';

export default class NavigateToRecordPage extends NavigationMixin(LightningElement) {
    @api recordId;

    recordViewMode() {
        this[NavigationMixin.Navigate]({
            type: 'standard__recordPage',
            attributes: {
                recordId: '003bm00001eJ9JNAA0',
                objectApiName: 'Contact',
                actionName: 'view'
            }
        });
    }

    recordEditMode() {
        this[NavigationMixin.Navigate]({
            type: 'standard__recordPage',
            attributes: {
                recordId: '003bm00001eJ9JNAA0',
                objectApiName: 'Contact',
                actionName: 'edit'
            }
        });
    }
}
```

### Recommended improvement: use the component's `recordId`

The screenshot imports `api` and declares `@api recordId`, but its navigation methods still hardcode the record ID. If the component is placed on a Contact record page, use the provided `recordId` so the buttons open the current Contact.

Use this improved version when placing the component on a Contact record page:

```javascript
import { LightningElement, api } from 'lwc';
import { NavigationMixin } from 'lightning/navigation';

export default class NavigateToRecordPage extends NavigationMixin(LightningElement) {
    @api recordId;

    recordViewMode() {
        this[NavigationMixin.Navigate]({
            type: 'standard__recordPage',
            attributes: {
                recordId: this.recordId,
                objectApiName: 'Contact',
                actionName: 'view'
            }
        });
    }

    recordEditMode() {
        this[NavigationMixin.Navigate]({
            type: 'standard__recordPage',
            attributes: {
                recordId: this.recordId,
                objectApiName: 'Contact',
                actionName: 'edit'
            }
        });
    }
}
```

This version assumes the component is placed on a Contact record page, where Salesforce supplies the current record ID. If you place the component on an App Page, Salesforce will not automatically provide a Contact record ID; in that case, pass or select a valid Contact ID.

## 6. Metadata — `navigateToRecordPage.js-meta.xml`

The screenshot exposes the component on a Lightning App Page and uses API version `67.0`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<LightningComponentBundle xmlns="http://soap.sforce.com/2006/04/metadata">
    <apiVersion>67.0</apiVersion>
    <isExposed>true</isExposed>
    <targets>
        <target>lightning__AppPage</target>
    </targets>
</LightningComponentBundle>
```

Use an API version supported by your Salesforce org. The `lightning__AppPage` target makes the component available in Lightning App Builder for Lightning App Pages.

> If you use the improved `@api recordId` version on a Contact record page, add `<target>lightning__RecordPage</target>` to the `<targets>` list so it can be placed on record pages. Keep `lightning__AppPage` only if you also want it on App Pages.


8. Open **Setup → Lightning App Builder**.
9. Create or edit a Lightning App Page, or use a Contact Record Page if you enabled the `lightning__RecordPage` target.
10. Drag the component onto the page, save, and activate if required.
11. Click **View Mode** and confirm the selected Contact opens in view mode.
12. Click **Edit Mode** and confirm the selected Contact opens in edit mode. Save changes only if you intend to update the record.

## 8. Troubleshooting

- **The page does not open:** Verify the Contact ID exists in the current org and the user can access that record.
- **A different Contact opens:** Check the `recordId` in the PageReference. Prefer `this.recordId` when the component is on a Contact record page.
- **`recordId` is undefined:** The component may be on an App Page, which does not automatically supply a record ID. Use a record page or provide a record ID another way.
- **Component does not appear in App Builder:** Check `isExposed`, the relevant target (`lightning__AppPage` or `lightning__RecordPage`), and deployment status.
- **Edit mode is unavailable:** Check the user's edit permissions and field-level security.
- **Deployment fails:** Check file names, JavaScript syntax, XML syntax, API version, and the CLI output.

## 9. Interview Topics

### Navigation Service
A Salesforce service that lets components navigate to supported Salesforce pages using PageReference objects.

### `NavigationMixin`
A mixin imported from `lightning/navigation` that adds navigation methods to an LWC.

### PageReference
A structured object that describes a destination page and its supported parameters.

### `standard__recordPage`
A PageReference type for navigating to a Salesforce record page.

### `recordId`
The Salesforce record's unique identifier. In an LWC on a record page, Salesforce can provide the current record ID through a public `@api recordId` property.

### `objectApiName`
The API name of the object that owns the record, such as `Contact`.

### `actionName`
The requested record-page action. This example uses `view` and `edit`.

### `@api`
A decorator that exposes a public property or method so it can receive values from a parent component or the Salesforce page context.

## 10. Interview Questions and Answers

**Q1. What is the Navigation Service in LWC?**  
It lets an LWC navigate to supported Salesforce pages without hardcoding URL formats.

**Q2. What is `NavigationMixin`?**  
It is a mixin from `lightning/navigation` that provides navigation functionality to an LWC.

**Q3. What is a PageReference?**  
An object that describes the page to navigate to, including its type, attributes, and optional state.

**Q4. What does `standard__recordPage` mean?**  
It identifies a Salesforce record page as the navigation destination.

**Q5. What is the difference between `actionName: 'view'` and `actionName: 'edit'`?**  
`view` requests the record's view page, while `edit` requests the edit page.

**Q6. Why is `@api recordId` useful?**  
It allows Salesforce to provide the current record ID to a component placed on a record page.

**Q7. Why should you avoid hardcoding a record ID?**  
Hardcoded IDs are specific to a particular org and record. Using `this.recordId` makes the component reusable on different records.

**Q8. What does `lightning__AppPage` do in the metadata file?**  
It makes the component available for placement on Lightning App Pages.

**Q9. What metadata target is needed to use the component on a record page?**  
`lightning__RecordPage`.

**Q10. What can prevent a user from editing a record?**  
Insufficient object permissions, record access, field-level security, validation rules, or other Salesforce business logic can prevent edits.

## 11. Scenario-Based Interview Questions

**Scenario 1: The component opens a Contact from another org or an invalid record.**  
Replace the hardcoded ID with a valid ID in the current org, or use `this.recordId` on a Contact record page.

**Scenario 2: `this.recordId` is undefined.**  
Check whether the component is on a record page and whether the metadata includes `lightning__RecordPage`. An App Page does not automatically provide a record ID.

**Scenario 3: View mode works but edit mode fails.**  
Check the user's edit access, record-level access, field-level security, validation rules, and any other save restrictions.

**Scenario 4: The component is not available in Lightning App Builder.**  
Verify `isExposed`, the correct target, and successful deployment.
