# Navigate To LWC Page 

## 1. Overview

This project demonstrates how to navigate from one Lightning Web Component (LWC) to another LWC by using Salesforce's **Navigation Service**.

The source component displays a **Navigate To LWC** button. When clicked, it navigates to a target LWC named `navigateTarget` and passes a value for `recordId` through a URL-encoded component definition.

The screenshots demonstrate these main concepts:

- `NavigationMixin` and `NavigationMixin.Navigate()`
- `standard__webPage`
- `btoa()` and `JSON.stringify()`
- A target component with a public `@api recordId` property
- LWC metadata targets

> **Important:** The screenshot's example `recordId: '123456789'` is a placeholder, not a valid Salesforce record ID. Replace it with an appropriate value for your use case.

## 2. Definitions from the Screenshots

### Navigation Service

In an LWC JavaScript class, import the `lightning/navigation` module and use `NavigationMixin` in the component's base class.

```javascript
import { NavigationMixin } from 'lightning/navigation';

export default class MyCustomElement extends NavigationMixin(LightningElement) {}
```

To dispatch a navigation request, call the navigation method:

```javascript
this[NavigationMixin.Navigate](pageReference, [replace]);
```

- **`pageReference`** — an object that describes the destination page.
- **`replace`** — an optional Boolean. It defaults to `false`. If `true`, the current browser-history entry is replaced.

### PageReference

A PageReference is an object that describes the destination page for Salesforce navigation. Its `type` identifies the page type, while `attributes` and optional `state` provide the details required by that page.

### `standard__webPage`

`standard__webPage` is a PageReference type used to navigate to a web page using a URL. In this example, the URL is a Salesforce Lightning URL fragment that carries a URL-encoded component definition.

## 5. Source Component JavaScript — `navigateToLWC.js`

The screenshot's code, formatted for readability:

```javascript
import { LightningElement } from 'lwc';
import { NavigationMixin } from 'lightning/navigation';

export default class NavigateToLWC extends NavigationMixin(LightningElement) {
    navigateToLWC() {
        const definition = {
            componentDef: 'c:navigateTarget',
            attributes: {
                recordId: '123456789'
            }
        };

        this[NavigationMixin.Navigate]({
            type: 'standard__webPage',
            attributes: {
                url: '/one/one.app#' + btoa(JSON.stringify(definition))
            }
        });
    }
}
```

### Explanation of each important part

1. `NavigationMixin` adds navigation methods to the component.
2. `definition` describes the component to load and the attributes to pass to it.
3. `componentDef: 'c:navigateTarget'` identifies the target component. `c` is the default namespace for an unpackaged/custom component.
4. `attributes.recordId` is the value passed to the target component's public property.
5. `JSON.stringify(definition)` converts the JavaScript object into a JSON string.
6. `btoa(...)` Base64-encodes that JSON string.
7. `'/one/one.app#' + ...` builds a Lightning URL containing the encoded component definition.
8. `NavigationMixin.Navigate()` navigates to that URL.

> **Implementation note:** This is the URL/hash-based pattern shown in the training screenshot. It relies on a Lightning URL format and a component-definition payload that may be sensitive to Salesforce navigation changes. For production applications, prefer a supported navigation approach where possible, and test this pattern in the exact Lightning experience and org where it will be used.

## 10. Deployment and Testing

1. Open your Salesforce DX project in VS Code.
2. Create both LWC bundles: `navigateToLWC` and `navigateTarget`.
3. Add the HTML, JavaScript, and metadata files for both bundles.
4. Ensure the component name in `componentDef` matches the target bundle: `c:navigateTarget`.
5. Replace `'123456789'` with a valid Salesforce record ID if you intend to pass a real record.
6. Save the files.
7. Deploy both bundles from VS Code, or run:

   ```bash
   sf project deploy start --source-dir force-app/main/default/lwc/navigateToLWC
   sf project deploy start --source-dir force-app/main/default/lwc/navigateTarget
   ```

   Alternatively, deploy the whole `lwc` directory in one command:

   ```bash
   sf project deploy start --source-dir force-app/main/default/lwc
   ```

8. Open **Setup → Lightning App Builder** and add `navigateToLWC` to a Lightning App Page.
9. Save and activate the page if required.
10. Open the page and click **Navigate To LWC**.
11. Verify that the target component displays the passed `recordId`.

## 11. Troubleshooting

- **Target component does not load:** Check the component name and namespace in `componentDef`, and verify both bundles deployed successfully.
- **`recordId` is blank:** Check the attribute name in the source definition and the public property name in the target. Both should be `recordId`.
- **The target displays `123456789` but the record cannot be found:** That value is a placeholder. Use a real record ID if you need to work with a real Salesforce record.
- **Navigation URL fails:** The screenshot's `/one/one.app#...` URL pattern may behave differently across Salesforce interfaces. Test in the intended org and Lightning experience.
- **`btoa()` errors with non-ASCII characters:** `btoa()` expects a binary string; non-ASCII content may need UTF-8-safe encoding before Base64 encoding. The screenshot's simple numeric ID does not create this issue.
- **Component not available in App Builder:** Verify `isExposed`, the relevant metadata target, and deployment status.
- **Deployment errors:** Check the bundle names, file names, XML syntax, API version, and CLI error output.

## 12. Interview Topics

- **Navigation Service:** Salesforce's supported mechanism for navigating to pages from Lightning components.
- **`NavigationMixin`:** Adds navigation methods to an LWC.
- **PageReference:** Describes a navigation destination with a type and associated details.
- **`standard__webPage`:** PageReference type for navigation to a URL.
- **`componentDef`:** Identifies the component to load in the encoded definition used in this example.
- **`attributes`:** Values passed to the target component.
- **`JSON.stringify()`:** Converts a JavaScript object to a JSON string.
- **`btoa()`:** Encodes a string as Base64; it is encoding, not encryption.
- **`@api`:** Makes a property or method public so it can receive a value from a parent or supported framework context.
- **LWC bundle metadata:** Controls component API version and where the component can be used in Lightning App Builder.

## 13. Interview Questions and Answers

**Q1. How can one LWC pass a value to another LWC?**  
Values can be passed through public `@api` properties when the component relationship or supported navigation mechanism allows it. In this example, the source includes `recordId` in the encoded component definition.

**Q2. What is `NavigationMixin`?**  
A mixin from `lightning/navigation` that adds navigation methods to an LWC.

**Q3. What does `componentDef` mean in this example?**  
It identifies the component to load, using the component's namespace and name, such as `c:navigateTarget`.

**Q4. Why use `JSON.stringify()`?**  
It converts the JavaScript object into a JSON string before it is encoded.

**Q5. What does `btoa()` do?**  
It Base64-encodes a string. Base64 is an encoding format, not encryption or a security boundary.

**Q6. What does `@api recordId` do in the target component?**  
It exposes `recordId` as a public property so the value can be assigned from outside the component.

**Q7. Is `'123456789'` a valid Salesforce record ID?**  
It is a placeholder in the screenshot and should not be treated as a valid record ID.

**Q8. What is `standard__webPage`?**  
A PageReference type that navigates to a URL. Here, the URL contains a Lightning application path and an encoded definition.

**Q9. Is the URL/hash technique the best choice for every production app?**  
No. It depends on a specific URL pattern and encoded payload. Prefer supported navigation patterns and test compatibility with the target Salesforce experience.

**Q10. Does Base64 encoding protect the passed data?**  
No. Base64 is reversible encoding and must not be used to protect confidential information.

## Summary

This example demonstrates a training pattern for navigating from one LWC to another by encoding a component definition into a Lightning URL. The source component defines `c:navigateTarget` and passes a `recordId`; the target component exposes that value with `@api recordId` and displays it. The screenshot's URL-based approach is useful to understand the underlying concepts, but it should be tested carefully and evaluated against supported navigation options before production use.
