# Fetch Current Page Reference 

## 1. Overview

This example demonstrates how to retrieve and display the **current page reference** in a Lightning Web Component (LWC).

A page reference is a structured JavaScript object that describes the current Salesforce page, including its page type, attributes, and optional state parameters. Salesforce provides the `CurrentPageReference` wire adapter from `lightning/navigation` to access this information.

The component in the screenshots displays the page reference as formatted JSON inside a `lightning-card`. The example output is:

```json
{
  "type": "standard__navItemPage",
  "attributes": {
    "apiName": "Navigation"
  },
  "state": {}
}
```

This output means the current page is a custom navigation item whose API name is `Navigation`. The exact output depends on where the component is placed and how the user reached the page.

## 2. Definition from the Screenshot

> **Current Page Reference:** A PageReference is a structured object that describes a page in Salesforce Lightning Experience, a Lightning Experience site, or the Salesforce mobile app. It identifies the page type and includes the attributes and optional state values needed to describe that page.

The screenshot imports `CurrentPageReference` from the `lightning/navigation` module and uses it with the `@wire` decorator.

```javascript
import { CurrentPageReference } from 'lightning/navigation';
```

`CurrentPageReference` is a wire adapter that provides information about the current page. It does not navigate to another page; it reads the current page context.

## 4. Code from the Screenshots

### 4.1 JavaScript — `currentReference.js`

The following code matches the screenshot, with formatting cleaned up:

```javascript
import { LightningElement, wire } from 'lwc';
import { CurrentPageReference } from 'lightning/navigation';

export default class CurrentReference extends LightningElement {
    @wire(CurrentPageReference)
    pageRef;

    get pageReference() {
        return this.pageRef
            ? JSON.stringify(this.pageRef, null, 2)
            : '';
    }
}
```

**Explanation**

- `LightningElement` is the base class for an LWC.
- `wire` connects the component to a Salesforce wire adapter.
- `CurrentPageReference` supplies the current page's PageReference object.
- `@wire(CurrentPageReference)` provisions the current page reference to the `pageRef` property.
- `JSON.stringify(this.pageRef, null, 2)` converts the object to readable JSON with two-space indentation.
- The conditional expression returns an empty string until the page reference is available.

The getter is named `pageReference`, while the wired property is named `pageRef`. This is intentional: the getter formats the object for display.

### 4.2 HTML — `currentReference.html`

This matches the screenshot:

```html
<template>
    <lightning-card title="Current Page Reference">
        <p>{pageReference}</p>
    </lightning-card>
</template>
```

**Explanation**

- `lightning-card` provides a standard Salesforce card with the title **Current Page Reference**.
- `{pageReference}` displays the formatted JSON returned by the JavaScript getter.

**Display tip:** A `<pre>` element preserves line breaks and indentation better than `<p>`. If you want the JSON to appear as formatted multi-line output, you can use:

```html
<template>
    <lightning-card title="Current Page Reference">
        <pre>{pageReference}</pre>
    </lightning-card>
</template>
```

The screenshot uses `<p>`, so keep the original version if you want to reproduce the video exactly.

## 5. Understanding the PageReference Object

A PageReference typically contains these parts:

| Property | Meaning |
|---|---|
| `type` | Identifies the kind of Salesforce page |
| `attributes` | Contains destination-specific details, such as an API name or record ID |
| `state` | Contains optional URL state parameters |

In the screenshot, the output is:

```json
{
  "type": "standard__navItemPage",
  "attributes": {
    "apiName": "Navigation"
  },
  "state": {}
}
```

- `standard__navItemPage` identifies a custom navigation-item page.
- `apiName: "Navigation"` identifies the navigation item's API name.
- `state: {}` indicates that no state parameters are present in this example.

The values change depending on the page. For example, a record page can include a record ID, while a web page reference can include a URL.

## 7. Deploy and Test

1. Open your Salesforce DX project in VS Code.
2. Create the `currentReference` LWC bundle with the three files shown above.
3. Deploy the component from the root of the Salesforce DX project:

   ```bash
   sf project deploy start --source-dir force-app/main/default/lwc/currentReference
   ```

4. Open **Setup → Lightning App Builder**.
5. Create or edit a Lightning App Page.
6. Drag the **currentReference** component onto the page.
7. Save and activate the page if required.
8. Open the Lightning App Page in Salesforce.
9. Confirm that the **Current Page Reference** card displays the PageReference JSON.

If your component folder is located elsewhere, use its actual path in the deployment command.

## 8. Troubleshooting

- **The component is not available in Lightning App Builder:** Confirm `isExposed` is `true`, the `lightning__AppPage` target is present, and deployment succeeded.
- **The displayed value is blank:** The page reference may not have been provisioned yet. Confirm the component is running in a supported Lightning context.
- **The output is difficult to read:** Use `<pre>{pageReference}</pre>` instead of a paragraph to preserve JSON indentation and line breaks.
- **The output is different from the screenshot:** This is expected when the component is placed on a different page. The PageReference describes the actual current page.
- **The wire property is undefined during initial rendering:** Wire data is asynchronous/reactive; the getter safely returns an empty string until data arrives.

## 9. Interview Topics

- **`JSON.stringify()`:** Converts a JavaScript value into a JSON string. The `null, 2` arguments make the JSON easier to read.

- **PageReference `attributes`:** Holds values required to identify the particular page.
- **PageReference `state`:** Holds optional URL parameters, often represented as strings.

## 10. Interview Questions and Answers

**Q1. What is a PageReference in Salesforce LWC?**  
It is a structured object that describes a Salesforce page using a page type, attributes, and optional state parameters.

**Q2. What is `CurrentPageReference`?**  
It is a wire adapter from `lightning/navigation` that provides the current page reference to an LWC.

**Q3. Does `CurrentPageReference` navigate to another page?**  
No. It reads the current page context. To navigate, use `NavigationMixin.Navigate()`.

**Q4. What does `@wire(CurrentPageReference)` do?**  
It provisions the current page reference to the component's `pageRef` property.

**Q5. Why use `JSON.stringify(this.pageRef, null, 2)`?**  
It converts the PageReference object into readable JSON with two-space indentation.

**Q6. What is the difference between `pageRef` and `pageReference` in this code?**  
`pageRef` stores the wired PageReference object. `pageReference` is a getter that converts that object to a string for display.

**Q7. What does `standard__navItemPage` mean?**  
It identifies a page associated with a custom navigation item.

**Q8. What is the purpose of the `state` property?**  
It holds optional URL state parameters associated with a page reference.

**Q9. Why might the PageReference output differ between pages?**  
Because the object describes the current page. Different page types have different attributes and state values.

**Q10. What is the difference between `CurrentPageReference` and `NavigationMixin`?**  
`CurrentPageReference` reads the current page reference; `NavigationMixin` provides methods to navigate to another page.

**Q11. Why might the component show blank output at first?**  
Wire data may not be available during the first render. The getter returns an empty string until `pageRef` is populated.

**Q12. Why might `<pre>` be preferable to `<p>` for JSON?**  
`<pre>` preserves whitespace and line breaks, making formatted JSON easier to read.

## 11. Scenario-Based Interview Questions

**Scenario 1: The component displays a different `type` from the screenshot.**  
That is normal if the component is placed on a different Salesforce page. Inspect the actual PageReference instead of assuming every page uses the same type.

**Scenario 2: You need the current record ID.**  
Inspect the PageReference's attributes for the current page type. On a record page, the reference commonly includes `attributes.recordId`. Check that the component is actually running in the record-page context.

**Scenario 3: You need to navigate after reading the current page reference.**  
Use `NavigationMixin.Navigate()` with a PageReference object describing the destination. Do not use `CurrentPageReference` as a navigation method.

**Scenario 4: JSON appears on one line.**  
Use `JSON.stringify(this.pageRef, null, 2)` and render it in a `<pre>` element.

**Scenario 5: A state parameter is missing.**  
Check the actual PageReference and how the current page was opened. State parameters are optional and may not be present on every page.
