# LWC in Utility Bar

This folder demonstrates how to create a Lightning Web Component (LWC), expose it as a **Utility Bar** item, and display Account record information using `lightning-record-form`.

The example shown in the screenshots displays the Account's **Name** and **Phone** fields inside a utility panel. The component can be opened from the Salesforce Utility Bar without navigating away from the current page.

## 1. What is the Utility Bar?

The **Utility Bar** is a fixed footer area in a Salesforce Lightning application that gives users quick access to productivity tools. Users can open utility items without leaving the page they are currently working on.

Examples of utility items include:

- Notes
- History
- Open CTI softphone
- Custom Lightning Web Components
- Other supported utility tools

A Lightning Web Component can be added to the Utility Bar by exposing it with the `lightning__UtilityBar` target in its `.js-meta.xml` configuration file.

## 2. What does this example do?

This example creates a component named `lwcUtilityBar`.

It:

1. Uses `lightning-record-form` to display an Account record.
2. Uses the `Account` object.
3. Displays the `Name` and `Phone` fields.
4. Uses `columns="1"` to display the fields in one column.
5. Uses `mode="view"` to display the record in read-only mode.
6. Exposes the component to the Utility Bar through its metadata file.

The screenshots show the component added to a Salesforce application's Utility Bar. When the user opens the utility item, the panel displays the Account Name and Phone fields. The Account record shown in the screenshot is **Arun**.

> **Important:** The screenshot's HTML does not specify a `record-id` on `lightning-record-form`. The component code shown therefore demonstrates the form configuration, but does not itself identify which Account record should be displayed. See the note in [Section 5](#5-explanation-of-the-code) for how to provide a record ID when you want a specific Account.

## 3. Folder structure

Create the following LWC bundle in your Salesforce DX project:

```text
force-app/
└── main/
    └── default/
        └── lwc/
            └── lwcUtilityBar/
                ├── lwcUtilityBar.html
                ├── lwcUtilityBar.js
                └── lwcUtilityBar.js-meta.xml
```

The folder name and the three file names must use the same component name: `lwcUtilityBar`.

## 4. Complete code from the screenshots

### 4.1 `lwcUtilityBar.html`

This is the HTML template shown in the screenshot:

```html
<template>
    <lightning-card title="LWC in Utility Bar">
        <div class="slds-p-around_medium">
            <lightning-record-form
                object-api-name="Account"
                fields={fieldList}
                columns="1"
                mode="view">
            </lightning-record-form>
        </div>
    </lightning-card>
</template>
```

### 4.2 `lwcUtilityBar.js`

This is the JavaScript code shown in the screenshot:

```javascript
import { LightningElement } from 'lwc';

export default class LwcUtilityBar extends LightningElement {
    fieldList = ['Name', 'Phone'];
}
```

### 4.3 `lwcUtilityBar.js-meta.xml`

This is the metadata configuration shown in the screenshot:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<LightningComponentBundle xmlns="http://soap.sforce.com/2006/04/metadata">
    <apiVersion>67.0</apiVersion>
    <isExposed>true</isExposed>
    <targets>
        <target>lightning__UtilityBar</target>
    </targets>
</LightningComponentBundle>
```

## 5. Explanation of the code

### 5.1 `lightning-card`

```html
<lightning-card title="LWC in Utility Bar">
```

`lightning-card` is a base Lightning component used to display content inside a card with a title and standard styling.

In this example, the card title is **LWC in Utility Bar**.

### 5.2 `slds-p-around_medium`

```html
<div class="slds-p-around_medium">
```

`SLDS` stands for **Salesforce Lightning Design System**.

The `slds-p-around_medium` utility class adds medium padding around the content.

### 5.3 `lightning-record-form`

```html
<lightning-record-form
    object-api-name="Account"
    fields={fieldList}
    columns="1"
    mode="view">
</lightning-record-form>
```

`lightning-record-form` is a Salesforce base component that provides a form for viewing, creating, or editing a record. It uses Lightning Data Service (LDS), so you do not need to write Apex just to perform the supported record-form operations.

| Attribute | Meaning |
|---|---|
| `object-api-name="Account"` | Specifies that the form is for the Account object. |
| `fields={fieldList}` | Gets the fields to display from the JavaScript property named `fieldList`. |
| `columns="1"` | Displays the fields in one column. |
| `mode="view"` | Displays the record in read-only view mode. |

### 5.4 JavaScript `fieldList`

```javascript
fieldList = ['Name', 'Phone'];
```

This property stores the API names of the Account fields that the record form should display:

- `Name` — Account Name.
- `Phone` — Account Phone.

The HTML uses `{fieldList}` to pass this array to the `lightning-record-form` component.

### 5.5 Metadata file

The `.js-meta.xml` file controls the component's metadata, including its API version, exposure, and supported targets.

```xml
<apiVersion>67.0</apiVersion>
<isExposed>true</isExposed>
<targets>
    <target>lightning__UtilityBar</target>
</targets>
```

| Tag | Meaning |
|---|---|
| `apiVersion` | Sets the Salesforce API version used by the component bundle. The screenshot uses `67.0`. |
| `isExposed` | Set to `true` to make the component available for supported builder targets. |
| `targets` | Contains the targets where the component can be used. |
| `target` | Declares one supported target. |
| `lightning__UtilityBar` | Makes the component available as a Utility Bar item. |

### 5.6 Important note: selecting a specific Account record

The HTML in the screenshot does not contain a `record-id` attribute. A record form normally needs a record ID to display an existing record in view mode.

If your goal is to display a particular Account, provide its ID. For example, the component can accept a record ID through a public property:

```javascript
import { LightningElement, api } from 'lwc';

export default class LwcUtilityBar extends LightningElement {
    @api recordId;
    fieldList = ['Name', 'Phone'];
}
```

Then update the form:

```html
<lightning-record-form
    record-id={recordId}
    object-api-name="Account"
    fields={fieldList}
    columns="1"
    mode="view">
</lightning-record-form>
```

This is an additional implementation option; it is **not present in the original screenshot code**. A Utility Bar component does not automatically receive the record ID of whichever record page the user happens to be viewing. You must provide the intended record ID through a supported design, configuration, or data-selection approach.

If you want a form that always displays a chosen Account, you can configure or retrieve that Account's ID and pass it to the component. If you want users to choose an Account, add an appropriate record-selection mechanism and pass the selected record's ID to `lightning-record-form`.

## 6. How to create the LWC

### Step 1: Open your Salesforce project

Open your Salesforce DX project in Visual Studio Code.

### Step 2: Create the Lightning Web Component

1. Open the Command Palette using `Ctrl + Shift + P`.
2. Search for **SFDX: Create Lightning Web Component**.
3. Select the command.
4. Enter the component name:

```text
lwcUtilityBar
```

5. Select the `force-app/main/default/lwc` directory.

VS Code creates the component bundle and its initial files.

### Step 3: Add the HTML code

Open `lwcUtilityBar.html` and add the code from [Section 4.1](#41-lwcutilitybarhtml).

### Step 4: Add the JavaScript code

Open `lwcUtilityBar.js` and add the code from [Section 4.2](#42-lwcutilitybarjs).

### Step 5: Configure the metadata file

Open `lwcUtilityBar.js-meta.xml` and add the code from [Section 4.3](#43-lwcutilitybarjs-meta-xml).

The important target is:

```xml
<target>lightning__UtilityBar</target>
```

### Step 6: Save and deploy

Save all files. Right-click the `lwcUtilityBar` folder and select **SFDX: Deploy This Source to Org**, or deploy it using Salesforce CLI.

Example CLI command:

```bash
sf project deploy start --source-dir force-app/main/default/lwc/lwcUtilityBar
```

Make sure you are connected to the correct Salesforce org.

## 7. How to add the component to the Utility Bar

After deploying the component, add it to a Lightning application's Utility Bar.

### Step 1: Open Setup

1. Log in to Salesforce.
2. Click the gear icon.
3. Select **Setup**.

### Step 2: Open App Manager

1. In Setup, search for **App Manager** in the Quick Find box.
2. Open **App Manager**.
3. Find the Lightning application where you want to add the component.
4. Open its dropdown menu.
5. Select **Edit**.

### Step 3: Open Utility Items

In the App Settings navigation:

1. Select **Utility Items (Desktop Only)**.
2. Click **Add Utility Item**.

### Step 4: Select the LWC

1. Search for `lwcUtilityBar`.
2. Select the component.
3. Configure the utility item's label and other available settings.
4. Save the application.

### Step 5: Test the Utility Bar

1. Open the Lightning application you edited.
2. Locate the Utility Bar at the bottom of the page.
3. Click the `lwcUtilityBar` utility item.
4. Confirm that the **LWC in Utility Bar** panel opens.
5. Check whether the Account Name and Phone fields appear as expected.

The screenshots demonstrate the utility panel in both collapsed and expanded states, with the Account Name and Phone values displayed.

> The exact menu labels and available options can vary depending on the Salesforce application and org configuration.

## 8. How the component works

The flow of this example is:

```text
Salesforce Lightning Application
             |
             v
         Utility Bar
             |
             v
        lwcUtilityBar
             |
             v
       lightning-card
             |
             v
    lightning-record-form
             |
             v
        Account Object
             |
             v
       Name and Phone
```

1. The metadata file exposes the component to the Utility Bar.
2. The administrator adds the component as a Utility Item in App Manager.
3. The user clicks the Utility Bar item.
4. Salesforce loads the LWC utility panel.
5. The HTML renders a Lightning card and `lightning-record-form`.
6. The JavaScript `fieldList` property supplies the `Name` and `Phone` field API names.
7. The record form uses Lightning Data Service to display the configured record data when a valid record context is supplied.

## 9. Important concepts

### 9.1 What is a Lightning Web Component?

A Lightning Web Component is a Salesforce UI framework based on modern web standards such as JavaScript, HTML, and CSS. It is used to build reusable user-interface components on the Salesforce Platform.

### 9.2 What is the Utility Bar?

The Utility Bar is a fixed area in a Lightning application that provides quick access to utility tools without requiring users to leave their current page.

### 9.3 What is `lightning__UtilityBar`?

`lightning__UtilityBar` is a component target declared in the `.js-meta.xml` file. It allows an exposed LWC to be selected as a Utility Bar item.

### 9.4 What is `lightning-record-form`?

`lightning-record-form` is a base Lightning component that provides a form for viewing, creating, or editing Salesforce records. It uses Lightning Data Service.

### 9.5 What is Lightning Data Service (LDS)?

Lightning Data Service is the Salesforce service used by supported Lightning components to work with record data. It handles supported record operations and respects Salesforce security, including sharing and field-level security.

### 9.6 What is `object-api-name`?

`object-api-name` identifies the Salesforce object used by a record form.

Example:

```html
object-api-name="Account"
```

### 9.7 What is `fields`?

The `fields` attribute identifies the fields that should be displayed by the record form.

Example:

```javascript
fieldList = ['Name', 'Phone'];
```

### 9.8 What is `mode`?

The `mode` attribute determines the form mode:

| Mode | Purpose |
|---|---|
| `view` | Displays record fields in read-only mode. |
| `edit` | Displays the record in edit mode. |
| `readonly` | Displays fields as read-only. |
| `create` | Creates a new record. |

For this example, the screenshot uses `mode="view"`.

## 10. Common issues and troubleshooting

| Issue | Possible reason | What to check |
|---|---|---|
| Component is not visible in App Manager | Component is not exposed to the Utility Bar | Check `isExposed` and `lightning__UtilityBar` in the metadata file. |
| Utility item does not appear | Component deployment failed or the wrong app is being edited | Verify deployment and confirm that you are editing the correct Lightning app. |
| Account fields do not display | The record form has no valid record ID or record context | Supply a valid Account record ID when displaying an existing record. |
| Phone field is blank | The selected Account has no Phone value, or the user cannot access the field | Check the Account record and the user's field-level security. |
| Component does not open | Utility item was not saved or the wrong app is open | Recheck App Manager configuration and open the correct application. |
| Deployment error in XML | Invalid XML or incorrect target value | Check the XML structure and spelling of `lightning__UtilityBar`. |
| User cannot see Account information | User lacks object or field permissions | Check Account read access and access to the Name and Phone fields. |

## 11. Interview questions and answers

### Q1. What is the Utility Bar in Salesforce?

The Utility Bar is a fixed footer area in a Lightning application that provides quick access to productivity tools without navigating away from the current page.

### Q2. Can we add a custom LWC to the Utility Bar?

Yes. Expose the component using the `lightning__UtilityBar` target in its `.js-meta.xml` file, deploy it, and add it through App Manager.

### Q3. Which target is used to expose an LWC to the Utility Bar?

```xml
<target>lightning__UtilityBar</target>
```

### Q4. Where do we configure the Utility Bar?

Go to **Setup → App Manager → Edit the Lightning App → Utility Items (Desktop Only)**.

### Q5. What is `lightning-record-form`?

It is a Salesforce base Lightning component that provides a standard form to view, create, or edit Salesforce records.

### Q6. What is the purpose of `object-api-name`?

It specifies which Salesforce object the record form works with, such as Account or Contact.

### Q7. What is the purpose of the `fields` attribute?

It specifies the fields that should be displayed or used by the record form.

### Q8. What does `columns="1"` mean?

It displays the form fields in one column.

### Q9. What does `mode="view"` do?

It displays the record in read-only view mode.

### Q10. What is the purpose of the `.js-meta.xml` file?

It defines component metadata, including API version, exposure, supported targets, and design-time configuration.

### Q11. What is `isExposed`?

It determines whether the component is exposed for supported builder targets. It must be `true` for the component to be available through the declared target.

### Q12. Do we need Apex to display Account fields using `lightning-record-form`?

No. `lightning-record-form` uses Lightning Data Service for its supported operations, so Apex is not required for this simple form.

### Q13. What is Lightning Data Service?

Lightning Data Service is a Salesforce service that allows Lightning components to work with record data while handling supported caching and security behavior.

### Q14. Does a Utility Bar LWC automatically receive the current record ID?

No. A Utility Bar component should not be assumed to receive the record ID of the record page currently open. Pass or retrieve the required record ID explicitly.

### Q15. What is the difference between `lightning-record-form` and `lightning-record-edit-form`?

`lightning-record-form` is a higher-level component that provides standard view, edit, and create form modes. `lightning-record-edit-form` gives more control over the form layout and requires you to compose it with components such as `lightning-input-field`.

### Q16. Can we use a Utility Bar component on different pages of the same Lightning application?

Yes. A Utility Bar item belongs to the Lightning application configuration and can be accessed while users navigate within that application, subject to the app and utility configuration.

### Q17. What happens if the Account Phone field is blank?

The form can display the field without a value. The user should also have the required object and field permissions.

### Q18. What is SLDS?

SLDS stands for Salesforce Lightning Design System. It provides styling utilities and design patterns for Salesforce user interfaces.

### Q19. What is the difference between `lightning__AppPage` and `lightning__UtilityBar`?

`lightning__AppPage` exposes a component for use on a Lightning App Page. `lightning__UtilityBar` exposes a component as a Utility Bar item in a Lightning application.

### Q20. Can a Utility Bar LWC call Apex?

Yes. A Utility Bar LWC can import and call Apex methods using the supported LWC Apex integration patterns. The component target does not prevent Apex usage.

## Conclusion

In this project, we created a Lightning Web Component named `lwcUtilityBar` and exposed it to the Salesforce Utility Bar using the `lightning__UtilityBar` target.

The component uses `lightning-record-form` to display the Account Name and Phone fields in a one-column, read-only form. After deployment, the component is added to a Lightning application's Utility Bar through App Manager.

This example is useful for understanding how to create reusable LWC utility items and how to use Lightning Data Service through Salesforce base components.
