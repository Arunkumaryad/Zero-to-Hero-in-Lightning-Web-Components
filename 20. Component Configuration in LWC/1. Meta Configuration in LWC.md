# Meta Configuration in LWC

This folder explains the **Lightning Web Component (LWC) configuration file** (`.js-meta.xml`), its metadata tags, and the attributes used to control where a component can be displayed and how users can configure it in Lightning App Builder.

The documentation is based on the supplied screenshots. The original definitions and terminology from the screenshots are retained in the **Definitions from the screenshots** sections. Additional explanations and examples are clearly separated to make the topic easier to understand and prepare for interviews.

---

## 1. What is the LWC Configuration File?

**Definition from the screenshot:**

> The configuration file defines the metadata values for the component, including the design configuration for the Lightning App Builder and Experience Builder.

In simple words, the `.js-meta.xml` file tells Salesforce information about an LWC component, such as:

- Which Salesforce API version the component uses.
- Whether the component is exposed for use in Lightning pages.
- Where the component can be placed.
- What label and description appear in the builder.
- Which configurable properties are available to an administrator.
- Whether the component is available for particular objects or page types.

Every LWC bundle has a configuration file with the name:

```text
componentName.js-meta.xml
```

For example, if the component is named `bookApp`, its configuration file is:

```text
bookApp.js-meta.xml
```

---

## 2. Basic Structure of the Configuration File

Example:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<LightningComponentBundle xmlns="http://soap.sforce.com/2006/04/metadata">
    <apiVersion>67.0</apiVersion>
    <isExposed>true</isExposed>
    <masterLabel>My LWC Component</masterLabel>
    <description>A sample Lightning Web Component.</description>

    <targets>
        <target>lightning__AppPage</target>
        <target>lightning__HomePage</target>
        <target>lightning__RecordPage</target>
    </targets>
</LightningComponentBundle>
```

### Explanation

| Tag | Purpose |
|---|---|
| `LightningComponentBundle` | Root element of the LWC metadata file. |
| `apiVersion` | Specifies the Salesforce API version for the component bundle. |
| `isExposed` | Controls whether the component is available for use in supported builders and targets. |
| `masterLabel` | Defines the component's display title in places such as Lightning App Builder. |
| `description` | Provides a short description of the component. |
| `targets` | Contains the page or experience targets where the component can be used. |
| `target` | Identifies one individual target. |

> **Important:** The API version `67.0` above is an example matching the version shown in some of the earlier project screenshots. Use an API version supported by your Salesforce org and development environment.

## 3. Component Configuration File Tags

The screenshots list the following tags.

### Tag 1 — `apiVersion`

**Definition from the screenshot:**

> Salesforce API version 45.0 or higher.

**Simple explanation:**

`apiVersion` specifies the Salesforce API version associated with the component bundle. It determines the platform API version against which the component metadata is interpreted.

Example:

```xml
<apiVersion>67.0</apiVersion>
```

### Tag 2 — `description`

**Definition from the screenshot:**

> A short description of the component, usually a single sentence. The description appears in list views, like the list of Lightning Components in Setup, and as a tooltip in Lightning App Builder and Experience Builder.

**Simple explanation:**

The `description` tag provides information about what the component does. It helps administrators and developers identify the component.

Example:

```xml
<description>Displays a list of books from an external API.</description>
```

### Tag 3 — `isExposed`

**Definition from the screenshot:**

> If isExposed is false, the component isn’t exposed to Lightning App Builder or Experience Builder. To allow the component to be used in Lightning App Builder or Experience Builder, set isExposed to true and define at least one `<target>`, which is a type of Lightning page.

**Simple explanation:**

The `isExposed` tag determines whether the component is available to be selected and added in supported builders.

Example:

```xml
<isExposed>true</isExposed>
```

When `isExposed` is `false`, the component isn't exposed for placement through Lightning App Builder or Experience Builder. To make it available, set it to `true` and define at least one supported target.

### Tag 4 — `masterLabel`

**Definition from the screenshot:**

> The title of the component. Appears in list views, like the list of Lightning Components in Setup, and in the Lightning App Builder and in Experience Builder.

**Simple explanation:**

`masterLabel` is the user-friendly name shown to administrators when they search for or select the component in a builder.

Example:

```xml
<masterLabel>Books Listing App</masterLabel>
```

### Tag 5 — `targets`

**Definition from the screenshot:**

> Specifies where the component can be added, such as on a type of Lightning Page or in Embedded Service Chat. It support target subtag.

**Simple explanation:**

The `targets` tag is a container. Inside it, you add one or more `target` tags to specify the locations where the LWC can be used.

Example:

```xml
<targets>
    <target>lightning__AppPage</target>
    <target>lightning__HomePage</target>
    <target>lightning__RecordPage</target>
</targets>
```

### Tag 6 — `target`

**Definition from the screenshot:**

> A lightning page type. Valid values are:
>
> - `lightning__AppPage`
> - `lightning__HomePage`
> - `lightning__RecordPage`
> - `lightning__UtilityBar`
> - `lightning__UtilityBar` (the screenshot's list also includes the following targets)
> - `lightning__FlowScreen`
> - `lightning__Tab`
> - `lightning__Inbox`
> - `lightningCommunity__Page`
> - `lightningCommunity__Default`
> - `lightningSnapin__ChatMessage`
> - `lightningSnapin__Minimized`
> - `lightningSnapin__PreChat`

The screenshot's displayed list is reproduced below in its original sequence (with `lightning__UtilityBar` listed once):

```text
lightning__AppPage
lightning__HomePage
lightning__RecordPage
lightning__UtilityBar
lightning__FlowScreen
lightning__Tab
lightning__Inbox
lightningCommunity__Page
lightningCommunity__Default
lightningSnapin__ChatMessage
lightningSnapin__Minimized
lightningSnapin__PreChat
```

**Simple explanation:**

A `target` identifies a Salesforce page or supported experience location where the component can be added. You can define multiple targets inside the `targets` container.

Example:

```xml
<targets>
    <target>lightning__RecordPage</target>
</targets>
```

This declares the Record Page target for the component.

> **Version note:** Supported target names and availability can depend on the Salesforce platform and component type. Check the current Salesforce documentation when selecting targets for a new project.

### Tag 7 — `targetConfigs` and `targetConfig`

**Definition from the screenshot:**

> Configure the component for different page types and define component properties. Use targetConfig for each different page type configuration.
>
> The targetConfig tag supports the property, propertyType, objects, and supportedFormFactors sub tags.

**Simple explanation:**

- `targetConfigs` is the container for configuration specific to different targets.
- `targetConfig` defines configuration for one target.
- Inside `targetConfig`, you can define component properties and other supported configuration elements.

Example:

```xml
<targets>
    <target>lightning__RecordPage</target>
    <target>lightning__AppPage</target>
</targets>

<targetConfigs>
    <targetConfig targets="lightning__RecordPage">
        <objects>
            <object>Account</object>
            <object>Contact</object>
        </objects>
    </targetConfig>

    <targetConfig targets="lightning__AppPage">
        <property
            name="heading"
            type="String"
            label="Component Heading"
            default="My Component"/>
    </targetConfig>
</targetConfigs>
```

The example demonstrates target-specific configuration:

- The Record Page configuration restricts the component to Account and Contact records.
- The App Page configuration exposes a configurable heading property.

### Tag 8 — `property`

**Definition from the screenshot:**

> Specifies a public property of a component that can be set in Lightning App Builder, App Manager, Lightning Flow Builder, or Experience Builder. The component author defines the property in the component’s JavaScript class using the `@api` decorator.

**Simple explanation:**

The `property` tag exposes a public LWC property so an administrator or page builder can configure its value without changing the component's JavaScript code.

The property must be declared as a public property in the component JavaScript class using `@api`.

JavaScript example:

```javascript
import { LightningElement, api } from 'lwc';

export default class GreetingComponent extends LightningElement {
    @api heading = 'Welcome';
}
```

Metadata example:

```xml
<targetConfigs>
    <targetConfig targets="lightning__AppPage">
        <property
            name="heading"
            type="String"
            label="Heading"
            default="Welcome"/>
    </targetConfig>
</targetConfigs>
```

The `name` value must match the public property name in JavaScript. In this example, both use `heading`.

### Tag 9 — `objects` and `object`

**Definition from the screenshot:**

> Object is subtag of objects. Object tag allow you to expose component to specific object.

**Simple explanation:**

- `objects` is a container tag.
- `object` specifies an individual Salesforce object.
- This configuration is useful with the Record Page target when a component should be available only for selected objects.

Example:

```xml
<targets>
    <target>lightning__RecordPage</target>
</targets>

<targetConfigs>
    <targetConfig targets="lightning__RecordPage">
        <objects>
            <object>Account</object>
            <object>Contact</object>
            <object>Opportunity</object>
        </objects>
    </targetConfig>
</targetConfigs>
```

This example configures the component for Account, Contact, and Opportunity record pages.

## 4. Attributes Supported by the `property` Tag

The third screenshot shows the following property attributes.

### Attribute 1 — `datasource`

**Definition from the screenshot:**

> Renders a field as a picklist, with static values.

**Simple explanation:**

`datasource` can be used to provide static choices for a configurable property, allowing the value to be selected from a list.

Example:

```xml
<property
    name="displayMode"
    type="String"
    label="Display Mode"
    datasource="List;Grid"/>
```

The exact datasource syntax and supported values should follow the Salesforce metadata rules for the property type and target.

### Attribute 2 — `label`

**Definition from the screenshot:**

> Displays as a label for the attribute in the tool.

**Simple explanation:**

`label` is the user-friendly name displayed in the configuration panel.

Example:

```xml
<property
    name="heading"
    type="String"
    label="Component Heading"/>
```

The builder displays **Component Heading** to the administrator.

### Attribute 3 — `max` and `min`

**Definition from the screenshot:**

> The maximum and minimum allowed value for an attribute of type Integer.

**Simple explanation:**

`max` and `min` set the allowed upper and lower limits for an Integer property.

Example:

```xml
<property
    name="numberOfRecords"
    type="Integer"
    label="Number of Records"
    min="1"
    max="50"
    default="10"/>
```

This example configures a number property with a minimum of 1, maximum of 50, and default value of 10.

### Attribute 4 — `name`

**Definition from the screenshot:**

> Required if you’re setting properties for your component. The attribute name. This value must match the property name in the component’s JavaScript class.

**Simple explanation:**

`name` identifies the public JavaScript property that the metadata configures. It must match the property declared in the component's JavaScript class.

JavaScript:

```javascript
@api heading;
```

Metadata:

```xml
<property
    name="heading"
    type="String"
    label="Heading"/>
```

### Attribute 5 — `required`

**Definition from the screenshot:**

> Specifies whether the attribute is required. The default value is false.

**Simple explanation:**

`required` indicates whether the administrator must provide a value for the property in the builder.

Example:

```xml
<property
    name="heading"
    type="String"
    label="Heading"
    required="true"/>
```

### Attribute 6 — `type`

**Definition from the screenshot:**

> The attribute’s data type. These values are valid for all targets.
>
> - Boolean
> - Integer
> - String
> - Color

**Simple explanation:**

`type` defines the data type of the configurable property.

The screenshot lists these values:

| Type | Meaning | Example value |
|---|---|---|
| `Boolean` | True/false value | `true` |
| `Integer` | Whole number | `10` |
| `String` | Text value | `Welcome` |
| `Color` | Color value | `#008000` |

Example:

```xml
<property
    name="showHeading"
    type="Boolean"
    label="Show Heading"
    default="true"/>
```

> The screenshot shows the attribute numbering as 1, 2, 3, 4, 5, and 8. This README keeps the attribute names and definitions shown in the screenshot rather than assuming the missing numbers represent additional attributes.

## 5. Complete Example — Configurable LWC

This example combines the main tags and attributes from the screenshots.

### Folder structure

```text
force-app/
└── main/
    └── default/
        └── lwc/
            └── greetingComponent/
                ├── greetingComponent.html
                ├── greetingComponent.js
                └── greetingComponent.js-meta.xml
```

### File 1 — `greetingComponent.html`

```html
<template>
    <lightning-card title={heading}>
        <div class="slds-p-around_medium">
            <p>{message}</p>
        </div>
    </lightning-card>
</template>
```

### File 2 — `greetingComponent.js`

```javascript
import { LightningElement, api } from 'lwc';

export default class GreetingComponent extends LightningElement {
    @api heading = 'Welcome';
    @api message = 'Welcome to Salesforce Lightning Web Components!';
    @api showMessage = true;
}
```

### File 3 — `greetingComponent.js-meta.xml`

```xml
<?xml version="1.0" encoding="UTF-8"?>
<LightningComponentBundle xmlns="http://soap.sforce.com/2006/04/metadata">

    <apiVersion>67.0</apiVersion>

    <isExposed>true</isExposed>

    <masterLabel>Greeting Component</masterLabel>

    <description>
        A configurable greeting component for Lightning pages.
    </description>

    <targets>
        <target>lightning__AppPage</target>
        <target>lightning__HomePage</target>
        <target>lightning__RecordPage</target>
    </targets>

    <targetConfigs>
        <targetConfig targets="lightning__AppPage,lightning__HomePage">
            <property
                name="heading"
                type="String"
                label="Card Heading"
                default="Welcome"/>

            <property
                name="message"
                type="String"
                label="Message"
                default="Welcome to Salesforce!"/>

            <property
                name="showMessage"
                type="Boolean"
                label="Show Message"
                default="true"/>
        </targetConfig>

        <targetConfig targets="lightning__RecordPage">
            <objects>
                <object>Account</object>
                <object>Contact</object>
            </objects>
        </targetConfig>
    </targetConfigs>

</LightningComponentBundle>
```

**What happens?**

1. `isExposed` makes the component available for supported builder placement.
2. `targets` declares App, Home, and Record Page support.
3. `targetConfig` defines settings for particular page types.
4. `property` exposes public JavaScript properties in the builder.
5. `objects` and `object` configure the Record Page objects.

**Important implementation note:** In a complete component, the HTML should use `showMessage` to control whether the message is displayed. For example:

```html
<template>
    <lightning-card title={heading}>
        <div class="slds-p-around_medium">
            <template if:true={showMessage}>
                <p>{message}</p>
            </template>
        </div>
    </lightning-card>
</template>
```

## 6. Step-by-Step: Create and Configure an LWC

### Step 1 — Open VS Code

Open your Salesforce DX project in Visual Studio Code.

### Step 2 — Open the LWC directory

Navigate to:

```text
force-app/main/default/lwc/
```

### Step 3 — Create an LWC

Open the Command Palette:

```text
Ctrl + Shift + P
```

Select:

```text
SFDX: Create Lightning Web Component
```

Enter the component name, for example:

```text
greetingComponent
```

### Step 4 — Open the metadata file

Open:

```text
greetingComponent.js-meta.xml
```

### Step 5 — Configure the component

Set the required tags, such as:

- `apiVersion`
- `isExposed`
- `masterLabel`
- `description`
- `targets`

### Step 6 — Add target-specific configuration

Use `targetConfigs` and `targetConfig` to configure page-specific properties and object restrictions.

### Step 7 — Add public properties in JavaScript

Import `api` and declare properties using `@api`.

Example:

```javascript
import { LightningElement, api } from 'lwc';

export default class GreetingComponent extends LightningElement {
    @api heading;
}
```

### Step 8 — Deploy the component

Right-click the component folder and select:

```text
SFDX: Deploy Source to Org
```

Or use Salesforce CLI:

```bash
sf project deploy start --source-dir force-app/main/default/lwc/greetingComponent
```

### Step 9 — Add it to Lightning App Builder

1. Open Salesforce Setup.
2. Search for **Lightning App Builder**.
3. Create or edit a Lightning page.
4. Find the component under Custom Components.
5. Drag it onto the page.
6. Configure its public properties in the property panel.
7. Save and activate the page.

### Step 10 — Verify the configuration

Confirm that:

- The component appears in the builder.
- The component is available on the configured target.
- The public properties appear in the configuration panel.
- The property values are reflected in the component UI.
- Object restrictions are respected on Record Pages.

## 7. Important Differences for Interviews

### `targets` vs `target`

| `targets` | `target` |
|---|---|
| Container tag. | Individual target tag. |
| Holds one or more target declarations. | Identifies one page type or supported location. |
| Can contain multiple `target` elements. | Is placed inside `targets`. |

### `targetConfigs` vs `targetConfig`

| `targetConfigs` | `targetConfig` |
|---|---|
| Container for target-specific configurations. | Defines configuration for a particular target. |
| Can contain multiple `targetConfig` elements. | Can contain properties and other supported configuration elements. |

### `objects` vs `object`

| `objects` | `object` |
|---|---|
| Container tag. | Specifies one Salesforce object. |
| Contains one or more `object` tags. | Is placed inside `objects`. |

### `property` vs `@api`

| `property` in `.js-meta.xml` | `@api` in JavaScript |
|---|---|
| Exposes a configurable property in supported builders. | Declares a public JavaScript property. |
| Defines builder information such as label and type. | Defines the property used by the component. |
| Its `name` must match the JavaScript property. | The property name must match the metadata `name`. |

### `isExposed` vs `targets`

- `isExposed` controls whether the component is exposed for builder use.
- `targets` declares the supported page or experience locations.
- To make a component available in Lightning App Builder, set `isExposed` to `true` and specify an appropriate target.

## 8. Interview Questions and Answers

### Basic Questions

**Q1. What is the LWC configuration file?**

The LWC configuration file is the `.js-meta.xml` file. It defines metadata values for a component, including its API version, exposure, supported targets, and builder configuration.

**Q2. What is the file extension of an LWC configuration file?**

`.js-meta.xml`

**Q3. Why do we use `apiVersion`?**

It specifies the Salesforce API version associated with the component bundle.

**Q4. What is the purpose of `isExposed`?**

It controls whether the component is exposed for use in supported builders and targets.

**Q5. What happens if `isExposed` is false?**

The component isn't exposed for placement through Lightning App Builder or Experience Builder.

**Q6. What is the purpose of `masterLabel`?**

It defines the component's title or display name in places such as Setup and Lightning App Builder.

**Q7. What is the purpose of `description`?**

It provides a short description of the component, which can appear in component lists and as a tooltip in builders.

**Q8. What is the purpose of `targets`?**

It specifies where the component can be added, such as App Pages, Home Pages, or Record Pages.

**Q9. What is a `target`?**

A target identifies an individual Lightning page type or supported component location.

**Q10. Can we define multiple targets for one LWC?**

Yes. Multiple `target` tags can be placed inside the `targets` tag.

### Intermediate Questions

**Q11. What is `targetConfigs`?**

It is a container for configurations associated with different component targets.

**Q12. What is `targetConfig`?**

It defines the configuration for a particular target. It can include properties and other supported configuration elements.

**Q13. What is the purpose of the `property` tag?**

It exposes a public component property so that its value can be configured in supported builders.

**Q14. Which decorator is used to define a public property in LWC?**

`@api`

**Q15. What is the relationship between `property` and `@api`?**

The `property` tag exposes a public JavaScript property in the builder. The `name` attribute in the metadata must match the JavaScript property name declared using `@api`.

**Q16. What is the purpose of the `objects` tag?**

It acts as a container for the Salesforce object names on which a component is configured for Record Pages.

**Q17. What is the purpose of the `object` tag?**

It identifies an individual Salesforce object, such as Account or Contact.

**Q18. What is the difference between `objects` and `object`?**

`objects` is the parent container, while `object` identifies one object inside that container.

**Q19. What is the purpose of the `label` attribute?**

It defines the user-friendly label displayed for the property in the configuration tool.

**Q20. What is the purpose of the `name` attribute?**

It identifies the property and must match the public property name in the component's JavaScript class.

### Advanced Questions

**Q21. What is the purpose of the `type` attribute?**

It specifies the data type of the configurable property.

**Q22. Which property types are listed in the supplied screenshot?**

- Boolean
- Integer
- String
- Color

**Q23. What is the purpose of the `required` attribute?**

It specifies whether a property value is required. The screenshot states that its default value is `false`.

**Q24. What are `min` and `max` used for?**

They specify the minimum and maximum allowed values for an Integer property.

**Q25. What is the purpose of `datasource`?**

The screenshot describes it as an attribute that renders a field as a picklist with static values.

**Q26. Can we configure different properties for different page types?**

Yes. Use `targetConfigs` with separate `targetConfig` elements for the relevant targets.

**Q27. Can an LWC be restricted to specific Salesforce objects?**

Yes. For a Record Page target, configure the supported `objects` and `object` elements.

**Q28. What happens if the property name in XML does not match the JavaScript property?**

The builder configuration will not correctly correspond to the intended public JavaScript property. The names should match exactly.

**Q29. What is the purpose of the `lightning__RecordPage` target?**

It declares that the component can be used on supported Lightning Record Pages.

**Q30. What is the purpose of the `lightning__AppPage` target?**

It declares that the component can be used on supported Lightning App Pages.

## 10. Common Mistakes

| Mistake | Solution |
|---|---|
| Component does not appear in Lightning App Builder. | Check `isExposed` and confirm that a supported target is declared. |
| Component is missing from a Record Page. | Check that `lightning__RecordPage` is included in `targets`. |
| Property does not appear in the builder. | Check the `property` element and ensure its `name` matches the `@api` property. |
| Component is not available for the expected object. | Check the `objects` and `object` configuration under the Record Page `targetConfig`. |
| XML deployment fails. | Check XML syntax, tag nesting, attribute values, and target support. |
| Property value is not reflected in the UI. | Confirm that the JavaScript class declares the matching public property and the HTML uses it correctly. |

The most important tags to remember are:

- `apiVersion`
- `isExposed`
- `masterLabel`
- `description`
- `targets`
- `target`
- `targetConfigs`
- `targetConfig`
- `property`

## 12. Complete Metadata Configuration Example from the Latest Screenshot

This section adds the complete `.js-meta.xml` configuration shown in the latest screenshot. It demonstrates how to:

- Expose an LWC to App, Home, and Record pages.
- Configure a property specifically for a Record Page.
- Restrict the Record Page component to the Account object.
- Define configurable properties for an App Page.
- Set a default value for a String property.
- Set minimum, maximum, and default values for an Integer property.
- Display a static list of values for a String property using `datasource`.

### 12.1 Complete code from the screenshot

Create or open the component's metadata file:

```text
metaConfigDemo.js-meta.xml
```

Add the following XML:

```xml
<?xml version="1.0" encoding="UTF-8"?>

    <description>This component explain about Meta Configuration!</description>
    <isExposed>true</isExposed>
    <masterLabel>Meta Config Demo</masterLabel>

    <targets>
        <target>lightning__AppPage</target>
        <target>lightning__HomePage</target>
        <target>lightning__RecordPage</target>
    </targets>

    <targetConfigs>
        <targetConfig targets="lightning__RecordPage">
            <property name="recordId" type="String"/>
            <objects>
                <object>Account</object>
            </objects>
        </targetConfig>

        <targetConfig targets="lightning__AppPage">
            <property
                name="heading"
                type="String"
                default="Meta Config in LWC"/>

            <property
                name="age"
                type="Integer"
                min="5"
                max="10"
                default="7"/>

            <property
                name="levels"
                label="Level"
                type="String"
                datasource="High, Medium, Low"
                default="High"/>
        </targetConfig>
    </targetConfigs>
</LightningComponentBundle>
```

### 12.2 Explanation of the code

#### Component-level metadata


#### Record Page configuration

```xml
<targetConfig targets="lightning__RecordPage">
    <property name="recordId" type="String"/>
    <objects>
        <object>Account</object>
    </objects>
</targetConfig>
```

Explanation:

- `targetConfig targets="lightning__RecordPage"` applies this configuration to Record Pages.
- `property name="recordId" type="String"` declares a String property named `recordId` in the page configuration.
- `objects` is the container for the object restriction.
- `object>Account</object>` specifies the Account object.

**Important distinction:** The XML property declaration does not, by itself, create or populate a JavaScript property. If the component needs to receive the current record ID, declare the public property in JavaScript:

```javascript
import { LightningElement, api } from 'lwc';

export default class MetaConfigDemo extends LightningElement {
    @api recordId;
}
```

For a Record Page component, Salesforce can provide the current record ID through the public `recordId` property when the component is configured for the record page.
