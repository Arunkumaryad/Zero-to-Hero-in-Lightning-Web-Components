# Adding Custom Labels to Fields in lightning-record-edit-form

## 1. Overview

This Salesforce Lightning Web Component (LWC) example demonstrates how to add a custom label above a field rendered by `lightning-record-edit-form`.

The Contact form includes Account, Name, Title, Phone, and Email fields. The Email field uses `variant="label-hidden"` so its built-in label is hidden. A separate HTML `<label>` element displays the custom text **Enter Your Email** above the Email field.

## 2. Definition

**Adding a custom label to a field in `lightning-record-edit-form`** means displaying a developer-defined label or prompt for a form field instead of (or in addition to) the field's default Salesforce label.

In the screenshot, the Email field uses `variant="label-hidden"` to hide its built-in label, while this markup displays the custom label:

```html
<label class="slds-p-left_x-small">Enter Your Email</label>
<lightning-input-field
    variant="label-hidden"
    field-name={fields.emailField}>
</lightning-input-field>
```

This is useful when the standard field label does not provide the wording or context needed by the user.

```html

            record-id="003bm000025TtYHAA0">

            <lightning-messages></lightning-messages>

            <lightning-input-field
                field-name={fields.accountField}>
            </lightning-input-field>

            <lightning-input-field
                field-name={fields.nameField}>
            </lightning-input-field>

            <lightning-input-field
                field-name={fields.titleField}>
            </lightning-input-field>

            <lightning-input-field
                field-name={fields.phoneField}>
            </lightning-input-field>

            <label class="slds-p-left_x-small">Enter Your Email</label>
            <lightning-input-field
                variant="label-hidden"

                variant="brand"
                type="submit"

                label="Save">
            </lightning-button>

        </lightning-record-edit-form>
    </lightning-card>
</template>
```

### `customFieldLabel.js`

This is the JavaScript shown in the screenshot:

```javascript
import { LightningElement } from 'lwc';
import CONTACT_OBJECT from '@salesforce/schema/Contact';
import NAME_FIELD from '@salesforce/schema/Contact.Name';
import TITLE_FIELD from '@salesforce/schema/Contact.Title';
import PHONE_FIELD from '@salesforce/schema/Contact.Phone';
import EMAIL_FIELD from '@salesforce/schema/Contact.Email';
import ACCOUNT_FIELD from '@salesforce/schema/Contact.AccountId';

export default class RecordEditFormDemo extends LightningElement {
    objectName = CONTACT_OBJECT;

    fields = {
        accountField: ACCOUNT_FIELD,
        nameField: NAME_FIELD,
        titleField: TITLE_FIELD,
        phoneField: PHONE_FIELD,
        emailField: EMAIL_FIELD
    };

    handleReset() {
        const inputField = this.template.querySelectorAll('lightning-input-field');

        if (inputField) {
            Array.from(inputField).forEach(field => {
                field.reset();
            });
        }
    }
}
```

## 5. Explanation of the Important Parts

### `variant="label-hidden"`

```html
<lightning-input-field
    variant="label-hidden"
    field-name={fields.emailField}>
</lightning-input-field>
```

This hides the default Salesforce field label but keeps the input visible. In the example, the separate label displays the text `Enter Your Email`.

### Custom label text

```html
<label class="slds-p-left_x-small">Enter Your Email</label>
```

- `<label>` displays the custom text.
- `slds-p-left_x-small` is a Salesforce Lightning Design System (SLDS) utility class that adds a small amount of left padding.
- The label text can be changed to match the business requirement.

**Accessibility note:** A plain HTML `<label>` may not programmatically associate itself with the internal input rendered by `lightning-input-field`. For a production component, check the accessibility requirements and prefer a supported label mechanism where possible. Another option is to use `lightning-input` with an explicit `label` when you do not need `lightning-input-field`'s metadata-driven behavior.

### Schema imports

The imports reference Contact fields:

- `Contact` — object being edited.
- `Contact.AccountId` — Account relationship field.
- `Contact.Name` — Contact name field.
- `Contact.Title` — job title.
- `Contact.Phone` — phone number.
- `Contact.Email` — email address.

### Cancel button

The `handleReset()` method finds all `lightning-input-field` elements and calls `reset()` on each one. It restores the fields to their initial values; it does not undo a record update that has already been saved.

### Save button

`type="submit"` submits the form. Salesforce handles the standard record update, field validation, and permission checks. `<lightning-messages>` displays form errors.

## 6. Setup and Testing

1. Open your Salesforce DX project in VS Code.
2. Generate a component bundle:

   ```bash
   sf lightning generate component --name customFieldLabel --type lwc --output-dir force-app/main/default/lwc
   ```

3. Paste the HTML, JavaScript, and XML into the corresponding files.
4. Replace the sample Contact record ID with a valid Contact ID from the same Salesforce org.
5. Deploy the component:

   ```bash
   sf project deploy start --source-dir force-app/main/default/lwc/customFieldLabel
   ```

6. Open **Setup → Lightning App Builder** and add the component to a Lightning App Page.
7. Save and activate the page.
8. Confirm the Email input displays `Enter Your Email` above it and that the built-in Email label is hidden.
9. Test **Cancel** and **Save**.

The running user must have access to the Contact record and the fields. The sample record ID will not necessarily exist in another sandbox or production org.

## 7. Recommended Improvement: Use a Dynamic Record ID

The screenshot hard-codes a record ID. For a reusable component on a record page, expose the ID with `@api` instead.

In JavaScript:

```javascript
import { LightningElement, api } from 'lwc';

export default class RecordEditFormDemo extends LightningElement {
    @api recordId;

    // Keep the objectName, fields, and handleReset members here.
}
```

Then update the form:

```html
<lightning-record-edit-form
    object-api-name={objectName}
    record-id={recordId}>
```

This allows Salesforce to supply the current record ID when the component is placed on a supported record page. Do not use the hard-coded ID and dynamic binding together.

## 8. Common Issues

### The custom label appears but the Email field label also appears
Verify that `variant="label-hidden"` is set on the correct `lightning-input-field`.

### The form does not load the Contact
Confirm the record ID is valid in the current org, the record is a Contact, and the running user has access.

### Save fails
Check required fields, validation rules, duplicate rules, field-level security, object permissions, and the messages shown by `lightning-messages`.

### Cancel does not clear the fields
`reset()` restores initial values; it does not necessarily clear every field. It also does not reverse a save that has already completed.

## 9. Interview Questions and Answers

### Q1. What is `lightning-record-edit-form`?
It is an LWC base component used to create or update Salesforce records using a form that supports Salesforce field metadata and validation.

### Q2. How do you hide the default label on `lightning-input-field`?
Set `variant="label-hidden"`.

### Q3. How can you display custom text above a field?
Display custom text in the template and hide the field's built-in label if appropriate. In production, also ensure the label is accessible and properly associated with the input.

### Q4. What does `slds-p-left_x-small` do?
It is an SLDS utility class that applies a small amount of left padding.

### Q5. What is the purpose of `lightning-messages`?
It displays errors returned by the record form, including validation and server-side errors.

### Q6. How does the Save button submit the form?
The button uses `type="submit"` inside `lightning-record-edit-form`.

### Q7. How does the Cancel button work in this example?
It calls `handleReset()`, which selects the form's `lightning-input-field` elements and calls `reset()` on each.

### Q8. Does `reset()` undo a saved record update?
No. It restores current input values to their initial values and does not roll back a completed server-side save.

### Q9. Why import fields from `@salesforce/schema`?
Schema imports provide references to Salesforce objects and fields, improve validation of references, and help protect against field renames.

### Q10. Why should record IDs not be hard-coded?
Record IDs differ between orgs and environments. A dynamic `@api recordId` makes the component reusable.

### Q11. Does this form require Apex?
Not for ordinary create or update operations. `lightning-record-edit-form` uses Lightning Data Service for standard record operations.

### Q12. What could prevent the form from saving?
Missing required values, validation rules, insufficient permissions, invalid data, duplicate rules, or errors from Salesforce automation.

## Summary

This example adds the custom text **Enter Your Email** above the Contact Email field. The field's default label is hidden using `variant="label-hidden"`. The rest of the form uses schema imports, `lightning-input-field`, `lightning-messages`, a reset handler, and a submit button to update a Contact record.
