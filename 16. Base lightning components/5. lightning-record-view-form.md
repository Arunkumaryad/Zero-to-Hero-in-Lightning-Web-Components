# Lightning-record-view-form

## 1. Overview

`lightning-record-view-form` is a Salesforce Lightning Web Component (LWC) base component used to display Salesforce record data for specified fields. It renders field labels and current values in a read-only format. It also lets developers customize the form layout and how record data is rendered.

This README follows the supplied screenshots, includes the code shown in them, explains the code in simple language, and adds interview questions and answers.

---

## 2. Definition from the Screenshots

> Use the `lightning-record-view-form` component to create a form that displays Salesforce record data for specified fields associated with that record. The fields are rendered with their labels and current values as read-only.

- You can customize the form layout or provide custom rendering of record data. If you don't require customizations, use `lightning-record-form` instead.
- To specify read-only fields, use `lightning-output-field` components inside `lightning-record-view-form`.

### Feature comparison shown in the screenshot

| Feature | `lightning-record-form` | `lightning-record-view-form` | `lightning-record-edit-form` |
|---|---:|---:|---:|
| Create records | Yes | No | Yes |
| Edit records | Yes | No | Yes |
| View records | Yes | Yes | No (not its primary purpose) |
| Read-only display | Yes, with `mode="readonly"` | Yes | No (editable form) |
| Uses configured layout types | Yes | No | No |
| Multi-column layout | Built-in `columns` attribute | Custom layout | Custom layout |
| Custom field layout | Limited | Yes | Yes |
| Custom rendering of record data | Limited | Yes | Yes |

The table is a simplified summary of the screenshot. Exact behavior can depend on the component API and Salesforce platform version.

---

## 3. When to Use `lightning-record-view-form`

Use this component when:

- You need to display an existing record in read-only mode.
- You want to decide which fields appear and where they appear.
- You want to create a custom layout, such as two columns.
- You want to use `lightning-output-field` for standard Salesforce field rendering.
- You want the display to respect Salesforce record access and field-level security.

Use `lightning-record-form` when you want the quickest standard form and do not need much layout customization.

---

## 4. How It Works

1. Provide `object-api-name` to identify the Salesforce object.
2. Provide `record-id` to identify the record to display.
3. Place one or more `lightning-output-field` components inside `lightning-record-view-form`.
4. Arrange fields using HTML and Salesforce Lightning Design System (SLDS) layout classes.
5. Salesforce Lightning Data Service loads the record data and renders the fields as read-only.

No Apex is required for this standard record display.

### Screenshot example — component on a Record Page

#### `recordViewFormDemo.html`

```html
<template>
    <lightning-card title="Lightning record view form on Record Page">
        <lightning-record-view-form
            object-api-name={objectApiName}
            record-id={recordId}>

            <div class="slds-grid slds-gutters">
                <div class="slds-col slds-size_6-of-12">
                    <lightning-output-field field-name="Name"></lightning-output-field>
                    <lightning-output-field field-name="Phone"></lightning-output-field>
                    <lightning-output-field field-name="Industry"></lightning-output-field>
                </div>

                <div class="slds-col slds-size_6-of-12">
                    <lightning-output-field field-name="AnnualRevenue"></lightning-output-field>
                </div>
            </div>

        </lightning-record-view-form>
    </lightning-card>
</template>
```

#### `recordViewFormDemo.js`

```javascript
import { LightningElement, api } from 'lwc';

export default class RecordViewFormDemo extends LightningElement {
    @api recordId;
    @api objectApiName;
}
```

#### `recordViewFormDemo.js-meta.xml`

```xml
<?xml version="1.0" encoding="UTF-8"?>
<LightningComponentBundle xmlns="http://soap.sforce.com/2006/04/metadata">
    <apiVersion>67.0</apiVersion>
    <isExposed>true</isExposed>
    <targets>
        <target>lightning__AppPage</target>
        <target>lightning__RecordPage</target>
    </targets>
</LightningComponentBundle>
```

**How it works:**

- `@api recordId` exposes a public property that Salesforce can populate with the current record ID on a record page.
- `@api objectApiName` exposes the object API name, such as `Account`.
- The template passes both properties to `lightning-record-view-form`.
- The SLDS grid divides the content into two columns.
- `lightning-output-field` displays the field label and its value in read-only mode.

**Note:** When using the component on a record page, Salesforce supplies the record context. If you add it to an App Page instead, you must provide the record ID and object context by another supported method.

## 6. Important Attributes and Elements

| Attribute / element | Purpose | Example |
|---|---|---|
| `object-api-name` | Identifies the object being displayed | `object-api-name={objectApiName}` |
| `record-id` | Identifies the record to display | `record-id={recordId}` |
| `field-name` | Identifies a field to render | `field-name="Industry"` |
| `lightning-output-field` | Renders a field label and value read-only | `<lightning-output-field field-name="Name"></lightning-output-field>` |
| `slds-grid` | Creates an SLDS grid container | `class="slds-grid"` |
| `slds-gutters` | Adds spacing between grid columns | `class="slds-grid slds-gutters"` |
| `slds-col` | Defines a grid column | `class="slds-col"` |
| `slds-size_6-of-12` | Makes a column half of the 12-part grid | `class="slds-col slds-size_6-of-12"` |

The object API name and record ID are required for a record display. Use field API names, not field labels, in `field-name`.

## 7. Understanding the SLDS Two-Column Layout

```html
<div class="slds-grid slds-gutters">
    <div class="slds-col slds-size_6-of-12">
        <!-- First column fields -->
    </div>

    <div class="slds-col slds-size_6-of-12">
        <!-- Second column fields -->
    </div>
</div>
```

- `slds-grid` enables the grid layout.
- `slds-gutters` adds spacing between columns.
- `slds-size_6-of-12` allocates half the available width to each column.
- Put fields in the column where you want them to appear.

For example, Name, Phone, and Industry are in the first column; Annual Revenue is in the second.

## 8. Setup and Testing Steps

1. In VS Code, open your Salesforce DX project.
2. Create the component bundle:

   ```bash
   sf lightning generate component --name recordViewFormDemo --type lwc --output-dir force-app/main/default/lwc
   ```

3. Replace the generated HTML, JavaScript, and metadata XML with the examples above.
4. Deploy the component to your sandbox:

   ```bash
   sf project deploy start --source-dir force-app/main/default/lwc/recordViewFormDemo
   ```

5. Open **Setup → Lightning App Builder**.
6. Edit an Account Record Page and drag the component onto the page, or create an App Page.
7. Save and activate the page if required.
8. Open an Account record and confirm that Name, Phone, Industry, and Annual Revenue appear as read-only values.

Use a record ID that exists in the target org. A Salesforce record ID from one sandbox usually will not identify the same record in another org.

## 9. `lightning-record-view-form` vs. Related Components

### `lightning-record-view-form`

- Displays record fields as read-only.
- Allows custom field placement and layout.
- Uses `lightning-output-field` for standard field rendering.

### `lightning-record-edit-form`

- Creates or updates records.
- Lets you arrange fields manually using `lightning-input-field`.
- Supports custom Save and Cancel buttons and form event handling.

### `lightning-record-form`

- Provides a quick standard form for creating, viewing, or editing.
- Requires less markup.
- Offers less control over individual field placement.

### `lightning-output-field` vs. `lightning-input-field`

- `lightning-output-field`: displays a field as read-only.
- `lightning-input-field`: renders an editable input for a field inside `lightning-record-edit-form`.

## 10. Best Practices

- Use `@api recordId` and `@api objectApiName` when the component needs the current record context.
- Avoid hard-coding record IDs in reusable components.
- Use field API names such as `AnnualRevenue`, not labels such as “Annual Revenue.”
- Keep the field layout clear and accessible.
- Check object permissions, record access, and field-level security if a field is missing.
- Use `lightning-record-form` if a custom layout is not required.
- Prefer Lightning Data Service components for standard record operations instead of writing Apex unnecessarily.

## 11. Interview Questions and Answers

### Q1. What is `lightning-record-view-form`?

It is an LWC base component used to display specified Salesforce record fields in read-only mode.

### Q2. Does it allow users to edit fields?

No. It displays fields as read-only. Use `lightning-record-edit-form` for editable fields.

### Q3. What is `lightning-output-field`?

It renders a field's label and current value in a record form, in read-only format.

### Q4. What is the purpose of `object-api-name`?

It specifies the Salesforce object, for example `Account`.

### Q5. What is the purpose of `record-id`?

It specifies which existing record should be displayed.

### Q6. Why are `@api recordId` and `@api objectApiName` used?

They expose public component properties so Salesforce or a parent component can pass record context into the LWC.

### Q7. Does `lightning-record-view-form` need Apex?

No. It uses Lightning Data Service for supported record data access.

### Q8. Why use `lightning-record-view-form` instead of `lightning-record-form`?

Use it when you need control over the field layout or custom rendering of the displayed record data.

### Q9. What does `slds-size_6-of-12` mean?

It makes a grid column half the width of the 12-part SLDS grid.

### Q10. What is the difference between `lightning-output-field` and `lightning-input-field`?

`lightning-output-field` displays data read-only; `lightning-input-field` creates an editable field in an edit form.

### Q11. What should you check if a field is blank or missing?

Check that the field API name is correct, the record contains a value, and the running user has the required field-level security and record access.

### Q12. Can you use a hard-coded record ID?

You can for a quick demonstration, but it is not recommended for reusable code or deployment across orgs because record IDs differ between environments.

## 12. Scenario-Based Interview Questions

**Scenario 1: Display Account Name, Phone, Industry, and Annual Revenue in two columns.**  
Use `lightning-record-view-form`, place each `lightning-output-field` in the desired column, and use SLDS grid classes.

**Scenario 2: The component must work on any Account record page.**  
Expose `recordId` and `objectApiName` with `@api` and pass them to the form.

**Scenario 3: Users must be able to update a field.**  
Use `lightning-record-edit-form` with `lightning-input-field`, or use `lightning-record-form` if its standard UI is sufficient.

**Scenario 4: A field is not visible to a particular user.**  
Verify field-level security, object permissions, record access, and the field API name.

---


## Summary

`lightning-record-view-form` is useful when you want to show selected Salesforce record fields in a read-only form while controlling the field layout. The component uses Lightning Data Service, and `lightning-output-field` renders each field's label and value. Use `lightning-record-form` for a faster standard form, or `lightning-record-edit-form` when users need a customizable editable form.
