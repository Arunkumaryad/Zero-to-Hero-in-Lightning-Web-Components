# Base Lightning Components in Salesforce LWC

## 1. Introduction

Base Lightning Components are standard, reusable UI components provided by Salesforce. The three record-form components discussed here are built on Lightning Data Service (LDS), so LDS handles record data access and provides its caching and synchronization capabilities behind the scenes.

This README explains the definitions and points shown in the screenshots, compares the three components, gives practical examples, and covers common Salesforce interview questions.

---

## 2. Definitions from the Screenshots

### Base Lightning Components

> Base Lightning Components are built on Lightning Data Service. So, Lightning Data Service is used behind the scenes by base components and inherits its caching and synchronisation capabilities.

The three types of base Lightning Components built on LDS are:

1. `lightning-record-form`
2. `lightning-record-edit-form`
3. `lightning-record-view-form`

### When to Use These Forms?

The screenshots list these use cases:

- Create a metadata-driven UI or form-based UI similar to the record detail page in Salesforce.
- Display record values based on field metadata.
- Hide or show localized field labels.
- Display the help text on a custom field.
- Perform client-side validation and enforce validation rules.

These components are useful when you need a standard record UI without building every input, label, validation, and save operation from scratch.

---

## 3. What Each Component Does

- **`lightning-record-edit-form`** — displays an editable form for creating or updating a record.
- **`lightning-record-view-form`** — displays record fields in view mode.
- **`lightning-record-form`** — supports viewing, editing, and creating records using a simpler configuration.

### Quick comparison from the screenshots

| Feature | `lightning-record-form` | `lightning-record-view-form` | `lightning-record-edit-form` |
|---|---|---|---|
| Create records | Yes | No | Yes |
| Edit records | Yes | No | Yes |
| View records | Yes | Yes | Not its primary purpose |
| Read-only display | Yes, using view mode | Yes | Not its primary purpose |
| Configure layout type | Yes | Configure fields individually | Configure fields individually |
| Multi-column layout | Supported through layout options | Custom layout | Custom layout |
| Custom field layout | Limited compared with form/view components | Yes | Yes |
| Custom rendering of record data | Limited | Yes | Yes |

**Note:** The exact options available depend on the component, its attributes, and the Salesforce API version. For fully custom field layouts, `lightning-record-edit-form` and `lightning-record-view-form` are usually the better choices.

---

## 4. When Should You Use Each Component?

### Use `lightning-record-form` when:

- You want a record form with minimal code.
- You want Salesforce to determine the fields from the page layout using `layout-type`.
- You need a quick create, view, or edit experience.
- You do not need extensive control over the individual field layout.

### Use `lightning-record-view-form` when:

- You need to display record fields only.
- You want to control which fields are shown and how they are arranged.
- You want to use `lightning-output-field` for field display.

### Use `lightning-record-edit-form` when:

- You need a custom create or edit form.
- You want to choose and arrange individual fields.
- You need to handle submit, success, or error events.
- You want custom UI around the standard record-saving behavior.

## 5. Example 1: `lightning-record-form`

This example displays a Contact record in view mode and allows the user to switch to edit mode.

### `contactRecordForm.html`

```html
<template>
    <lightning-card title="Contact Record Form">
        <lightning-record-form
            record-id={recordId}
            object-api-name="Contact"
            layout-type="Full"
            mode="view"
            columns="2">
        </lightning-record-form>
    </lightning-card>
</template>
```

### `contactRecordForm.js`

```javascript
import { LightningElement, api } from 'lwc';

export default class ContactRecordForm extends LightningElement {
    @api recordId;
}
```

### `contactRecordForm.js-meta.xml`

```xml
<?xml version="1.0" encoding="UTF-8"?>
<LightningComponentBundle xmlns="http://soap.sforce.com/2006/04/metadata">
    <apiVersion>67.0</apiVersion>
    <isExposed>true</isExposed>
    <targets>
        <target>lightning__RecordPage</target>
        <target>lightning__AppPage</target>
    </targets>
</LightningComponentBundle>
```

**How it works:**

- `record-id` identifies the Contact record.
- `object-api-name` specifies the Salesforce object.
- `layout-type="Full"` asks Salesforce to use the full page layout.
- `mode="view"` starts in view mode; users can enter edit mode when the component supports it.
- `columns="2"` requests a two-column layout.

To create a new record instead, omit `record-id` and set the mode to `edit`, ensuring the object API name is supplied.

## 6. Example 2: `lightning-record-view-form`

Use this component when you want to display selected fields in a custom layout.

### `contactRecordViewForm.html`

```html
<template>
    <lightning-card title="Contact Details">
        <lightning-record-view-form
            record-id={recordId}
            object-api-name="Contact">

            <div class="slds-grid slds-wrap">
                <div class="slds-col slds-size_1-of-2 slds-p-around_x-small">
                    <lightning-output-field field-name="FirstName">
                    </lightning-output-field>
                </div>

                <div class="slds-col slds-size_1-of-2 slds-p-around_x-small">
                    <lightning-output-field field-name="LastName">
                    </lightning-output-field>
                </div>

                <div class="slds-col slds-size_1-of-1 slds-p-around_x-small">
                    <lightning-output-field field-name="Email">
                    </lightning-output-field>
                </div>
            </div>
        </lightning-record-view-form>
    </lightning-card>
</template>
```

### `contactRecordViewForm.js`

```javascript
import { LightningElement, api } from 'lwc';

export default class ContactRecordViewForm extends LightningElement {
    @api recordId;
}
```

**How it works:**

- `lightning-record-view-form` loads the record through LDS.
- `lightning-output-field` displays each selected field using Salesforce field metadata, including the appropriate label and formatting.
- The SLDS grid classes arrange fields into columns.

## 7. Example 3: `lightning-record-edit-form`

Use this component when you need to control the fields in a create or edit form.

### `contactRecordEditForm.html`

```html
<template>
    <lightning-card title="Edit Contact">
        <lightning-record-edit-form
            record-id={recordId}
            object-api-name="Contact"
            onsuccess={handleSuccess}
            onerror={handleError}>

            <lightning-messages></lightning-messages>

            <lightning-input-field field-name="FirstName">
            </lightning-input-field>

            <lightning-input-field field-name="LastName">
            </lightning-input-field>

            <lightning-input-field field-name="Email">
            </lightning-input-field>

            <div class="slds-m-top_medium">
                <lightning-button
                    type="submit"
                    variant="brand"
                    label="Save">
                </lightning-button>
            </div>
        </lightning-record-edit-form>
    </lightning-card>
</template>
```

### `contactRecordEditForm.js`

```javascript
import { LightningElement, api } from 'lwc';
import { ShowToastEvent } from 'lightning/platformShowToastEvent';

export default class ContactRecordEditForm extends LightningElement {
    @api recordId;

    handleSuccess() {
        this.dispatchEvent(
            new ShowToastEvent({
                title: 'Success',
                message: 'Contact saved successfully.',
                variant: 'success'
            })
        );
    }

    handleError() {
        this.dispatchEvent(
            new ShowToastEvent({
                title: 'Error',
                message: 'Unable to save the Contact. Check the form for details.',
                variant: 'error'
            })
        );
    }
}
```

**How it works:**

- When `record-id` is provided, the form edits that Contact.
- When `record-id` is omitted, the form can create a new Contact.
- `lightning-input-field` renders inputs based on Salesforce field metadata.
- `lightning-messages` displays validation and server-side errors.
- `type="submit"` submits the form.
- The success and error handlers display a toast notification.

**Important:** Contact's `LastName` is required. The example relies on Salesforce's standard validation and permissions.

## 8. Important Attributes and Elements

| Attribute / Element | Purpose |
|---|---|
| `record-id` | Identifies the record to view or edit. Omit it for record creation where supported. |
| `object-api-name` | API name of the object, such as `Contact` or `Account`. |
| `layout-type` | For `lightning-record-form`, selects a layout such as `Full` or `Compact`. |
| `mode` | For `lightning-record-form`, selects `view`, `edit`, or `readonly` where supported. |
| `columns` | Sets the number of columns in the `lightning-record-form` layout. |
| `lightning-input-field` | Displays an editable field inside `lightning-record-edit-form`. |
| `lightning-output-field` | Displays a field inside `lightning-record-view-form`. |
| `lightning-messages` | Shows form errors and messages. |
| `onsuccess` | Handles a successful form submission. |
| `onerror` | Handles a form error. |
| `onsubmit` | Lets the component intercept a form submission before it is submitted. |

## 9. Client-Side Validation and Salesforce Validation Rules

These forms support standard field-level behavior and validation, including required fields and applicable Salesforce validation rules. Client-side validation can give users immediate feedback, but server-side validation remains authoritative when the record is saved.

For a custom submit handler, use `event.preventDefault()` only when you intend to modify the fields before manually submitting the form with `event.detail.fields`. Do not prevent submission without submitting it again.

---

## 10. Base Lightning Components vs. Custom Inputs

Prefer `lightning-input-field` within a record edit form when you want Salesforce field metadata, standard formatting, and integrated validation behavior.

Use custom components such as `lightning-input` when you need a more customized input experience. In that case, you may need to manage field values, validation, and submission logic yourself.

## 11. Interview Questions and Answers

### Q1. What are Base Lightning Components?

They are reusable standard UI components provided by Salesforce. The record-form components use Lightning Data Service to handle supported record operations.

### Q2. Which three record-form components are built on LDS?

- `lightning-record-form`
- `lightning-record-edit-form`
- `lightning-record-view-form`

### Q3. What is the difference between `lightning-record-form` and `lightning-record-edit-form`?

`lightning-record-form` is simpler and can display, create, or edit records with less configuration. `lightning-record-edit-form` provides more control over the fields and layout in a create/edit form.

### Q4. What is the difference between `lightning-record-view-form` and `lightning-record-edit-form`?

The view form displays record fields using `lightning-output-field`. The edit form accepts field inputs using `lightning-input-field` and supports saving records.

### Q5. Which component should you use for a quick record form?

Use `lightning-record-form` when its standard layout and behavior meet the requirement.

### Q6. Which component should you use when you need a custom field layout?

Use `lightning-record-view-form` for a custom read-only layout or `lightning-record-edit-form` for a custom editable layout.

### Q7. How do you create a record using `lightning-record-edit-form`?

Specify `object-api-name`, omit `record-id`, include the required `lightning-input-field` elements, and provide a submit button with `type="submit"`.

### Q8. How do you edit an existing record?

Pass the record ID using `record-id` and specify the object API name.

### Q9. What is `lightning-input-field` used for?

It renders an editable Salesforce field inside `lightning-record-edit-form`, using field metadata and standard record-form behavior.

### Q10. What is `lightning-output-field` used for?

It displays a Salesforce field inside `lightning-record-view-form`.

### Q11. What is `lightning-messages` used for?

It displays errors and messages produced by the record form, including applicable validation errors.

### Q12. Do these components respect Salesforce security?

Supported LDS-backed record operations respect applicable Salesforce access controls, including record access, object permissions, and field-level security.

### Q13. Do you always need Apex to create or update a record?

No. For supported record operations, base Lightning record-form components or LDS APIs can handle the work without custom Apex.

### Q14. How can you respond after a record is saved?

Use the form's `onsuccess` event handler. You can show a toast, navigate to the saved record, or update component state.

### Q15. Can you customize the layout of `lightning-record-form`?

It offers layout options such as `layout-type` and `columns`, but it provides less control over individual field placement than `lightning-record-edit-form` and `lightning-record-view-form`.

## 12. Scenario-Based Interview Questions

**Scenario 1: You need to show three Contact fields in a specific order without editing. Which component should you use?**  
Use `lightning-record-view-form` with `lightning-output-field` elements for the required fields.

**Scenario 2: You need a quick Account form that admins can adjust through the page layout. Which component is a good fit?**  
Use `lightning-record-form` with the appropriate `layout-type`.

**Scenario 3: You need a Contact edit form with only First Name, Last Name, and Email. Which component should you use?**  
Use `lightning-record-edit-form` with the required `lightning-input-field` elements.

**Scenario 4: A user cannot save a record because a validation rule fails. What should the form do?**  
The form should display the validation error, commonly through `lightning-messages`, and allow the user to correct the values.

**Scenario 5: You need a toast after a successful save. What should you use?**  
Handle the `onsuccess` event and dispatch a `ShowToastEvent`.

---

## 13. Common Mistakes

- Using `lightning-output-field` inside an edit form instead of `lightning-input-field`.
- Using `lightning-input-field` inside a view form instead of `lightning-output-field`.
- Forgetting `object-api-name`.
- Forgetting required fields when creating a record.
- Omitting `lightning-messages` and making errors harder for users to understand.
- Assuming `lightning-record-form` offers the same field-by-field layout control as the edit and view form components.
- Assuming client-side validation replaces server-side validation.

## Summary

The three Base Lightning record-form components—`lightning-record-form`, `lightning-record-edit-form`, and `lightning-record-view-form`—make it easier to build standard Salesforce record UIs. They use Lightning Data Service for supported data operations, reducing boilerplate code while providing Salesforce-managed record behavior. Choose `lightning-record-form` for simplicity, `lightning-record-view-form` for a custom read-only layout, and `lightning-record-edit-form` for a custom create/edit layout.
