# Custom Validation in lightning-record-edit-form

## 1. Overview

This Salesforce Lightning Web Component (LWC) demonstrates **client-side custom validation** before creating an Account record. The form contains a text input for the Account Name. When the user submits the form, JavaScript checks whether the entered name includes the word `Australia`.

- If the name does **not** include `Australia`, the component sets a custom validation message and prevents submission.
- If the name includes `Australia`, the component clears the custom error and submits the Account form.
- On success or failure, a toast notification is displayed.

> This is a client-side example. For a real business rule that must always be enforced, also implement server-side validation (for example, a Salesforce validation rule), because client-side checks alone can be bypassed.

## 2. Definition

**Custom validation in `lightning-record-edit-form`** is the process of applying a developer-defined rule to form input, displaying a custom error message when the rule is not satisfied, and allowing the record to be submitted only when the input passes the check.

In this example, the Account Name must contain the text `Australia`.

### `customValidation.js`

This reproduces the JavaScript logic shown in the screenshot:

```javascript
import { LightningElement } from 'lwc';
import ACCOUNT_OBJECT from '@salesforce/schema/Account';
import { ShowToastEvent } from 'lightning/platformShowToastEvent';

export default class RecordEditCustomValidation extends LightningElement {
    objectName = ACCOUNT_OBJECT;
    inputValue = '';

    handleChange(event) {
        this.inputValue = event.target.value;
    }

    handleSubmit(event) {
        event.preventDefault();

        const inputCmp = this.template.querySelector('lightning-input');
        const value = inputCmp.value;

        if (!value.includes('Australia')) {
            inputCmp.setCustomValidity('The Account Name must include "Australia"');
        } else {
            inputCmp.setCustomValidity('');

            const fields = event.detail.fields;
            fields.Name = value;

            this.template.querySelector('lightning-record-edit-form').submit(fields);
        }

        inputCmp.reportValidity();
    }

    successHandler(event) {
        const toastEvent = new ShowToastEvent({
            title: 'Account Created',
            message: 'Record Id: ' + event.detail.id,
            variant: 'success'
        });

        this.dispatchEvent(toastEvent);
    }

    handleError(event) {
        const toastEvent = new ShowToastEvent({
            title: 'Error Creating Account',
            message: event.detail.message,
            variant: 'error'
        });

        this.dispatchEvent(toastEvent);
    }
}
```

## 5. Important Implementation Note

The screenshot's HTML uses a plain `lightning-input` inside `lightning-record-edit-form`. A `lightning-input` is not automatically included in the record form's submitted fields. The JavaScript explicitly assigns its value to `fields.Name`, which is why the Account Name is included in the submission.

For a robust implementation, add `required` to the input if the name must not be blank, and guard against empty values. The example below keeps the same behavior but handles empty input safely.

### Recommended safer validation logic

Replace `handleSubmit()` with this version if you want to prevent blank names as well:

```javascript
handleSubmit(event) {
    event.preventDefault();

    const inputCmp = this.template.querySelector('lightning-input');
    const value = (inputCmp.value || '').trim();

    if (!value.includes('Australia')) {
        inputCmp.setCustomValidity(
            'The Account Name must include "Australia".'
        );
    } else {
        inputCmp.setCustomValidity('');
        const fields = event.detail.fields;
        fields.Name = value;
        this.template
            .querySelector('lightning-record-edit-form')
            .submit(fields);
    }

    inputCmp.reportValidity();
}
```

The `includes()` check is case-sensitive: `Australia` passes, but `australia` does not. If the rule should ignore capitalization, compare using `value.toLowerCase().includes('australia')`.

## 6. How the Code Works

1. **Object reference:** `ACCOUNT_OBJECT` references the Salesforce Account object.
2. **Track input:** `handleChange()` copies the user's input into `inputValue`.
3. **Intercept submit:** `event.preventDefault()` stops the form from submitting automatically.
4. **Read the field:** `querySelector('lightning-input')` finds the input and reads its value.
5. **Validate:** `includes('Australia')` checks the custom business condition.
6. **Set or clear the error:** `setCustomValidity()` sets the message when invalid and clears it with an empty string when valid.
7. **Show the error:** `reportValidity()` asks the input to display its current validation state.
8. **Submit valid data:** The code adds the value to `event.detail.fields.Name` and calls the form's `submit(fields)` method.
9. **Handle success:** `successHandler()` displays a success toast with the new Account record ID.
10. **Handle errors:** `handleError()` displays an error toast if Salesforce rejects the save.

## 8. Common Issues

### The form does not save the Account Name
Ensure `fields.Name = value` is set before calling `submit(fields)`. A standalone `lightning-input` is not automatically mapped into `event.detail.fields`.

### The error stays visible after correcting the value
Clear the custom validity message with `inputCmp.setCustomValidity('')` before reporting validity or submitting.

### The toast does not appear
Check that `onsuccess` and `onerror` are correctly connected in the HTML and that the corresponding JavaScript methods exist.

### The user can bypass the validation
Client-side validation is for user experience, not a security boundary. Enforce critical business rules with a Salesforce validation rule or other server-side logic too.

## 9. Interview Questions and Answers

### Q1. What is custom validation in LWC?
It is a developer-defined check that validates user input against a business requirement and shows an appropriate error if the input is invalid.

### Q2. What does `setCustomValidity()` do?
It sets a custom validation error message on an input. Pass an empty string to clear that custom error.

### Q3. What does `reportValidity()` do?
It evaluates the input's validity and displays its current validation message when invalid.

### Q4. Why is `event.preventDefault()` used in `handleSubmit()`?
It stops the default form submission so the component can validate the input first.

### Q5. What is `event.detail.fields`?
It contains the field values collected by `lightning-record-edit-form` for submission. The example explicitly adds `Name` because the input is a standalone `lightning-input`.

### Q6. Why call `submit(fields)`?
It submits the supplied field values through `lightning-record-edit-form` after the custom check passes.

### Q7. What is the purpose of `onsuccess`?
It handles a successful record save. The success event provides the saved record's ID.

### Q8. What is the purpose of `onerror`?
It handles a failed record save so the component can report the error to the user.

### Q9. What does `ShowToastEvent` do?
It displays a toast notification such as success or error feedback.

### Q10. Is `includes('Australia')` case-sensitive?
Yes. The text must match the capitalization. Convert the input and search term to the same case if the rule should be case-insensitive.

### Q11. Can client-side validation replace a Salesforce validation rule?
No. Client-side validation improves user experience, but important business rules should also be enforced server-side.

### Q12. Does `lightning-record-edit-form` require Apex for a basic Account create operation?
No. It uses Lightning Data Service for standard record create and update operations.

## Summary

This example prevents an Account from being submitted unless its Name contains `Australia`. It demonstrates custom input validation, manual submission through `lightning-record-edit-form`, and success/error toast messages.
