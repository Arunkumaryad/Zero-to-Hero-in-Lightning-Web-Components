# Reset a lightning-record-edit-form

## 1. Overview

This example demonstrates how to reset editable fields in a Salesforce Lightning Web Component (LWC) that uses `lightning-record-edit-form`.

The component displays Contact fields such as Account, Name, Title, Phone, and Email. When the user clicks **Cancel**, JavaScript finds the `lightning-input-field` elements and calls `reset()` on each one.

## 2. Definition from the Screenshots

> Reset the values in the `lightning-record-edit-form` by selecting its `lightning-input-field` components and calling each field's `reset()` method.

The screenshot's JavaScript uses this logic:

```javascript
handleReset() {
    const inputField = this.template.querySelectorAll('lightning-input-field');
    if (inputField) {
        Array.from(inputField).forEach(field => {
            field.reset();
        });
    }
}
```

In simple terms:
1. Find all `lightning-input-field` components in the template.
2. Convert the returned collection into an array.
3. Call `reset()` on each field.
4. Each field returns to its initial value.

```javascript
import { LightningElement } from 'lwc';

        if (inputField) {
            Array.from(inputField).forEach((field) => {
                field.reset();

    }
}
```

## 5. How the Reset Function Works

```javascript
const inputField = this.template.querySelectorAll('lightning-input-field');
```

`querySelectorAll()` finds all matching `lightning-input-field` components in the template. It returns a collection, not a single field.

```javascript
Array.from(inputField).forEach((field) => {
    field.reset();
});
```

`Array.from()` converts the collection to an array. `forEach()` visits every field, and `reset()` restores that field's initial value.

A concise equivalent is:

```javascript
handleReset() {
    this.template
        .querySelectorAll('lightning-input-field')
        .forEach((field) => field.reset());
}
```

`querySelectorAll()` returns a NodeList, which supports `forEach()` in modern Salesforce environments. The screenshot's `Array.from()` approach is also valid.

## 6. What Does Reset Mean?

- **Creating a new Contact:** Reset clears entered values back to their initial/default values.
- **Editing an existing Contact:** Reset restores the values that were initially loaded in the form.
- **After a successful save:** Reset does not undo saved database changes. It only resets current form inputs.

This applies to `lightning-input-field`. If you add custom inputs such as `lightning-input`, you may need to reset those separately.

## 7. Create a New Record vs. Edit an Existing Record

The screenshot's form omits `record-id`, so it is configured to create a new Contact.

### Create a new Contact

```html
<lightning-record-edit-form object-api-name={objectName}>
    <lightning-messages></lightning-messages>
    <lightning-input-field field-name={fields.nameField}></lightning-input-field>
    <lightning-input-field field-name={fields.emailField}></lightning-input-field>
    <lightning-button type="submit" variant="brand" label="Save"></lightning-button>
</lightning-record-edit-form>
```

### Edit an existing Contact

Provide a valid Contact record ID:

```html
<lightning-record-edit-form
    object-api-name={objectName}
    record-id={recordId}>
    <lightning-messages></lightning-messages>
    <lightning-input-field field-name={fields.nameField}></lightning-input-field>
    <lightning-input-field field-name={fields.emailField}></lightning-input-field>
    <lightning-button type="submit" variant="brand" label="Save"></lightning-button>
</lightning-record-edit-form>
```

Expose the record ID if Salesforce or a parent component supplies it:

```javascript
import { LightningElement, api } from 'lwc';

export default class ResetRecordEditForm extends LightningElement {
    @api recordId;
}
```

Merge this property into the main JavaScript class if needed; do not replace the other imports or field definitions.

## 8. Setup and Testing

1. Open your Salesforce DX project in VS Code.
2. Generate the component:

   ```bash
   sf lightning generate component --name resetRecordEditForm --type lwc --output-dir force-app/main/default/lwc
   ```

3. Add the HTML, JavaScript, and XML code above.
4. Deploy the component:

   ```bash
   sf project deploy start --source-dir force-app/main/default/lwc/resetRecordEditForm
   ```

5. In Salesforce, open **Setup → Lightning App Builder**.
6. Add the component to a Lightning App Page, save, and activate the page.
7. Enter values in the Contact form and click **Cancel**.
8. Confirm the fields return to their initial values.
9. Enter valid values and click **Save** to test form submission.

Contact's Last Name is normally required, so saving without it should display a validation error.

## 9. Troubleshooting

### Cancel does not reset the fields
- Confirm the button uses `onclick={handleReset}`.
- Confirm the JavaScript method is named exactly `handleReset`.
- Confirm the selector matches `lightning-input-field`.
- Remember that reset restores initial values; it does not always mean every field becomes blank.

### Save fails
- Include `<lightning-messages></lightning-messages>`.
- Check required fields such as Contact Last Name.
- Check object permissions, field-level security, validation rules, duplicate rules, and flows/triggers.
- If editing, verify `record-id` belongs to a record in the current org.

### Custom inputs should reset too
`field.reset()` applies to `lightning-input-field`. Handle custom inputs such as `lightning-input` separately.

## 10. Interview Questions and Answers

### Q1. How do you reset a `lightning-record-edit-form`?
Use `this.template.querySelectorAll('lightning-input-field')` and call `reset()` on each returned field.

### Q2. What does `querySelectorAll()` return?
A collection of all matching elements in the component template. It can be empty if no elements match.

### Q3. Why is `Array.from()` used in the screenshot?
It converts the collection into an array so array methods such as `forEach()` can be used.

### Q4. What does `field.reset()` do?
It restores a field to its initial value. It does not undo a save already completed on the server.

### Q5. What is `lightning-record-edit-form`?
An LWC base component for creating and updating Salesforce records with a custom field layout.

### Q6. What is `lightning-input-field`?
It renders a Salesforce field as an input using the field's metadata.

### Q7. Why use `lightning-messages`?
It displays validation and server-side errors generated by the form.

### Q8. How do you create a new record?
Provide `object-api-name`, include input fields, omit `record-id`, and add a submit button.

### Q9. How do you edit an existing record?
Provide `object-api-name` and a valid `record-id`.

### Q10. Does resetting the form undo saved data?
No. Reset affects the current form inputs only. To change saved data, update the record and save again.

### Q11. Does this component require Apex?
Not for standard record creation or updates. It uses Lightning Data Service.

### Q12. Why might saving fail?
Possible causes include missing required fields, invalid values, insufficient permissions, validation rules, duplicate rules, or automation errors.



## Summary

The Cancel button calls `handleReset()`. That method finds each `lightning-input-field` in the template and calls `reset()` on it. This returns the fields to their initial values without updating the database. The Save button submits the form normally.
