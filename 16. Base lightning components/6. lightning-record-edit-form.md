Lightning-record-edit-form

## 1. Overview

`lightning-record-edit-form` is a Salesforce Lightning Web Component (LWC) base component that creates forms for creating or updating Salesforce records. It supports custom field layouts and custom rendering of record data. It uses Lightning Data Service (LDS), so standard record operations can usually be performed without writing Apex.

This README follows the supplied screenshots, explains the code in simple language, and includes interview questions and answers.

## 2. Definition from the Screenshot

> This component is used to create and edit the records.

> It provides custom layout of fields and custom rendering of record data.

### Feature comparison

| Feature | `lightning-record-form` | `lightning-record-view-form` | `lightning-record-edit-form` |
|---|---|---|---|
| Create records | Yes | No | Yes |
| Edit records | Yes | No | Yes |
| View records | Yes | Yes | Primarily for create/edit |
| Read-only mode | Yes, with `mode="readonly"` | Yes | Not its primary purpose |
| Uses configured layout types | Yes | No | No |
| Built-in multi-column layout | Yes, with `columns` | Custom markup | Custom markup |
| Custom field layout | Limited | Yes | Yes |
| Custom rendering of record data | Limited | Yes | Yes |

This table is a practical summary of the screenshot. Exact behavior can depend on the Salesforce API version.

## 3. When to Use `lightning-record-edit-form`

Use this component when:
- You need to create a new Salesforce record.
- You need to update an existing record.
- You want to choose the fields and their order yourself.
- You need custom Save and Cancel buttons.
- You need to respond to events such as success or error.
- You want to use Lightning Data Service rather than Apex for standard record operations.

Use `lightning-record-form` if you want a standard form with less code and do not need a custom field layout.

## 4. How It Works

1. `lightning-record-edit-form` identifies the Salesforce object and optionally the record to edit.
2. `lightning-input-field` renders editable inputs for the specified fields.
3. `lightning-messages` displays validation or server-side errors.
4. A button with `type="submit"` submits the form.
5. The form fires events such as `success` or `error`.
6. Lightning Data Service handles the standard save operation and respects applicable Salesforce access controls.

**Important:** To create a record, omit `record-id`. To edit an existing record, provide a valid `record-id`.

## 5. Code from the Screenshots

The screenshots show a Contact form with Account, Name, Title, Phone, and Email fields. The complete example below includes the missing object import and event handlers.

### `recordEditFormDemo.html`

```html
<template>
    <lightning-card title="lightning record edit form">
        <lightning-record-edit-form
            object-api-name={objectApiName}
            onsuccess={handleSuccess}
            onerror={handleError}>

            <lightning-messages></lightning-messages>

            <lightning-input-field field-name={fields.accountField}></lightning-input-field>
            <lightning-input-field field-name={fields.nameField}></lightning-input-field>
            <lightning-input-field field-name={fields.titleField}></lightning-input-field>
            <lightning-input-field field-name={fields.phoneField}></lightning-input-field>
            <lightning-input-field field-name={fields.emailField}></lightning-input-field>

            <div class="slds-m-around_xx-small">
                <lightning-button
                    label="Cancel"
                    onclick={handleCancel}>
                </lightning-button>

                <lightning-button
                    variant="brand"
                    type="submit"
                    label="Save"
                    class="slds-m-left_x-small">
                </lightning-button>
            </div>
        </lightning-record-edit-form>
    </lightning-card>
</template>
```

### `recordEditFormDemo.js`

```javascript
import { LightningElement } from 'lwc';
import CONTACT_OBJECT from '@salesforce/schema/Contact';
import NAME_FIELD from '@salesforce/schema/Contact.Name';
import TITLE_FIELD from '@salesforce/schema/Contact.Title';
import PHONE_FIELD from '@salesforce/schema/Contact.Phone';
import EMAIL_FIELD from '@salesforce/schema/Contact.Email';
import ACCOUNT_FIELD from '@salesforce/schema/Contact.AccountId';
import { ShowToastEvent } from 'lightning/platformShowToastEvent';

export default class RecordEditFormDemo extends LightningElement {
    objectApiName = CONTACT_OBJECT;

    fields = {
        accountField: ACCOUNT_FIELD,
        nameField: NAME_FIELD,
        titleField: TITLE_FIELD,
        phoneField: PHONE_FIELD,
        emailField: EMAIL_FIELD
    };

    handleSuccess(event) {
        this.dispatchEvent(
            new ShowToastEvent({
                title: 'Success',
                message: 'Contact saved successfully. Record ID: ' + event.detail.id,
                variant: 'success'
            })
        );
    }

    handleError(event) {
        // lightning-messages also displays form errors.
        // eslint-disable-next-line no-console
        console.error('Contact form error:', event.detail);
    }

    handleCancel() {
        const fields = this.template.querySelectorAll('lightning-input-field');
        fields.forEach((field) => field.reset());
    }
}
```

### `recordEditFormDemo.js-meta.xml`

```xml
<?xml version="1.0" encoding="UTF-8"?>
<LightningComponentBundle xmlns="http://soap.sforce.com/2006/04/metadata">
    <apiVersion>67.0</apiVersion>
    <isExposed>true</isExposed>
    <targets>
        <target>lightning__AppPage</target>
    </targets>
</LightningComponentBundle>
```

### Explanation

- The screenshot imports `NAME_FIELD`, `TITLE_FIELD`, `PHONE_FIELD`, `EMAIL_FIELD`, and `ACCOUNT_FIELD` from `@salesforce/schema/Contact`.
- `CONTACT_OBJECT` identifies the Contact object.
- The `fields` object lets the HTML template reference each imported field.
- `lightning-messages` displays validation and save errors.
- The Save button uses `type="submit"` to submit the form.
- The Cancel handler resets the fields to their initial values. It does not undo a record that has already been saved.

The screenshot shows the error “An error occurred while trying to update the record.” A screenshot alone cannot establish the cause. Check the detailed error, required fields, permissions, validation rules, duplicate rules, flows/triggers, and the Account lookup selection.

## 6. Create a Contact vs. Edit a Contact

### Create a new Contact

Omit `record-id` to create a new Contact.

```html
<lightning-record-edit-form object-api-name={objectApiName}>
    <lightning-messages></lightning-messages>
    <lightning-input-field field-name={fields.nameField}></lightning-input-field>
    <lightning-input-field field-name={fields.emailField}></lightning-input-field>
    <lightning-button type="submit" variant="brand" label="Save"></lightning-button>
</lightning-record-edit-form>
```

### Edit an existing Contact

Pass a valid Contact record ID.

```html
<lightning-record-edit-form
    object-api-name={objectApiName}
    record-id={recordId}
    onsuccess={handleSuccess}>
    <lightning-messages></lightning-messages>
    <lightning-input-field field-name={fields.nameField}></lightning-input-field>
    <lightning-input-field field-name={fields.emailField}></lightning-input-field>
    <lightning-button type="submit" variant="brand" label="Save"></lightning-button>
</lightning-record-edit-form>
```

Expose the record ID if Salesforce or a parent component supplies it:

```javascript
import { LightningElement, api } from 'lwc';

export default class ContactEditForm extends LightningElement {
    @api recordId;
}
```

When placed on a Contact Record Page, Salesforce supplies the current Contact record ID.

## 7. Important Attributes and Elements

| Attribute / element | Purpose |
|---|---|
| `object-api-name` | Specifies the object, such as Contact or Account. |
| `record-id` | Specifies an existing record to edit. Omit it to create a new record. |
| `lightning-input-field` | Renders an editable field using Salesforce metadata. |
| `lightning-messages` | Displays form validation and server errors. |
| `type="submit"` | Submits the form when the button is clicked. |
| `onsuccess` | Handles a successful save. |
| `onerror` | Handles a failed save. |
| `field-name` | Identifies the field using a field reference or field API name. |

## 8. Understanding Schema Imports

```javascript
import CONTACT_OBJECT from '@salesforce/schema/Contact';
import NAME_FIELD from '@salesforce/schema/Contact.Name';
import ACCOUNT_FIELD from '@salesforce/schema/Contact.AccountId';
```

- `CONTACT_OBJECT` is the Contact object reference.
- `NAME_FIELD` is the Contact Name field reference.
- `ACCOUNT_FIELD` is the Contact's Account lookup field reference.
- Schema imports provide references to Salesforce metadata and help Salesforce track dependencies.

## 9. Setup and Testing Steps

1. Open your Salesforce DX project in VS Code.
2. Create the component bundle:

   ```bash
   sf lightning generate component --name recordEditFormDemo --type lwc --output-dir force-app/main/default/lwc
   ```

3. Add the HTML, JavaScript, and XML code from this README.
4. Deploy the component:

   ```bash
   sf project deploy start --source-dir force-app/main/default/lwc/recordEditFormDemo
   ```

5. Open **Setup → Lightning App Builder**.
6. Add the component to a Lightning App Page, save, and activate the page.
7. Open the page and enter Contact details.
8. Click **Save** and confirm the success toast appears.
9. Test required fields and invalid values to see how errors are displayed.

The screenshot uses API version `67.0`. Use an API version supported by your Salesforce org and project.

## 10. Troubleshooting Save Errors

If the form shows “An error occurred while trying to update the record,” check:

1. The full error shown by `lightning-messages`.
2. Required Contact fields, especially Last Name.
3. Create/edit permissions for Contacts and access to the selected Account.
4. Field-level security.
5. Contact validation rules, duplicate rules, flows, and triggers.
6. Whether the Account lookup points to a valid Account.
7. If editing, whether `record-id` refers to a Contact in the current org.
8. Browser console and Salesforce debug logs if the visible message is not specific enough.

Do not assume the error is caused by the LWC itself; Salesforce validation or automation can also block a save.

## 11. Compare the Related Components

### `lightning-record-edit-form`
- Creates and updates records.
- Allows custom field placement.
- Uses `lightning-input-field`.
- Supports success and error events.

### `lightning-record-view-form`
- Displays specified fields in read-only mode.
- Uses `lightning-output-field`.
- Supports a custom field layout.

### `lightning-record-form`
- Provides a standard form with less markup.
- Can create, view, or edit records depending on attributes and mode.
- Offers less control over custom field placement than a manually composed form.

## 12. Interview Questions and Answers

### Q1. What is `lightning-record-edit-form`?
An LWC base component used to create or update Salesforce records with a customizable field layout.

### Q2. What is `lightning-input-field`?
It renders an editable field inside `lightning-record-edit-form`, using Salesforce field metadata.

### Q3. What is `lightning-messages`?
It displays errors and messages generated during form validation and record submission.

### Q4. How do you create a new record?
Specify `object-api-name`, include input fields, omit `record-id`, and provide a submit button.

### Q5. How do you update an existing record?
Provide both `object-api-name` and the existing record's `record-id`.

### Q6. What is the purpose of `onsuccess`?
It runs after Salesforce successfully saves the record. The event detail includes information such as the saved record ID.

### Q7. What is the purpose of `onerror`?
It lets you respond to a failed save. `lightning-messages` can display the associated form error.

### Q8. Does this component require Apex?
No. It uses Lightning Data Service for standard record create and update operations.

### Q9. How can you add a custom Save button?
Use `lightning-button` with `type="submit"` inside the form.

### Q10. How can you reset the form?
Select the `lightning-input-field` elements and call `reset()` on each one.

### Q11. Difference between `lightning-input-field` and `lightning-input`?
`lightning-input-field` is designed for Salesforce record fields and metadata inside record forms. `lightning-input` is a general input component and usually requires you to manage its value and save logic yourself.

### Q12. Why might a record fail to save?
Possible causes include missing required fields, invalid values, insufficient permissions, validation rules, duplicate rules, or errors in flows and triggers.

## 13. Scenario-Based Interview Questions

**Scenario 1: Create a Contact with Name, Title, Phone, Email, and Account.**  
Use `lightning-record-edit-form` with `object-api-name={objectApiName}` and one `lightning-input-field` for each field.

**Scenario 2: Update a Contact from its Record Page.**  
Expose `recordId` using `@api`, pass it to `record-id`, and handle success and error events.

**Scenario 3: Display a success message after saving.**  
Use the `onsuccess` handler and dispatch a `ShowToastEvent`.

**Scenario 4: Show users why a save failed.**  
Include `lightning-messages`, inspect the error event, and verify required fields, permissions, validation rules, and automation.

**Scenario 5: The form should have fields in a specific order.**  
Place `lightning-input-field` elements in the desired order and arrange them with SLDS layout classes.



## Summary

`lightning-record-edit-form` is an LWC base component for creating and updating Salesforce records with a custom field layout. Use `lightning-input-field` for editable Salesforce fields, `lightning-messages` to display errors, and a submit button to save. For standard record operations, Lightning Data Service handles the save process without requiring Apex.
