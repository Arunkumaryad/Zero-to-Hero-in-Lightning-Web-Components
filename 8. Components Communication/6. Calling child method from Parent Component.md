# Case 4 — Calling Child Method from Parent Component (LWC)

This project is part of a **Lightning Web Components (LWC)** learning series that demonstrates the different ways parent and child components can communicate with each other. This specific case (**Case 4**) shows how a **Parent Component can call a method defined inside a Child Component**.

---

## 📌 Concept Overview

In LWC, components are usually independent of each other, and data normally flows **one-way**, from parent to child, using properties (`@api` properties). But sometimes the parent needs to **trigger an action/method inside the child** — for example, resetting a slider, clearing a field, or refreshing child data.

To achieve this, LWC provides two key building blocks:

1. **`@api` decorator** — exposes a method (or property) of the child component so that it becomes *public* and can be accessed from outside the component (i.e., from the parent).
2. **`this.template.querySelector()`** — used inside the parent component to get a reference to the child component element that is present in the parent's own HTML template. Once you have this reference, you can directly call any `@api` decorated method on it.

### Flow Diagram

```
 ┌───────────────────────┐
 │    Parent Component    │
 └───────────┬────────────┘
             │
             ▼
 ┌───────────────────────┐
 │   Calling Child Method  │
 └───────────┬────────────┘
             │
             ▼
 ┌───────────────────────┐
 │    Child Component      │
 └───────────────────────┘
```

**In simple words:** The Parent Component contains a button. When the user clicks that button, the parent finds the child component in its own template and calls a public (`@api`) method that exists inside the child. This method then updates the child's internal state directly — without needing any custom event.

## 🧩 Component Code

### 1. Parent Component — `helloParentComponent.html`

This is the parent's template. Notice the `<c-child-slider-component>` tag — this is how the child component is embedded inside the parent. The **Reset Slider** button's `onclick` is wired to a handler in the parent JS.

```html
<template>
    <lightning-card title="Parent Component">
        <div class="slds-m-around_medium">
            <h1>Hello from Parent Component.</h1>
        </div>
    </lightning-card>

    <lightning-card title="Progress Bar Component">
        <div class="slds-m-around_medium">
            <h1>Progress Bar component</h1>
            <lightning-input type="text" label="Enter Percentage"
                onkeyup={handleChange}
                value={percentage}></lightning-input>
            <c-progress-component progress-value={percentage}></c-progress-component>
        </div>
    </lightning-card> <br> <br>

    <lightning-card title="Slider Component">
        <div class="slds-m-around_medium">
            <lightning-button variant="brand" label="Reset Slider" onclick={handleClick}></lightning-button>
            <c-child-slider-component></c-child-slider-component>
        </div>
    </lightning-card>
</template>
```

### 2. Parent Component — `helloParentComponent.js`

The important part here is the `handleClick` method:

```js
import { LightningElement } from 'lwc';

export default class HelloParentComponent extends LightningElement {
    percentage = 10;

    handleChange(event) {
        this.percentage = event.target.value;
    }

    handleClick(event) {
        this.template.querySelector('c-child-slider-component').resetSlider();
    }
}
```

- `this.template.querySelector('c-child-slider-component')` → finds the child component element inside the parent's template (the selector name is the **kebab-case** version of the child component's file name).
- `.resetSlider()` → directly invokes the `@api` decorated method exposed by the child component.

### 3. Child Component — `childSliderComponent.html`

```html
<template>
    <lightning-slider label="Volume" value={val} onclick={changeHandler}></lightning-slider>
</template>
```

### 4. Child Component — `childSliderComponent.js`

```js
import { LightningElement, api } from 'lwc';

export default class ChildSliderComponent extends LightningElement {
    val = 10;

    changeHandler(event) {
        this.val = event.target.value;
    }

    @api
    resetSlider() {
        this.val = 50;
    }
}
```

- `import { LightningElement, api } from 'lwc';` → `api` must be imported to use the `@api` decorator.
- `@api resetSlider() { ... }` → this decorator makes the method **public**, so it can be called from *outside* the component (i.e., from a parent component). Without `@api`, the method would remain private and inaccessible to the parent.

---

## ⚙️ How It Works (Step-by-Step)

1. The child component (`childSliderComponent`) defines a public method `resetSlider()` using the `@api` decorator.
2. The parent component (`helloParentComponent`) embeds the child using its custom tag: `<c-child-slider-component>`.
3. When the user clicks the **Reset Slider** button in the parent, the `handleClick` method runs.
4. Inside `handleClick`, `this.template.querySelector('c-child-slider-component')` locates the child element in the DOM (within the parent's own template).
5. `.resetSlider()` is then called directly on that child element reference, which executes the method defined inside the child component and updates the child's `val` property to `50`.
6. Since `val` is bound to the `lightning-slider` in the child's template, the slider UI updates immediately to reflect the reset value.

## 🔑 Key Takeaways

| Concept | Purpose |
|---|---|
| `@api` decorator | Exposes a property or method of a component so it can be accessed publicly from a parent |
| `this.template.querySelector()` | Lets the parent find a specific child element rendered in its own template |
| Kebab-case selector | Component tag names (e.g., `c-child-slider-component`) must be used in `querySelector`, not the class name |
| Direct method invocation | Once a reference to the child is obtained, any of its `@api` methods can be called like a normal JavaScript function |

## 💬 Interview Questions on This Topic

1. **What are the different ways components can communicate in LWC?**
   Parent-to-child (via `@api` properties), child-to-parent (via custom events), and unrelated components (via Lightning Message Service / pub-sub).

2. **How do you expose a method from a child component so the parent can call it?**
   By decorating the method with `@api` inside the child component's JavaScript class.

3. **How does a parent component get a reference to its child component?**
   Using `this.template.querySelector('child-component-tag-name')` inside the parent's JavaScript.

4. **What naming convention is used when referencing a child component inside `querySelector`?**
   The kebab-case version of the component's folder/file name, prefixed with `c-` (e.g., a component named `childSliderComponent` becomes `c-child-slider-component`).

5. **Can a parent component directly access a private (non-`@api`) property or method of a child?**
   No. Only members decorated with `@api` are accessible outside of the component; everything else is private by default.

6. **What is the difference between `@api` properties and `@api` methods?**
   `@api` properties expose *data* that flows from parent to child (often used for one-way data binding), while `@api` methods expose *behavior/functions* that the parent can invoke directly, typically to trigger an action inside the child.

7. **What happens if you call `querySelector` before the component is rendered?**
   It will return `null` because the child element does not yet exist in the DOM; this can cause a runtime error if you try to call a method on `null`. It's best to only call this inside event handlers or lifecycle hooks like `renderedCallback()`, after the DOM has been rendered.

8. **Why can't we use custom events for parent-to-child communication?**
   Custom events in LWC only flow *upward* (from child to parent). To go the other direction, you either pass data via `@api` properties or trigger behavior via `@api` methods.

9. **What is the significance of `this.template` in LWC?**
   `this.template` represents the shadow DOM of the current component. It allows querying only within that component's own rendered template, keeping DOM access scoped and encapsulated.

10. **Give a real-world use case for calling a child method from a parent.**
    Resetting a form or slider, refreshing a child's data table, opening/closing a modal defined in a child component, or triggering a validation check in a child component from a "Save" button in the parent.

## 🚀 How to Deploy

1. Create the LWC components using the Salesforce CLI or VS Code Salesforce Extension:
   ```
   sfdx force:lightning:component:create --type lwc --componentname helloParentComponent
   sfdx force:lightning:component:create --type lwc --componentname childSliderComponent
   ```
2. Copy the respective HTML/JS content into the generated files.
3. Deploy to your Salesforce org:
   ```
   sfdx force:source:deploy -p force-app/main/default/lwc/helloParentComponent
   sfdx force:source:deploy -p force-app/main/default/lwc/childSliderComponent
   ```
4. Add the `helloParentComponent` to an App Page / Record Page via the Lightning App Builder, or add it to an Aura/LWC tab for testing.

---

## 📝 Notes

- This pattern only works when the parent and child share a **direct parent-child relationship** (i.e., the child is embedded inside the parent's own template).
- For siblings or unrelated components, use **Lightning Message Service (LMS)** instead.
