## 📌 Topic

# Case 3 - Passing Data To Child On Action At Parent Component

This project demonstrates **Parent-to-Child communication in Lightning Web Components (LWC)** where the parent component changes its data based on a **user action** and then passes the updated data to the child component.

The example used in this project is a **Progress Bar Component**.

The user enters a percentage in the Parent Component. When the user performs the action of entering/updating the value, the Parent Component updates its `percentage` property and passes the updated value to the Child Component.

# 🧠 What is Parent-to-Child Communication?

Parent-to-Child communication means that a **Parent LWC passes information to its Child LWC**.

The basic communication flow is:

```text
Parent Component
       |
       | Data
       ↓
Child Component
```

In LWC, this is generally achieved using a public property created with the `@api` decorator in the child component.

Example:

```javascript
@api progressValue;
```

The parent can then pass a value to that property:

```html
<c-progress-component
    progress-value={percentage}>
</c-progress-component>
```

---

# 🔥 What Makes This Case Different?

In a basic Parent-to-Child example, the parent may simply have a fixed value:

```javascript
percentage = 10;
```

and directly pass it to the child.

But in this case, the value is **changed dynamically based on an action performed in the Parent Component**.

The flow is:

```text
User Action
     ↓
Parent Component
     ↓
handleChange()
     ↓
Update percentage
     ↓
Pass updated percentage
     ↓
Child Component
     ↓
Update Progress Bar
```

This is the important concept demonstrated by this example.

# 🧩 Why `progress-value` Instead of `progressValue`?

This is an important LWC concept.

JavaScript uses camelCase:

```javascript

```

HTML attributes use kebab-case:

```html
progress-value
```

Therefore:

```javascript
@api progressValue;
```

is passed from the parent as:

```html
progress-value={percentage}
```

This is the correct LWC naming convention.

# ⚡ Action-Based Communication

The special part of this example is the **action at the Parent Component**.

The action is:

```html
onkeyup={handleChange}
```

The parent reacts to this action.

```javascript
handleChange(event) {
    this.percentage = event.target.value;
}
```

Then the updated property is automatically passed to the child:

```html
<c-progress-component
    progress-value={percentage}>
</c-progress-component>
```

Therefore:

```text
ACTION
  ↓
Parent Data Changes
  ↓
Child Receives New Data
  ↓
Child UI Updates
```

Suppose the user enters the following values.

| User Input | Parent `percentage` | Child `progressValue` | Progress Bar |
| ---------: | ------------------: | --------------------: | -----------: |

|         25 |                  25 |                    25 |          25% |
|         50 |                  50 |                    50 |          50% |
|         75 |                  75 |                    75 |          75% |

The important point is that the Parent does not directly manipulate the Child's internal variable.

```text
Parent changes its own data
           ↓
Parent passes data
           ↓
Child receives data
```

LWC provides reactive rendering.

When the Parent property changes:


the template uses the updated value:

```html

```

and the Child receives the updated value.

This gives us:

```text
Data Change
    ↓
Template Re-evaluation
    ↓
Child Property Update
    ↓
Child Rendering
```

# ❌ Common Mistakes

## Mistake 1 — Forgetting `@api`

Incorrect:

```javascript
progressValue;
```

Correct:

```javascript
@api progressValue;
```

---

## Mistake 2 — Incorrect Attribute Name

If Child JavaScript contains:

```javascript
@api progressValue;
```

Parent HTML should use:

```html
progress-value={percentage}
```

not:

```html
progressValue={percentage}
```

---

## Mistake 3 — Incorrect Event Handler

Correct:

```html
onkeyup={handleChange}
```

and JavaScript:

```javascript
handleChange(event) {
    this.percentage = event.target.value;
}
```

The handler name must match.

---

## Mistake 4 — Trying to Access Child Property Directly

The Parent should not try to directly manipulate the Child's internal state.

Instead:

```text
Parent Data
    ↓
@api Property
    ↓
Child
```

---

## Mistake 5 — Confusing `@api` with Events

`@api` is primarily used for exposing public properties/methods from the Child.

For communication in the opposite direction:

```text
Child → Parent
```

Custom Events are commonly used.

# 🎤 Interview Questions

## 1. What is Parent-to-Child communication in LWC?

**Answer:**

Parent-to-Child communication is the process of passing data from a Parent LWC to a Child LWC. In LWC, this is commonly achieved by exposing a public property in the Child using the `@api` decorator.

---

## 2. What is the purpose of `@api`?

**Answer:**

`@api` is used to expose a property or method as part of the component's public API.

For Parent-to-Child communication, it allows the Parent to pass data to the Child.

Example:

```javascript
@api progressValue;
```

---

## 3. How is data passed from Parent to Child?

**Answer:**

The Child defines an `@api` property and the Parent passes a value to that property through the Child component's HTML attribute.

Example:

Child:

```javascript
@api progressValue;
```

Parent:

```html
<c-progress-component
    progress-value={percentage}>
</c-progress-component>
```

---

## 4. What is the purpose of `onkeyup` in this example?

**Answer:**

`onkeyup` listens for the keyboard key-release event. When the user enters or changes the percentage, it invokes the `handleChange()` method in the Parent Component.

```html
onkeyup={handleChange}
```

---

## 5. What does `event.target.value` mean?

**Answer:**

It represents the current value of the input element that triggered the event.

In this example:

```javascript
this.percentage = event.target.value;
```

takes the entered percentage and stores it in the Parent's `percentage` property.

---

## 6. Explain the complete data flow in this example.

**Answer:**

The user enters a percentage in the Parent.

```text
User Input
    ↓
keyup event
    ↓
handleChange()
    ↓
percentage updated
    ↓
progress-value={percentage}
    ↓
@api progressValue
    ↓
lightning-progress-bar
```

---

## 7. Why is `progressValue` written as `progress-value` in HTML?

**Answer:**

LWC uses JavaScript naming conventions in JavaScript and kebab-case for HTML attributes.

Therefore:

```javascript
progressValue
```

becomes:

```html
progress-value
```

---

## 8. Can the Parent pass dynamic data to the Child?

**Answer:**

Yes.

The Parent can pass a property whose value changes dynamically.

Example:

```html
<c-progress-component
    progress-value={percentage}>
</c-progress-component>
```

Whenever `percentage` changes, the Child receives the updated value.

---

## 9. Can we pass Objects using `@api`?

**Answer:**

Yes.

Example:

```javascript
@api account;
```

The Parent can pass an Account object.

---

## 10. Can we pass Arrays using `@api`?

**Answer:**

Yes.

Example:

```javascript
@api accounts;
```

The Parent can pass an Array or Array of Objects.

---

## 11. What is Child-to-Parent communication?

**Answer:**

Child-to-Parent communication is communication from the Child component back to the Parent component. Custom Events are commonly used for this.

Example:

```javascript
this.dispatchEvent(
    new CustomEvent('change')
);
```

---

## 12. Can the Child directly modify the Parent property?

**Answer:**

The recommended architecture is that the Parent owns its state. The Child should communicate a requested change back to the Parent using a Custom Event rather than directly modifying the Parent's state.

---

## 13. What happens when the Parent property changes?

**Answer:**

The updated value is passed to the Child's public property, and the Child's template can re-render using the new value.

---

## 14. What is the difference between `@api` property and `@api` method?

**Answer:**

An `@api` property is generally used to pass data to a Child.

Example:

```javascript
@api progressValue;
```

An `@api` method exposes functionality that the Parent can invoke on the Child.

Example:

```javascript
@api resetProgress() {
    // logic
}
```

---

## 15. What are the three common LWC communication patterns?

```text
Parent → Child
       ↓
      @api

Child → Parent
       ↓
Custom Event

Unrelated Components
       ↓
Lightning Message Service
```

Parent:

```javascript
percentage = 10;

handleChange(event) {
    this.percentage = event.target.value;
}
```

Then pass the value to the Child:

```html
<c-progress-component
    progress-value={percentage}>
</c-progress-component>
```

The Child exposes a public property:

```javascript
@api progressValue;
```

and uses it in the progress bar:

```html
<lightning-progress-bar
    value={progressValue}>
</lightning-progress-bar>
```

So the communication becomes:

```text
User Action
    ↓
Parent handleChange()
    ↓
percentage changes
    ↓
Child receives progressValue
    ↓
Progress Bar updates
```
