This project demonstrates **Parent-to-Child communication in Lightning Web Components (LWC)** using **non-primitive data types such as Objects and Arrays**.

The main purpose of this example is to understand how a parent LWC component can pass complex data to a child LWC component using the `@api` decorator.

# Introduction

Lightning Web Components provide different ways for components to communicate with each other.

When one LWC is placed inside another LWC:

```text
Parent Component
       |
       |  Data
       ↓
Child Component
```

The parent component can pass data to the child component.

For **Parent-to-Child communication**, the most common approach is to:

1. Define a public property in the child using `@api`.
2. Pass a value to that property from the parent.
3. The child receives the value and can use it in its HTML or JavaScript.

This project specifically focuses on passing **non-primitive data**, such as:

* Object
* Array
* Array of Objects

---

# What is Parent-to-Child Communication?

## Definition

**Parent-to-Child communication is the process of passing data or information from a parent Lightning Web Component to its child component.**

In LWC, this is commonly achieved by exposing a property or method in the child component using the `@api` decorator.

The parent then provides the value to that public property.

### Simple Flow

```text
Parent LWC
    |
    |  @api property
    |
    ↓
Child LWC
```

Example:

```text
Parent
  |
  |-- student object
  |
  ↓
Child
  |
  |-- displays student information
```

# Primitive vs Non-Primitive Data Types

Before understanding non-primitive communication, it is important to understand the difference between primitive and non-primitive data types.

## Primitive Data Types

Primitive data types represent a single value.

Examples:

```javascript
String
Number
Boolean
Null
Undefined
BigInt
Symbol
```

Example:

```javascript
studentName = 'Arun';
age = 25;
isActive = true;
```

Here:

```text
studentName → String
age         → Number
isActive    → Boolean
```

---

# Non-Primitive Data Types

Non-primitive data types can contain multiple values or structured data.

In JavaScript, the most commonly used non-primitive data types are:

* Object
* Array
* Array of Objects

### Object Example

```javascript
student = {
    name: 'Arun',
    age: 25,
    city: 'Delhi'
};
```

The variable `student` contains multiple properties.

```text
student
  |
  ├── name
  ├── age
  └── city
```

---

## Array Example

```javascript
students = [
    'Arun',
    'Rahul',
    'Amit'
];
```

An array can contain multiple values.

```text
students
   |
   ├── Arun
   ├── Rahul
   └── Amit
```

---

## Array of Objects

This is one of the most common structures used in Salesforce LWC.

```javascript
students = [
    {
        name: 'Arun',
        age: 25,
        city: 'Delhi'
    },
    {
        name: 'Rahul',
        age: 26,
        city: 'Noida'
    }
];
```

The structure is:

```text
Array
 |
 ├── Object
 |     ├── name
 |     ├── age
 |     └── city
 |
 └── Object
       ├── name
       ├── age
       └── city
```

# How Parent-to-Child Communication Works

For non-primitive data types, the parent passes an Object or Array to a public property of the child.

The child exposes the property using:

```javascript
@api
```

Example:

```javascript
@api student;
```

The parent can then pass the object:

```html
<c-child-component
    student={student}>
</c-child-component>
```

The communication looks like this:

```text
             PARENT
               |
               |
       student Object
               |
               ↓
        <c-child-component>
               |
               |
               ↓
             CHILD
               |
          @api student
```

# Parent Component

## parentComponent.js

```javascript
import { LightningElement } from 'lwc';

export default class ParentComponent extends LightningElement {

    student = {
        name: 'Arun',
        age: 25,
        city: 'Delhi',
        course: 'Salesforce'
    };
}
```

Here, `student` is an **Object**, which means it is a non-primitive data type.

---

## parentComponent.html

```html
<template>

    <lightning-card title="Parent Component">

        <div class="slds-p-around_medium">

            <p>
                Parent Component
            </p>

            <c-child-component
                student={student}>
            </c-child-component>

        </div>

    </lightning-card>

</template>
```

The important part is:

```html
<c-child-component
    student={student}>
</c-child-component>
```

This means:

```text
Parent's student property
          ↓
Child's student public property
```

# Child Component

## childComponent.js

```javascript
import { LightningElement, api } from 'lwc';

export default class ChildComponent extends LightningElement {

    @api student;

}
```

The important part is:

```javascript
@api student;
```

The `@api` decorator makes `student` a **public property** of the child component.

This allows the parent component to pass data to it.

```html
            </p>

            <p>
                Course: {student.course}

    </lightning-card>

</template>
```

The child can access the object properties using:

```javascript
student.name
student.age
student.city
student.course
```

# Understanding @api

`@api` is one of the most important decorators in Lightning Web Components.

It is used to expose a property or method as **public**, allowing other components to access it.

For Parent-to-Child communication:

```javascript
import { LightningElement, api } from 'lwc';
```

Then:

```javascript
@api student;
```

The child now exposes a public property named:

```text
student
```

The parent can set its value:

```html
<c-child-component
    student={student}>
</c-child-component>
```

# Real-World Salesforce Example

Suppose the parent component retrieves Account information.

```javascript
account = {
    Id: '001XXXXXXXXXXXX',
```

The parent can pass the Account object to the child:

```html
<c-account-details
```

Child:

```javascript
import { LightningElement, api } from 'lwc';

export default class AccountDetails extends LightningElement {
```

```html
<template>

```

This approach is very useful when a parent component already has data and multiple child components need to display different parts of that data.

# Important Points

## 1. Parent controls the data

The parent component owns the data that it passes to the child.

```text
Parent
  |
  └── Data
```

---

## 2. Child receives the data

The child exposes a public property using:

```javascript
@api
```

Example:

```javascript
@api student;
```

---

## 3. @api is required for public properties

Without `@api`, the parent cannot directly pass a value to the child's property.

Correct:

```javascript
@api student;
```

---

## 4. Parent-to-Child communication is one-way

The normal communication direction is:

```text
Parent
  ↓
Child
```

For communication in the opposite direction:

```text
Child
  ↓
Parent
```

we generally use **Custom Events**.

# Parent-to-Child vs Child-to-Parent

| Communication                   | Common Approach           |
| ------------------------------- | ------------------------- |
| Parent → Child                  | `@api`                    |
| Child → Parent                  | Custom Event              |
| Component → Unrelated Component | Lightning Message Service |
| Parent → Child Property         | `@api`                    |
| Parent → Child Method           | `@api` method             |

# Non-Primitive Data Types and References

One important JavaScript concept is that Objects and Arrays are reference types.

For example:

```javascript
student = {
    name: 'Arun'
};
```

The variable does not simply behave like an independent primitive value.

It refers to an object.

Therefore, when working with Objects and Arrays, developers should understand **reference behavior and data mutation**.

A safer pattern when creating modified data is often to create a new Object or Array rather than directly mutating an existing structure.

Example:

```javascript
this.student = {
    ...this.student,
    age: 26
};
```

For arrays:

```javascript
this.students = [
    ...this.students,
    newStudent
];
```

This creates a new reference and is a useful pattern when working with reactive data.

# Common Mistakes

## Mistake 1: Forgetting @api

Incorrect:

```javascript
import { LightningElement } from 'lwc';

export default class ChildComponent extends LightningElement {

    student;

}
```

Correct:

```javascript
import { LightningElement, api } from 'lwc';

export default class ChildComponent extends LightningElement {

    @api student;

}
```

---

## Mistake 2: Incorrect component name

If the child component folder is:

```text
childComponent
```

the parent normally references it as:

```html
<c-child-component>
</c-child-component>
```

---

## Mistake 3: Accessing the object incorrectly

If the object is:

```javascript
student = {
    name: 'Arun',
    age: 25
};
```

Correct:

```html
{student.name}
```

Incorrect:

```html
{name}
```

---

## Mistake 4: Forgetting key while iterating an array

Incorrect:

```html
<template for:each={students} for:item="student">

    <p>{student.name}</p>

</template>
```

Correct:

```html
<template for:each={students} for:item="student">

    <div key={student.id}>
        {student.name}
    </div>

</template>
```

# Interview Questions

## 1. What is Parent-to-Child communication in LWC?

**Answer:**

Parent-to-Child communication is the process of passing data from a parent LWC to a child LWC. In LWC, this is commonly achieved by exposing a public property or method in the child using the `@api` decorator.

---

## 2. How do you pass data from Parent to Child in LWC?

**Answer:**

The child exposes a property using `@api`, and the parent passes the value through the child's HTML tag.

Example:

Child:

```javascript
@api student;
```

Parent:

```html
<c-child-component
    student={student}>
</c-child-component>
```

---

## 3. Can we pass an Object from Parent to Child?

**Answer:**

Yes.

Objects are non-primitive/reference data types and can be passed to a child using an `@api` property.

Example:

```javascript
@api student;
```

Parent:

```html
<c-child-component
    student={student}>
</c-child-component>
```

---

## 4. Can we pass an Array from Parent to Child?

**Answer:**

Yes.

For example:

```javascript
@api students;
```

The parent can pass an array:

```html
<c-child-component
    students={students}>
</c-child-component>
```

---

## 5. What is @api in LWC?

**Answer:**

`@api` is a decorator used to expose a property or method as public so that it can be accessed by the component's parent.

---

## 6. Can @api be used with Objects?

**Answer:**

Yes.

Example:

```javascript
@api account;
```

The parent can pass an Account object to the child.

---

## 7. Can @api be used with Arrays?

**Answer:**

Yes.

Example:

```javascript
@api accounts;
```

The parent can pass an array of Account records.

---

## 8. What is the difference between primitive and non-primitive data?

**Answer:**

Primitive data represents a single value, such as:

```javascript
String
Number
Boolean
```

Non-primitive data can contain structured or multiple values, such as:

```javascript
Object
Array
Array of Objects
```

---

## 9. How does Child-to-Parent communication work?

**Answer:**

Child-to-Parent communication is normally implemented using **Custom Events**.

The child dispatches an event:

```javascript
this.dispatchEvent(
    new CustomEvent('message')
);
```

The parent listens to it:

```html
<c-child-component
    onmessage={handleMessage}>
</c-child-component>
```

---

## 10. Can a child directly modify the parent's property?

**Answer:**

A child should not directly mutate data received from the parent.

The recommended design is that the parent owns the state, while the child communicates changes back to the parent using an event.

---

## 11. What is the difference between @api property and @api method?

### @api Property

Used to pass data.

```javascript
@api student;
```

### @api Method

Used when the parent needs to call a method exposed by the child.

Example:

```javascript
@api
resetForm() {
    // logic
}
```

---

## 12. What happens if @api is not used?

The property will not be exposed as a public property of the child, so the parent cannot use it as a public API for Parent-to-Child communication.

---

## 13. Can we pass Salesforce records as Objects?

**Answer:**

Yes.

Salesforce records returned from Apex, LDS, or other Salesforce data services are commonly represented in JavaScript as objects and can be passed to child components through public `@api` properties.

Example:

```javascript
@api account;
```

---

## 14. Why are Objects and Arrays called non-primitive?

Because they represent structured data and can contain multiple values or properties, unlike primitive values such as a String, Number, or Boolean.

---

## 15. What is the communication mechanism for unrelated LWCs?

**Answer:**

When components do not have a direct parent-child relationship, **Lightning Message Service (LMS)** can be used for communication.

# Conclusion

Parent-to-Child communication is one of the fundamental concepts in Lightning Web Components.

For simple data:

```text
Parent → @api → Child
```

For complex/non-primitive data:

```text
Parent
   |
   | Object / Array / Array of Objects
   ↓
Child
   |
   | @api
   ↓
Consume Data
```

The most important thing to remember is:

> **The parent passes data, and the child exposes a public property using `@api` to receive that data.**

Understanding this concept is essential before moving to more advanced LWC communication patterns such as:

* Child-to-Parent communication
* Custom Events
* Sibling communication
* Lightning Message Service
* Public methods
* Reactive properties
* Apex data communication
* Lightning Data Service
