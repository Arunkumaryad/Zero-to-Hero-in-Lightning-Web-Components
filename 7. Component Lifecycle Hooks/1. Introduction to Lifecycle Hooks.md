# Introduction to Lifecycle Hooks (LWC)

## 📌 What is a Lifecycle Hook?

> **Definition:** A lifecycle hook is a callback method triggered at a specific phase of a component instance's lifecycle.

In simple words — when a Lightning Web Component (LWC) is created, rendered, updated, or removed from the page, Salesforce automatically calls certain special methods at those exact moments. These special methods are called **lifecycle hooks**.

Think of it like the "stages of life" of a component:
- It is **born** (created)
- It **grows up** and connects to the page (mounted)
- It **changes/updates** while being used (re-rendered)
- It eventually **leaves** the page (unmounted)
- Sometimes it **fails/errors** along the way

At each of these stages, LWC gives you a hook (a method) where you can write your own custom logic.

---

## 🔄 Phases of the LWC Lifecycle

The lifecycle of an LWC component is divided into **3 main phases**:

1. **Mounting Phase** – when the component is being inserted into the DOM
2. **Unmounting Phase** – when the component is being removed from the DOM
3. **Error Phase** – when something goes wrong in a descendant component

---

## 1️⃣ Mounting Phase

This is the phase when a component is being created and inserted into the DOM (the webpage). It runs the following hooks **in this exact order**:

### `constructor()`
- The first method called when a component instance is created.
- Used to initialize the component (set default values, etc.)
- **Important:** You cannot access child elements or component attributes (like public properties) here yet, because the component is not yet fully set up.

### `connectedCallback()`
- Called when the component is **inserted into the DOM**.
- Commonly used to:
  - Fetch data from Apex/server
  - Subscribe to events
  - Perform initialization logic that needs the component to be part of the DOM
- This can be called multiple times if a component is removed and re-inserted.

### `render()`
- An advanced/optional hook, rarely used directly.
- Lets you decide which HTML template should be rendered for the component (useful when a component has multiple templates).

### `renderedCallback()`
- Called **after** the component's template has been rendered into the DOM.
- Useful when you need to interact with the rendered DOM elements (e.g., using `this.template.querySelector`).
- Can be called multiple times — every time the component re-renders due to a data change.

---

## 2️⃣ Unmounting Phase

This phase happens when the component is being **removed** from the DOM.

### `disconnectedCallback()`
- Called when the component is removed from the DOM.
- Used for **cleanup** tasks, such as:
  - Unsubscribing from events
  - Clearing intervals/timeouts
  - Releasing resources

---

## 3️⃣ Error Phase

This phase is triggered only when something goes wrong.

### `errorCallback(error, stack)`
- Captures errors thrown in a **child component's** lifecycle hooks or in its template.
- Only works when defined in a **parent component** — it catches errors from its children.
- Useful for implementing error boundaries (showing a friendly error message instead of breaking the whole UI).

---

## 🧭 Visual Summary

| Phase | Hook | When it Fires |
|---|---|---|
| Mounting | `constructor()` | Component instance created |
| Mounting | `connectedCallback()` | Component inserted into DOM |
| Mounting | `render()` | Deciding which template to render |
| Mounting | `renderedCallback()` | After template is rendered into DOM |
| Unmounting | `disconnectedCallback()` | Component removed from DOM |
| Error | `errorCallback()` | Error occurs in a child component |

---

## 💡 Simple Real-Life Analogy

Imagine setting up a new shop:
1. **constructor()** → You get the empty shop space and basic setup done (no customers yet).
2. **connectedCallback()** → You officially open the shop and connect to your suppliers (fetch data).
3. **render()** → You decide the layout/decoration of the shop.
4. **renderedCallback()** → Customers can now see the shop as fully set up; you make final touch-ups.
5. **disconnectedCallback()** → You close the shop and clean everything up.
6. **errorCallback()** → If something goes wrong with a staff member (child component), the shop manager (parent component) handles it.

## 🎯 Interview Questions on LWC Lifecycle Hooks

Below are commonly asked interview questions on this topic, along with brief pointers to help you answer confidently:

1. **What is a lifecycle hook in LWC?**
   - A callback method automatically invoked by the framework at a specific stage of a component's life (creation, rendering, update, removal).

2. **What are the different lifecycle hooks available in LWC?**
   - `constructor()`, `connectedCallback()`, `render()`, `renderedCallback()`, `disconnectedCallback()`, `errorCallback()`.

3. **What is the order of execution of lifecycle hooks when a component is created?**
   - `constructor()` → `connectedCallback()` → `render()` → `renderedCallback()`.

4. **Can you access child elements inside the constructor()?**
   - No, because the DOM elements are not yet rendered when the constructor runs.

5. **What is the difference between `connectedCallback()` and `renderedCallback()`?**
   - `connectedCallback()` runs when the component is inserted into the DOM (before rendering completes), while `renderedCallback()` runs after the template has been rendered — so DOM elements are accessible in `renderedCallback()`.

6. **Is `connectedCallback()` called only once?**
   - No. It can be called multiple times if the component is removed and re-added to the DOM.

7. **What is `disconnectedCallback()` used for?**
   - Cleanup operations like removing event listeners, clearing timers/intervals, or unsubscribing from data streams when a component is removed from the DOM.

8. **What is `errorCallback()` and where should it be defined?**
   - It captures errors thrown in a child component's lifecycle hooks or template, and it must be defined in the **parent** component (not the component that throws the error).

9. **Can `renderedCallback()` cause an infinite loop?**
   - Yes, if you update reactive properties inside `renderedCallback()` without proper conditions, it can trigger repeated re-renders, causing performance issues or an infinite loop.

10. **Why can't you use `super()` arguments or access `this` before calling `super()` in the constructor?**
    - Just like standard JavaScript classes, LWC components extend `LightningElement`, so `super()` must be called first before using `this`, ensuring the base class is properly initialized.

11. **What is the difference between `render()` and `renderedCallback()`?**
    - `render()` decides *which* template to render (used mainly for conditional templates), while `renderedCallback()` runs *after* the template is rendered.

12. **What are the 3 phases of the LWC component lifecycle?**
    - Mounting Phase, Unmounting Phase, and Error Phase.

---

## 📚 Quick Recap

- Lifecycle hooks = special methods called automatically at different stages of a component's life.
- **Mounting Phase:** `constructor()` → `connectedCallback()` → `render()` → `renderedCallback()`
- **Unmounting Phase:** `disconnectedCallback()`
- **Error Phase:** `errorCallback()`
