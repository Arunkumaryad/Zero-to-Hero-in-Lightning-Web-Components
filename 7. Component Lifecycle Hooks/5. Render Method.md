# Render Method in LWC

## 📌 Overview

In Lightning Web Components (LWC), the `render()` method is used when a component needs to choose **which HTML template should be rendered** based on some condition.

Normally, an LWC component has one HTML template:

```text
myComponent/
│
├── myComponent.html
├── myComponent.js
└── myComponent.js-meta.xml
```

However, sometimes the same component needs to display completely different UI designs.

For example:

```text
Same LWC Component
        │
        ├── Signup Template
        │
        └── Signin Template
```

Instead of putting both designs into one large HTML file and using many conditional statements, we can create multiple HTML templates and use the `render()` method to select the appropriate template.

---

# 📖 Definition

> **Render is a method that tells the component which template to load based on some conditions. It always return the template reference.**

In simple words:

`render()` decides **which HTML template should be displayed**.

Example:

```javascript
render() {
    return this.selectedBtn === 'Signin'
        ? signinTemplate
        : signupTemplate;
}
```

The `render()` method must return a valid HTML template reference. Salesforce describes `render()` as a protected method on `LightningElement`, rather than technically being a lifecycle hook.

---

# ⭐ Points to Remember

The following points are taken from the provided screenshots.

## 1. `render()` is not technically a lifecycle hook

> **The render() method is not technically a lifecycle hook. It is a protected method on the LightningElement class.**

This is an important interview point.

Although `render()` is commonly discussed along with lifecycle hooks, technically it is a **protected method inherited from `LightningElement`**.

```javascript
export default class MyComponent extends LightningElement {

    render() {
        return myTemplate;
    }

}
```

Salesforce specifically documents `render()` as a protected method rather than a lifecycle hook.

---

# 2. `render()` updates the UI

> **Call this method to update the UI. It may be called before or after connectedCallback().**

The `render()` method determines the template used to render the component.

It can be called before or after `connectedCallback()`.

Salesforce recommends defining `render()` only when there is a specific need, such as choosing between multiple templates.

---

# 3. `render()` is rarely used

> **It’s rare to call render() in a component. The main use case is to conditionally render a template.**

In most LWC components, you don't need to write a custom `render()` method.

For normal conditional UI, use conditional template directives such as:

```html
<template lwc:if={condition}>
```

or:

```html
<template lwc:else>
```

The main reason to use `render()` is when you have **multiple separate HTML templates** and need to choose one of them.

---

# 🎯 Why Do We Need Multiple Templates?

Suppose we have a component that needs two completely different designs:

```text
User Component
      │
      ├── Sign In UI
      │
      └── Sign Up UI
```

We could put everything in one HTML file:

```html
<template>

    <template lwc:if={isSignin}>
        <!-- Signin HTML -->
    </template>

    <template lwc:else>
        <!-- Signup HTML -->
    </template>

</template>
```

This works.

But when the two designs become large, the HTML file can become difficult to maintain.

Instead, we can create:

```text
renderMethod/
│
├── renderMethod.html
├── renderMethod.js
├── renderMethod.js-meta.xml
├── signinTemplate.html
└── signupTemplate.html
```

Then `render()` decides which template to display.

# 💻 Main JavaScript

## renderMethod.js

```javascript
import { LightningElement } from 'lwc';

import signinTemplate from './signinTemplate.html';
import signupTemplate from './signupTemplate.html';
import renderTemplate from './renderMethod.html';

export default class RenderMethod extends LightningElement {

    selectedBtn = '';

    render() {

        return this.selectedBtn === 'Signin'
            ? signinTemplate
            : this.selectedBtn === 'Signup'
                ? signupTemplate
                : renderTemplate;
    }

    handleClick(event) {

        this.selectedBtn = event.target.label;
    }

    handleSubmit(event) {

        console.log(`${event.target.label} successfully`);
    }
}
```

# 🔄 Why Does Changing `selectedBtn` Cause Rerendering?

`selectedBtn` is used by the component's rendering logic.

When its value changes:

```javascript
this.selectedBtn = 'Signin';
```

the component's UI can be reevaluated.

The LWC rendering system updates the component when reactive state used by the template changes. Salesforce describes this as the component becoming dirty and a rerender being queued.

# ⚠️ Important: `render()` vs Conditional Rendering

There are two common approaches.

## Approach 1 — Conditional Rendering

Use:

```html
<template lwc:if={condition}>
```

Example:

```html
<template>

    <template lwc:if={isSignin}>

        <c-signin-form></c-signin-form>

    </template>

    <template lwc:else>

        <c-signup-form></c-signup-form>

    </template>

</template>
```

This is preferred for normal conditional UI.

---

# Approach 2 — Multiple Templates with render()

Use:

```javascript
render() {
    return signinTemplate;
}
```

when you have multiple completely different HTML templates that belong to the same component.

---

# 🆚 Multiple Templates vs `lwc:if`

| Feature                                   | `lwc:if` / `lwc:else` | `render()`            |
| ----------------------------------------- | --------------------- | --------------------- |
| Simple show/hide                          | ✅ Best choice         | ❌ Usually unnecessary |
| Small UI differences                      | ✅ Best choice         | ❌ Usually unnecessary |
| Completely different layouts              | ⚠️ Can become large   | ✅ Good choice         |
| Separate HTML files                       | ❌                     | ✅                     |
| Same business logic                       | ✅                     | ✅                     |
| Multiple designs/look & feel              | ⚠️                    | ✅                     |
| Easy to maintain large separate templates | ⚠️                    | ✅                     |

Salesforce currently recommends `lwc:if`, `lwc:elseif`, and `lwc:else` over the older `if:true` and `if:false` directives.

# ⚠️ Important Rule

Do not use `render()` just because you need to hide or show a small element.

For example, don't do this:

```javascript
render() {
    return this.showButton
        ? template1
        : template2;
}
```

when the difference is only one button.

Instead:

```html
<template lwc:if={showButton}>
    <lightning-button label="Save"></lightning-button>
</template>
```

This is simpler and more readable.

# 🔥 `render()` vs `renderedCallback()`

This is a very common interview question.

## `render()`

```javascript
render() {
    return myTemplate;
}
```

Purpose:

**Choose which template should be rendered.**

It is a protected method on `LightningElement`, not technically a lifecycle hook.

---

## `renderedCallback()`

```javascript
renderedCallback() {

    console.log('Component rendered');
}
```

Purpose:

**Run code after the component has finished rendering.**

Salesforce documents `renderedCallback()` as a lifecycle hook that runs after rendering.

---

# 🆚 Quick Comparison

| `render()`                           | `renderedCallback()`                     |
| ------------------------------------ | ---------------------------------------- |
| Selects a template                   | Executes after rendering                 |
| Returns template reference           | Does not return a template               |
| Protected method                     | Lifecycle callback                       |
| Used for multiple templates          | Used for post-render logic               |
| Runs before/around rendering process | Runs after rendering                     |
| Rarely overridden                    | Common when post-render work is required |

# 🚨 Common Mistakes

## Mistake 1 — Forgetting to return a template

Incorrect:

```javascript
render() {

    this.selectedBtn === 'Signin'
        ? signinTemplate
        : signupTemplate;
}
```

Correct:

```javascript
render() {

    return this.selectedBtn === 'Signin'
        ? signinTemplate
        : signupTemplate;
}
```

`render()` must return a valid template reference.

---

# Mistake 2 — Using `render()` for every condition

Don't use multiple templates for tiny UI changes.

Prefer:

```html
<template lwc:if={condition}>
```

for normal conditional rendering. Salesforce's current guidance recommends the modern `lwc:if`, `lwc:elseif`, and `lwc:else` directives.

---

# Mistake 3 — Creating One Huge Template

If you have:

```text
500+ lines
```

of HTML containing multiple unrelated designs, consider breaking the UI into smaller components or separate templates.

---

# Mistake 4 — Mixing Business Logic with HTML

Keep business logic in:

```text
component.js
```

and UI structures in:

```text
template.html
```

This makes the code easier to maintain.

# 🎯 Interview Questions

## 1. What is the `render()` method in LWC?

### Answer

`render()` is a protected method of `LightningElement` that determines which HTML template the component should render.

It is primarily used when a component needs to conditionally render one of multiple HTML templates.

---

## 2. Is `render()` a lifecycle hook?

### Answer

Technically, **no**.

`render()` is a protected method on the `LightningElement` class.

Although it is commonly discussed with lifecycle hooks, Salesforce explicitly distinguishes it from lifecycle callbacks.

---

## 3. What does `render()` return?

### Answer

It returns a valid HTML template reference.

Example:

```javascript
render() {
    return signinTemplate;
}
```

---

## 4. Why would you use multiple templates?

### Answer

Multiple templates are useful when the same component has:

* Same business logic
* Different UI designs
* Different look and feel
* Large independent HTML structures

For example:

```text
Same Logic
   │
   ├── Desktop Template
   └── Mobile Template
```

---

## 5. Can an LWC have multiple HTML files?

### Answer

Yes.

A component bundle can contain multiple HTML templates, and JavaScript can import those templates and return the appropriate one from `render()`.

Example:

```javascript
import template1 from './template1.html';
import template2 from './template2.html';
```

---

## 6. What is the difference between `render()` and `renderedCallback()`?

### Answer

`render()` determines which template should be rendered.

`renderedCallback()` runs after the component has rendered.

```text
render()
   ↓
Choose Template
   ↓
Render UI
   ↓
renderedCallback()
```

---

## 7. When should you use `lwc:if` instead of `render()`?

### Answer

Use `lwc:if`, `lwc:elseif`, and `lwc:else` for normal conditional rendering, especially when only a small section of the UI needs to be shown or hidden.

Use `render()` when the component needs to switch between separate HTML templates.

---

## 8. Is `render()` called automatically?

### Answer

The LWC framework invokes the rendering process. Developers generally don't manually call `render()`.

You define/override it when you need custom template selection.

---

## 9. What happens when a reactive property used by the component changes?

### Answer

The component can be marked dirty and rerendered.

For example:

```javascript
this.selectedBtn = 'Signin';
```

changes the component state.

The rendering process reevaluates the component and `render()` can return the appropriate template.

---

## 10. Can `render()` return any JavaScript object?

### Answer

No.

It must return a valid HTML template reference.

For example:

```javascript
return signinTemplate;
```

is valid.

---

## 11. Can we use the same JavaScript logic with multiple templates?

### Answer

Yes.

This is one of the main benefits of multiple templates.

For example:

```text
renderMethod.js
      │
      ├── signinTemplate.html
      └── signupTemplate.html
```

The JavaScript contains common logic while the templates contain different UI structures.

---

## 12. What is the main use case of `render()`?

### Answer

The main use case is **conditionally rendering multiple templates**.

Salesforce specifically identifies conditional template selection as the primary reason to define `render()`.

---

# ✅ Final Takeaway

The most important concept is:

```text
render()
   ↓
Selects the template
   ↓
Based on component state/condition
   ↓
Returns template reference
   ↓
LWC renders that template
```

Use `render()` mainly when you have **multiple substantially different templates** that should share the same JavaScript/business logic.

For simple show/hide requirements, prefer the modern:

```html
<template lwc:if={condition}>
```

```html
<template lwc:elseif={condition}>
```

```html
<template lwc:else>
```

This keeps the component simpler and follows current Salesforce LWC guidance.
